# Справка, документы и таблицы для «Связного» — договор с приложениями

Этот файл — договор между Tridot «Связной» и приложениями, к которым он
подключается (склад halowarekeep, склад DepotDesk, «Автосервис» severauto).
Приложение отдаёт данные, Связной их показывает и объясняет. Нейросети в
Связном нет: он ничего не сочиняет, все тексты справки пишет приложение.

Описание команд — прежнее `assistant.json` формата `assistant/1`
(`docs/CONNECTORS.md`, у halowarekeep — `tools/assistant/README.md`).
Здесь — три дополнения:

1. **Справка** — отдельный файл `assistant-help.json` формата
   `assistant-help/1`: темы «как сделать…», шаги, что за что отвечает,
   куда уходят данные, кто за это отвечает.
2. **Документ** — ответ команды `answer.doc`: сводка одного документа
   (приход, операция, отгрузка, заявка на запчасть) с фактами, таблицами и
   «что дальше».
3. **Таблица** — `answer.table` у списочных команд: колонки, итоги,
   группировка; Связной показывает её в чате и в режиме «Документ».

Все дополнения обратно совместимы: старый Связной их пропускает, новый
Связной работает и со старым описанием (без справки и документов).

## 1. Справка `assistant-help/1`

### Где лежит

Ссылка в `assistant.json`:

```json
"help": { "url": "assistant-help.json", "version": "1.4.74" }
```

- `url` — того же источника (схема, хост, порт), что и `assistant.json`;
  относительный путь — от адреса описания.
- Файл ≤ 512 КБ, `Content-Type: application/json`, отдаётся с `ETag` или
  `Last-Modified` (Связной спрашивает с `If-None-Match`).
- Справка публичная, как памятка в самом приложении: без логинов, имён,
  телефонов, адресов, ключей, путей к серверу. Читается без входа.
- В справке нет действий (`call`) — она не расширяет права помощника,
  поэтому Связной берёт новую версию с сервера без выпуска приложения.

### Формат

```json
{
  "format": "assistant-help/1",
  "app": "halowarekeep",
  "version": "1.4.74",
  "source": { "file": "guide/guide.json", "hash": "sha256:…" },

  "perms": {
    "moves": { "label": "Перемещения и пересчёт", "group": "Склад" },
    "kit":   { "label": "Комплекты", "group": "Склад", "fallback": "moves" }
  },
  "roles": {
    "keeper":  { "label": "Кладовщик", "perms": ["entryAdd", "moves", "kit"] },
    "manager": { "label": "Менеджер", "perms": [] }
  },
  "grantedBy": "администратор склада: «Управление» → «Роли»",

  "topics": [
    {
      "id": "move",
      "title": "Переместить и пересчитать",
      "tabs": ["moves"],
      "audience": "user",
      "say": [
        "как переместить {thing}",
        "как перенести {thing} в ячейку",
        "как сделать перемещение"
      ],
      "keywords": ["перемест", "перенес", "переложить", "ячейк"],
      "need": { "perms": ["moves"] },
      "owner": {
        "roles": ["keeper"],
        "text": "Перемещения делает кладовщик — у кого право «Перемещения и пересчёт»."
      },
      "summary": "Перемещение меняет ячейку товара, пересчёт исправляет количество.",
      "outsider": "Коротко: во вкладке «Операции» выбирают товар, ячейку «откуда» и «куда» и сохраняют.",
      "steps": [
        {
          "id": "move.open",
          "short": "Операции → «+» → «Перемещение».",
          "detail": "Кнопка «+» внизу вкладки открывает новую операцию. …",
          "controls": [
            { "name": "«Откуда»", "does": "ячейка, где товар лежит сейчас; в списке только ячейки с остатком" },
            { "name": "«Куда»", "does": "новая ячейка; можно ввести код с наклейки или выбрать на схеме" }
          ],
          "data": "Сохранение создаёт операцию ПЕР-… во вкладке «Операции» и строку в «Истории». Остаток по ячейкам меняется сразу.",
          "need": { "perms": ["moves"] }
        }
      ],
      "more": ["Пересчёт — та же вкладка, «+» → «Пересчёт»: …"],
      "related": { "commands": ["where", "cell"], "docs": ["op"], "topics": ["find"] }
    }
  ]
}
```

### Поля

| Поле | Что это |
|---|---|
| `perms` | Все права приложения: id → подпись, группа, `fallback` (право, которое его заменяет). |
| `roles` | Готовые роли: id → подпись и права. Нужны, чтобы назвать, **кто** это делает. |
| `grantedBy` | Кто выдаёт права — одной фразой. |
| `topics[].id` | Стабильный id темы (латиница, `a-z0-9._-`). Не меняется при правке текста. |
| `title` | Название темы, как в памятке. |
| `tabs` | Вкладки или разделы приложения, к которым относится тема. |
| `audience` | `user` — всем; `admin` — только администраторам (копии, ключи, сервер). Остальным Связной отвечает лишь `owner.text`. |
| `say` | Вопросы, по которым тема находится («как переместить {thing}»). `{thing}` — любой текст: Связной предложит «Найти, где лежит «стул»». |
| `keywords` | Начала слов для запасного поиска, если вопрос не совпал с `say`. |
| `need.perms` | Права, нужные для темы целиком. Любое из списка достаточно. |
| `owner` | Кто за это отвечает: роли (`roles`) и готовая фраза (`text`). |
| `summary` | Зачем это — одна-две фразы. |
| `outsider` | Короткое объяснение для того, у кого нет права (одна-три фразы). |
| `steps[]` | Шаги по порядку, не больше 15. |
| `steps[].id` | Стабильный id шага `<тема>.<слово>`. |
| `steps[].short` | Шаг одной строкой (≤ 140 знаков) — как в памятке. |
| `steps[].detail` | Подробно (≤ 800 знаков): что происходит и зачем. |
| `steps[].controls` | Кнопки и поля шага: `name` — как подписано на экране, `does` — за что отвечает. |
| `steps[].data` | Куда уходят данные: какой документ создаётся или меняется, что попадает в историю, что видят другие. |
| `steps[].need` | Права для этого шага, если они другие, чем у темы. |
| `more` | Дополнительные пункты («Подробнее» в памятке). |
| `related` | Связанные команды помощника, виды документов и темы. |

Пределы: тем ≤ 200, фраз `say` в теме ≤ 30 и ≤ 120 знаков каждая,
`summary` и `outsider` ≤ 400 знаков. Неизвестные поля Связной пропускает,
неверный `format` — отклоняет файл целиком (остаётся прежняя справка).

### Как Связной этим пользуется

1. «Как мне переместить стул в ячейку?» → тема `move`: `summary` и шаги
   (`short`) списком; под ответом — «Понятно», «Не понял шаг…» и
   связанные темы. Фразы-действия («перемести 64115 в A-1-2») идут к
   команде, а не к справке: вопрос «как …» — справка.
2. «Не понял» → «Какой шаг непонятен?» с кнопками «1», «2», … Ответ
   «второй», «2», «шаг 2» → `detail`, затем «Что за что отвечает»
   (`controls`) и «Куда уходят данные» (`data`). Дальше — «Следующий шаг» и
   «Всё понятно».
3. **Роль.** Права пользователя Связной знает из `ask_me` (или аналога).
   - Право есть — полные шаги и подробности.
   - Права нет — `outsider` (или первые три `short`) и пояснение: «Подробно
     не расписываю: это не входит в вашу роль (Менеджер). Это делает
     Кладовщик — у кого право «Перемещения и пересчёт». Право выдаёт
     администратор склада». Подробности шагов такой темы не раскрываются.
   - Тема `admin` у не-администратора — только `owner.text`.
   - Вход без личного ключа (роль неизвестна) — полные шаги и приписка
     «Войдите под своим логином — подскажу с учётом вашей роли».
   Роль в справке — подсказка, а не защита: права по-прежнему проверяет
   сервер.

### Откуда справка берётся

Справку **не пишут второй раз**: её собирает сборка приложения из его же
документации (памятка, руководство пользователя) и из таблицы прав в коде.
Тест сборки падает, если справка устарела, если тема ссылается на
несуществующее право или вкладку, или если `owner.roles` не держит нужное
право. Так памятка в приложении, справка Связного и настоящие права не
расходятся.

## 2. Документ `answer.doc`

Команда, которая читает **один** документ (по номеру или «последний»),
вместо списка отдаёт документ:

```json
{
  "id": "entry",
  "title": "Приход",
  "say": ["последний приход", "мой последний приход", "приход {no}",
          "расскажи про приход {no}", "что по приходу {no}"],
  "slots": { "no": { "label": "номер прихода", "type": "docno",
                     "words": { "последний": { "last": true },
                                "мой последний": { "last": true, "mine": true } } } },
  "access": "staff",
  "call": { "action": "ask_entry", "body": { "no": "{no}" } },
  "answer": {
    "say": "Приход {no} от {day|date}: {totals.positions|num} поз., {stageLabel}.",
    "empty": "Прихода {no} нет.",
    "doc": {
      "title": "Приход {no}",
      "facts": [
        { "label": "Вид", "value": "{kindLabel}" },
        { "label": "Стадия", "value": "{stageLabel}" },
        { "label": "Создал", "value": "{created.who}, {created.at|date}" }
      ],
      "sections": [
        { "title": "Позиции", "table": {
            "rows": "items",
            "columns": [
              { "key": "sku", "label": "Артикул" },
              { "key": "name", "label": "Товар" },
              { "key": "qtyDoc", "label": "По док.", "type": "num", "total": "sum" },
              { "key": "qty", "label": "Факт", "type": "num", "total": "sum" },
              { "key": "diff", "label": "Расх.", "type": "num", "highlight": "nonzero" },
              { "key": "clsLabel", "label": "Класс", "type": "badge" }
            ],
            "max": 300 } },
        { "title": "История", "table": {
            "rows": "history",
            "columns": [
              { "key": "at", "label": "Когда", "type": "datetime" },
              { "key": "who", "label": "Кто" },
              { "key": "what", "label": "Что" }
            ] } }
      ],
      "next": "next"
    }
  }
}
```

- **Слот `docno`** — номер документа; `shape` в слоте задаёт, как он
  выглядит у приложения. `words` превращает «последний» в
  `{"last": true}` в теле запроса.
- **`facts`** — пары «подпись — значение», ≤ 12.
- **`sections[].table`** — `rows` (путь к массиву в ответе), `columns`
  (`key`, `label`, `type`: `text` | `num` | `money` | `date` | `datetime` |
  `badge` | `list` | `yesno`; `total`: `sum` | `count`; `highlight`:
  `nonzero`), `max` строк (≤ 500). Колонок ≤ 12, секций ≤ 20.
- **`sections[].text`** — абзац вместо таблицы.
- **`next`** — путь к массиву «что дальше с документом», который считает
  **сервер**: `[{ "id": "post", "title": "Провести в SV и 1С",
  "need": { "perms": ["post"] }, "topic": "post" }]`. Связной покажет шаги и
  пометит чужие: «(это делает Кладовщик)»; `topic` — ссылка на тему
  справки, «Как это сделать?».

В чате Связной показывает `say`, до пяти фактов и первые восемь строк
таблицы; кнопка «Открыть в Документе» — весь документ в режиме «Документ»
(таблицы с итогами, «Скопировать», «Обновить»).

## 3. Таблица `answer.table` у списочных команд

```json
"answer": {
  "say": "За неделю {count|plural:приход,прихода,приходов}.",
  "list": "items",
  "item": { "title": "{no}", "text": "{reason}", "badge": "{positions|num} поз." },
  "table": {
    "title": "Приходы за неделю",
    "columns": [
      { "key": "day", "label": "День", "type": "date" },
      { "key": "no", "label": "Номер" },
      { "key": "kindLabel", "label": "Вид", "type": "badge" },
      { "key": "positions", "label": "Позиций", "type": "num", "total": "sum" },
      { "key": "qty", "label": "Штук", "type": "num", "total": "sum" }
    ],
    "groupBy": "kindLabel"
  }
}
```

`rows` по умолчанию — `list`. «Сделай таблицу», «сводкой», «сведи в
таблицу» после такого ответа (или вместе с вопросом: «сводка приходов за
неделю») — Связной собирает таблицу и открывает её в режиме «Документ».
Без `table` Связной построит колонки сам из `item` (`title`, `text`,
`badge`).

## 4. «Кто я» и роли

Связной уже спрашивает «кто я» (`ask_me` у склада). Для справки по ролям
ответ должен содержать:

```json
{ "ok": true, "login": "ivanov", "name": "Иван Петров",
  "role": "keeper", "roleLabel": "Кладовщик",
  "all": false, "perms": ["entryAdd", "moves", "kit"],
  "helpVersion": "1.4.74" }
```

`perms` — уже с учётом `fallback` (раскрытые). Отказ сервера по праву —
`403` с `"need": "perm"` и `"perm": "<id>"`: Связной назовёт право и того,
кто за него отвечает.
