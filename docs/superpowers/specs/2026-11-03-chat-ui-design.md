# Chat-first UI: тёмный минимализм

## Цель

Обновить визуальное взаимодействие с локальным помощником до современного chat-first интерфейса, знакомого по ChatGPT, Claude Code и Kimi Code, без копирования конкретного продукта и без изменения сценариев/хранилища.

## Что выбрал пользователь

- Основное место занимает диалог; задачи скрыты по умолчанию и открываются в правой панели.
- Тёмный developer-стиль, затем смягчённый до минималистичного: глубокий чёрный фон, спокойный текст, тонкие разделители, почти нет теней.
- Капсульные кнопки и поле ввода, приглушённый серо-зелёный акцент.
- Схема активности из квадратиков нужна только как визуальный эскиз, без правил наполнения реальными данными.

## Подходы

1. Выбран: chat-first со скрываемой правой панелью задач. Даёт диалогу больше места и сохраняет быстрый доступ к контексту.
2. Отклонён: постоянная правая колонка на desktop и список снизу на Android. Занимает слишком много пространства.
3. Отклонён: постоянный блок статистики с демонстрационными числами. Противоречит честному поведению помощника.

## Объём реализации

- Единая тёмная Material-тема: `#000000` фон, поверхности около `#0C0D0F`, нейтральные границы и приглушённый акцент.
- Центральная читаемая колонка сообщений с ограничением ширины и адаптивными отступами.
- Ответы помощника без тяжёлых карточек; команды пользователя в аккуратных пузырях; моноширинный текст команд там, где это уместно.
- Автоматическая прокрутка к последнему сообщению после отправки/ответа, чтобы ответ не оставался скрытым.
- Капсульное поле команды с круглой кнопкой отправки и рабочими быстрыми действиями. «Покажи задачи» и «Заверши её» отправляют команду; «Новая задача» подставляет шаблон, не отправляя его автоматически.
- Панель задач через существующий `Scaffold.endDrawer`, скрытая по умолчанию на всех размерах. Она показывает активные задачи и позволяет выбрать задачу без изменения `AssistantController`.
- Компактная строка выбранной задачи над полем ввода. `HomePage` хранит только выбранный в UI `Task?`: создание устанавливает её, перенос обновляет, завершение очищает, новый процесс начинается без выбора. Публичные интерфейсы не меняются.
- Все кнопки макета получают реальное поведение либо не добавляются. Панель закрывается после выбора на узком экране.

## Не входит

- Статистика и квадратики с выдуманными значениями, телеметрия и новый журнал команд.
- История чатов, аккаунты, сервер, языковые модели, облачная синхронизация и SQLite.
- Новый state management, новые зависимости и изменения `TaskService`/`TaskRepository`.
- Реальная схема активности: её источник и правила будут отдельным этапом.

## Тесты и проверка

- Добавить widget-тесты через существующий `flutter_test`: панель закрыта по умолчанию и открывается кнопкой; выбор задачи показывает её контекст; быстрые действия выполняют ожидаемую команду/подстановку; последний ответ виден на маленьком экране после переполнения списка.
- Для изменений поведения сначала написать failing tests, затем минимальную реализацию.
- `dart format --output=none --set-exit-if-changed .`, `flutter analyze`, `flutter test` должны пройти.
- Повторить реальный macOS-сценарий: создание, список, открытие/закрытие панели, выбор, перенос, завершение и сохранение JSON после перезапуска.
- Проверить узкое окно и увеличенный текст без потери доступа к полю ввода и панели.
- Собрать локальный macOS Release. В GitHub Actions на обычном `push` должен по-прежнему запускаться только `verify`; тег/платный Android Release не создавать для этой проверки.
