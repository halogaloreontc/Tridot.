# Экономия минут GitHub Actions: Android-only release

## Цель

Сохранить автоматическую проверку каждого изменения, но тратить минуты на release-сборку только для значимых обновлений Android.

## Текущее состояние

`.github/workflows/ci.yml` запускает format/analyze/test и четыре release-сборки на каждый `push` и pull request. Первый запуск подтвердил, что все jobs работают, но Windows занял 12m30s, Android — 6m1s, macOS — 3m45s, Linux — 1m30s.

## Выбранный подход

- `verify` с `flutter pub get`, format, analyze и test продолжает запускаться на каждый `push` и pull request.
- `android` запускается после успешного `verify` только для тегов `v*` и события `workflow_dispatch`.
- Windows, Linux и macOS jobs удаляются из активного workflow. Их platform runners остаются в репозитории и могут собираться локально.
- Android artifact `assistant-android-apk` и существующие команды сборки сохраняются.

## Альтернативы

- Android на каждый `push`: проще, но продолжает расходовать около шести минут на каждое изменение.
- Только ручной запуск: экономит больше минут, но не даёт автоматической сборки версионных обновлений.

Пользователь выбрал теги `v*` плюс ручной запуск, поскольку это сочетает автоматические релизы и экономию на обычных изменениях.

## Ограничения

- Код приложения, зависимости и public interfaces не меняются.
- SQLite и новые функции не входят в изменение.
- Само изменение отправляется непосредственно в `main`; на его `push` должен запуститься только `verify`, без новой release-сборки.
- Не создавать тег и не запускать Android job лишь для проверки условия, чтобы не тратить минуты.

## Проверка

- Разобрать YAML и проверить diff: release jobs кроме Android отсутствуют, условия триггеров и `needs: verify` корректны.
- Локально повторить format/analyze/test, поскольку это команды `verify`.
- Отправить изменение в `origin/main` и проверить фактический GitHub Actions run: только `verify`, успешно.
- README обновить краткими правилами запуска APK и удалить устаревшее утверждение, что GitHub Actions и платформенные CI-сборки не запускались: первый полный run уже успешен, но теперь активна только Android-сборка по тегам и вручную.
