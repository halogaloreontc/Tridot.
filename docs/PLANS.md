## Слои понимания

Помощник понимает фразу последовательными слоями. Каждый отвечает на свой
вопрос, и действие выполняется только тогда, когда его пропустили все слои.
Решение должно объясняться: помощник может показать, как он понял фразу.

| Слой | Вопрос | Что делает |
|---|---|---|
| 1. Нормализация | Что написано? | Регистр, «ё», латинские буквы-двойники, опечатки; числа-коды (артикул 64115) не путаются с датой и временем. |
| 2. Ассоциации | Что это значит? | Словарь связей «звонок ≈ позвонить», «остаток ≈ сколько ≈ наличие»: общий и свой у каждого коннектора, с весами. |
| 3. Распознавание | Какая команда? | Каждый коннектор оценивает фразу (команда и уверенность 0..1). |
| 4. Контекст | О чём сейчас разговор? | Выбранная задача, последний коннектор, предыдущие реплики меняют оценку. |
| 5. Решение | Уверен ли я? | Выше порога — действие; два близких варианта — вопрос «какой из»; ниже порога — уточнение. |
| 6. Проверка перед действием | Можно ли? | Объект существует, права есть; любое изменение данных во внешнем приложении — только после подтверждения пользователя. |
| 7. Ответ | Что сказать? | Только из настоящих данных, с пометкой «понял как: …». |
| 8. Обучение (вне приложения) | Где ошибаюсь? | Генератор фраз, корпус, `known_gap`, подбор весов и порогов. |

## Расширения: Связной под себя

Человек настраивает Связной под свои нужды, а не получает всё сразу. Общее
название — «Расширения», три вида:

| Вид | Что это | Примеры | Как ставится |
|---|---|---|---|
| Навыки | своя логика без сети | задачи, калькулятор, таймеры, беседа | встроены, включаются и выключаются |
| Коннекторы | связь с внешним приложением | halowarekeep, expeora | кодом в составе приложения или по описанию `assistant.json` |
| Паки | только содержимое, без кода | шутки, каламбуры, стили, словари ассоциаций, тематические фразы | из файла или по ссылке, как паки «Своей игры» |

- В интерфейсе коннекторы — раздел «Подключения» («подключить склад»).
- На лету ставятся только паки и коннекторы по описанию: это данные, они
  ничего не выполняют. Код коннекторов — только в составе приложения
  (скачивать и запускать чужой код небезопасно и запрещено магазинами).
- Изначально включён минимум: задачи, калькулятор, беседа, базовый пак шуток.
- Пак: название, автор, язык, записи с метками (тема, для Liorio/Noda, стиль).
  Паков может быть несколько; пак или отдельную запись можно выключить.
- «Настройки → Расширения»: включённое, установленное, доступное.

### Роли: следующие

- **«Продавец expeora»** — вторая роль: слот `ConnectionSlots.expeora`
  (тот же `ManifestConnector`), свои кнопки («Заказы сегодня», «Остаток
  по артикулу»), подсказки маршрутизации и самоописание («с продажами»),
  встроенное описание expeora — главное, как у склада. Перед этим —
  прочитать код expeora и дописать его действия входа в
  `ManifestDescription.authActions`.
- **Мастер адаптеров** (для сторонних API без своего `assistant.json`):
  OpenAPI, коллекция Postman или примеры запросов и ответов → черновик
  адаптера `assistant/1` (команды, `api.only` только из чтений, шаблоны
  ответов) → локальные модели генерируют фразы (`tools/corpus_gen`) →
  проверка корпусом (перехваты задач, беседы, калькулятора) → пак
  адаптера. Адаптер — данные, проверяется так же строго, как описание с
  сервера; права — только чтение, запись — по ADR-004 с подтверждением.
- Роль из пака (только данные: набор id навыков, кнопки, самоописание) —
  после того как появятся роли сторонних авторов; подсказки маршрутизации
  — только из встроенного списка.

- **Словарь ассоциаций (слой 2).** Модели в `tools/corpus_gen` предлагают связи

## Навык «Пароли» (следующий)

Включаемый навык вне ролей: сейф паролей с подсказками на устройстве и помощь, когда пароль забыт. Проект готов, решения владельца приняты:
- хранятся сайт, логин, пароль, заметка и подсказка; шифрование на устройстве, наружу ничего не уходит;
- открытие мастер-паролем; на Android и macOS — ещё отпечатком (на macOS после подписи командой); на Windows только мастер-пароль; автозапирание;
- забыт мастер-пароль, но отпечаток работает (Android, macOS) — можно задать новый;
- подсказка и пароль — только во временной карточке, в историю чата не попадают; логин в ответах — в маске;
- в v1: генератор (только английский словарь EFF large, 7776 слов; русских режимов — раскладки, транслита, кириллицы — нет: «русскоязычный мало где используется»), проверка слабых, повторяющихся и старых паролей, зашифрованная резервная копия и перенос, импорт CSV браузера, тренировка памяти.
- готово (этап 3, часть 1): генератор (слова EFF и символы, `randombytes` + отбраковка, энтропия видна), оценка надёжности (частые пароли SecLists, ряды QWERTY/ЙЦУКЕН, даты 1940–2035, русское слово в английской раскладке, l33t, данные записи), «Проверка» (в чат — только числа), `HintGuard`, лестница подсказок и «Проверить себя», тренировка важных записей.
- готово (этап 3, часть 2): импорт CSV из Chrome/Edge/Яндекса, Firefox, Safari, Bitwarden, KeePassXC и ручное сопоставление колонок (свой разборщик RFC 4180, Windows-1251 по вопросу, предпросмотр «новая / дубль / дубль с другим паролем», по умолчанию «оставить обе»; враждебный CSV: пределы длины, управляющие символы и символы направления текста, только `http`/`https`/`android://`, хост в punycode, пароли в колонке «Название»/«Логин» — отказ, подсказки и «Важный» из файла не берутся); резервная копия `.relaybak` (свой ключ и соль, Argon2id не слабее хранилища, проверка чтением, мастер-пароль или отдельный пароль копии) и восстановление: «Создать хранилище из копии», слияние по `entry.id` и (сервис, логин) с выбором «оставить обе / из копии / текущую», «Заменить всё» — текущее в архив. Копия — недоверенные данные: только записи и `k_fp`, производные поля пересчитываются. Выбор файла — свой, на `dart:io` (без нового нативного пакета). Дальше (этап 4): `file_selector`/`share_plus`, напоминание о копии, тренировка пароля копии и мастер-пароля.

## Подключение своих приложений к помощнику

Сейчас подключения работают по описанию `assistant/1`: его пишет автор приложения (у склада — `tools/assistant/gen.mjs`), а в «Связном» лежит встроенная копия, и она главная. Подключить новое приложение может только тот, чьё описание встроено в сборку. Цель — дать это любому человеку. Порядок: 1 → 2 → пакет → 3, после навыка «Пароли».

1. **Набор для разработчика.**
   - Спецификация формата `assistant/1` с примерами.
   - Проверка описания одной командой, отдельно от склада (вынести из `gen.mjs --check`).
   - Экран «Проверить описание» в «Связном»: какие фразы поймёт и что с ними сделает.
2. **Подключение по адресу.**
   - Человек вводит адрес приложения, где лежит `assistant.json`.
   - «Связной» показывает экран прав: какие данные читает, какие ключи нужны, есть ли запись.
   - После «Разрешить» описание сохраняется у человека и становится главным для этого подключения.
   - Новая версия с большими правами снова идёт на одобрение.
3. **Пакет адаптера** (один файл, например `.relay`).
   - Содержимое: `assistant.json`, фразы и корпус для проверки, тексты ответов в 4 стилях, значок и описание, при желании — подпись автора.
   - Импорт проверяется по тем же правилам и показывает экран прав.
4. **Мастер адаптеров** — для приложений без `assistant.json`.
   - На входе OpenAPI/Swagger, выгрузка Postman или примеры запросов.
   - Помощник собирает черновик: какие запросы только читают, какие фразы им подходят, как показать ответ.
   - Человек отмечает нужное, проверяет на тестовых фразах и сохраняет как свой адаптер.
   - Фразы можно улучшить локальными моделями (qwen, gemma) на компьютере, без отправки данных наружу.

**Правила для чужих подключений:**
- Только чтение. Действия с записью — только у встроенных подключений, по схеме «расчёт → карточка → Подтвердить».
- Адаптер не видит сейф паролей, задачи и другие подключения: только фразу, сказанную для него.
- Ключи хранятся как у склада и уходят только на адрес своего приложения.

## Память и отношения помощников

После истории чатов. Порядок: сначала память о пользователе, затем
отношения с помощниками, затем «настроение» помощника. Всё — только на
устройстве, всё выключается в «Настройки → Помощники».

- **Память о пользователе (профиль).** Файл `<документы>/assistant/profile.json`
  (версия формата, атомарная запись, битый файл → `*.broken`, как у чатов).
  - *Явная:* «меня зовут Аня», «запомни, что я работаю до шести», «зови
    меня на ты», «забудь, как меня зовут», «забудь всё». На «запомни» —
    короткое подтверждение, что именно запомнено; без подтверждения
    ничего не пишется.
  - *Выведенная из поведения* — только с порогом уверенности и числом
    наблюдений: обычное время задач («утром» у этого пользователя — 8:00,
    а не 9:00), частые метки (#работа), любимый стиль и помощник. Догадка
    до порога не используется; использованная — объяснима («поставил на
    8:00 — обычно вы так делаете») и отменяема.
  - *Экран «Что помощники знают обо мне»:* список фактов с источником
    (сказали / заметили), правка, удаление по одному и «Забыть всё».
  - Никакой сети и отправки: профиль — как задачи, локальные данные.
- **Отношения с каждым помощником.** Уровень у Liorio и Noda свой:
  знакомство → приятели → близкие; растёт от взаимодействий (дни с
  разговором, выполненные вместе задачи), а не от времени.
  - Влияет **только на тон**: обращение по имени, вспомнить недавнее («как
    прошёл отчёт?»), серии («пятый день подряд закрываете всё»), свои
    шутки. Факты и команды на любом уровне одинаковы.
  - Отношение пользователя влияет на теплоту: «спасибо» — теплее, грубость
    — суше и спокойнее (как `talk.rude` сейчас), без обиды.
  - Реплики — записи каталога ответов с вариантами по уровню.
- **Лёгкий тамагочи.** Настроение помощника — из состояния задач
  пользователя (всё закрыто — довольный, много просроченных —
  озабоченный): видно в аватаре и кубике статуса. Вехи: первая неделя,
  сотая выполненная задача, месяц без просрочек.
- **Не делаем:**
  - не давим чувством вины («я расстроилась, что вы не закрыли задачу»);
  - не утверждаем, что у помощника настоящие чувства;
  - ничего не отнимаем и не «портим» за отсутствие: уровень не падает,
    настроение не наказывает, возвращение — просто «с возвращением»;
  - всё отключаемо: память, выводы из поведения, отношения, настроение —
    по отдельности.

## Потом

- **Жалобы на состояние сервера и коннектора с эскалацией.** Помощник с
  подтверждением отправляет жалобу редакторам приложения; если за 3–5 часов
  (настройка коннектора) никто не ответил — администратору. Отсчёт и
  эскалация — на сервере приложения (у halowarekeep — новое действие «принять
  жалобу»), а не в помощнике: закрытое приложение не должно терять жалобу.
  Требования к серверу — в `docs/CONNECTORS.md`, «Жалобы: что должен уметь
  сервер»; вопрос «Передать жалобу администратору?» уже задаёт «Как дела?».

- **Сделано — коннектор склада halowarekeep** (ADR-011, `ManifestConnector`):
  по описанию `assistant/1`, только чтение — «где лежит», «сколько», «что в
  ячейке», приходы за сегодня, вчера и неделю, приходы без фото, «сколько
  стоит» (честный ответ без сети), справка. Вход вставкой ссылки из «Войти на
  телефоне» или вручную (пароль склада, по желанию логин), выход с `sess_end`
  у склада 1.4.56. Дальше по складу:
  - **ссылки и переходы**: открывать артикул, ячейку и приход в складе
    (`links.*.url` в описании и разбор `#sku=`, `#cell=`, `#entry=` в складе);
  - карточка ответа чтения вместо строк текстом (`AssistantResponse.card`
    уже занят карточкой действия, ADR-013, — нужна своя модель);
  - секреты в Keychain/Keystore вместо файла (`SecretStore`, новая
    зависимость — отдельным ADR);
  - `http://` в своей сети на Android (`network_security_config`);
  - слот expeora тем же коннектором; `ask_backups` для «Контроля копий».
- **Сделано — действия с записью на складе** (ADR-013, склад 1.4.57):
  отметка проведения прихода и перемещение между ячейками — расчёт
  `act_*_check`, карточка, запись только по «Подтвердить», `act_settle` при
  неизвестном итоге; «Разрешить действия» в роли «Кладовщик» для одного
  логина. **Вторая очередь** (решения владельца, сейчас не делаем):
  - **отмена перемещения обратным документом**: кнопка «Отменить» под
    выполненной карточкой — новое перемещение `to → from` того же
    количества своим расчётом и карточкой, с проверкой, что строка в
    приёмнике ещё есть; пока ответ называет номер ПЕР-… для отката вручную;
  - **замок для ручных сохранений склада** (`ASSIST_LOCK_SET` на сервере):
    `set`/`delete` для `wh:(e|m|s):` берут тот же замок, что запись
    помощника, — закрывает окно гонки с интерфейсом склада в файловом
    режиме и затирание отметки проведения встречной записью формы;
  - правка маршрутизатора для глаголов задач («перенеси 3 стула из … в …»,
    «закрой приход 318» — сейчас `known_gap` в корпусе);
  - партии (`lot`) в карточке перемещения, многострочные перемещения,
    раскладка «БЕЗ МЕСТА», снятие отметок проведения — по запросу.
- **Описание приложения `assistant.json` и его генератор.** Приложение
  описывает свои команды, вход и API одним файлом (по образцу MCP); генератор
  составляет черновик по коду приложения, человек проверяет. Так подключаются
  expeora и чужие приложения без изменений в коде помощника. Сделано на
  стороне «Связного»: `ManifestConnector` читает такие описания (ADR-011);
  формат и генератор — у halowarekeep (`tools/assistant/`).

## Открытый проект и распространение

- **Лицензия — MPL-2.0** (`LICENSE`). Изменённые файлы самого помощника при
  распространении остаются открытыми; расширения, паки и сайты хостов — под
  любой лицензией. Чужие правки попадают в проект только пулл-реквестом с
  зелёным CI и одобрением владельца: ветка `main` защищена, корпус ловит
  поломки парсера до слияния.
- **Ядро отдельно от интерфейса.** Разбор фраз, коннекторы, навыки, паки и
  маршрутизатор — пакет `assistant_core` на чистом Dart без Flutter. Одно ядро
  — несколько «лиц».
- **Дистрибутив для хостов.** Другие приложения (halowarekeep, expeora,
  чужие) встраивают помощника:
  - веб — ядро, скомпилированное в JavaScript, и лёгкий чат-виджет
    (`<script>` + `<halo-assistant>`), сотни килобайт вместо мегабайт
    Flutter Web: быстро открывается при слабой сети, подхватывает стили
    хоста, текст выделяется и читается экранными чтецами;
  - внутри хоста помощник работает с правами текущего пользователя, без
    отдельного входа;
  - установка и обновление командой (`assistant install --host …`,
    `assistant update`): только подписанные сборки, каналы стабильный и
    тестовый, обновление подтверждает администратор хоста, есть откат;
  - своя версия под хоста: имя и личности, набор расширений и паков, свой
    коннектор.
- **Обратная связь по согласию.** «Не так» под ответом сохраняет фразу и
  правильный ответ на устройстве. Отправка — только при включённом
  «Помогать улучшать помощника» (по умолчанию выключен), после обезличивания
  (имена, числа, телефоны, адреса → заглушки) и показа того, что уйдёт.
  Дальше — обычный цикл генератора: два судьи, человек, корпус, выпуск.
- **Витрина расширений на expeora.** Пак, описание коннектора или форк
  публикуется карточкой с кнопкой «Добавить в помощника».
  - Сами паки бесплатны и открыты; авторов награждает Aerarium по
    использованию; «первый тираж» и рамки — коллекционная часть.
  - Дерево форков — в Иггдрасиле, со ссылкой на исходники каждой ветви.
  - На expeora — только данные (паки, `assistant.json`); код форков — в их
    репозиториях. Проверка тем же валидатором паков, модерация патрулём,
    жалобы, подпись автора; помощник предупреждает, если пак изменился после
    публикации.
  - Коннектор expeora в помощнике: «найди пак шуток про склад», «поставь пак
    …» (с подтверждением).
