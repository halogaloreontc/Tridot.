# Принятые решения

## ADR-001. Локальная кроссплатформенная основа

- Основной стек технического прототипа: Dart + Flutter.
- Основные платформы: Android и Windows.
- Дополнительные сборки: Linux и macOS.
- Приоритеты: единая кодовая база и интерфейс, простота MVP, контроль размера и ресурсов.
- Языковая модель не используется.
- Собственный аккаунт и сервер не требуются.
- Синхронизация проектируется через подключённые диски с append-only журналом изменений.
- GitHub используется для исходного кода, проверок и сборок, но не для автоматической публикации приватных журналов.

## ADR-002. Сначала вертикальный срез

Первый прототип доказывает путь «сообщение → сценарий → операция → постоянное хранение → ответ». Облачные адаптеры и расширенные таблицы не включаются до прохождения базовых проверок.

## ADR-003. Ресурсные требования проверяются измерением

Принятие Flutter окончательно подтверждается после release-замеров размера, холодного запуска, памяти в простое и пиковой памяти при обработке файлов. Если показатели неприемлемы, рассматривается перенос ядра на Rust с нативными интерфейсами.

## ADR-004. Коннекторы и сеть только внутри них

Контекст: помощник должен понимать команды не только для задач, но и для других приложений владельца (первым — склад halowarekeep, затем expeora) и сторонних программ, не превращаясь в монолит и не нарушая ADR-001.

Решение:

- Команды подключаются коннекторами (`lib/core/connectors/`, инструкция — `docs/CONNECTORS.md`). Маршрутизатор `AssistantController` один раз строит общий разбор сообщения (`Utterance`), спрашивает каждый коннектор, выбирает самое уверенное совпадение, а при спорном выборе переспрашивает. Задачи — встроенный коннектор `tasks`.
- Языковая модель в приложении по-прежнему не используется: коннекторы распознают фразы правилами.
- Сеть разрешена только внутри коннекторов и только через внедрённый `HttpTransport`. Ядро, хранилище, интерфейс и распознавание (`match`) в сеть не ходят.
- По умолчанию коннектор только читает (`ConnectorAccess.readOnly`).
- Каждое изменяющее действие во внешнем приложении выполняется только после явного подтверждения пользователя в диалоге. Стандартный способ — ожидание подтверждения в `AssistantSession` на одно сообщение: маршрутизатор отдаёт «да»/«нет» коннектору, задавшему вопрос, раньше обычного разбора (`docs/CONNECTORS.md`, «Подтверждение изменяющих действий»).
- Встроенные задачи — свои данные приложения: команда над одной задачей выполняется сразу, а массовая («перенеси всё на выходные», «закрой все просроченные») — только после вопроса со списком задач, которые пользователь может снять галочками или словами «кроме …», и с возможностью отменить применённое (`docs/CONNECTORS.md`, «Массовые команды задач: вопрос со списком»). Тот же вопрос со списком подходит любому коннектору, который меняет много объектов сразу.
- Секреты (токены, ключи, пароли) хранятся только через `SecretStore` на защищённом хранилище платформы, не в открытых файлах вроде `settings.json`, не в коде и не в ответах.
- Разрешения на сеть в release-сборках (Android `INTERNET`, macOS `com.apple.security.network.client`) добавляются вместе с первым сетевым коннектором, не раньше.

Последствия: новый источник команд добавляется без правки ядра и интерфейса; фразы всех коннекторов живут в общем корпусе (поле `connector`), и тест проверяет, что коннекторы не перехватывают чужие фразы.


## ADR-005. Расширения: навыки, подключения и паки

Контекст: помощник должен собираться под человека, а не давать всё сразу (`docs/PLANS.md`, «Расширения»). Нужны новые возможности — калькулятор, беседа, шутки, внешние приложения — без монолита, без перезапуска при переключении и без выполнения чужого кода.

Решение:

- Всё сверх ядра — расширения трёх видов (`ExtensionKind`): **навык** (своя логика без сети: задачи, калькулятор), **подключение** (внешнее приложение, ADR-004) и **пак** (только данные: шутки, каламбуры, фразы). Описание и формат — `docs/EXTENSIONS.md`.
- Навыки и подключения реализуют интерфейс `Connector`; их вид, версия, автор, `defaultEnabled` и `required` — поля `ConnectorInfo`. Код навыков и подключений поставляется **только в составе приложения**: никакой загрузки и выполнения кода во время работы.
- Паки — **только данные** в формате `assistant-pack/1` со строгой проверкой (`PackFormat`). Текст записей не выполняется и не читается как разметка. Паки ставятся на лету: встроенные из `assets/packs`, пользовательские — вставкой JSON в настройках, хранятся в `<документы>/assistant/packs`.
- `ExtensionRegistry` знает все расширения и выбор пользователя; маршрутизатор спрашивает только включённые. Выбор хранится в `settings.json` как набор выключенных (из включённых по умолчанию) и явно включённых (из выключенных по умолчанию): новое расширение, включённое по умолчанию, появляется включённым после обновления.
- Включение и выключение применяется сразу и ничего не сбрасывает: задачи, история, выбор, черновик и ожидания других коннекторов остаются; снимается только ожидание подтверждения выключенного коннектора.
- Изначально включён минимальный набор: задачи (выключить нельзя), калькулятор, базовый пак шуток.

Последствия: новая возможность добавляется навыком или паком без правки ядра и интерфейса; пользователь видит и выбирает, что помощник умеет; загрузка содержимого не открывает пути для выполнения кода. Паки по ссылке, выключение отдельных записей пака и описание подключений файлом `assistant.json` — следующие шаги в рамках этого решения.

## ADR-006. Каталог ответов и личности Liorio и Noda

**Уточнено ADR-016:** помощников трое (Садо, Лиорио, Нода), режимов три (Соло, Дуэт, Трио), главный всегда Садо; имена и род — из настроек. Правила каталога (записи, разметка, инвариант) действуют. **Уточнено ADR-017:** главный по умолчанию — «Связной» («Связная» в женском роде).

Контекст: у помощника две личности (Liorio — мужской род, Noda — женский; до ADR-008 Liorio звался Rio) и стили общения на выбор (`docs/PLANS.md`). Тексты, зашитые в коде коннекторов, не дают ни сменить стиль, ни сказать «добавила», ни гарантировать, что в другом стиле не потеряется факт или вопрос.

Решение:

- Каждый ответ — запись каталога по id с подстановками фактов (`docs/REPLIES.md`). Коннекторы передают только факты (`session.reply`), слова добавляет каталог. Свои записи коннектор объявляет в `ConnectorInfo.replies`.
- Каталоги — данные, по файлу на стиль (`assets/replies/*.json`): нейтральный, дружеский, краткий, деловой. Нейтральный — основа: в нём каждая запись, он задаёт подстановки; остальные стили берут недостающее из него. Нейтральный стиль Liorio на «вы» дословно повторяет прежние тексты.
- Род и обращение — небольшая разметка внутри текста (`{м:…|ж:…}`, `{вы:…|ты:…}`, `{мн:…}`), эмодзи — только в метке `{э:…}`, чтобы их можно было выключить. Языковой модели нет (ADR-001): разметка только выбирает и подставляет готовые слова.
- Инвариант проверяется при загрузке каждого стиля и пака: факты во всех вариантах рода и обращения, вопросы остаются вопросами, «≈» не пропадает. Битый встроенный каталог — ошибка, битый пак — не принимается.
- Выбор варианта детерминированный: хеш id + номер реплики разговора.
- Стиль можно поставить паком `assistant-pack/1` вида `replies` (ADR-005) — только данные с той же проверкой.
- Ядро остаётся на чистом Dart: каталоги из assets попадают в него сгенерированной копией (`tool/gen_replies.dart`), тест сверяет её с файлами.
- Личности: дуэт (по умолчанию, основной Liorio) или соло. В дуэте отвечает основной или тот, к кому обратились по имени («Noda, …») или кого выбрали в поле ввода; обращение по имени закрепляет адресата в открытом чате, как выбор в поле (к кому обратились, тот и продолжает); второй пишет первым (сейчас — о просроченных задачах, раз в день). В истории хранится готовый текст и автор. Голос фиксируется в начале сообщения: смена настроек посреди ответа применяется со следующего.
- Смена настроек помощников ничего не сбрасывает: задачи, история, выбор, черновик, ожидание подтверждения и расширения остаются (проверено тестами).

Последствия: новый стиль — файл данных или пак без правки кода; коннекторы автоматически говорят голосом Liorio или Noda; беседа и напоминания пользуются тем же механизмом. Цена — каждая новая фраза сначала заводится записью нейтрального каталога, а после правки JSON нужно перезапустить генератор.

## ADR-007. Беседа и проверка здоровья коннекторов

Контекст: помощнику нужно отвечать на «привет», «как дела», «кто ты», рассказывать шутки из паков и менять стиль по просьбе (`docs/PLANS.md`), но без языковой модели (ADR-001) и так, чтобы короткие реплики не перехватывали команды («привет, добавь задачу …», «пока не забыл, …»). «Как дела?» должен говорить правду о состоянии подключений.

Решение:

- Беседа — встроенный навык `talk` (ADR-005) с заготовленными репликами: распознаётся только сообщение целиком, ответы — записи каталога `talk.*` (ADR-006). Свободного разговора нет.
- Новый флаг `ConnectorMatch.fallback`: такое совпадение уступает любому другому, даже без маркера. Беседа всегда отвечает с `fallback`. Разбор задач сам снимает приветствие, благодарность и «пока не забыл» в начале команды.
- Необязательный интерфейс `ConnectorHealth` (`ok`/`degraded`/`down`, пояснение по-русски, `since`). «Как дела?» спрашивает его у включённых коннекторов с ограничением по времени. При проблеме помощник спрашивает, передать ли жалобу; передача и эскалация (редакторы, через 3–5 часов администратор) — забота сервера приложения коннектора (`docs/CONNECTORS.md`), пока её нет, помощник честно об этом говорит и ничего не отправляет.
- Просьбы о стиле возвращают `PersonaSettingsChange` в ответе — изменение, а не готовые настройки. Интерфейс применяет его тем же путём, что экран настроек, поэтому действуют все проверки неизменности данных. Подтверждение звучит уже новым голосом — единственное исключение из «голос фиксируется в начале сообщения».
- Шутки — только из включённых паков, по помощнику и стилю, без повторов среди последних 10; частота шуток влияет только на каламбур к приветствию и благодарности, детерминированно.

Последствия: новые реплики беседы — строки в `TalkPhrases` и записи каталога; новый коннектор сообщает о своём здоровье, реализовав `ConnectorHealth`; корпус `test/corpus/talk.jsonl` ловит перехват команд беседой.

## ADR-008. Название Qenqrit и имя Liorio без смены id

**Уточнено ADR-016:** название теперь Tridot; id `rio` и `noda` прежние, у нового главного помощника id `sado`. Имена для обращения берутся из настроек (`PersonaCast`), встроенные формы — пока имя прежнее.

Название «Qenqrit» заменено на «Связной» / Relay — ADR-009; правила про id, пакет и папку данных из этого решения действуют.

Контекст: приложение получило название «Qenqrit» (латиницей: рукописная «д» похожа на «q», читается как «Дендрит»), помощник Rio переименован в Liorio, а к обоим помощникам обращаются и другими формами имени. Настройки пользователя при этом не должны меняться (`docs/PLANS.md`, «Смена настроек помощников ничего не сбрасывает»).

Решение:

- Название — одна константа `AppInfo.name` (`lib/core/app_info.dart`): меню, заголовок окна, «О приложении», автор встроенных расширений; в нативных обёртках — заголовки окон и подпись (`PRODUCT_NAME` macOS, `my_application.cc`, `main.cpp`/`Runner.rc`, `AndroidManifest.xml`). Dart-пакет `local_assistant`, bundle id, application id, имя исполняемого файла Linux/Windows и папка данных (`<документы>/assistant`) прежние: путь к данным от названия не зависит.
- Id помощника остаётся `rio`: он в `settings.json` (`main_persona`, `solo_persona`, `persona_styles`), в авторе сообщений чата, в паках (`persona: rio`) и в ключах интерфейса (`addressee-rio`, `style-rio-…`). Меняются только данные личности: имя «Liorio»/«Лиорио», метка «L». Старый файл настроек читается без миграции и сохраняется тем же; подпись у ответов берётся по id при показе, поэтому старые сообщения подписаны новым именем, а их текст не меняется. В паке `persona: liorio` читается как `rio`.
- Имена для обращения — данные личности (`Persona.addressNames`): Liorio — «Liorio», «Лиорио», «Lio», «Лио»; Noda — «Noda», «Нода», «Нодочка», «Нодь». Косвенные падежи («Ноду», «Ноде») — только в просьбах беседы («сделай Ноду основной»); «Лиорио» не склоняется. Обращение, вступление перед командой и беседа строят свои списки из этих данных. Слово, которое лишь начинается с имени («Лион», «нодальный»), обращением не считается. «Рио» и «Rio» больше не имена, особый случай «Рио де Жанейро» не нужен.

Последствия: новое имя или форма — строка в `Personas`, без правки разборщиков; переименование не трогает данные пользователя. Цена — id `rio` не совпадает с именем, это поясняют комментарии у `Persona.id` и `Personas.liorio`.

## ADR-009. Название «Связной» (Relay): хаб и помощники не путаются

**Уточнено ADR-016:** название «Связной» заменено на Tridot; Relay осталось служебным латинским именем (`PRODUCT_NAME`, `ProductName`). Правило «хаб и помощники не путаются» действует. **Уточнено ADR-017:** «Связной» теперь имя главного помощника по умолчанию; приложение — Tridot, поэтому хаб и помощник по-прежнему не путаются.

Контекст: пользователь решил заменить латинское «Qenqrit» (ADR-008) русским названием. Приложение — хаб, в котором работают помощники Liorio и Noda; название должно говорить о связи с ними, но не совпадать с ролью помощника. «Связной» — известная в России торговая марка (сеть салонов связи); пользователь это знает и название принял. В английском и латинском контексте приложение называется Relay — так нет совпадения с маркой и есть имя для идентификаторов.

Решение:

- `AppInfo` (`lib/core/app_info.dart`): `name` = «Связной» и `latinName` = «Relay»; падежные формы — `nameGenitive` («Связного»), `nameDative`, `nameInstrumental`, `namePrepositional` («в Связном»). «Связной» — субстантивированное прилагательное и склоняется как прилагательное; текст с названием в косвенном падеже берёт форму из `AppInfo`, а не пишет её сам. Где естественно, фраза оставляет именительный («Связной · приложение с помощниками»).
- «Связной» — там, где пользователь видит русский интерфейс: боковая панель, `MaterialApp.title`, «О приложении» и страница лицензий, заголовок окна Linux (`my_application.cc`) и Windows (`main.cpp`, кодами символов: без `/utf-8` MSVC читает исходник в кодовой странице системы, а с `/WX` предупреждение о ней — ошибка), подпись на Android (`AndroidManifest.xml`), заголовок окна и меню приложения macOS (`MainMenu.xib`: «О программе Связной», «Настройки…», «Службы», «Скрыть Связной», «Скрыть остальные», «Показать все», «Завершить Связной»; меню «Правка», «Вид», «Окно», «Справка» тоже по-русски — меню целиком на одном языке), строка меню приложения и панель «О программе» на macOS (`CFBundleName` и `CFBundleDisplayName` в `Info.plist` = `$(APP_DISPLAY_NAME)` из `AppInfo.xcconfig`), начало `README.md`.
- «Relay» — где нужно латинское имя или текст английский: `PRODUCT_NAME` macOS (`Relay.app`, `TEST_HOST` и `BuildableName` в `project.pbxproj` и `Runner.xcscheme`), `ProductName` и `FileDescription` в `Runner.rc` (английский блок версии `040904e4`). Имя пакета `Relay.app` и `CFBundleName` разведены: `CFBundleName` берётся из `APP_DISPLAY_NAME`, а не из `PRODUCT_NAME`, поэтому рядом с «О программе Связной» строка меню и панель «О программе» не показывают Relay.
- Автор встроенных расширений (`ConnectorInfo.defaultAuthor` = `AppInfo.name`) и пака `jokes_basic.json` — «Связной»: автор показан в «Настройки → Расширения», по-русски.
- Помощники остаются «помощник Liorio» и «помощница Noda». Себя «связным» или «связной» они не называют; представляясь вместе с приложением, называют роль в своём роде и приложение отдельно: «Я Liorio, основной помощник в Связном», «Я Noda, вторая помощница в Связном» (`talk.who.*`, `docs/REPLIES.md`). О втором помощнике пары запись говорит в обратном роде: Liorio и Noda разного рода, это проверяет тест. «О приложении» не называет приложение помощником: «Связной · приложение с помощниками…». Не называют его помощником и подсказка «Настройки → Расширения» («Настройте Связной под себя…»: расширения ставятся в приложение, а не в Liorio или Noda), и `description` в `pubspec.yaml`.
- Как в ADR-008, не меняются Dart-пакет `local_assistant`, bundle id (`com.example.localAssistant`), application id, имена исполняемых файлов Linux/Windows и папка данных (`<документы>/assistant`).

Последствия: новое название — правка `AppInfo` и списка нативных файлов выше; в тексте ответов — подстановка `{appPrepositional}`, а не слово в каталоге. Цена — две формы названия (русская и латинская); на macOS русское название записано дважды — в `MainMenu.xib` и `APP_DISPLAY_NAME`, их держит вместе `test/app_info_test.dart`.

## ADR-010. История чатов: файл на чат и чат задачи

Контекст: пользователь попросил сохранять историю чатов, а задачу сделать ещё и отдельным чатом, в котором её можно закрыть. До этого был один чат в памяти и выбор задачи («её») поверх него; после перезапуска история пропадала.

Решение:

- **Где и как.** Папка `<документы>/assistant/chats/`: `index.json` (метаданные всех чатов) и файл на чат — `session-<id>.json`, `task-<id>.json` (прежний `main.json` — см. «Обновление: только сессии»), у всех `schema_version: 1`. Не один `chats.json`: ответ в чате задачи переписывает только её файл (до 1000 сообщений) и маленький index, а не историю всех задач; при старте читается только index, сообщения чата — при открытии. Запись отложенная (500 мс) и атомарная (`.tmp` → `rename`), по очереди; `flush` при уходе в фон и закрытии. Потерять можно только последние полсекунды при аварийном завершении.
- **Лимит** — последние 1000 сообщений на чат, обрезка молча. Пара «команда → ответ» может разорваться на границе — это допустимо: хроника берёт только команды.
- **Повреждения не стоят данных.** Битый файл переименовывается в `*.broken` (рядом, для ручного разбора), чат начинается пустым, остальные чаты и `tasks.json` не тронуты; битый index пересобирается по файлам чатов. Хранилище чатов — отдельный класс с отдельным путём: `tasks.json` оно не открывает.
- **Что не восстанавливается:** ожидание «да»/«нет» (карточка массовой команды читается устаревшей — `BulkChecklist.fromJson`), «Отменить» массового изменения, «обрабатывается…», выбор задачи в сессии, курсор истории команд. Открывается новая пустая сессия. Восстанавливать вопрос после перезапуска опасно: «да» применилось бы к списку, которого пользователь уже не видит.
- **Чат задачи — `task:<taskId>`**, создаётся лениво (при первом открытии или создании задачи), пустой на диск не пишется. Задача в любом списке (панель «Активные», Обзор, Проекты, Планирование, плитка под ответом) открывает свой чат; документ задачи — кнопкой в шапке чата.
- **Контекст — задача чата.** `handle(…, chatTaskId:)` → `AssistantSession.chatTaskId`: «готово», «сделано», «выполнено», «закрой», «готово, спасибо» закрывают эту задачу, «перенеси на завтра» и «на завтра» переносят её, без вопроса «какую?» даже при многих активных задачах. Явно названная другая задача («закрой «Хлеб»», точное название) — она. Названная, но не найденная или неоднозначная («заверши отчёт» при двух отчётах, «перенеси звонок на завтра») — тот же вопрос, что в главном чате, а не тихая подмена задачей чата; задачей чата остаются только междометия после «готово» («спасибо», «ура», «наконец-то»). Реплики беседы («до завтра», «до понедельника») — не перенос. Задачу закрыли в её чате — при возврате в главный она больше не «её». Короткие фразы без объекта понимаются только в чате задачи (`TaskChatPhrases`); в главном они по-прежнему не поняты — там неясно, о чём речь. Создание задач, калькулятор, беседа и массовые команды контекста не видят. В чате выполненной задачи «готово» и перенос ничего не меняют (`task.chat.alreadyDone`); вернуть — кнопкой «Вернуть в работу» (`task.reopened`).
- **Создание задачи из чата:** в чат новой задачи копируются команда и ответ (новые id, ссылка «из чата «…»» на исходный), в исходном чате под ответом — «Открыть чат задачи». Отдельной системной реплики нет: чат задачи читается как продолжение разговора.
- **`parentTaskId` хранится в чате, а не в задаче:** формат `tasks.json` не меняется, а иерархия контекста (PLANS) начинается с чатов.
- **Удаление и выполнение.** Чат удалённой задачи убирается из списка (`ChatBook.prune`), а файл уходит в `chats/archive/`: «удалённой» задача может оказаться и потому, что `tasks.json` потерялся (синхронизация, восстановление копии не в том порядке). Задача вернулась — при открытии её чата история возвращается из архива. «Очистить историю» стирает и архив. Выполненная задача свой чат сохраняет.
- **Запись не теряется.** Запись в чат, который ещё читается с диска, ждёт чтения (иначе новое осталось бы только в памяти, а сохранённое затёрлось бы); файл не UTF-8 — тоже повреждение (`*.broken`), а не «пустой чат» с перезаписью; файл чата без строки в index добавляется в index по шапке; на компьютере выход ждёт записи (`didRequestAppExit`, не дольше 3 с).
- **Смена чата снимает ожидание подтверждения:** вопрос остаётся в своём чате устаревшим, «да» в другом чате его не применит. Ответ, который готовился при смене чата, пишется в исходный чат (у того — «не прочитано»).
- **Адресат «Кому:»** — у каждого чата свой и сохраняется. Смена настроек помощников чаты не трогает (проверки — `test/home_personas_test.dart`).

**Обновление: только сессии (чат «Главный» убран).** Пользователь: «главный чат не нужен — все предложения функций и так есть в новой сессии до первого сообщения».

- Приложение — только сессии и чаты задач. При старте открыта новая пустая сессия (пустая сессия — она же приветствие: знак помощника, «Что сделать?», «Задача / Напомнить / Пароль»); на диск она пишется с первым сообщением, пустых в памяти не больше одной: «+» на пустой сессии оставляет её и ставит курсор в поле. Прежние сессии — в меню (с обновления «Ж1» — по дням), закреплённого «Главного» нет.
- Сообщения-приветствия «Я готов к работе…» больше нет. Помощник сам в сессию не пишет: о просроченных задачах — строка в пустой сессии («Просрочена 1 задача ›» → «Мой Связной» → «Сводка»), о тренировке паролей — «Пора потренировать пароль ›» (нажатие — команда человека «Потренируй меня» в открытую сессию: сессия получает название, как после любой команды; безымянных сессий с одним ответом помощника не бывает). Сессия без команд пользователя в счёте «сессий N» не учитывается ни до, ни после перезапуска (с диска — по названию, оно появляется с первой командой). `notice_day` в `settings.json` читается, но больше не пишется; ключи `common.welcome` и `task.overdue` остались для паков реплик. Карточки склада и так живут в сессии, где дали команду; ждущие «Подтвердить» — в блоке «Сводки».
- «Назад» из чата задачи — в чат, откуда пришли, иначе в пустую сессию; под копией в чате задачи — «из сессии «<название>»», ссылка ведёт в сессию, где задачу создали. «Очистить историю» удаляет все сессии и чаты задач и открывает новую пустую.
- **Перенос старых файлов (без потери данных).** `ChatKind.main` читается только для переноса. Если в index.json (или по шапке файла, если index потерян) есть `main` и в нём есть хоть одна команда пользователя, он становится обычной сессией `session:main` (`session-main.json`): те же сообщения с теми же id и порядком, карточки, ссылки и задачи, «не прочитано» и время последней активности; название — первая команда (очищенная от секретов, до 40 знаков), иначе «Ранее»; время создания — не позже первого сообщения. «Главный» только с приветствиями и напоминаниями не переносится. Затем `main.json` уходит в `chats/archive/` и из index.json. Старые копии в чатах задач ссылаются на `main` — `ChatBook.resolve` ведёт их в `session:main`, файлы задач не переписываются. Перенос повторяется без вреда (сбой между записью сессии и архивом — при следующем запуске `session:main` уже есть, её новые сообщения не трогаются). `main.json` уходит в архив, только когда `session-main.json` перечитан с диска с сообщениями: запись не удалась (полный диск, нет прав; ошибки записи хранилище только пишет в журнал) — `main.json` остаётся, строка `session:main` в index.json без файла за ней переносится заново при следующем запуске. `schemaVersion` остаётся 1. Проверки — `test/chats/chat_book_test.dart` («перенос прежнего «Главного»»), `test/home_chats_test.dart`.

**Обновление: меню «Ж1» и действия с сессией («Ж2»).** Владелец выбрал боковую панель «Ж1», а меню долгого нажатия — из «Ж2».

- Меню: сверху «Связной» с версией, внизу поиск и «+»; между ними прокручиваются «Мой Связной», разделы со счётчиками (открытые задачи и «N просрочена», проекты с открытыми задачами, задачи со сроком сегодня и дальше — только из имеющихся данных, нет данных — нет счётчика), «Закреплённые», сессии по местным датам последней активности («Сегодня», «Вчера», «На неделе» — 2–6 дней, «Ранее»), «Расширения». На компьютере (колонка 312) от 6 сессий «Вчера», «На неделе» и «Ранее» свёрнуты в заголовки со счётом; группа с открытой сессией раскрыта. Выдвижное меню на телефоне — `min(360, ширина − 30)`.
- Строка сессии: знак того, кто ответил последним, название (своё, если переименовали), время, вторая строка — последний ответ помощника. Долгое нажатие (на компьютере ещё «⋯» и правая кнопка, для экранного диктора — свои действия) — «Переименовать» (1–60 знаков; только у сессии, у чата задачи название задачи), «Закрепить/Открепить», «Удалить» с подтверждением «Удалить сессию «…»? Это нельзя отменить.».
- **Удалить — насовсем.** `ChatStore.erase` стирает файл чата, его копию в `archive/` и строку index.json и отменяет отложенную запись этого чата. В отличие от `delete` (чат пропавшей задачи уходит в архив и возвращается, если задача вернулась) пользователь сам попросил удалить. У чата задачи стирается только переписка: задача остаётся, её чат при следующем открытии пустой. Удалили открытую — открыта новая пустая сессия, меню не закрывается.
- **Новые поля в index.json и шапке файла** (необязательные, `schemaVersion` остаётся 1; старые файлы без них читаются, поле не того типа — как его нет): `custom_title` (своё название сессии), `pinned_at` (когда закреплена), `preview` и `last_persona` (вторая строка и знак в меню).
- **`preview` — копия текста вне файла чата.** Это тот же текст, что уже записан в файл чата (прошёл SecretGuard на входе и выходной фильтр помощника), одной строкой до 80 знаков. Карточка «Паролей», карточка действия и список массовой команды в превью не попадают — вместо них «Защищённая карточка», «Карточка действия», «Список задач». Ответы навыков с секретами (намерения `passwords*`, `secret*`, коннектор с пометкой `sensitive`; то же правило, что прячет ответ из уведомления в «Документе») — «Защищённая карточка» уже в момент ответа: после перезапуска карточки «Паролей» нет (она только в памяти), и узнать по файлу, что ответ был о пароле, нельзя. У чатов прежних версий превью нет в index.json: при старте оно берётся из последнего ответа в файле (свежие 50 чатов), только в памяти, до следующей записи чата.
- Поиск по сессиям находит и своё название; удалённые чаты из поиска пропадают. Проверки — `test/chats/chat_book_test.dart` («действия с сессией»), `test/chats/chat_store_test.dart` (erase, старый index.json), `test/chats/chat_preview_test.dart`, `test/shell/relay_drawer_test.dart`, `test/home_chats_test.dart` («действия с сессией из меню»).

**Обновление: логика сессий в панели и шапка.** Владелец: «что-то странно работают чаты — посмотри их логику» и «зачем в чате в панели сверху в названии переход к настройке помощников». Найденные дефекты исправлены, у каждого — регрессионный тест (`test/chats/chat_book_logic_test.dart`, `test/home_chats_test.dart`, «логика сессий (аудит чатов)»):

- **Чаты задач не засоряют «Сессии».** Раньше каждая созданная задача добавляла строку своего чата рядом с сессией, где её создали (в чате только копия команды и ответа). Теперь в панели среди сессий чат задачи стоит, только если пользователь сам что-то в нём написал (`ChatThread.ownTalk`), или если он открыт. Признак пишется в index.json и шапку файла (`own_talk`, только у чатов задач; необязательное поле, `schemaVersion` остаётся 1). В старых файлах признака нет: догадка — сообщений больше двух копий, при открытии чата признак уточняется по сообщениям. Копия команды при создании задачи своей репликой не считается, ответы и напоминания помощника — тоже. Закреплённые чаты задач видны всегда.
- **Сессии сверх лимита не пропадают.** Панель показывает 50 сессий (`ChatBook.sessionsLimit`), а `groups()` возвращает, сколько не вошло (`hidden`): строка «Показать ещё N» (`sessions-more`) добавляет ещё 50. Раньше 51-я и более старые сессии в панели не появлялись никак (только поиском).
- **Пустая сессия — всегда «сейчас».** «+» снова открывает оставленную пустую сессию (их в памяти не больше одной), но её время теперь «сейчас» (`ChatThread.touchEmpty`): вчерашняя пустая сессия не встаёт во «Вчера», а пустая, открытая в 23:50, после полуночи — в «Сегодня». На диск пустая сессия по-прежнему не пишется.
- **Поиск ведёт к сообщению.** Результат поиска открывает сессию у найденного сообщения: лента прокручивается к нему, оно подсвечено (рамка у команды, черта слева у ответа). Копии команды и ответа в чате задачи поиск пропускает: тот же текст уже найден в сессии, где его написали (чат задачи по названию задачи по-прежнему находится).
- **В шапке — тот, кто отвечает в этой сессии:** последний ответивший (`lastPersonaId`), до первого ответа — кто ответит по составу.
- **Ответ в другой сессии.** Пока готовится ответ в одной сессии, новая пустая показывает заставку, а отправка в другой сессии не пропадает молча: текст остаётся в поле, внизу — «Дождитесь ответа в другой сессии».
- **История ↑/↓ — своя у каждого чата** (команды открытого чата), а не общая на все сессии.
- **Удаление открытой сессии из панели** на компьютере не уводит из открытого раздела («Задачи», «Проекты»): открывается пустая сессия, раздел остаётся. Выбор («её») удалённой сессии забывается (`AssistantController.forgetChat`).
- **Шапка без перехода в «Помощники».** В центре шапки — название сессии со стрелкой ▾, под ним мелко — знак и имя того, кто отвечает. Нажатие на название открывает то же меню сессии, что долгое нажатие в панели («Переименовать», «Закрепить», «Удалить»); у пустой сессии меню нет (стрелки нет). Когда в сессии выбрана задача (шапка «Задачи › «её»»), меню сессии не пропадает: справа от этой строки — кнопка меню сессии (`session-title`) с тем же меню. Настройки помощников — в «Мой Tridot» → «Помощники». Название видно и на телефоне (раньше — только подпись «сессия «…»» на компьютере). Шапка чата задачи прежняя.
- Неиспользуемый `ChatBook.recent()` удалён.

Последствия: история переживает перезапуск и смену настроек; новый вид чата (проект, документ) — новый `ChatKind` и правило контекста, без смены формата файлов. Цена — `home_page.dart` держит переключение чатов, а правила — `ChatBook` (тесты без виджетов); копия команды и ответа дублирует пару сообщений; поиска по истории и резервной копии чатов пока нет (PLANS).

## ADR-011. Подключения по описанию `assistant/1`: склад, вход и секреты, только чтение

Контекст: первое внешнее приложение — склад halowarekeep. Он сам описывает, что помощник может спросить: `assistant.json` формата `assistant/1` (команды с образцами фраз, API, вход, шаблоны ответов; образец чтения — `tools/assistant/core.mjs` склада). Так же будут подключаться expeora и чужие приложения. Пользователь решил: адрес сервера не зашит в приложение, вход — вставкой ссылки из окна «Войти на телефоне» (без камеры), в первой версии — все четыре чтения склада, записи нет; склад 1.4.56 добавит в описание `version`, `auth.qr`, `auth.logout`.

Решение:

- **Один коннектор на любое описание** — `ManifestConnector` (`lib/core/connectors/manifest/`, `docs/CONNECTORS.md`, «Коннектор по описанию `assistant/1`»). Описание — данные (ADR-005): берутся только образцы фраз, регулярные выражения `shape` и шаблоны; чужой код не выполняется. Разбор, тело запроса и шаблоны ответа — порт `core.mjs` один к одному, чтобы склад и «Связной» считали числа, формы слов и даты одинаково.
- **Слот — код приложения.** Каждое приложение — `ConnectionSlot` (`ConnectionSlots.warehouse`: id `warehouse`, `app.id` `halowarekeep`): тексты каталога ответов, обращения, фразы справки, встроенный профиль входа по ссылке для описаний без `auth.qr`. Хранилище подключения — по `app.id` (`connections/<app.id>.json` и `connections/<app.id>.assistant.json`), секреты — по id коннектора (`warehouse.token`, `warehouse.sid`). Второе приложение (expeora) — второй слот, тот же коннектор.
- **Только чтение** (действия с записью добавил ADR-013 — отдельным путём, не командами). Коннектор зовёт только действия из `api.only`; вход (`qr_take`, `auth_check`) и выход (`sess_end`) — отдельно, в `ConnectionService`, не командами. Изменяющих команд нет; когда появятся — по ADR-004, с подтверждением. Имена действий входа и выхода приходят из описания, но описание — недоверенные данные (его перечитывают раз в сутки): проверка пускает только действия из списка `ManifestDescription.authActions` (`qr` — `qr_take`, `login` — `auth_check`, `logout` — `sess_end`), не совпадающие с командами `api.only`, а тело `credentials.sid.get.body` — только поля `{login}`/`{pass}`. Иначе подменённое описание заставило бы помощника звать запись (`item_delete`, `user_set_role`) с паролем и ключом сотрудника. Новое приложение добавляет свои действия в этот список после чтения его кода.
- **Описание проверяется строго** (`askCheck` плюс пределы: 256 КБ, 100 команд, 50 фраз, `shape` ≤ 200 знаков, сообщение для разбора ≤ 200 знаков) и **`api.url` должен быть того же источника, что и описание**: иначе подменённое описание отправило бы пароль склада на чужой хост. Битое описание не заменяет принятое. Встроенная копия (`assets/connectors/`) нужна, чтобы фразы понимались и проверялись корпусом до подключения; она же — главное описание (ADR-012).
- **Маршрутизация не отдаёт складу чужое.** Однословные фразы без поля («сегодня», «помощь», «привет») склад не берёт — только с обращением («склад, сегодня»); справка — только своими фразами слота. Поэтому «привет» из `help` описания **не** перекрывает приветствие беседы: беседа — `fallback`, и любое совпадение склада её бы вытеснило. Текстовое поле со словами задач, обращения к помощнику, примера, времени или срока отклоняет фразу. Коды 5–6 цифр и ячейки (`215-1-1-1`) датой и примером не становятся.
- **Голос — каталог «Связного».** Тексты описания — нейтральный факт (`{text}`), обёртка («Показаны не все — уточни запрос»), отказы и ошибки — записи `warehouse.*` в `ConnectorInfo.replies`; предупреждения `protected`, паки ответов их не переписывают. Тексты `auth.need` описания не используются: они отсылают к интерфейсу склада.
- **Вход.** По ссылке `https://<склад>/#qr=<32 hex>`: адрес — из ссылки, `https` (`http` — только своя сеть), без логина в адресе; затем описание, затем `auth.qr` описания или встроенный профиль (`qr_take`). Вручную — адрес и «Пароль склада» (проверка безвредным чтением уровня `shared`), по желанию логин и пароль сотрудника → `auth_check` → личный ключ; пароль сотрудника не хранится. QR камерой не сканируется: ссылка открылась бы в браузере, и одноразовый код потратил бы сайт склада.
- **Выход.** Если в описании есть `auth.logout` — `sess_end` с ключом, ответ и ошибки не важны; иначе только на устройстве (ключ на сервере истечёт сам через 30 дней). Пароль и ключ удаляются всегда, подключение выключается; адрес и кэш описания остаются.
- **Секреты** — только `SecretStore`. В приложении — `FileSecretStore`: отдельный файл в служебной папке приложения (`getApplicationSupportDirectory`, не «Документы» и не `settings.json`), права `600` на macOS и Linux. Это **отступление** от ADR-004 («защищённое хранилище платформы»): пакета `flutter_secure_storage` нет в зависимостях, а новые зависимости мы не добавляем без нужды; интерфейс `SecretStore` позволяет заменить хранилище без правок коннекторов — следующий шаг в docs/PLANS.md. Секреты не попадают в ответы, `settings.json`, состояние подключения и тексты экрана — это проверяют тесты (все значения в тестах — заведомые подделки).
- **Сеть** — `IoHttpTransport` на `dart:io` `HttpClient`, без пакета `http`: тайм-аут на весь запрос, тело до 2 МБ, без перенаправлений. Release-сборки получили разрешения: Android `INTERNET` в `main/AndroidManifest.xml`, macOS `com.apple.security.network.client` в обоих `.entitlements`. Тесты в сеть не ходят (`FakeHttpTransport`).
- **Пояс.** `{$tz}` — `-timeZoneOffset` в минутах (как `getTimezoneOffset()`), `{$zone}` — пусто: имени пояса IANA в Dart без пакета нет; сервер тогда считает по смещению.

Последствия: склад подключается без кода под него, второе приложение — слотом и текстами; работают оба вида описания (до 1.4.56 и после). Цена: строки ответа пока текстом в сообщении (карточки и открытие ссылок — позже), секреты — в файле, а не в Keychain/Keystore; правила маршрутизации «Связного» поверх `core.mjs` нужно держать в согласии с корпусом (`test/corpus/warehouse.jsonl`).

## ADR-012. Роли — заготовки поверх навыков; «наше описание главное»

**Уточнено ADR-016:** «Кто ведёт роль» больше не действует — роль только включает навыки, а отвечает тот, кто ведёт обязанность (расширения или оповещения). `role_owners` читается и пишется для отката, но на ответы не влияет.

Контекст: пользователь попросил сделать умения помощника включаемыми под сферу работы — например, роль «Кладовщик» для склада, — и чтобы склад halowarekeep был в этом главным. Договорённость о слоях: **подключение** — канал к сервису (склад), **навык** — что умеет помощник (задачи, калькулятор, беседа, «Склад» — вопросы складу через его подключение), **роль** — заготовка поверх навыков и настроек для сферы работы, включается одним переключателем. Отдельно: описание `assistant.json`, которое отдаёт сервер, не должно перекрывать то, что знает приложение («наше описание главное»).

Решение:

- **Роль — данные в составе приложения** (`RoleInfo`, `lib/core/extensions/role.dart`), не новый вид расширения и не отдельный реестр: роли знает `ExtensionRegistry`, а выбор пользователя — тот же `ExtensionChoice` (`disabled_roles`, `enabled_roles`, `role_owners` рядом с `disabled_extensions`/`enabled_extensions` в `settings.json`). Так модель выбора остаётся в одном месте, и применение (`apply`) по-прежнему мгновенное и ничего не сбрасывает. Роль объявляет: свои расширения, кнопки быстрых действий (отправить или вставить шаблон), подсказки маршрутизации (`<id>.<подсказка>` → `RoleHints`), кусок самоописания («со складом»), подключение (статус и «Подключить склад» в карточке), расширение, которым роль на деле помогает (`helpsThrough`), и расширение, без которого кнопка бесполезна (`RoleChip.needs`). Отдельного названия у навыка поверх подключения нет: навык склада везде зовётся так же, как подключение, — «Склад» (в карточке роли, в «Расширениях», в «что умеешь»).
- **Встроенные роли.** «Личное» — задачи, калькулятор, беседа; включено по умолчанию и **выключается**: задачи — ядро (`required`) и остаются всегда, калькулятор и беседа выключаются вместе с ролью. «Кладовщик» — склад и беседа (без «Личного» помощник всё равно отвечает на «привет» и «кто ты»); выключен по умолчанию. Включать можно несколько.
- **Старшинство выбора** (`ExtensionRegistry.enabledUnder`): обязательное включено всегда → выключенное явно (`disabled_extensions`) выключено, даже если роль включена → расширение, которое входит хоть в одну роль, включено, только пока включена одна из его ролей (`enabled_extensions` для него не действует) → остальное (паки, расширения вне ролей) — как раньше. Строка такого расширения в «Расширениях» неактивна, пока все его роли выключены. Навык, выключенный в «Расширениях» при включённой роли, роль не рекламирует: его кнопки спрятаны, «кто ты» и «что умеешь» о нём молчат, а карточка роли говорит прямо — «Навык «Склад» выключен в «Расширениях»…». Поэтому выключенный «Кладовщик» прячет склад полностью — подключённый склад не отвечает вовсе, — а подключение, адрес и секреты остаются: снова включённая роль работает без нового входа.
- **Подсказки маршрутизации — только из кода.** С «Кладовщиком» и подключённым складом голый артикул — «где лежит» (0.9 вместо 0.7), «сегодня»/«вчера» — приходы (0.85, без «склад, …»); без подключения подсказки молчат. Подсказка для голых слов уступает задачам: в чате задачи и в ответ на вопрос помощника («На когда перенести задачу?») склад слово не берёт. Начало фразы без поля («Где лежит» — кнопка и сразу «Отправить») — вопрос «что искать?», а не поиск слова «лежит». Подсказки читает сам коннектор (`ManifestConnector.applyRoleHints`), маршрутизатор не меняется.
- **Не подключено — честная подсказка.** Роль включена, входа нет: фразы склада получают `role.notConnected` каталога («Склад ещё не подключён — Настройки → Роли → Кладовщик → Подключить склад.»), а не «не понял». «Как дела» такое состояние сбоем не считает: без жалобы администратору, только та же короткая подсказка (`HealthStatus.notConnected`). Вход из карточки роли или из «Расширений» включает роль, если она выключена; выход роль не выключает.
- **Кто ведёт роль.** В дуэте у роли выбирается ведущий («Ведёт: Liorio / Noda», по умолчанию — основной; выбор основного не записывается — роль идёт за основным). Фразу, которую забрал навык роли, отвечает ведущий, если к помощнику не обратились явно: имя в сообщении и адресат в поле ввода важнее (правила ADR-006 не меняются). **Явный выбор в «Кому:» важнее всегда, и выбор основного тоже**: «выбрали основного» (`AssistantController.mainAddressee`, хранится как `main` — основной, кто бы им ни был) и «никого не выбирали» (`null`) — разные состояния. Переключатель показывает выбранным только того, кто ответит: если никого не выбирали, а какую-то роль ведёт второй помощник, не выделен никто и рядом подпись «по роли»; нажатие на выбранного тогда снимает выбор. Правило «к кому обратились, тот и продолжает» сохраняется: после «Лиорио, …» при роли, которую ведёт Noda, адресат — основной явно. Общий навык (беседа) ведёт владелец первой включённой роли по порядку («Личное» раньше «Кладовщика»). «Обрабатывается…» звучит голосом того же ведущего. В соло — единственный помощник.
- **Самоописание.** «Кто ты» добавляет `talk.roles` («Сейчас помогаю с задачами и со складом.»), «что умеешь» отвечает одной записью `talk.capabilities.roles` («Помогаю с задачами и со складом. Умею: …»), если включено что-то сверх «Личного» или «Личное» выключено; иначе тексты прежние. «Что умеешь» ведёт в «Настройки → Роли», а за точной настройкой — в «Расширения».
- **Перенос настроек.** Файл без `enabled_roles` и `disabled_roles` (до ролей): подключение из `enabled_extensions`, которое входит только в выключенные по умолчанию роли, включает свою роль — подключённый раньше склад продолжает отвечать. Списки ролей пишутся всегда, поэтому перенос не повторяется.
- **«Наше описание главное».** Встроенная копия описания (`assets/connectors/halowarekeep.assistant.json`, теперь — 1.4.56 с `version`, `auth.qr`, `auth.logout`) — главная: по ней понимаются фразы, идут вход по ссылке и выход, в том числе со старым складом (команды `ask_*` не менялись). Описание сервера в работе, только если прошло полную проверку (ADR-011, с `authActions`), его `version` новее встроенной и оно не расширяет права — `DescriptionAuthority`. «Не расширяет» — это не только имена действий: команды и `api.only` — из `api.only` встроенного; действия входа и выхода (`authActions`) — только в разделе `auth`, командой чата они не бывают (это правило и самой проверки формата); `api.url`, `api.action` (`in`, `name`) и `auth.headers` — те же, что во встроенном, иначе знакомое имя действия уехало бы на другой адрес (`api.php?action=item_delete&a=ask_stock`) или ключи — в другие заголовки. Описание того же приложения, не прошедшее проверку или расширяющее права, вход не останавливает, в кэш не попадает и **ничего не заменяет**: если кэш взят с этого же сервера, описание в работе, кэш и запись подключения (версия, `etag`) остаются прежними, иначе в работе встроенное без `etag` — так состояние сейчас и после перезапуска совпадает, а следующая проверка не получает «не изменилось» про отвергнутый ответ. Кэш привязан к серверу (`cached_from` в записи подключения): описание одного склада не управляет другим после выхода и нового входа. Экран подключения пишет, какое описание в работе и почему.

Последствия: новая сфера работы — строка `RoleInfo` (и слот, если нужно подключение), без правки маршрутизатора и интерфейса; подключённое приложение больше не «включено навсегда» — его голос зависит от роли. Сервер не может ни сузить понимание фраз старым описанием, ни расширить права новым: обновить фразы можно только вместе с версией, а новые действия, другой адрес API и другие заголовки — только новой сборкой приложения. Цена: встроенную копию описания нужно обновлять вместе со складом; роль и расширения связаны по строковым id (`warehouse`, `talk`), это держат тесты `test/extensions/roles_test.dart`; корпус по умолчанию гоняется с обеими ролями (`docs/CORPUS.md`).

## ADR-013. Действия с записью на складе: отметка проведения и перемещение

Контекст: склад halowarekeep 1.4.57 научился двум узким действиям для помощника — отметить проведение прихода (SV, 1С) и переместить товар между ячейками. До этого подключение было только для чтения (ADR-011), а описание сервера `assistant.json` — открытый статический файл, который можно подменить. Владелец решил: «проведи приход N» ставит обе недостающие отметки, «в 1с» / «в sv» — только одну, снятия отметок нет; на сервере действия выключены, пока не вписана строка `ASSIST_ACTIONS`; каждое перемещение пишется в «Историю» с логином и «через Связного»; переезжает самая старая партия; отмена перемещения обратным документом и замок для ручных сохранений — вторая очередь.

Решение:

- **Два шага.** Сначала расчёт `act_*_check` — только чтение (генератор склада доказывает это статически): сервер сам составляет карточку, точные поля записи `commit` и подпись `stamp` (HMAC на ключе сервера, привязана к логину, полям, сроку и состоянию). Потом запись `act_*` — только по кнопке «Подтвердить», ровно одним запросом с одноразовым `rid` (16 знаков `[0-9a-z]`, `Random.secure`). Неизвестный итог (обрыв, тайм-аут, любой 5xx записи, кроме `storage`/`selfcheck` — «ничего не изменилось»: `unknown` склада, сбой без кода, 5xx без тела) — одна проверка `act_settle` через 3 с; кнопка «Проверить» зовёт её же; отказ, который `act_settle` достал из книги, разбирается как отказ записи (по коду в запись каталога). Запись не повторяется никогда.
- **Действия — только из встроенной копии.** Раздел `actions[]` описания разбирается только у встроенной копии (`ManifestDescription.parse(..., builtIn: true)`, `assets/connectors/halowarekeep.assistant.json` — теперь 1.4.57); у описания сервера он не разбирается вовсе, даже когда описание сервера в работе для чтения. Пара «расчёт — запись» для каждого вида — в коде (`ManifestDescription.writeActions`: `move` — `act_move_check`/`act_move`, `post` — `act_post_check`/`act_post`; `settleAction` — `act_settle`); встроенная копия с другой парой не проходит проверку. Тела запросов, карточку и ответы задаёт код по виду действия, а не описание: у записи `actions[]` нет `call`, `answer`, `reply`.
- **Описание сервера для записи не значит ничего** (`DescriptionAuthority.widening`): описание, которое называет действие записи или `act_settle` в `api.only` или у команды, отвергается целиком; команды не зовут ни записей, ни расчётов (правило проверки формата, как в `core.mjs`). Сверх ADR-012 закреплены `api.method`, `api.errors`, уровни `auth.access`, вход по логину (`credentials.sid.get`: действие, тело, `take`), вход по ссылке (`auth.qr`: действие, `param`, `take`), выход (`auth.logout`: действие, `needs`), а у знакомого действия в теле запроса — только знакомые поля. Сборка до 1.4.57 отвергает описание 1.4.57 (расчёты шире её `api.only`) и остаётся на своём встроенном — только чтение, как и раньше.
- **Шлюзы без сети.** Действие идёт, только если: включена роль «Кладовщик»; склад подключён под своим логином (уровень `staff`, личный ключ есть); переключатель «Разрешить действия» включён для этого же логина; перед записью логин карточки совпадает со входом. Иначе ответ без единого запроса (`warehouse.act.needLogin`, `.off`, `.otherLogin`). Фразы действий понимаются, пока включена роль, даже при выключенном переключателе — иначе «перемести…» ушла бы в задачи или в «не понял».
- **«Разрешить действия»** — второй переключатель в карточке роли «Кладовщик» (`RoleInfo.actionHint = 'warehouse.actions'`, не в `hints`: те включаются вместе с ролью). Выключен по умолчанию; включается диалогом, только под своим логином; хранится как `role_actions: {"storekeeper": "<логин>"}` в `settings.json` (логин — не секрет). Любая смена входа — новый вход по ссылке или вручную, «Войти под логином», выход, устаревший личный ключ — снимает разрешение сразу (`ConnectionService.addSessionListener`), а после перезапуска разрешение для другого входа снимается при загрузке настроек. Реестр передаёт логин только коннектору из подсказки действий включённой роли (`RoleActions.applyRoleActions`); коннектор сам сверяет его с логином входа. `ConnectorInfo.access` — `readWrite` только при действующем разрешении.
- **Подтверждает только кнопка.** У `ConfirmationAnswer` появился `viaButton`: запись — только по «Подтвердить» на карточке (`AssistantController.answerCard`). Текстовые согласия («да», «ок», «давай», «отметь», «+») лишь просят нажать кнопку, и карточка ждёт дальше; «нет», «отмена» и кнопка «Отмена» отменяют; любое другое сообщение снимает ожидание — карточка устаревает. Набор текстовых согласий широк, а «отметь» — ещё и глагол команды: поэтому так.
- **Сверка ответа расчёта со сказанным.** Перед карточкой: «откуда», «куда», «сколько» и класс — те, что сказал человек (`"all"` — ровно весь остаток строки), отметки — только из запрошенных, приход — выбранный в вопросе, логин карточки — логин входа; в карточке «откуда», «куда», «сколько» — из `commit`. Не сошлось — `warehouse.act.mismatch`, карточки нет.
- **Карточка** (`ActionCard`, `lib/core/models/action_card.dart`; виджет `lib/app/widgets/action_card_view.dart`): подписи — в виджете, значения сервера — одной строкой без управляющих знаков и знаков направления, не длиннее 80 знаков (второй раз чистит `ActionCard.cardText`). Срок — по `exp`, но не больше 5 минут по часам устройства; кнопки гаснут при первом нажатии и по сроку. В историю чата пишется без `commit`, `stamp`, `exp`: после перезапуска ждущая карточка — устаревшая, отправленная — «итог неизвестен» с «Проверить». Поэтому `sending` сохраняется **до** запроса записи (`ActionCard.onSending`, интерфейс пишет чат и ждёт диска не дольше 2 с): иначе закрытое посреди записи приложение показало бы «устарела», и человек повторил бы уже сделанное.
- **Разговор.** Вопросы по ходу — по ответу расчёта (`ask: row/qty/to/entry`): номер варианта («2», «второй»), число или «все», ячейка; не больше 4 вопросов. Количество не угадывается. Глаголы — «перемести», «переложи», «проведи», «отметь проведение»; «перенеси», «закрой» — слова задач, правку маршрутизатора откладываем (в корпусе — `known_gap`). Поле-ячейка с `shape` вшивается в выражение фразы: «стул из бука из 215-1-1-1 в …» режется по той « из », после которой ячейка (`core.mjs`-порт для команд не меняется).
- **Ответы — каталог «Связного»**: записи `warehouse.act.*` во всех четырёх стилях (`assets/replies/*.json`), предупреждения и вопросы — `protected`.

Последствия: украденный личный ключ не даёт больше, чем сегодня (`set` склада и так пишет что угодно), но действие помощника — узкое, проверяемое, с подтверждением кнопкой и видно в «Истории». Цена: встроенную копию описания нужно обновлять вместе со складом; новое действие — новый вид в `writeActions`, код карточки и ответов. Остаточные риски: затирание отметки встречной записью клиента склада и гонка перемещения с интерфейсом склада закрываются только правкой клиента склада (замок ручных сохранений — вторая очередь, `docs/PLANS.md`).

## ADR-014. Навык «Пароли» (сейф)

Записано задним числом: на это решение давно ссылаются код (`lib/core/passwords/vault_format.dart`, `vault.dart`, `lib/main.dart`) и README, а в журнале его не было. Номера разделов и решений в комментариях кода (3.1, 4.3, 15.2, D5, D7, D25 и др.) — из рабочего плана навыка; здесь — то, что из него стало правилами.

Контекст: помощнику нужен менеджер паролей без сети и без облака. Пароль не должен попадать в историю чата, логи, уведомления, каталог ответов, корпус и запросы сетевых коннекторов; файл на диске — читаться только с мастер-паролем; утечка старого мастер-пароля или старой копии — не открывать нынешнее. В интерфейсе навык называется «Сейф» (слово «Хранилище» зарезервировано за «Хранилищем контекста», `docs/PLANS.md`).

Решение:

- **Файл.** `vault.relayvault` — JSON-конверт (`format: relay-vault`, `v`, `kind: vault|backup`, `vault_id`, параметры Argon2id13, `wrap_pw`, необязательный `wrap_bio`, `rev`, зашифрованный `index`, `secrets`). Снаружи нет названий, логинов, дат и числа записей в индексе; видно только **число секретов** (= число записей) — известное раскрытие, принятое ради простоты формата.
- **Ключи.** Мастер-пароль → Argon2id13 (калибровка 0,7–1,0 с, границы при загрузке до вывода ключа) → KEK; случайный VK обёрнут KEK (`wrap_pw`). Из VK — `K_index` и `K_secret` (`crypto_kdf`). Шифр — XChaCha20-Poly1305; AD привязывает каждый шифротекст к версии, виду, `vault_id`, записи и её `srev` — секрет не пересадить в другую запись и не откатить по частям (`VaultKeys.checkConsistency`). Индекс дополняется до 4 КиБ, секрет — до 256 байт: длина пароля не видна. Отпечатки паролей (`fp`, `fp_loose`, до 5 `fp_old`) — BLAKE2b с отдельным ключом `k_fp` внутри индекса.
- **D5.** Смена мастер-пароля — всегда с новым VK: индекс и все секреты перешифровываются, `vault.prev` и `vault.v<N>.bak` перезаписываются.
- **D7.** Прежние пароль и заметка не живут нигде: при их смене и при удалении записи `vault.prev` сразу перезаписывается текущей версией. Исключение — только хронология паролей, если её включили (ADR-015).
- **D25.** Неверный ввод мастер-пароля сразу пробует его варианты (раскладка, Caps Lock, регистр первой буквы, пробелы) в той же попытке общего счётчика ошибок; паузы растут.
- **Версии и миграции.** Новая версия формата — чистая функция `VaultMigrations`; перед записью мигрированной версии кладётся `vault.v<N>.bak`, после проверки чтением удаляется. Файл новее приложения — `tooNew`, файл не трогается.
- **Резервная копия** `.relaybak` — тот же конверт с `kind: backup`, своими `vault_id`, VK и солью, Argon2id не слабее сейфа; после расшифровки — недоверенные данные (строгая схема, нарушение — запись пропускается).
- **Граница с чатом.** Навыку отдаётся `VaultFacade` — без методов, возвращающих пароль; пароль показывает только слой приложения (карточка, экран записи) по кнопке, на время. `SecretGuard` скрывает пароли из ввода до истории, команд и маршрутизатора; сетевые коннекторы похожих на пароль фраз не получают.

Последствия: пароли живут только в шифротексте; канарейки проверяет `test/passwords/no_leak_test.dart`. Цена: восстановить сейф без мастер-пароля нельзя (только «Начать заново» с архивом файла); снаружи видно число записей.

## ADR-015. Хронология паролей

Контекст: владелец попросил опцию «хронология паролей» — хранить прежние пароли записи и уметь править хронологию, чтобы удалять опечатки (решение 1 из разбора корпуса «Паролей»). Это прямо противоречит D7 (ADR-014): прежний пароль не должен жить нигде.

Решение:

- **Опция, выключена по умолчанию.** «Пароли → Настройки → Защита → Хранить прежние пароли (хронология)» (`VaultPrefs.passwordHistory`, `pw_history` в зашифрованных `prefs`). Включение — ослабление защиты: только с мастер-паролем (тот же путь и счётчик ошибок, что у других ослаблений). Выключенная опция — D7 без исключений: формат файла тот же, что был бы без неё (ни `hist`, ни `history`).
- **Что хранится.** При смене пароля прежний ложится в хронологию записи: до **10** элементов, новые первыми, самый старый уходит вместе с шифротекстом. Пароль, равный текущему или уже сохранённому (по отпечатку), не повторяется: возврат к прежнему паролю убирает его из хронологии. В индексе у записи — `hist: [{h, from, to, src}]` (неизвестные поля элемента сохраняются как есть, как у записи; id элемента — 16 случайных байт в hex, даты — только внутри шифра); в конверте — плоская карта `history: {h → {n, c}}`. Тело — то же, что у секрета (пароль, пустая заметка, дополнение до 256 байт), ключ `K_secret`, своя AD `relay-vault|v|kind|vault_id|entry_id|hist|h`: элемент нельзя пересадить к другой записи или под другой id. `checkConsistency`: набор id в индексе (без повторов) равен ключам `history` — лишний или пропавший элемент делает файл `corrupt`.
- **Правка хронологии восстанавливает D7.** Удалить элемент (опечатку), очистить хронологию записи, удалить прежние пароли всех записей — одна запись файла; `vault.prev` и все `vault.v<N>.bak` перезаписываются текущей версией, отпечаток удалённого пароля уходит и из `fp_old` («это прежний пароль» о нём молчит). Вернуть удалённое можно только из резервной копии. Архивы сейфа (`archive/*.relayvault` — после «Заменить всё» и «Отложить сейф в архив») — отдельные файлы, их правка хронологии не трогает: там удалённый элемент остаётся, пока лежит архив; об этом говорит и диалог удаления. Важную запись под охраной (переспрос) показывают и правят только после мастер-пароля.
- **Выключение опции** спрашивает: «Удалить сохранённые прежние пароли всех записей?» — «Удалить» стирает всё (как выше), «Оставить» — новые не копятся, сохранённые видны и удаляются по одному. Новый пароль, равный оставленному элементу, убирает этот элемент и при выключенной опции: текущий пароль не показывается как прежний.
- **Показ — только в карточке записи** («Прежние пароли (N)», «с 12.11.2026 по 13.11.2026», в один день — «10.11.2026, 09:00–09:10», без известной даты начала (CSV без дат) — «до 13.11.2026»; показ на время по кнопке; подсказка «использовался меньше часа — похоже на опечатку» — только при известной дате начала: пароль из CSV без дат мог служить годами). Ни в чате, ни через `VaultFacade`, ни в каталоге ответов хронологии нет; «покажи старый пароль от почты» в чате её не раскрывает.
- **Пересборка.** Смена мастер-пароля, «Перешифровать всё», выгрузка копии и миграция перешифровывают и элементы хронологии; удаление записи убирает её элементы.
- **Копия.** `.relaybak` версии 2 несёт хронологию; битый элемент копии пропускается, запись остаётся. Слияние в сейф с включённой опцией сливает хронологию копии (без повторов, до 10); с выключенной — отбрасывает, предпросмотр пишет «Прежние пароли из копии не перенесены: хронология выключена». «Создать сейф из копии» спрашивает «Включить хронологию паролей?» (по умолчанию — нет); «Заменить всё» переносит хронологию, только если она включена в текущем сейфе.
- **Формат — версия 2.** Миграция v1 → v2 не меняет содержимого (хронологии в v1 нет), но по общему правилу пишет `vault.v1.bak` и удаляет его после проверки. Приложение с форматом v1 получает `tooNew` и ничего не теряет молча.

Последствия: с включённой опцией прежние пароли живут — зашифрованными, внутри сейфа и его копий; утечка файла вместе с мастер-паролем раскрывает и их. Снаружи видно общее число элементов хронологии (как и число записей). Копию, сделанную новой версией, не открыть в старой (текст `tooNew` уже есть). Большой сейф с полной хронологией упирается в пределы файла (32 МБ) и копии (20 МБ): запись, которая не помещается, не пишется (существующие ошибки «не помещается в формат» и «копия больше предела»).

## ADR-016. Tridot; Садо, Лиорио и Нода

**Уточнено ADR-017:** главный помощник по умолчанию называется «Связной» (в женском роде — «Связная»), а не «Садо»; id `sado` прежний. Ниже «Садо» — прежнее встроенное имя главного; правила режимов, обязанностей, проверки имён, настроек и цвета действуют для Связного так же. `instrumentalForms` заменена `nameCaseForms` (осталась обёрткой).

Контекст: владелец переименовал приложение в **Tridot** (по-русски «Тридот») и разделил работу между тремя помощниками: главный **Садо** и два помощника с разными обязанностями — **Лиорио** (расширения) и **Нода** (оповещения) (`docs/PLANS.md`, «Tridot: Садо, Лиорио и Нода»). Новая версия ставится поверх установленной: данные пользователя, настройки и история должны читаться без потерь, а откат на прошлую версию — не ломать файл настроек.

Решение:

- **Название.** `AppInfo.name` = «Tridot», косвенные падежи — тоже «Tridot» (не склоняется: «в Tridot», «установите Tridot»), `AppInfo.hubName` = «Мой Tridot». Название — на плашке меню, в `MaterialApp.title`, «О приложении», заголовке окна Linux (`my_application.cc`) и Windows (`main.cpp`, латиница — коды символов больше не нужны), в подписи на Android (`android:label`), в `APP_DISPLAY_NAME` и меню macOS (`MainMenu.xib`), в `FileDescription` Windows, авторе встроенных расширений и пака шуток. В русском тексте название пишется латиницей.
- **Что не меняется и почему.** applicationId и namespace Android (`com.example.local_assistant`), bundle id macOS (`com.example.localAssistant`), `APPLICATION_ID` и `BINARY_NAME` Linux, Dart-пакет `local_assistant`, папка данных (`<документы>/assistant`). `AppInfo.latinName` = «Relay» остаётся служебным: от `PRODUCT_NAME` (Relay.app) зависят пути сборки macOS, от `ProductName` и `CompanyName` в `Runner.rc` — папка данных в RoamingAppData на Windows. Смена любого из них потеряла бы данные при обновлении; `test/app_info_test.dart` держит их на месте. Каталогов `ios/` и `web/` в репозитории нет.
- **Знак.** Три закрашенные точки цветами помощников на сетке 24 (центры (5,12), (12,12), (19,12), радиус 3): в приложении — `RelayGlyphPainter` на плашке меню (`app-glyph`), на иконках запуска (Android `mipmap-*`, macOS `AppIcon.appiconset`, Windows `app_icon.ico`) — та же сетка на 80 % плитки цвета фона `#131514` (`test/launcher_icons_test.dart`).
- **Помощники.** `Personas.all` = Садо (`sado`), Лиорио (`rio`), Нода (`noda`); id `rio` и `noda` прежние (ADR-008). Садо — главный: беседа, задачи, планирование, калькулятор, «Данные»; встречает в новой сессии. Лиорио — расширения: склад (вопросы, действия и карточка «Подтвердить»), «Пароли», будущие конвертер, архиватор, загрузчик видео, любое подключение. Нода — оповещения: напоминания, строка просрочки на экране новой сессии, сигналы склада (действие ждёт подтверждения, жалоба). Итогов фоновых задач и утренней сводки в коде пока нет; когда появятся, их пишет ведущий оповещений — это правило решения.
- **Режимы** (`TeamMode`): **Соло** — Садо делает всё; **Дуэт** — Садо и один помощник на выбор (`duo_helper`), зона второго возвращается к Садо; **Трио** — все трое (по умолчанию). Имя выключенного режимом помощника обращением не считается, но из начала фразы снимается до разбора: «Нода, добавь задачу хлеб» в Дуэте с Лиорио — задача «Хлеб» от Садо. Режим, сменённый с экрана, снимает продолжение разговора с выключенным помощником; на его вопрос, оставшийся без ответа, отвечает ведущий зоны навыка (как у карточек).
- **Обязанности** (`PersonaDuty`): расширения по умолчанию ведёт `rio`, оповещения — `noda`; обе можно переназначить, в том числе на одного помощника. Главный — всегда Садо. `PersonaCast.ownerOf(duty)` — назначенный, если он активен в режиме, иначе Садо; `notifier` и `extensionsLead` — его частные случаи. Зона фразы — `DutyZones.dutyOf(connectorId)`; без обращения по имени отвечает хозяин зоны: так Садо «передаёт» фразу помощнику. Роли (ADR-012) только включают навыки.
- **Под себя.** Каждого можно переименовать и выбрать пол, у каждого свой стиль. `PersonaCast` строит состав из настроек (имя, род, метка — первая буква текущего имени: С, Л, Н); обращение по имени, вступление перед командой и беседа пересобирают свои списки при смене состава (`PersonaCast.version`). Встроенные формы («Ноду», «Нодочка», «Лио») действуют, только пока имя прежнее; к новому имени обращаются в именительном падеже, а в просьбах беседы («включи дуэт с Мирой») понимается и творительный (`instrumentalForms`). «Е» и «ё» в именах — одна буква (`Persona.fold`). В каталоге имена (`{name}`, `{main}`, `{other}`) — только в именительном падеже.
- **Проверка имени** (`PersonaNames.validate`): одно слово от 2 до 24 знаков, только буквы и дефис (имя из нескольких слов понималось бы только в начале фразы); не обычное слово в начале фраз (команды «добавь», «напомни», «покажи», приветствие, «да», «нет» и другие ответы на вопрос, местоимения и союзы: имя после пробела отрезается как обращение и забрало бы фразу); не совпадает (без учёта регистра и «ё») с именем или формой имени другого помощника и с обращением к подключению — «склад», «пароли», «сейф», «задачи», «калькулятор», слова слотов подключений, «Данных» и названия сервисов «Паролей». Иначе — понятное сообщение («Имя «Склад» занято обращением к подключению — фраза «склад, …» ушла бы не туда»), имя не сохраняется. Неверное имя в файле настроек читается как встроенное. Имена файла проверяются против состава из всех остальных имён файла (не встроенных), поэтому принятое экраном читается без потерь, даже после обмена именами через третье; из двух одинаковых остаётся первое (Садо, Лиорио, Нода). В файл пишутся только переименованные.
- **Настройки** (`settings.json`): `team_mode`, `duo_helper`, `persona_names`, `persona_genders` (у Садо ключа нет, пока пол не выбран), `duty_extensions`, `duty_notifications`, `persona_styles` с ключом `sado`. Битое значение — по умолчанию. **Для отката** пишутся и прежние ключи: `assistant_mode` (`solo` в Соло, иначе `duo`), `main_persona` и `solo_persona` — как были в файле прежней версии (`rio`, если их не было): откат возвращает пользователю его прежнего отвечающего, даже если файл с тех пор сохранялся.
- **Переход со старых настроек** (в файле нет `team_mode`): `assistant_mode` = `duo` или ключа нет (прежний дуэт Лиорио + Нода) — Трио; `solo` — Соло, всё делает Садо. Садо получает стиль прежнего отвечающего (`persona_styles[main_persona]` в дуэте, `[solo_persona]` в соло, иначе нейтральный); стили `rio` и `noda` сохраняются. `role_owners` в обязанности **не** переносится: прежний выбор «Кладовщика ведёт Нода» отдал бы склад Ноде, а склад — у Лиорио. Новая установка — Трио, пол Садо не выбран.
- **Пол Садо до выбора.** При первом запуске на экране новой сессии — карточка «Садо — он или она?» (`sado-gender-choice`), без модального окна; выбор пишется в `persona_genders.sado`. До выбора подписи интерфейса говорят без рода, а ответы каталога склоняются в мужском роде: разметка рода двоичная (`{м|ж}`), третий род означал бы переписать около 45 записей во всех стилях и валидатор. Строго нейтральные ответы до выбора — отдельная работа.
- **Ответы.** Голос Садо — стиль плюс род, как у остальных: он говорит всеми записями во всех четырёх стилях (по умолчанию — нейтральный). «Кто ты» разбит на `talk.who.main`, `talk.who.helper`, `talk.who.self.helper`, `talk.who.mainRef`; род в фразе — род того, о ком она (`ReplyVoice.copyWith(gender:)`), обратного рода больше нет. «Пусть отвечает Лио» настроек не меняет (`talk.set.mainFixed`), «включи трио/дуэт/соло» меняет режим (`docs/REPLIES.md`).
- **Цвет Садо** — третий акцент П1, фиолетовый `#B69CFF` (фон знака `#2A1D4D`), рядом с лазурным Лиорио `#8ED1F2` и нежно-розовой Нодой `#F5A8CB`. Контраст по WCAG не ниже 4.5:1 на всех тёмных поверхностях и на своём фоне проверяет `test/app/theme_tokens_test.dart`. Один цвет не даёт 4.5:1 и на тёмном, и на светлом фоне (у лазурного и розового на белом — меньше 2); светлой темы нет, для неё заготовлен `sadoOnLight` `#6A40D8` (≥ 4.5:1 на `#FFFFFF` и `#F5F7F6`).

Последствия: обновление поверх установленной версии сохраняет данные, а прошлая версия читает файл настроек после отката (как дуэт Лиорио + Нода). Новая обязанность или навык — строка в `DutyZones`, а не правка маршрутизатора. Цена: два имени приложения (Tridot для людей, Relay в служебных местах), мужской род Садо в ответах до выбора пола и обращение к переименованному помощнику только в именительном падеже (творительный — только в просьбах беседы). Свободность имени в Google Play и домен владелец проверяет сам перед выпуском.

## ADR-017. Главный помощник — Связной

Контекст: владелец решил, что главный помощник по умолчанию называется **«Связной»** — «именно главный помощник», а при женском роде — **«Связная»**; имя по-прежнему можно поменять на любое. «Связной» — субстантивированное прилагательное: «Связного», «Связному», «дуэт со Связным», «о Связном»; у «Связной» женского рода — «Связной», «Связную». Прежнее имя по умолчанию — «Садо» (ADR-016). Название приложения остаётся Tridot.

Решение:

- **Модель.** `Personas.sado`: id `sado` (не меняется: настройки, история, паки), `russianName` = «Связной», новое поле `feminineName` = «Связная», латинское `name` = «Svyaznoy» (в интерфейсе не показывается; обращение «Svyaznoy, …» работает, как «Noda, …»). Буква «С» и фиолетовый цвет прежние. `Persona.defaultNameFor(gender)` — встроенное имя рода, `Persona.isDefaultName(value)` — встроенное имя любого рода без учёта регистра и «ё».
- **Имя следует за родом.** Пока имя не меняли, `PersonaSettings.nameOf('sado')` = «Связной» до выбора рода и в мужском роде, «Связная» — в женском. `withName` со встроенным именем любого рода ключ имени удаляет; ввод «Связная» при мужском роде род **не** меняет и показывается «Связной»: род меняется только переключателем (поле имени в «Помощниках» после сохранения показывает то, что вышло). Своё имя от рода не зависит.
- **Обращение и падежи.** Обращение «Связной, …» и «Связная, …» — при любом роде (встроенные `nicknames`). Косвенные падежи (только в беседе, обращением не считаются): «связного», «связному», «связным», «связном», «связную», «связною»; женская форма «связной» совпадает с именительным и уже обращение. В беседе «со» перед именем читается как «с»: «включи дуэт со Связным», «дуэт со Светой» — тот же образец, что «дуэт с <имя>». «Садо» больше не обращение; «Садовник», «Связного, …» и слова, лишь начинающиеся с имени, — тоже не обращение. Слово «связной» в начале фразы («Связной список …») теперь читается как обращение — цена имени-прилагательного.
- **Падежи своих имён** — `nameCaseForms(name, gender)` вместо `instrumentalForms` (ADR-016; та осталась тонкой обёрткой): родительный, дательный, винительный, творительный и предложный по окончанию — «-а» (Мира: миры/миру/мирой/мире; после г, к, х, ж, ш, ч, щ — «-и»), «-я» (Аглая: аглаи/аглаю/аглаей), «-ий» (Дмитрий: дмитрия/дмитрию/дмитрием/дмитрии), «-й», «-ь» по роду, согласный у мужского имени. Мужское на «-ой»/«-ый» — как прилагательное (Шустрый: шустрого/шустрому/шустрым/шустром), женское длиннее пяти букв на «-ая»/«-яя» — тоже (Связная: связной/связную); короткие на «-ая» (Аглая, Тая) — существительные. Женское имя на согласный и несклоняемые («Лиорио», «Садо») форм не получают. Так «сделай Свету основной» понимается при Ноде, переименованной в «Свету».
- **Карточка первого запуска** (`sado-gender-choice`, ключи чипов прежние): при встроенном имени — «Связной или Связная?» и чипы «Связной (он)» / «Связная (она)»; при своём — «Мира — он или она?» и «Он» / «Она». Подсказка режима в «Помощниках» называет главного только в именительном («Связная и один помощник на выбор; зона выключенного — снова у главного», «Связная делает всё сама»): своё имя пользователя интерфейс не склоняет. Каталог ответов подставляет имена тоже только в именительном (`talk.who.*`, `talk.set.*`).
- **Перенос.** Прежние версии не писали встроенное имя в `persona_names`, поэтому у кого главный был «Садо» по умолчанию, ключа нет — после обновления он «Связной» или «Связная» по роду. Своё имя остаётся, в том числе «Садо», если его ввести теперь. Имя «Связной»/«Связная», записанное как своё, при чтении снимается (`fromJson` через `isDefaultName`) и снова следует за родом.
- **Коллизия.** Если у Лиорио или Ноды в файле своё имя из форм главного («Связная», «Связного»), цикл проверки имён `fromJson` сбрасывает его к встроенному («Нода»); экран такое имя не примет (`PersonaNames.validate`: «уже у помощника Связной»). Прежнее «Садо» у другого помощника — просто имя.
- **Название приложения** не меняется: Tridot (ADR-016). Прежнее название приложения «Связной» (ADR-009) — теперь имя помощника; помощник по-прежнему не называет себя названием приложения («Я Связной, главный помощник в Tridot»). Генератор паролей и дальше не берёт «связной» (`forbiddenInMaster`).

Последствия: в истории старые ответы «Я Садо…» остаются как были, метки и подписи показывают текущее имя. Откат на прошлую версию снова покажет «Садо» (у нового своего имени — его). Тесты: `test/personas/svyaznoy_default_test.dart`, строки корпуса `talk-157`, `talk-158`, `talk-162`–`talk-166`.

## ADR-018. Проекты-папки

Контекст: владелец: «проекты что такое — сейчас это просто выбор чатов через добавление уже созданных, а должны быть как бы папки… и из них тоже можно создавать сессии сразу связанные с проектом, в котором эта сессия создалась». До этого раздел «Проекты» только группировал активные задачи по первой метке (`#работа`), а сессии с проектами никак не связывались.

Решение:

- **Проект — папка для сессий**, а не новый вид чата: у сессии (и чата задачи) необязательное поле `project_id` в шапке файла и index.json (`ChatThread.projectId`). Это уточнение ADR-010: «новый вид чата — новый `ChatKind`» для проектов не нужен, сессия в проекте остаётся обычной сессией. `schemaVersion` остаётся 1; старые версии поле пропускают.
- **Где лежат.** `chats/projects/projects.json` — `{schema_version: 1, projects: [{id, name, description?, task_tag?, created_at, updated_at, pinned_at?}]}`; id — `project:<микросекунды>_<случайное>`. Пишется целиком и атомарно (`JsonChatStore.saveProjects`, та же очередь записи, что у чатов), только когда появилась первая папка: у кого папок нет, файла нет. В подпапке, а не рядом с чатами: прежние версии при каждом запуске пересобирают index.json по всем `*.json` верхнего уровня и непонятный файл откладывают в `.broken` — `chats/projects.json` откат стирал бы. Подпапку они не читают и при очистке истории не удаляют. Если нового файла нет, читается прежнее место — `chats/projects.json` или отложенный старой версией `chats/projects.json.broken`, когда он разбирается (сборки этой ветки до переноса); следующая запись — уже в подпапку. Битый файл (не UTF-8, не JSON, не та структура) уходит в `projects.json.broken`, чаты читаются без проектов. Ссылка `project_id` на проект, которого нет, при чтении становится «вне проектов» (`ChatBook.load`).
- **Файл не прочитался** (ошибка файловой системы: заблокирован синхронизацией или антивирусом, нет доступа) — это не «папок нет». `JsonChatStore.loadProjects` бросает исключение, `ChatBook` запоминает это (`projectsUnreadable`): папки не показываются, но ссылки `project_id` у сессий не сбрасываются, а перед первой записью файл читается ещё раз — прочитался, и папки с диска сливаются с созданными за это время; снова нет — запись пропускается (папки на диске целы, изменения папок живут до перезапуска). Экран говорит: «Не удалось прочитать проекты — они целы, попробуйте перезапустить приложение».
- **Операции** (`ChatBook`): `createProject`, `renameProject`, `setProjectDescription`, `linkProjectTag`, `setProjectPinned`, `moveToProject` (пишется сразу), `sessionsOf`, `projectOf`, `projectSessionCount`, `deleteProject(deleteSessions:)`. `newSession(projectId:)` — «Новая сессия в проекте»: пустая сессия сразу лежит в проекте и попадает в него на диск с первым сообщением; «+» без проекта — сессия вне проектов, даже если открытая пустая была проектной; оставленная пустая сессия, открытая снова, — вне проектов. Задача, созданная в сессии проекта, кладёт свой чат в тот же проект.
- **Интерфейс.** В панели под строкой «Проекты» — до пяти папок с числом сессий (`project-<id>`; дальше «Все проекты»), «Новый проект» — кнопка «+» в строке «Проекты» (`project-new`: панель не становится длиннее). Счётчик «Проектов» — число папок. Экран проекта (`AppSection.project`): название, описание, «Новая сессия в проекте» (`project-new-session`), сессии проекта (закреплённые сверху; долгое нажатие — меню сессии), задачи связанной метки и меню «⋯»: «Переименовать», «Описание», «Метка задач», «Закрепить», «Удалить проект». Как в других чат-приложениях, сессии проекта остаются и в «Сегодня/Вчера/…» — с маленькой подписью: значок папки и название проекта; в шапке — то же под названием сессии, на заставке пустой сессии — «Проект «…»»; на экране самого проекта подписи папки у строк нет. Поиск подписывает результат «Проект · …» и умеет искать в одном проекте (`search(projectId:)`).
- **Перенос.** В меню сессии (долгое нажатие в панели и на экране проекта, нажатие на название в шапке) — «В проект…»: лист с папками, «Новый проект…» и «Убрать из проекта». У чата задачи пункта нет (его место — по задаче).
- **Удаление проекта.** Пустой — простое подтверждение. С сессиями — выбор: «Вынести сессии из проекта» (по умолчанию) или «Удалить вместе с сессиями (N)» (насовсем, как «Удалить» у сессии; ответ, который ещё готовится в такой сессии, пропадает, открытая — сменяется пустой). Задачи остаются в любом случае.
- **Метки задач остаются.** `#метка` в команде, `Task.project` (первая метка), корпус и подстановки не меняются; отдельного поля «проект» у задачи нет. Папку можно связать с меткой («Метка задач» в меню проекта или «Сделать папкой» у метки на экране «Проекты»): на экране папки — задачи с этой меткой, а задача, созданная в сессии папки без своей метки, получает метку папки (`AssistantController.enterChat(projectTag:)` → `AssistantSession.projectTag`; своя `#метка` в команде важнее). Одна метка — не больше одной папки. Экран «Проекты» — два блока: «Папки» и «Метки задач» (метки без связанной папки, как раньше; ключи карточек — `tag-<метка>`).
- **Проект в документе задачи — первая метка.** Поле подписано «Проект — первая метка задачи»: новое значение заменяет первую метку, а если такая метка уже есть среди остальных, она не повторяется (`[a, b]` + «b» → `[b]`, раньше было `[b, b]`); очистка поля убирает только первую метку (`[a, b]` → `[b]`) — это сознательное поведение, подсказка поля говорит об этом честно.
- **«Очистить историю сессий»** стирает сессии и чаты задач, а папки остаются — пустыми (в окне подтверждения: «проекты — пустыми»).

Последствия: проекты появляются без переноса данных — старые файлы читаются как есть, у сессий просто нет `project_id`. Откат на прошлую версию не видит подпапку `projects/` и не трогает её; сессии в ней снова только в «Сегодня/…», а сессия, которую старая версия перезапишет (новое сообщение, переименование), теряет `project_id` — после возврата на новую версию она вне проектов, сами папки на месте. Следующий шаг — контекст «в чате проекта — о проекте» (`docs/PLANS.md`, «Чаты проектов»). Проверки — `test/chats/chat_projects_test.dart`, `test/home_projects_test.dart`, `test/screens/projects_screen_test.dart`, `test/shell/relay_drawer_test.dart` («проекты-папки»), `test/assistant_controller_test.dart` («метка проекта-папки»), `test/task_service_test.dart`.

## ADR-019. Вложения и облачный диск

Контекст: владелец: «+» в поле ввода должен открывать три пункта со своими списками — «Облачный диск» (Яндекс Диск / Google Диск; если подключён один — сразу он), «Прикрепить файл» (скрепка: фото, видео, аудио, документ…) и «Шаблоны команд». Файлы должны действительно выбираться, лежать в папке сессии рядом с её чатом, показываться в сообщении и пропадать вместе с сессией; никуда сами не отправляться. Облачные диски в приложении ещё не подключены (OAuth — отдельный этап).

Решение:

- **Выбор файлов — пакет `file_selector`** (официальный пакет Flutter; на Android — Storage Access Framework, без разрешений и правок манифеста). Это и есть «`file_selector` (этап 4)» из плана «Паролей»: импорт CSV и копий сейфа по-прежнему на своём выборе, их перевод — отдельно. В интерфейсе выбор спрятан за `AttachmentPicker` (`lib/app/attachments/attachment_picker.dart`): в приложении — `FileSelectorAttachmentPicker` (группы типов с `mimeTypes` и `extensions`: фото, видео, аудио, документы, любой файл), в тестах — подделка. Ядро от Flutter не зависит: файл приходит как `AttachmentSource` (имя, MIME, размер, `saveTo`).
- **Модель.** `ChatAttachment` (`lib/core/chats/attachments.dart`): id `<id сообщения>-<номер>`, вид (`image`/`video`/`audio`/`document`/`other` — по MIME, без него по расширению), имя для показа, путь копии относительно папки чатов, размер, MIME, время. `ChatMessage.attachments` пишется в JSON чата, только если список не пуст; битая запись пропускается, путь принимается только вида `files/<папка>/<файл>` из латиницы, цифр, `_`, `-`, `.` — файл чата не может указать на чужой файл. `withLink`/`withText` вложения сохраняют, `copyAs` (копия команды в чат задачи) — нет: файлы остаются в сессии.
- **Где лежат.** `chats/files/<имя файла чата без .json>/<id сообщения>-<номер>.<расширение>`: имя файла пользователя на диске не хранится (только в JSON, после `SecretGuard` и `LoginLinks.redact` — токен или пароль в имени файла скрыт). `AttachmentStore`: `IoAttachmentStore` (копия через `XFile.saveTo` во временный файл и переименование — без чтения файла в память Dart) и `InMemoryAttachmentStore` (тесты). `ChatStore.attachments` — хранилище вложений: `erase` («Удалить» сессию) стирает папку её файлов, `clearAll` — всю `files/`, `delete` (архив чата удалённой задачи) файлы не трогает. Обрезка чата до 1000 сообщений и чтение чата убирают файлы без сообщения (сбой между копированием и записью); файлы, уже скопированные для отправляемого сообщения, при этом не трогаются. «Данные» считают размер вместе с `files/`.
- **Лимиты.** Файл — до 25 МБ («Файл больше 25 МБ — такие пока не прикрепляются»), до 10 файлов в сообщении. 25 МБ — потому что дальнейшая обработка (конвертер, архиватор) на телефоне будет читать файл целиком, а папка сессии не должна раздувать место приложения незаметно.
- **Гонки копирования.** Путь копии становится «ждущим» до начала копирования, а уборка не трогает `<файл>.tmp` ждущего вложения и удаляет папку чата только пустой: обрезка ленты или `discard` во время копирования не стирают новый файл. Сессию удалили, пока копировались её файлы, — копирование останавливается, а папка стирается ещё раз: на диске файлов удалённой сессии не остаётся. Файлы, выбранные, но ещё не отправленные, общие для поля ввода, как и черновик текста: отправленные в другой сессии ложатся в её папку.
- **Только в памяти.** В режиме «Только в памяти» (`AttachmentStore.persistent == false`) «Прикрепить файл» честно говорит «В режиме «Только в памяти» файлы не сохраняются» и выбор не открывает.
- **Резервная копия Android.** `chats/files/` исключена из облачной копии (`data_extraction_rules.xml`, `backup_rules.xml`): фото и документы пользователя не уходят в облако Google сами; при переносе «телефон → телефон» переносятся.
- **Отправка.** Выбранные файлы ждут чипами над полем (крестик убирает); кнопка отправки работает и без текста. Файлы копируются в папку сессии до записи сообщения. Сообщение только из файлов в помощника не идёт: отвечает главный ключом каталога `attachments.saved` («Сохранил в этой сессии 2 файла. Обрабатывать файлы я пока не умею — позже ими смогут пользоваться расширения, например конвертер и архиватор»); название сессии — «Фото», «Видео», «Аудио» или «Файл: <имя>». С текстом команда обрабатывается как обычно, а под ответом — строка `attachments.savedNote`. Файлы никуда не отправляются, в уведомлениях их имён нет.
- **Показ.** В ленте картинки — превью (`cacheWidth: 480`, ошибка чтения → чип), остальное — чип со значком вида, именем и размером; нажатие — лист со сведениями и путём (без передачи в другие приложения). Копии нет — чип «файл не найден», без падения.
- **Облачный диск — только интерфейс.** `CloudDisk` (Яндекс Диск, Google Диск) заменяет прежний `DocumentSource` с пометкой «скоро». `CloudDiskMenu.entries(connected)`: ни одного диска — «Подключить диск» (лист: диски появятся позже, пока — «Прикрепить файл» с устройства); один — пункт сразу действует на него, без выбора; несколько — список. Подключённых дисков сейчас нет (список пуст, в настройках не хранится); OAuth не делается.
- **Меню «+»** — нижний лист на всех ширинах: «Облачный диск», «Прикрепить файл», «Шаблоны команд» раскрываются своими списками (ключи `composer-cloud`, `composer-attach`, `composer-templates`); пункты «Паролей» сначала были отдельной группой под ними; с ADR-020 «Шаблоны команд» строятся из каталога команд, а действия сейфа переехали в «Найти команду», раздел «Сейф».

Последствия: старые чаты читаются без изменений (поля `attachments` нет). Откат на прошлую версию не показывает `attachments` (сообщение только из файлов покажется пустым пузырём) и не трогает папку `files/`, но чат, который старая версия перезапишет (новое сообщение, переименование), теряет описание вложений: после возврата на новую версию уборка при чтении этого чата сочтёт его файлы ненужными и сотрёт их. Вложения в чатах, не тронутых во время отката, сохраняются. Новая зависимость `file_selector` тянет платформенные реализации (Android, Linux, Windows, macOS); на Linux нужен портал выбора файлов или zenity. Обработки файлов нет: конвертер и архиватор как расширения будут брать файлы из папки сессии.

## ADR-020. Каталог команд: «Шаблоны команд» и «Найти команду»

Контекст: владелец: «+» → «Шаблоны команд» должен показывать около четырёх часто используемых команд (по настоящим счётчикам, хранящимся на устройстве, с разумным порядком по умолчанию) и пятым пунктом «Найти команду» — список всех команд включённых навыков по разделам с поиском, чтобы подобрать нужную. Выбор, как и раньше, вставляет шаблон в поле (`|` — место курсора). До этого шаблоны были жёстким списком из пяти команд о задачах, а пункты «Паролей» — отдельной группой в «+».

Решение:

- **Каталог — чистый Dart** (`lib/core/commands/command_catalog.dart`, без Flutter): `CommandEntry` (постоянный id, раздел, подпись, шаблон с `|`, пример заполнения, навык, значок по имени, «нужна выбранная задача»), `CommandCatalog.build(connectors:, hasSelection:, projectTag:, passwordActions:)`. Источник — встроенный список `CommandCatalog.curated` и **включённые** навыки и подключения (`AssistantController.connectors`): команда выключенного навыка в каталог не попадает, потому что помощник её всё равно не выполнит. Расширение, о котором каталог не знает, попадает в раздел «Другое» своими примерами (`ext.<id>.<номер>`, не больше шести).
- **Разделы**: Задачи, Планирование, Беседа, Калькулятор, Склад, Сейф (навык «Пароли»), Данные, Другое. Задачи делятся по смыслу: перенос и просроченные — «Планирование». Склад показывается, только пока у подключения есть описание с командами.
- **Команды о выбранной задаче** («Перенести выбранную» — `Перенеси её на |`, «Завершить выбранную») — только когда в сессии выбрана активная задача. «Задача в проект» — `Добавь задачу «|» #`, курсор в названии; в сессии папки, связанной с меткой (ADR-018), метка уже подставлена: `Добавь задачу «|» #метка`. Голая `#` меткой не считается.
- **Действия сейфа** («Пароли», «Сгенерировать пароль», «Добавить запись») — команды вида `action` в разделе «Сейф»: открывают экран, ничего не вставляют. Отдельной группы «Паролей» в «+» больше нет.
- **Частые команды.** «Шаблоны команд» — четыре команды `CommandCatalog.top(usage)`: по убыванию счёта, при равенстве — порядок по умолчанию (Новая задача, Задача на завтра в 10:00, Показать задачи, Посчитать), затем порядок каталога; только включённые. Пятый пункт — «Найти команду» (ключ `command-find`).
- **Счётчики — только по id.** `AppSettings.commandUsage` (`command_usage` в `settings.json`): id → число. +1 только при выборе из «+» или «Найти команду»; по набранному тексту не считается никогда, текст команды (и то, что пользователь дописал) не хранится — в том числе для `pw.*`. При чтении неизвестные id (кроме `ext.*`) и не положительные числа отбрасываются, записей не больше 50 (остаются частые), счётчик не больше 2^20. Хранится в общем `settings.json` через `SettingsStore`, а не в `shared_preferences`: у приложения один файл настроек с атомарной записью и осторожным чтением, а новый плагин ради одной таблицы чисел не нужен.
- **«Найти команду»** — нижний лист (`command_finder_sheet.dart`, `DraggableScrollableSheet`): поле поиска (`command-search`, без учёта регистра и «ё», по подписи, шаблону, примеру и названию раздела), заголовки разделов (`command-category-<раздел>`), строки команд (`command-entry-<id>`): подпись и шаблон. Ничего не нашлось — честно: «Такой команды нет. Возможно, нужный навык выключен в «Расширениях»».
- **Вставка шаблона.** Пустое поле шаблон заменяет; в начатый черновик шаблон вставляется на место курсора через пробел — набранное не теряется. Так же работают быстрые действия и «Перенести» в шапке задачи.
- **Шаблон без времени.** «Перенеси её на завтра в» (шаблон, где время не дописали): висящий в конце предлог («в», «во», «на», «к», «ко», «до», «около») не становится ни целью, ни названием, а при известном дне без времени помощник спрашивает «Во сколько?» (`DueIssue.missingTime`, `task.due.missingTime`); «Перенеси её на» без срока — обычное «На когда перенести задачу?». Корпус: `reschedule.jsonl`, `move-017`…`move-022`.
- **Проверки.** Каждый шаблон каталога с примером заполнения проходит через тот же маршрутизатор, что корпус, и должен дойти до своего навыка (`test/commands/command_catalog_test.dart`).

Последствия: новый навык попадает в «Найти команду» без правок интерфейса (примерами), а встроенный — строкой в `CommandCatalog.curated`. Id команд менять нельзя: по ним хранятся счётчики. Откат на прошлую версию игнорирует `command_usage`. Счётчики не попадают ни в корпус, ни в журналы, ни в уведомления.

## ADR-021. Шрифты и подсветка команды

Контекст: владелец: моноширинный JetBrains Mono был почти везде, где есть цифры и подписи (`technicalTextStyle`: время, счётчики, версия, подписи, чипы вроде «Открыть сессию задачи») — около 114 мест в 29 файлах. «Пароли оставляем моноширинными». Нужна подсветка команды, как подсветка синтаксиса: части фразы, которые навыки поняли, — моноширинным с мягким цветом, и в поле ввода по ходу набора, и в отправленных сообщениях. Название «Tridot» и названия проектов — отдельным шрифтом Cormorant Unicase SemiBold.

Решение:

- **Три шрифта, у каждого своя работа** (`AppFonts` в `lib/app/assistant_theme.dart`). Inter — весь текст. JetBrains Mono — только значения паролей (показанный пароль, маска «••••», вывод генератора, поле ввода пароля `SecretField`) и распознанные части команды. Cormorant Unicase SemiBold (`assets/fonts/CormorantUnicase-SemiBold.ttf`, SIL OFL, лицензия — в «Настройки → Лицензии») — «Tridot» в шапке панели, «Мой Tridot» (только само слово, `appNameSpan`), названия проектов-папок: строки панели, экран проекта, карточки «Папки», меню «В проект…», подпись «Проект «…»» на заставке пустой сессии. Кириллица в шрифте есть целиком (А–я, Ё/ё, «», —, №).
- **Метаданные — Inter с табличными цифрами.** `technicalTextStyle` заменён на `metaTextStyle`: Inter 12 px с `FontFeature.tabularFigures()` — время, счётчики и версия не прыгают по ширине. Моноширинный стиль — `monoTextStyle`, используется только в навыке «Пароли» и в подсветке.
- **Подсветка — из настоящего разбора.** `AssistantController.highlight(text)` возвращает части `CommandSpan(start, end, kind)` (`lib/core/scenario/command_spans.dart`): обращение по имени (`address`), слово команды (`verb`), название или цель (`title`), срок (`due`), метки (`tag`), числа и пример (`number`). Навык выбирается так же, как при отправке (`RoutePolicy.pick` по `match` всех включённых навыков), но без контекста сессии, чата и вопросов, ничего не запускается и не запоминается. Части даёт сам навык через `CommandSpanSource`: задачи — `ScenarioParser.spansOf` (тот же `parseUtterance`; слова названия — те, из которых разбор собрал название), калькулятор — числа и знаки примера; у остальных — метки и числа фразы. Беседа (ответ «по умолчанию») и нераспознанная фраза не подсвечиваются.
- **Пароли не подсвечиваются вовсе.** Если в тексте есть маска «•», код входа, пароль по правилам `SecretGuard`, фраза о паролях (`PasswordPhrases.looksLike`) или фразу узнал навык с `sensitive` — подсветки нет никакой, даже у слова команды: секрет не выделяется ни цветом, ни шрифтом. Защита паролей не менялась: подсветка смотрит на текст, который уже показан.
- **Поле ввода** — `CommandInputController` (`lib/app/widgets/command_highlight.dart`): разбор через 180 мс после последней правки, а не на каждую букву; пока новый не готов, прежняя подсветка остаётся, если текст только дописан в конец. Набираемое слово клавиатуры подчёркивается, как в обычном поле. Длиннее 400 знаков — без подсветки.
- **Лента** — разбор при отрисовке с кэшем по id и тексту сообщения (не больше 600 записей): в JSON чата ничего нового не пишется, старые версии приложения ничего не теряют.
- **Цвета** мягкие (`AssistantColors.commandVerb`, `commandValue`, `commandTag`, `commandAddress`), контраст на пузыре и поле не ниже 7:1; название — цветом текста, выделяет его только шрифт. Моноширинные части на 8 % мельче: строка не прыгает.

Последствия: новый навык подсвечивает метки и числа сам собой, а точнее — если реализует `CommandSpanSource`. Подсветка — подсказка, а не проверка: она показывает, что понял разбор сейчас, без контекста разговора («да», «закрой» в чате задачи остаются без цвета).

## ADR-022. Помощь в постановке задачи: подсказка команд вместо «не понял»

Контекст: владелец: когда запрос совсем непонятен — ничего не подошло, слово искажено опечаткой, — вместо голого «не понял» Связной коротко отвечает «Не до конца понял. Возможно, подойдёт:» и предлагает две-три самые близкие команды из «Найти команду» кнопками, последней — «Найти команду». Выбор вставляет шаблон команды в поле ввода, отправляет пользователь сам. Условие владельца: «там должны быть супер непонятные запросы, они не должны становиться нормой — это вспомогательное, если, например, человек опечатался».

Решение:

- **Только вместо `common.unknown`.** Подсказка включается в единственном месте маршрутизатора — где ни один коннектор не забрал фразу (`AssistantController._unknownFor`). Понятые фразы (в том числе с опечатками, которые разбор уже прощает: «дабавь задчу хлеб», «пакажи задачи»), фразы с уточняющим вопросом коннектора («добавь задачу» → «Как называется задача?», «перенеси» → «Какую задачу?»), спор двух навыков (`router.ambiguous`), вопрос «да/нет» — без изменений. Случай «понимание потребовало бы больше одного-двух вопросов» отдельно не распознаётся: такие фразы либо доходят до коннектора с его вопросом, либо остаются непонятыми и получают подсказку.
- **Похожесть** (`lib/core/commands/command_suggest.dart`, чистый Dart): слова фразы сравниваются с ключевыми словами команд каталога (`CommandCatalog.build` из включённых навыков, ADR-020; у встроенных команд — свой короткий список: глагол и предмет, у расширений — слова примера). Совпадение: то же слово — 1; та же основа (общее начало от 4 букв) — 0,9; опечатка (расстояние Дамерау — Левенштейна 1, или 2 у длинных слов, в том числе без окончания) — 0,75 или 0,6. Общие слова («покажи», «задачу», «сделай») весят вдвое меньше: одного такого слова мало. Порог — 0,75; показываются не больше трёх команд и только близкие к лучшей (не меньше 60 % её веса и не ниже порога).
- **Только при опечатке.** Подсказка — не обычный ответ на непонятую фразу. В фразе должно быть хотя бы одно слово-опечатка: оно похоже на слово команды (пропущена, лишняя или заменена внутри слова одна буква, переставлены соседние, или расстояние 2 у длинных слов), но не совпадает ни с одним словом команд (всех встроенных, и выключенных навыков тоже) и не их форма с другим окончанием («задачу», «сделал», «выполненные»). Разговорное «скока» считается опечаткой. Команда подсказывается, только если на неё похожа сама опечатка. Правильно написанные фразы со словом команды — «сколько тебе лет», «расскажи сказку», «список покупок», «новая машина», «проект мечты», «процент по кредиту», «напоминание» — получают прежний ответ без кнопок: это понятная просьба, которую навыки не умеют, а не ошибка в команде. Фраза длиннее 12 слов подсказки не получает. При равной похожести решают счётчики выбора команд (`AppSettings.commandUsage`, передаются в `AssistantController.commandUsage`), затем порядок по умолчанию «Шаблонов команд» и каталога.
- **Что предлагается.** Только команды-вставки: без действий и команд сейфа, без команд о выбранной задаче. Похожих нет («ывапр олдж», «хлеб», «хочу пиццу») — прежний ответ `common.unknown` без кнопок: «Найти команду» под каждым непонятым ответом сделало бы подсказку нормой; эта кнопка есть только рядом с похожими командами, а сам список — в «+» → «Шаблоны команд».
- **Слова пользователя в шаблоне** — только когда это безопасно и очевидно: слова команды стоят в начале фразы, а после них короткий хвост, который ложится на место `|` — название задачи («сделй задачу купить хлеб» → `Добавь задачу «купить хлеб»`, курсор в конце) или пример из цифр для калькулятора («посчетай 2+2» → `Сколько будет 2+2`). Иначе — шаблон как есть, курсор на пустом месте. В тексте ответа — только подписи команд, слова пользователя не повторяются.
- **Пароли.** Фраза о паролях (`PasswordPhrases.looksLike`), пароль (`SecretGuard`), маска «•», ссылка входа, слово «пароль» с опечаткой («пороль»), «пин», «код», «логин», «сейф», слово из букв с цифрами длиной от 6 знаков — прежний ответ `common.unknown` без кнопок и без подстановки.
- **Ничего не запоминается.** Ни «фраза → команда», ни выбор подсказки: нажатие кнопки не меняет счётчики `command_usage` (в отличие от выбора в «+» и «Найти команду»). Та же фраза завтра получит тот же ответ.
- **Ответ** — запись каталога `common.unknown.suggest` во всех четырёх стилях («Не до конца {м:понял|ж:поняла}. Возможно, подойдёт: {options}. …»); `intent` остаётся `unknown`, статус — `noAction`. Кнопки (`suggest-<id>`, `suggest-find`) — `AssistantResponse.suggestions` / `ChatMessage.suggestions`: только в памяти и только под последним ответом; в JSON чата их нет, после перезапуска остаётся текст с подписями команд.

Последствия: новая встроенная команда попадает в подсказку через ключевые слова в `CommandSuggester` (без них — словами шаблона), команда расширения — словами своего примера. Пороги подобраны так, чтобы случайное созвучие не давало подсказки; если подсказки начнут появляться слишком часто, порог поднимается, а не расширяется путь.

## ADR-023. Голосовой ввод: Vosk через dart:ffi

Контекст: решение владельца (docs/PLANS.md, «Голосовой ввод»): только голосовой **ввод**, без ответов голосом; распознавание офлайн через Vosk, маленькая русская модель (~45 МБ) в сборку не входит и скачивается при включении. Удерживать микрофон — говорить, отпустить — текст в поле ввода с подсветкой команды; правка перед отправкой; настройка «Отправлять сразу». Ни звук, ни текст до отправки не покидают устройство и не сохраняются. Главная платформа — телефон на Android.

Решение:

- **Движок — собственная привязка `dart:ffi` к `libvosk.so`** (`lib/core/voice/vosk_ffi.dart`, около десяти функций C API), микрофон — пакет `record` 7.2.0 (BSD-3, поток PCM 16 бит, 16 кГц, моно). Готовые плагины отвергнуты: `vosk_flutter` не разрешается на Dart 3; `vosk_flutter_service` не собирался без подмены зависимости, тянет buildscript AGP 8.0.0, а его сборки для компьютеров сломаны; путь через Kotlin `SpeechService` требует JNA и правил ProGuard. Пробная сборка `flutter build apk --release --target-platform android-arm64` с AGP 9.1.0 и Kotlin 2.4.0 прошла только с ffi-привязкой.
- **Библиотека** — из `com.alphacephei:vosk-android:0.3.75@aar` (Maven Central, Apache-2.0): «@aar» без транзитивных зависимостей, Java-классы Vosk и JNA не используются. В APK попадает только `lib/arm64-v8a/libvosk.so` (`packaging.jniLibs.excludes` для остальных ABI), около +10 МБ. При сборке под выбранные ABI (`--target-platform`) из APK исключаются и чужие библиотеки других ABI (например, `libdartjni.so` пакета `record`): иначе Android выбрал бы ABI без `libflutter.so`, и приложение падало бы при запуске на x86_64 и 32-битном ARM. Лицензии Vosk, Kaldi, OpenFST (Apache-2.0), OpenBLAS и CLAPACK (BSD) — `assets/voice/NOTICE.txt`, на экране «Лицензии».
- **Распознаватель за интерфейсом** `VoiceRecognizer` (`lib/core/voice/voice_recognizer.dart`): доступ к микрофону, загрузка модели, поток событий «промежуточный текст / итог / ошибка», остановка с итогом и отмена без итога. Настоящий — `VoskVoiceRecognizer`: модель и распознаватель живут в отдельной долгоживущей изоляте, куски звука передаются туда в памяти. В тестах — подделка (`test/support/fake_voice.dart`), а сам `VoskVoiceRecognizer` проверяется с поддельным изолятом и поддельным микрофоном (`test/voice/vosk_voice_recognizer_test.dart`). Микрофон выключается при любой отмене, даже пришедшей, пока он ещё включался (короткое касание, уход в фон).
- **Модель скачивается по требованию** (`VoiceKit`, `lib/app/voice/voice_kit.dart`): `vosk-model-small-ru-0.22` с `https://alphacephei.com/vosk/models/`, только https. Размер (46 236 750 байт) и SHA-256 закреплены в коде (`VoiceModelSpec.ruSmall`); сумма вычислена по архиву, md5 которого совпал с официальным `model-list.json`. **Подписи у моделей Vosk нет** — проверка только по закреплённой сумме; новая версия модели — новые значения в коде. Загрузка — во временный `.part` с продолжением после обрыва (Range), отмена сохраняет скачанное; переадресации — не больше трёх, только https и только в пределах того же сайта (запрос не уходит третьим лицам); ошибка диска (нет места) показывается как «Проверьте свободное место», а не как ошибка сети, и проверенный архив при этом не удаляется — «Повторить» не скачивает его заново; сумма проверяется до распаковки, при несовпадении файл удаляется. Распаковка безопасная (`lib/core/downloads/safe_zip.dart`): без абсолютных путей, `..`, `\`, ссылок; не больше 64 файлов, 64 МБ на файл и 128 МБ всего, размер считается и при записи. Распаковка — во временную папку, затем переименование и последним — `installed.json`. Место: `<поддержка приложения>/assistant/voice`, исключено из облачной копии и переноса Android. «Удалить модель» в настройках освобождает место и выключает голосовой ввод.
- **Загрузчик и безопасная распаковка общие** (`lib/core/downloads/`): их же возьмут ffmpeg и yt-dlp у расширений.
- **Интерфейс.** Микрофон — на месте кнопки отправки при пустом поле (`assistant-voice`, 44×44, отдельно от `assistant-send`). На телефоне — удержание (`Listener`, без задержки долгого нажатия): палец лёг — слушает, отпущен — итог в поле ввода на место курсора (после черновика — через пробел), с той же подсветкой команды, что у набранного текста. Касание короче 0,3 с — отмена без итога с подсказкой удерживать. Пока говорят, промежуточный текст виден серой строкой над полем (`voice-partial`) и в поле не попадает, а подсказка поля — «Говорите…». Подсказки голосового ввода («Удерживайте микрофон…», «Нет доступа к микрофону…», «Голосовой ввод готов») — строкой над полем (`voice-notice`) на 4 с, а не всплывающим уведомлением: оно закрыло бы сам микрофон. Модель загружается в память заранее, как только ввод включён и модель скачана; если отпустить микрофон, пока она ещё загружается, — честное «сказанное не услышано». Каждая попытка нумеруется: после прерывания (фон, шторка) устаревшая попытка не начинает слушать, и одновременно слушает только одна; системный диалог доступа к микрофону попытку не прерывает. Экранный диктор нажимает двойным касанием: начать и закончить. На компьютере — нажатие (держать кнопку мыши неудобно) и Ctrl+Shift+M (Cmd+Shift+M на macOS).
- **Включение.** По умолчанию выключено (`voice.enabled`). Первое нажатие на микрофон предлагает включить: «Один раз скачается модель распознавания (~44 МБ) с сайта alphacephei.com», затем лист с ходом загрузки («12 из 44 МБ»), «Отменой», проверкой и распаковкой, ошибкой с «Повторить». То же — переключатель «Голосовой ввод» в настройках: без модели он сначала показывает то же предложение, загрузка без явного «Скачать» не начинается. В предложении и в настройках назван источник — сайт alphacephei.com, размер берётся из закреплённого в коде. Лист загрузки можно скрыть («Скрыть»): загрузка продолжается, о готовности скажет поле ввода. Перед первым запросом доступа к микрофону — честное объяснение («звук не записывается в файл и никуда не отправляется», `voice.mic_explained`); доступ проверяется при каждом начале (на Android 13+ «Только в этот раз» отзывается сам). Отказ — «Нет доступа к микрофону. Разрешите его в настройках Android».
- **«Отправлять сразу»** (`voice.send_now`, по умолчанию выключено): распознанное уходит тем же путём `_send`, что и набранное, со всеми фильтрами. Если текст похож на пароль (`SecretGuard`), фразу о паролях (`PasswordPhrases.looksLike`) или ссылку входа (`LoginLinks`), он сразу не отправляется: остаётся в поле с предупреждением «Похоже на пароль — проверьте текст и отправьте вручную».
- **Приватность.** Звук только в памяти: не пишется в файл, не отправляется; распознанный текст не попадает в журнал и в уведомления (уведомления голосового ввода текст не повторяют). `vosk_set_log_level(-1)` — движок не пишет в logcat. Уход приложения в фон прерывает распознавание без итога.
- **Платформы.** Сейчас только Android (arm64). На Windows, macOS и Linux `VoiceKit` не создаётся: микрофона нет, в настройках раздела «Голосовой ввод» — «На этой платформе пока недоступен — сейчас только Android». Нажатие и сочетание клавиш для компьютера уже есть и проверены тестами с подделкой. Путь вперёд: собрать и положить libvosk для каждой системы рядом с приложением, а для macOS добавить `NSMicrophoneUsageDescription` в Info.plist и entitlement `com.apple.security.device.audio-input`.

Последствия: APK больше примерно на 10 МБ; модель — ещё ~87 МБ на устройстве после распаковки, только у тех, кто включил. Качество малой модели скромное (ошибки в 12–32 % слов в зависимости от записи), поэтому по умолчанию текст правится перед отправкой. Работа `libvosk.so` с моделью на настоящем телефоне (время загрузки, память, совместимость ABI) в автотестах не проверяется — нужна проверка на устройстве.

## ADR-024. Расширения с карточкой-формой: архиватор ZIP, конвертер и загрузчик видео (шаги 1–3)

Контекст: решения владельца (docs/PLANS.md, «Расширения: конвертер, архиватор, загрузчик видео» и «Карточки-формы»): три расширения выключены по умолчанию, ведёт их Лиорио; фраза или шаблон из «+» открывает в чате карточку-форму, поля из фразы уже заполнены; одна общая карточка, чтобы будущие расширения вставали в тот же формат. Здесь записаны шаг 1 — общая карточка, исполнитель задач и архиватор целиком, шаг 2 — конвертер (ffmpeg) и шаг 3 — загрузчик видео (yt-dlp).

Решение:

- **Карточка-форма** (`lib/core/jobs/extension_card.dart`): `ExtensionCard` — id (`j<микросекунды>_<номер>`, он же имя папки результата), id расширения, версия формы, значения полей, состояние (`form`, `running`, `done`, `failed`, `cancelled`, `interrupted`), результаты, папка результата, код ошибки, временные пути (`cleanup`), содержимое архива. Схему полей карточка не хранит: её строит ядро по id расширения (`ExtensionForms.of` → `FieldSpec`: `files`, `file`, `folder`, `choice`, `url`; варианты выбора с причиной недоступности; `ExtensionForms.blocker` — почему «Запустить» неактивна). Новое расширение добавляет только описание формы и работу задачи.
- **История чата.** Карточка пишется в сообщение (`ChatMessage.job`) и переживает перезапуск; ход работы (`progress`, `stage`) — только в памяти. Задача, которая шла, после перезапуска — «Прервано» с «Повторить», её временные пути убираются, как только чат прочитан с диска (`ChatBook.onThreadLoaded`). Удаляются только пути вида временных путей этой карточки (`.<имя>.<id>.part`, `.<имя>.tmp-<id>`, `.tridot-<id>.tmp`): любой другой путь из чужого или изменённого файла чата отбрасывается при чтении и не удаляется (`JobPlacement.isTempFor`). Чат, который после перезапуска ни разу не открывали, держит свои хвосты до первого открытия. Неизвестное расширение — карточка только для чтения. Строки из файла чата очищаются (управляющие и bidi-знаки), пути с такими знаками отбрасываются.
- **Исполнитель** (`lib/core/jobs/job_runner.dart`): `IsolateJobRunner` — каждая задача в своём изоляте, ход работы — не чаще 10 раз в секунду; отмена — `Isolate.kill` и удаление временных путей, известных до запуска; после выхода изолята они удаляются ещё раз (kill не мгновенный, изолят мог успеть записать ещё одну запись). Удаление чата или «Очистить историю» останавливает его задачи, закрытие окна на компьютере — все задачи. `JobHub` (`lib/app/jobs/job_hub.dart`) меняет состояние карточки на месте и сохраняет чат только при смене состояния. Ошибки наружу — только кодом (`disk`, `limits`, `badZip`, `password`, `unsafe`, `missing`, `cancelled`, `failed`): пути и тексты исключений в историю не попадают.
- **Архиватор** (`lib/core/skills/archiver/`, id `archiver`, вид «навык», выключен по умолчанию, зона расширений — отвечает Лиорио). Фразы — повелительное наклонение и объект: «сожми в zip», «заархивируй папку», «распакуй архив», «покажи что в архиве»; инфинитив, задачи («добавь задачу сжать отчёт», «напомни распаковать коробки») и «купить архив» остаются задачами (корпус `test/corpus/extensions.jsonl`). Только ZIP, чистый Dart (`archive` 4.6.0): создать (файлы, папка целиком на компьютере, без ссылок; запись в скрытый `.<имя>.zip.<id карточки>.part` — две задачи с одним именем результата не пишут в один файл; в конце имя занимается без замены чужого файла: сначала пустой файл с `exclusive`, затем переименование на него, занято — «(2)», «(3)»; имена записей — только имя файла, без `/`, `..` и знаков, запрещённых в Windows), посмотреть (первые 200 записей и «ещё N»), распаковать (во временную папку рядом, переименование в конце; папку с тем же именем, появившуюся за время работы, не трогает — следующее имя). Распаковка — общий `safe_zip.dart` голосовой модели: проверка всех записей до первого байта, `..`, абсолютные пути, буква диска, ссылки, повторы, имена, недопустимые в Windows (`:*?"<>|`, CON/PRN/AUX/NUL/COM1-9/LPT1-9, точка или пробел в конце).
- **Пределы архиватора:** 10 000 записей; всего 2 ГБ на компьютере и 1 ГБ на телефоне; сжатие не больше 200:1 у записей больше 1 МБ. Свободное место проверяется до распаковки только на 64-битных Linux и Android (`statvfs` через `dart:ffi`); на macOS и Windows нехватку места покажет ошибка записи.
- **ZIP с паролем** не поддерживается: шифрованные записи узнаются по флагу в центральном каталоге, ответ — «ZIP с паролем пока не поддерживается»; пароль не спрашивается и нигде не появляется.
- **Куда кладётся результат.** Исходники не меняются никогда. Файлы с диска на Windows и Linux — рядом с исходником; на macOS (песочница, право `com.apple.security.files.user-selected.read-write`) — через окно сохранения или выбор папки с подставленными местом и именем. Вложения сессии и любые файлы на телефоне — в `files/<сессия>/out/<id карточки>/`: у папки нет предела 25 МБ, её держит карточка, уборка вложений удаляет папки без карточки. Режим «Только в памяти» — во временную папку `tridot-jobs`, она удаляется при запуске. Копии, которые выбор файлов Android кладёт во временную папку, удаляются после успешной задачи (после ошибки и отмены они нужны «Повторить»); оставшиеся старше суток — при запуске приложения. Копия вложения из хранилища в памяти пишется под очищенным именем внутри временной папки задачи. Под готовой карточкой — «Результат во временной папке и удалится при выходе».
- **«Открыть», «Открыть папку».** Компьютер — отдельный процесс со списком аргументов, без оболочки: `xdg-open`, `explorer.exe` (`/select,` для папки), `open` (`-R`). Android — канал `tridot/files` в `MainActivity`: копия в `cache/tridot-open` и `FileProvider` только на чтение; путь вне папки помощника (`app_flutter/assistant`) и временной папки отклоняется и в Dart, и в Kotlin — настройки, базы и хранилище паролей наружу не отдаются; «Открыть папку» нет, у распакованной папки — список её файлов (до 30), каждый открывается.
- **Выключенное расширение.** `ConnectorInfo.offHint`: если выключенный архиватор явно узнаёт фразу, а включённые навыки взяли бы её только без маркера или не взяли вовсе, ответ — «Архиватор выключен — включите его в «Настройки → Расширения»». Фразы включённых навыков он не перехватывает. Карточка выключенного расширения остаётся в чате, но «Запустить» неактивна с причиной «… выключен — включите в «Настройки → Расширения»».
- **Каталог команд.** Раздел «Файлы»: «Сжать в ZIP», «Распаковать ZIP», «Что внутри ZIP» (`ext.archiver.zip`, `.extract`, `.list`) — действия, которые открывают пустую карточку от Лиорио; видны, пока архиватор включён. Подсказка «не до конца понял» действий не предлагает.

Ограничения шага 1:

- Имена в кодировке cp866 без флага UTF-8 (старые архивы Windows) покажутся кракозябрами.
- На телефоне результат лежит в папке приложения: «Сохранить в Загрузки» пока нет — только «Открыть» через другое приложение.
- Готовый файл не прикрепляется к сообщению отдельным чипом: открыть его можно из карточки.

- **Перетаскивание в карточку не подключено.** `desktop_drop` 0.8.4 (0.9.x конфликтует с `file_selector` 1.1.0 через `cross_file`) попадает и в APK и тянет в buildscript Kotlin Gradle Plugin 2.2.0; сборка APK с ним не проходит (артефакты KGP 2.2.0 не разрешаются, два повтора). В v1 файлы и папки выбираются только кнопками «Выбрать файлы» и «Выбрать папку»; у `ExtensionCardView` есть точка подключения `dropTarget`, чтобы добавить перетаскивание без переделки карточки.

### Шаг 2 — конвертер

Решение:

- **Навык** `converter` (`lib/core/skills/converter/`, вид «навык», выключен по умолчанию, ведёт Лиорио, `offHint`). Фразы — повелительное наклонение и объект или формат: «сконвертируй в mp3», «конвертируй фото в png», «сконвертируй файл», «преобразуй картинку в jpg»; «переведи», «перегони», «сохрани» — только с форматом («переведи видео в mp3»). Не его: «переведи 100 долларов в рубли», «переведи файл на английский», «конвертируй доллары в рубли», инфинитив и задачи (корпус `test/corpus/extensions.jsonl`, `ext-016`…). Команда `converter.convert`, шаблон «Сконвертировать файл» (`ext.converter`) в разделе «Файлы».
- **Карточка:** файл (один; из сообщения, недавних сообщений сессии или «Выбрать файл») → «Во что» → «Запустить». Варианты — по расширению имени, без своего формата: картинки png/jpeg/webp/bmp/gif → png, jpeg; звук wav/flac/ogg/m4a/mp3/opus/aac → mp3; видео mp4/webm/mkv/mov/avi → mp3 (звуковая дорожка), mp4, webm, кадр в jpeg или png. Цель и тип файла из фразы подставляются. Варианты, которым нужен ffmpeg, не прячутся и не подделываются: они видны с причиной («Нужен ffmpeg: Настройки → Расширения → Конвертер → Настроить» или «На этой платформе недоступно»), «Запустить» неактивна. HEIC и неизвестное — «Этот формат пока не поддерживается».
- **Картинки — на Dart** (пакет `image` 4.12.0, MIT) в отдельном изоляте: размер по заголовку до декодирования, предел 50 мегапикселей и 200 МБ файла; поворот по EXIF применяется, EXIF (с GPS) и текстовые поля не переносятся; у GIF и анимаций — первый кадр; прозрачное в JPEG — на белом; JPEG с качеством 90. Работает на всех платформах.
- **Звук и видео — ffmpeg отдельным процессом** (`FfmpegJobRunner`): `Process.start` со списком аргументов, `runInShell: false`, `-hide_banner -nostdin -n -protocol_whitelist file -i <исходник> … -progress pipe:1 -nostats -f <формат> <временный файл>` (вход — только файл: «.mp4», который на деле список HLS или concat, не откроет сеть); mp3 — `libmp3lame -q:a 2`, mp4 — `libopenh264` + `aac` (x264 в LGPL-сборке нет), webm — `libvpx-vp9` + `libopus`, кадр — на первой секунде, у видео короче секунды — первый кадр. Ход работы — `out_time_us` к длительности из `Duration:`; результат пишется в скрытый `.<имя>.<id карточки>.part` и после кода 0 занимает имя без замены чужого файла (как у архиватора); отмена — `SIGKILL` (Windows — `taskkill /T /F /PID`) и удаление временного файла. Наружу — только код (`media`, `noStream`, `disk`, `noTool`, `failed`), stderr с путями никуда не попадает. Аргументы и все цели проверены на настоящей закреплённой сборке Linux x64 (mp4 → mp3, webm, кадр; webm → mp4; wav → mp3; видео без звука → «нет нужной дорожки»).
- **Исключение из ADR-005** (запуск скачанного кода) — узкое: только ffmpeg, только Windows и Linux, только по кнопке в «Настройки → Расширения → Конвертер → Настроить» или в предложении при включении конвертера, после предупреждения о размере (~161 МБ загрузки Windows x64, ~130 МБ Linux x64; после установки ~126–134 МБ) и источнике. Ставится только сама программа `ffmpeg` (без ffprobe и ffplay) в `<поддержка>/assistant/tools/ffmpeg/<версия>/` (`ToolKit`).
- **Закреплённые сборки** (`lib/core/extensions/tools/tool_spec.dart`): FFmpeg-Builds (BtbN; репозиторий `github.com/BtbN/FFmpeg-Builds` переадресует на `github.com/FFmpeg-Builds/FFmpeg-Builds`, закреплён новый адрес), вариант LGPL (`--enable-version3`, с libmp3lame, без x264/x265), FFmpeg n9.0.2, месячный тег `autobuild-2026-10-31-12-59` (такие теги хранятся около двух лет — константы обновляются выпусками приложения). Сборки: win64, winarm64, linux64, linuxarm64. Суммы SHA-256 и размеры взяты из официального `checksums.sha256` этого тега (скачан 2026-11-14) и сверены со скачанными архивами. Подписей GPG у BtbN нет: проверка только по закреплённой сумме — как у модели Vosk. Сборка с пустой суммой считается недоступной: кнопки «Скачать» нет, `ToolKit.install` отказывает (тест).
- **Загрузка и распаковка.** `IoFileDownloader` получил `allowedRedirectHosts`: кроме того же сайта переадресация разрешена только на точные имена `release-assets.githubusercontent.com` и `objects.githubusercontent.com`. Архив проверяется по размеру и SHA-256, затем из него извлекается одна запись: ZIP — общий `safe_zip.dart` (`onlyEntries`), tar.xz — новый `safe_tar.dart` (xz потоком во временный `.tar` с пределом размера, затем tar с диска; все записи проверяются как у ZIP до первого байта, ссылки и особые записи — отказ). Права `755` — `chmod` списком аргументов. SHA-256 самой программы пишется в `installed.json`; перед первым запуском в сеансе приложения она считается заново (в изоляте), не совпала — программа удаляется; у программы без архива (yt-dlp) сумма сверяется ещё и с закреплённой в приложении, а не только с `installed.json`. Между проверкой и запуском программу может подменить процесс того же пользователя — от него приложение не защищается никак (он может подменить и само приложение), поэтому сумма считается один раз за сеанс, карточка показывает «ffmpeg не установлен или не прошёл проверку».

Где что работает (конвертер):

| Возможность | Android | Windows | Linux x64/arm64 | macOS |
|---|---|---|---|---|
| Картинки png/jpeg/webp/bmp/gif → png/jpeg | да | да | да | да |
| Звук и видео → mp3 / mp4 / webm / кадр (ffmpeg) | **нет** | да (x64, arm64) | да | **нет** |
| Куда кладётся результат | папка сессии | рядом с исходником | рядом с исходником | окно сохранения |

Почему нет:

- **Android.** С targetSdk ≥ 29 (Android 10+) система запрещает запуск исполняемых файлов из папки данных приложения (W^X); скачивать и подгружать `.so` запрещают правила Google Play; ffmpeg-kit снят с распространения; встраивать ffmpeg владелец запретил; mp3-кодировщика в Android нет. На телефоне конвертер честно умеет только картинки, у звука и видео в карточке — «На этой платформе недоступно».
- **macOS.** Официальной LGPL-сборки ffmpeg с libmp3lame нет (evermeet и martin-riedl собраны под GPL); песочница App Store и карантин Gatekeeper не дают запустить скачанную программу. В v1 — только картинки.

Ограничения шага 2:

- mp4 кодируется OpenH264 с постоянным битрейтом 4 Мбит/с: качество ниже, чем у x264, которого в LGPL-сборке нет.
- Кадр берётся на первой секунде, выбрать момент нельзя.
- WebM (VP9) кодируется медленно; ход работы и «Отмена» есть.
- Результат не прикрепляется к сообщению отдельным чипом — «Открыть» в карточке.
- Обновление ffmpeg — только новой версией приложения с новыми константами.

Открытые вопросы владельцу: нужен ли на телефоне «Сохранить в…» для результата архиватора и конвертера (Storage Access Framework); на Android нет ffmpeg и mp3 — делать ли кадр из видео через `MediaMetadataRetriever` (≈30 строк Kotlin, без скачивания) и, возможно, звуковую дорожку в m4a через `MediaExtractor`/`MediaMuxer`; macOS — своя LGPL-сборка ffmpeg с lame на своём хостинге, сборка вне песочницы с Developer ID или только картинки; достаточно ли закреплённого SHA-256 для ffmpeg без подписи GPG.

Последствия: новый формат сообщения (`job`) старые версии приложения пропускают — карточка у них пропадёт, текст ответа останется. APK получает `androidx.core` (FileProvider) и чистый Dart-пакет `image`, macOS — право записи в выбранные пользователем места; проверить на устройствах в контейнере нельзя. На Windows и Linux приложение может запускать скачанные ffmpeg и yt-dlp — единственное исключение из ADR-005 (шаг 3); лицензии ffmpeg и LAME — в `assets/extensions/NOTICE.txt` («Настройки → Лицензии»). Запуск ffmpeg на Windows и окно сохранения на macOS в контейнере не проверялись.

### Шаг 3 — загрузчик видео

Решение:

- **Навык** `ytdl` (`lib/core/skills/ytdl/`, вид «навык», выключен по умолчанию, ведёт Лиорио, `offHint`, `requiresNetwork` — фразы о паролях он не видит). Фразы — повелительное наклонение и объект или ссылка: «скачай видео по ссылке …», «скачай ролик https://…», «скачай звук из видео …», «скачай видео»; «загрузи» и «сохрани» — только со ссылкой. Не его: голая ссылка без глагола, «скачай музыку» без ссылки, инфинитив («скачать музыку» — задача), напоминания и задачи («напомни скачать видео завтра»), «загрузи видео на ютуб …» (выложить, а не скачать), «сохрани видео в mp3» (конвертер). Конвертер больше не берёт фразы со ссылкой. Корпус — `test/corpus/extensions.jsonl`, `ext-032`…`ext-045`; существующие строки маршрутизации не изменились. Команда `ytdl.download`, шаблон «Скачать видео по ссылке» (`ext.ytdl`) в разделе «Файлы».
- **Карточка:** ссылка (поле `url`, Inter, проверка — только http/https с именем сайта, до 2048 знаков) → «Что скачать»: «Видео: лучшее до 1080p / 720p / 480p» или «Только звук (mp3)» → «Скачать». Ссылка и качество из фразы подставляются; по умолчанию — 720p. «Только звук» без ffmpeg конвертера виден с причиной («Нужен ffmpeg: …»); без yt-dlp «Скачать» неактивна с подсказкой, где его скачать; на других платформах — «На этой платформе недоступно».
- **Ссылка уходит только в yt-dlp.** Навык кладёт её в данные совпадения и в поле карточки; текст ответа Лиорио (`ytdl.form`, `ytdl.form.url`) её не содержит. Задача получает её в `JobRequest.url` и передаёт последним аргументом после `--`. Вывод yt-dlp (ссылка, название, пути) наружу не уходит: ход работы, путь результата (только если он внутри папки загрузок) и код ошибки (`network`, `unavailable`, `badUrl`, `noDownloader`, `noTool`, `disk`, `failed`). Журналов приложение не ведёт; счётчик команд хранит только id шаблона. В сообщении пользователя ссылка остаётся — это его история.
- **Запуск** (`YtdlJobRunner`, `lib/core/skills/ytdl/ytdl_job.dart`): `Process.start` со списком аргументов, `runInShell: false`; `--ignore-config --no-plugin-dirs --no-playlist --no-cookies --no-cookies-from-browser --no-mtime --windows-filenames --color never --newline --progress --progress-template … --print after_move:… --no-simulate [--ffmpeg-location <ffmpeg конвертера>] -P home:<папка> -P temp:<скрытая временная папка> -o "%(title).150B [%(id)s].%(ext)s" -f … -- <ссылка>`. С ffmpeg видео — лучшая дорожка до выбранной высоты плюс звук (`bv*[height<=H]+ba/b[height<=H]/bv*+ba/b`), без ffmpeg — только цельный файл (`b[height<=H][ext=mp4]/b[height<=H]/b`); звук — `-x --audio-format mp3 --audio-quality 2`, только с ffmpeg. Названия опций сверены с `yt_dlp/options.py` релиза 2026.10.26 (колесо PyPI); сам yt-dlp в контейнере не запускался. Отмена: на Windows `taskkill /T /F /PID`; на Linux yt-dlp запускается в своей группе процессов (`setsid`), и SIGTERM, а через 3 с SIGKILL, получает вся группа — вместе с ffmpeg склейки и mp3 (нет `setsid` — сигнал только самому yt-dlp); временная папка `.tridot-<id>.tmp` удаляется сразу и после выхода, её же убирает «Прервано» после перезапуска.
- **Папка загрузок** — `<Загрузки>/Tridot` (`getDownloadsDirectory`); другую можно выбрать в «Настройки → Расширения → Загрузчик видео → Настроить» (`<поддержка>/assistant/ytdl.json`, хранится только путь папки). «Открыть», «Открыть папку»; если путь файла не известен — «Открыть папку».
- **Включение** — только после предупреждения: «Правила YouTube и других площадок запрещают скачивание без разрешения. Скачивайте только своё или то, на что есть права.» («Понятно, включить» / «Отмена»); затем предложение скачать yt-dlp с размером и источником; экран «Настроить» — «Скачать», «Обновить», «Удалить», папка загрузок, подсказка про ffmpeg и deno.
- **Исключение из ADR-005** расширено на yt-dlp на тех же условиях, что ffmpeg: только Windows и Linux, только по кнопке после предупреждения о размере (~22 МБ Windows, ~39 МБ Linux), источник закреплён в коде (`ToolSpecs.ytdlp`): официальный релиз `github.com/yt-dlp/yt-dlp` **2026.10.26**, одиночные файлы `yt-dlp.exe`, `yt-dlp_arm64.exe`, `yt-dlp_linux`, `yt-dlp_linux_aarch64`; суммы SHA-256 — из `SHA2-256SUMS` релиза, его подпись `SHA2-256SUMS.sig` проверена GPG ключом AC0C BBE6 848D 6A87 3464 AF4E 57CF 6593 3B5A 7581 (yt-dlp signing key, `public.key` из репозитория) 2026-11-14 — в момент закрепления, не в приложении; файлы `yt-dlp_linux` и `yt-dlp.exe` скачаны и сверены с суммами. Размеры — по ответу сервера релизов. Переадресация — только на `release-assets.githubusercontent.com` и `objects.githubusercontent.com`. Программа без архива: проверенный файл становится программой (`ToolArchive.none`), права `755`, сумма программы — в `installed.json` и заново перед первым запуском в сеансе. Сумма для macOS (`yt-dlp_macos`) закреплена «на будущее» (`ToolSpecs.ytdlpMacos`), в набор сборок не входит.
- **«Обновить»** ставит только версию, закреплённую в текущей сборке приложения, если установлена прежняя (`ToolKit.olderVersion`; прежняя не запускается — её сумма закреплена уже не здесь); иначе — «Установлена последняя версия, известная приложению». `yt-dlp -U` не используется: он обошёл бы закреплённую сумму.
- **Сборка для Google Play** — `flutter build appbundle --dart-define=TRIDOT_STORE=play`: константа `kPlayBuild` (`lib/core/build_flags.dart`); при ней навык не регистрируется, ToolKit yt-dlp не создаётся, исполнитель загрузок не создаётся, формы загрузчика, шаблона в «+», плитки в настройках и закреплённых ссылок yt-dlp нет (`ExtensionForms.of`, `CommandCatalog`, `ExtensionsSection`, `ToolSpecs.all`). Код за константой выбрасывается при сборке: в `libapp.so` сборки с `TRIDOT_STORE=play` нет ни аргументов yt-dlp (`--ignore-config`, `tridot-progress`), ни ссылок на его файлы (проверено по строкам APK); остаются только подписи вроде «Загрузчик видео» в общих таблицах текстов. Флейворов Gradle нет.

Где что работает (загрузчик видео):

| | Android (Google Play) | Android (вне Play) | Windows | Linux x64/arm64 | macOS |
|---|---|---|---|---|---|
| Загрузчик видео (yt-dlp) | **нет** (флаг сборки) | **нет** | да | да | **нет** |
| «Только звук (mp3)», склейка дорожек | — | — | с ffmpeg конвертера | с ffmpeg конвертера | — |
| Куда кладётся результат | — | — | `<Загрузки>/Tridot` или выбранная папка | так же | — |

Почему нет:

- **Android, в том числе вне Google Play** — расхождение с решением владельца (он хотел загрузчик и в Android-сборке вне Play). yt-dlp — программа на Python (≥ 3.11 по метаданным релиза), одиночные файлы собраны PyInstaller под glibc; Android запрещает запуск скачанных исполняемых файлов из папки данных приложения (W^X, targetSdk ≥ 29), а встроить Python (Chaquopy, youtubedl-android) — значит встроить интерпретатор и исполнять скачанный код, что противоречит ADR-005 и запрету встраивать ffmpeg. В v1 загрузчик на Android скрыт во всех сборках: навык не регистрируется, плитки и шаблона нет. Флаг для Play всё равно введён, как просил владелец.
- **macOS** — песочница App Store и карантин Gatekeeper не дают запустить скачанную программу, ffmpeg (склейка, mp3) там тоже нет. До решения владельца — нет.

Ограничения шага 3:

- deno не ставится: для полной поддержки YouTube yt-dlp нужен JavaScript-движок, без него часть роликов YouTube не скачается или будет в худшем качестве. Если deno уже установлен у пользователя и есть в `PATH`, yt-dlp им воспользуется (поведение yt-dlp по умолчанию).
- Без ffmpeg видео — только цельным файлом (обычно не выше 720p), «Только звук» недоступен.
- Путь готового файла берётся из вывода yt-dlp; на Windows при не-UTF-8 выводе путь может не прочитаться — тогда карточка покажет «Открыть папку» без имени файла.
- Плейлисты не скачиваются (`--no-playlist`), cookies и вход на сайты не поддерживаются — закрытые и «только для подписчиков» ролики дают «Видео недоступно».
- yt-dlp ломается при изменениях сайтов; новая версия приходит только с новой версией приложения (новые константы).
- Запуск yt-dlp в контейнере не проверялся: аргументы, разбор вывода, отмена и коды ошибок проверены тестами с подделкой процесса.

Открытые вопросы владельцу (шаг 3): загрузчик в Android-сборке вне Play невозможен без встраивания Python — согласен ли владелец скрыть его на Android; deno для полной поддержки YouTube — третья загрузка (~40 МБ, MIT) или задокументированное ограничение; обновление yt-dlp — только закреплённые в приложении версии или проверка подписи OpenPGP прямо в приложении (свежие `SHA2-256SUMS` и `.sig`; нужен новый пакет); macOS — сборка вне песочницы с Developer ID или без загрузчика.
