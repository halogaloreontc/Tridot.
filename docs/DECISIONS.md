# Принятые решения

## ADR-001. Локальная кроссплатформенная основа

- Основной стек технического прототипа: Dart + Flutter.
- Основные платформы: Android и Windows.
- Дополнительные сборки: Linux и macOS.
- Приоритеты: единая кодовая база и интерфейс, простота MVP, контроль размера и ресурсов.
- Языковая модель не используется.
- Собственный аккаунт и сервер не требуются.
- Синхронизация проектируется через подключённые диски с append-only журналом изменений.
- GitHub используется для исходного кода, проверок и сборок, но не для автоматической публикации приватных журналов.

## ADR-002. Сначала вертикальный срез

Первый прототип доказывает путь «сообщение → сценарий → операция → постоянное хранение → ответ». Облачные адаптеры и расширенные таблицы не включаются до прохождения базовых проверок.

## ADR-003. Ресурсные требования проверяются измерением

Принятие Flutter окончательно подтверждается после release-замеров размера, холодного запуска, памяти в простое и пиковой памяти при обработке файлов. Если показатели неприемлемы, рассматривается перенос ядра на Rust с нативными интерфейсами.

## ADR-004. Коннекторы и сеть только внутри них

Контекст: помощник должен понимать команды не только для задач, но и для других приложений владельца (первым — склад halowarekeep, затем expeora) и сторонних программ, не превращаясь в монолит и не нарушая ADR-001.

Решение:

- Команды подключаются коннекторами (`lib/core/connectors/`, инструкция — `docs/CONNECTORS.md`). Маршрутизатор `AssistantController` один раз строит общий разбор сообщения (`Utterance`), спрашивает каждый коннектор, выбирает самое уверенное совпадение, а при спорном выборе переспрашивает. Задачи — встроенный коннектор `tasks`.
- Языковая модель в приложении по-прежнему не используется: коннекторы распознают фразы правилами.
- Сеть разрешена только внутри коннекторов и только через внедрённый `HttpTransport`. Ядро, хранилище, интерфейс и распознавание (`match`) в сеть не ходят.
- По умолчанию коннектор только читает (`ConnectorAccess.readOnly`).
- Каждое изменяющее действие во внешнем приложении выполняется только после явного подтверждения пользователя в диалоге. Стандартный способ — ожидание подтверждения в `AssistantSession` на одно сообщение: маршрутизатор отдаёт «да»/«нет» коннектору, задавшему вопрос, раньше обычного разбора (`docs/CONNECTORS.md`, «Подтверждение изменяющих действий»).
- Секреты (токены, ключи, пароли) хранятся только через `SecretStore` на защищённом хранилище платформы, не в открытых файлах вроде `settings.json`, не в коде и не в ответах.
- Разрешения на сеть в release-сборках (Android `INTERNET`, macOS `com.apple.security.network.client`) добавляются вместе с первым сетевым коннектором, не раньше.

Последствия: новый источник команд добавляется без правки ядра и интерфейса; фразы всех коннекторов живут в общем корпусе (поле `connector`), и тест проверяет, что коннекторы не перехватывают чужие фразы.


## ADR-005. Расширения: навыки, подключения и паки

Контекст: помощник должен собираться под человека, а не давать всё сразу (`docs/PLANS.md`, «Расширения»). Нужны новые возможности — калькулятор, беседа, шутки, внешние приложения — без монолита, без перезапуска при переключении и без выполнения чужого кода.

Решение:

- Всё сверх ядра — расширения трёх видов (`ExtensionKind`): **навык** (своя логика без сети: задачи, калькулятор), **подключение** (внешнее приложение, ADR-004) и **пак** (только данные: шутки, каламбуры, фразы). Описание и формат — `docs/EXTENSIONS.md`.
- Навыки и подключения реализуют интерфейс `Connector`; их вид, версия, автор, `defaultEnabled` и `required` — поля `ConnectorInfo`. Код навыков и подключений поставляется **только в составе приложения**: никакой загрузки и выполнения кода во время работы.
- Паки — **только данные** в формате `assistant-pack/1` со строгой проверкой (`PackFormat`). Текст записей не выполняется и не читается как разметка. Паки ставятся на лету: встроенные из `assets/packs`, пользовательские — вставкой JSON в настройках, хранятся в `<документы>/assistant/packs`.
- `ExtensionRegistry` знает все расширения и выбор пользователя; маршрутизатор спрашивает только включённые. Выбор хранится в `settings.json` как набор выключенных (из включённых по умолчанию) и явно включённых (из выключенных по умолчанию): новое расширение, включённое по умолчанию, появляется включённым после обновления.
- Включение и выключение применяется сразу и ничего не сбрасывает: задачи, история, выбор, черновик и ожидания других коннекторов остаются; снимается только ожидание подтверждения выключенного коннектора.
- Изначально включён минимальный набор: задачи (выключить нельзя), калькулятор, базовый пак шуток.

Последствия: новая возможность добавляется навыком или паком без правки ядра и интерфейса; пользователь видит и выбирает, что помощник умеет; загрузка содержимого не открывает пути для выполнения кода. Паки по ссылке, выключение отдельных записей пака и описание подключений файлом `assistant.json` — следующие шаги в рамках этого решения.
