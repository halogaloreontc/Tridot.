# Промт для halowarekeep: справка, документы и роли для «Связного»

Скопируйте текст ниже в сессию Claude Code с репозиторием
`halogaloreontc/halowarekeep`.

---

Работаем в halowarekeep на ветке `claude/tridot-assistant` (создай от
актуального `main`, если её нет; PR не открывай, пока я не попрошу).

**Задача.** Помощник «Связной» (Tridot) должен уметь три вещи, для которых
склад пока не отдаёт данных:

1. **Обучать.** «Как мне переместить стул в ячейку?» → короткие шаги; «не
   понял второй шаг» → подробно: что за что отвечает и куда уходят данные.
   С учётом роли: тому, у кого нет права, — коротко, плюс кто это делает и
   кто выдаёт право.
2. **Объяснять документ.** «Что по последнему приходу?», «расскажи про
   приход 2223», «что с перемещением ПЕР-15» → сводка: шапка, стадия,
   позиции с расхождениями, ячейки, фото, история «кто и когда», что
   дальше.
3. **Сводить в таблицу.** «Сводка приходов за неделю», «сделай таблицу» →
   таблица с колонками и итогами.

Договор с помощником (формат справки `assistant-help/1`, `answer.doc`,
`answer.table`, слот `docno`, `next`, «кто я»):
https://github.com/halogaloreontc/Tridot./blob/claude/nice-davinci-swz8vx/docs/ASSISTANT_HELP.md
Прочитай его целиком перед началом. Формат описания `assistant/1` —
`tools/assistant/README.md` этого репозитория.

**Главное правило: справку не пишем второй раз.** Источник — памятка
приложения (`GUIDE` в `src/22-guide-notify.jsx`, 17 разделов). Памятка в
приложении и справка помощника собираются из одних данных при сборке и не
расходятся.

### Что сделать

**1. Памятка — в данные.**
- Перенеси `GUIDE` из `src/22-guide-notify.jsx` в `guide/guide.json`
  (иконка — строкой, в jsx — словарь строка → компонент lucide). Памятка в
  приложении рендерится из этих данных, вид не меняется.
- Каждой теме и каждому шагу — стабильный id (`move`, `move.open`).
- Допиши то, чего в памятке нет и что нужно помощнику (поля — в договоре):
  `say` (как люди спрашивают: «как переместить {thing}», «как принять
  товар»), `keywords`, `need.perms`, `owner` (роли и фраза «это делает …»),
  `outsider` (коротко для тех, у кого нет права), у шагов — `detail`,
  `controls` (кнопки и поля: как подписаны на экране и за что отвечают),
  `data` (куда уходят данные: какой документ, вкладка, запись в «Истории»,
  что меняется в остатках).
- Темы для администраторов (копии склада, `BACKUP_KEY`, `config.php`,
  cron) — `audience: "admin"`. В справку не попадают пути сервера, ключи,
  логины и телефоны.
- Проверь тексты по коду: раздел «Роли и права» устарел («Менеджер:
  приходы, проведение…», «Готовых четыре» — в коде у `manager` прав нет,
  готовых ролей шесть). Список ролей в этой теме генерируй из
  `DEFAULT_ROLES`, а не пиши руками.

**2. Роли и права — одним источником.**
- Вынеси `PERMS`, `PERM_FALLBACK`, `DEFAULT_ROLES` из `src/16-roles-api.js`
  в `src/roles.json` (или генерируй его): его читают JS, PHP и сборщик
  справки.
- `askPermLabel` в `ask.php` — все 25 прав, подписи из `roles.json`.
- `ask_me`: добавь `role` (id), раскрытые с `fallback` права и
  `helpVersion`.
- Новое чтение `ask_roles` → права (id, подпись, группа, fallback) и роли
  (id, подпись, права, скрыта ли). Без логинов и имён.
- Отказ по праву — `403` с `need: "perm"` и `perm: "<id>"`.

**3. Сборка справки.**
- `tools/assistant/help.mjs`: из `guide/guide.json` + `src/roles.json`
  пишет `assistant-help.json` в корень сайта (рядом с `assistant.json`,
  `version` = `VERSION`, `source.hash`). Вызывается из `tools/build.mjs`,
  уезжает на сервер тем же deploy, что и сайт.
- `help.mjs --check` (в тестах и CI) падает, если: файл устарел; тема
  ссылается на несуществующую вкладку или право; `owner.roles` не держит
  нужное право (с учётом fallback); id повторяются; превышены пределы
  договора; `assistant.json.version` ≠ `VERSION` ≠ версии справки.
- В `assistant.json` — `"help": {"url": "assistant-help.json", "version": …}`.

**4. Документы — чтение по одному.**
Сейчас есть только списки (`ask_arrivals` отдаёт шапки без позиций). Нужно:
- `ask_entry {id | no ("2223", "2223-25") | doc ("ВР-00001") | last, mine}`
  — приход целиком: шапка, вид, номер, накладные, перевозчик, места,
  отметки SV / 1С, стадия и шаг работы (порты `stageOf`, `workStepOf`,
  `diffOf`, `hasMedia` на PHP), кто и когда создал и правил, позиции
  (артикул, название, по документу, факт, расхождение, класс, ячейки, фото,
  стадия акта), комплекты, итоги, история (≤ 20 строк), `next` (что
  дальше: разложить, расхождение, снимки, провести — с нужными правами и id
  темы справки). Черновики не отдаются. «Последний» — по `createdAt`;
  «мой» — по автору из истории.
- `ask_op {doc | batch | last}` — операция (перемещение, пересчёт,
  комплект, сдача, утиль) строками.
- `ask_ship {doc | invoice | pickNo | last}` — отгрузка, статус, позиции,
  `next`.
- `ask_act {entry, uid}` — акт о браке: стадия, причина, решение, дела
  «наши / их», даты, `next`.
- `ask_doc_history {ref}` — строки «Истории» по документу. Для этого в
  `logEvent` (`src/47-app.jsx`) и `actHistory` (`act.php`) добавь поле
  `ref: {type, id, no}`; для старых строк — поиск по тексту.
- Права на чтение — как у соответствующих списков (`staff`, свои права).
  Одинаковость PHP-портов и JS проверь общими примерами
  (`tests/fixtures/entries.json` через оба).

**5. Описание `assistant.json`.**
- Команды `entry` («последний приход», «мой последний приход», «приход
  {no}», «расскажи про приход {no}», «что по приходу {no}»), `op`, `ship`,
  `act`, `roles` («кто делает …», «какие есть роли»).
- `answer.doc` для них и `answer.table` для `today`, `week`, `unposted`,
  `unshipped`, `acts` (с итогами и `groupBy`, где уместно).
- Слот `docno` с `shape` для номеров склада:
  `^\d{1,6}(-\d{2})?$`, `^ВР-\d{5}$`, `^(ПЕР|СП|КМ|СД|УТ)-\d+$`.
- Опиши `doc`, `table`, `next`, `help`, `docno` в
  `tools/assistant/README.md` и проверяй их в `gen.mjs --check`.

**6. Права на запись — на сервере (отдельным коммитом).** Сейчас `set`
для `wh:e:` / `wh:m:` / `wh:s:` отказывает только учётке совсем без прав.
Справка будет говорить «это может только кладовщик» — пусть это будет
правдой: новый `wh:e:` — `entryAdd`, существующий — `entryEdit`, `wh:m:` —
`moves` / `kit` / `inventory` по типу, `wh:s:` — `ships`, `wh:inv:v1` —
`inventory`. Проверь, что сам интерфейс от этого не ломается ни у одной из
шести готовых ролей.

### Как проверить
- `node tools/build.mjs` и `--check`, `node tools/assistant/gen.mjs --check`,
  `node tools/assistant/help.mjs --check`, prettier, `php -l`, Playwright
  (`cd tests && npx playwright test --reporter=line`).
- Тесты API: `ask_entry` по номеру, `last`, `mine`, несуществующий (404
  `need: "none"`), черновик не отдаётся, без права — 403 `need: "perm"` с
  `perm`; `ask_roles` без логинов; `ask_me` с `role` и раскрытыми правами.
- Памятка в приложении выглядит как раньше (снимок вкладки до и после).

### Чего не делать
- Не читать и не коммитить `config.php`, `.env*`, `data/`, ключи.
- Не класть в справку логины, телефоны, адреса и пути сервера.
- Не менять существующие ответы `ask_*` несовместимо: старый Связной
  должен работать.
- Не поднимать `VERSION` без записи в `CHANGELOG`.
