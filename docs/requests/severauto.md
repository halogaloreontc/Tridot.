# Промт для severauto: расширение «Автосервис» для «Связного»

Скопируйте текст ниже в сессию Claude Code с репозиторием
`halogaloreontc/severauto`.

---

Работаем в severauto на ветке `claude/tridot-assistant` (создай от
актуального `main`; PR не открывай, пока я не попрошу).

**Задача.** Подключить CRM сервиса к помощнику «Связной» (Tridot) как
отдельное расширение **«Автосервис»** (не склад). Помощник должен:

1. **Отвечать на вопросы по данным** — только чтение: «мои задачи»,
   «записи на сегодня», «кто на смене», «статус заявки 152», «какие
   запчасти пришли», «кому звонить», «кампании по VIN …», «шаблон ТО-2
   X70», «найди клиента 8 701 …».
2. **Обучать.** «Как записать клиента на ТО?», «как оприходовать
   запчасть?» → короткие шаги; «не понял шаг 2» → подробно: что за что
   отвечает и куда уходят данные. С учётом должности: мастеру-приёмщику —
   полностью, механику про заказ запчасти — коротко и «это делает инженер
   по гарантии».
3. **Объяснять документ и сводить в таблицу.** «Что с заявкой 152?» →
   этап, кто сейчас отвечает, сроки, что дальше. «Сводка записей за
   неделю» → таблица с итогами.

Договор с помощником (формат справки `assistant-help/1`, описание команд,
`answer.doc`, `answer.table`, «кто я»):
https://github.com/halogaloreontc/Tridot./blob/claude/nice-davinci-swz8vx/docs/ASSISTANT_HELP.md
Формат описания команд `assistant/1` — раздел «Коннектор по описанию
`assistant/1`» в
https://github.com/halogaloreontc/Tridot./blob/claude/nice-davinci-swz8vx/docs/CONNECTORS.md
Для образца — то же у склада halowarekeep (`assistant.json`,
`tools/assistant/README.md`), если есть доступ.

**Главное правило: справку не пишем второй раз.** Источник —
`docs/user-guide.md` и таблица прав `PERMISSIONS`
(`src/core/auth/permissions.ts`). Справка собирается при сборке и
проверяется тестом.

### Что сделать

**1. Дверь для помощника: ключ сотрудника.**
- Миграция: таблица `assist_keys(id, staff_id, digest, scope 'assist',
  label, created_at, last_used_at, revoked_at)`. Хранить только хеш, как у
  сессий (`accounts.ts`).
- Методы `createAssistKey` (ключ показывается один раз), `listAssistKeys`,
  `revokeAssistKey` — только над своими ключами; в интерфейсе — «Настройки
  → Профиль → Помощник «Связной»». Ключи гаснут при деактивации
  сотрудника и смене пароля.
- Отдельный путь `POST /assist/api?action=<метод>` (тело — JSON, как у
  `/api`), ключ — только в заголовке `Authorization: Bearer <ключ>`, без
  cookie. Существующий `/api` и его cookie не трогаем.
- `assistUser()` рядом с `sessionUser()` и тот же шлюз `createGateway`:
  `refusal()` → метод → `redactResult()`. Права и скрытие телефонов —
  ровно как у сессии.
- Список разрешённых методов `ASSIST_METHODS`, только чтение: getSession,
  getMeta, listTasks, listAppointments, getAppointment, listFollowUps,
  listPartOrders, getPartOrder, listCampaigns, matchCampaigns,
  listTemplates, getTemplate, searchClients, getClientCard, listShifts,
  journalCounts, assistMe, assistRoles (добавь `getAppointment`,
  `getPartOrder`, `getClientCard`, если их нет). Метод вне списка — 403
  `{"error": …, "need": "scope"}`; нет ключа, ключ отозван, сотрудник
  неактивен — 401 `need: "login"`; нет права — 403 `need: "perm"`,
  `perm: "<метод>"`.
- Лимит запросов на ключ. CORS — только на `/assist/*` и только если
  помощник открыт с другого адреса; без credentials.

**2. «Кто я» и должности.**
- `assistMe` → `{ok, login, name, role, roleLabel, perms, helpVersion}`:
  `perms` — методы, которые этому сотруднику разрешены (`can()`),
  `roleLabel` — из `STAFF_ROLE_LABELS`.
- `assistRoles` → должности (id, подпись), методы (id, подпись, кому
  разрешены) и этапы заявки на запчасть (статус, подпись, кто отвечает,
  метод) — из `PERMISSIONS` и `tasks.ts`. Без логинов и имён. Это нужно
  для ответов «этап «Поступление» — заведующий складом».
- В текстах «руководитель» = «Технический директор» (`director`):
  выровняй руководство и подписи.

**3. Документ по одному.**
- `getPartOrder` дополни: `statusLabel`, кто отвечает за текущий этап
  (`stageOwner`, `stageOwnerLabel`), `next` (что дальше: `[{method, title,
  roles}]`), сроки (заказать до, позвонить до, заменить до) и `overdue`.
- `getAppointment`: подписи подтверждения и отметки ОРК, связанные
  кампании и заявка.
- Истории «кто что сделал» по заявке сейчас нет — добавь
  `part_order_events(order_id, status, staff_id, at, note)` и пиши в неё на
  каждом этапе; `getPartOrder` отдаёт последние 20 строк.

**4. Описание команд `assistant.json`.**
- `GET /assist/assistant.json`, формат `assistant/1`, `app.id`
  `"severauto"`, `app.name` «Автосервис», `version` = версия из
  `package.json`. `api.url` — `/assist/api` того же адреса, действие —
  в `?action=`. Вход — `Authorization: Bearer {$key}` (ключ из профиля).
- Команды (фразы — как говорят в сервисе):
  - «мои задачи» → `listTasks`;
  - «записи на сегодня», «записи на {date}», «кто записан завтра» →
    `listAppointments` (`answer.table`: время, подъёмник, клиент,
    автомобиль, вид работ, подтверждение);
  - «найди клиента {q}» → `searchClients`;
  - «заявка {no}», «что с заявкой {no}» → `getPartOrder` (`answer.doc`:
    факты, позиции таблицей, история, `next`);
  - «какие запчасти пришли», «кому звонить» → `listPartOrders`
    (`arrived` / `to_call`);
  - «кампании для VIN {vin}» → `matchCampaigns`;
  - «шаблон {kind} {model}» → `getTemplate` (`answer.doc`: таблицы
    «Работы» и «Расходники», итоги в тенге);
  - «кто на смене» → `listShifts`;
  - «сводка записей за неделю» → `listAppointments` (`answer.table`,
    `groupBy` по виду работ);
  - «что ты умеешь», «помощь» → список команд и тем справки.
- Подписи статусов (`PART_STATUS_LABELS`, `CONFIRMATION_LABELS`,
  `FOLLOWUP_LABELS`, `TEMPLATE_KIND_LABELS`) — в ответах сервера, чтобы
  помощник говорил словами интерфейса.
- `"help": {"url": "help.json", "version": …}` → `GET /assist/help.json`.

**5. Справка из руководства.**
- В `docs/user-guide.md` перед каждым разделом `##` / `###` — маркер
  темы, например:
  `<!-- topic: parts.receive; methods: receivePart; owner: warehouse; say: как оприходовать запчасть | как принять запчасть -->`.
  Шаги — нумерованный список, подробности — вложенные пункты; строки
  «Кнопки:» и «Где данные:» → `controls` и `data` (поля — в договоре).
  Допиши в руководство то, чего не хватает помощнику: за что отвечает
  каждая кнопка и куда уходят данные (журнал, карточка клиента, задачи
  другой должности, история кампании).
- `scripts/build-help.ts` собирает `assistant-help/1`: `need.perms` —
  методы темы, должности **вычисляются** из `PERMISSIONS`, `owner` — из
  маркера и проверяется. Результат отдаётся как `GET /assist/help.json`,
  сборка — часть `npm run build` и `npm run package`.
- Таблицу «Кто что может» в руководстве генерируй из `PERMISSIONS`
  между маркерами `<!-- roles:begin -->` / `<!-- roles:end -->`.
- Тест падает, если: справка устарела; метод не существует; `owner` не
  может выполнить ни один метод темы; таблица ролей разошлась с
  `PERMISSIONS`; у раздела руководства нет маркера. Когда выйдет итерация 5
  (раздел «Документы»), тест заставит обновить справку.
- В справке нет логинов, телефонов, VIN, имён клиентов и путей сервера.

**6. Документация.**
- `docs/architecture.md` — раздел «Дверь помощника»: ключи, путь
  `/assist`, список методов, отказы.
- `docs/operations.md`: сервер стоит в локальной сети. Помощник на
  телефоне вне сети сервиса его не увидит — нужен туннель или обратный
  прокси (nginx уже упомянут); внутри сети — по адресу компьютера.
- `docs/user-guide.md`: как выпустить ключ помощника в профиле и
  подключить «Связного».

### Как проверить
- `npm test` (vitest) и e2e, если затронут интерфейс профиля.
- Тесты двери (в стиле `auth.test.ts`): ключ даёт те же 401/403 и то же
  скрытие телефонов, что сессия; отозванный ключ и неактивный сотрудник —
  401; метод вне списка — 403 `need: "scope"`; cookie на `/assist` не
  принимается; `/api` по ключу не работает.
- `assistMe` для каждой из 8 должностей — верные `perms`.
- Сборка справки: `--check` проходит, порча маркера валит тест.

### Чего не делать
- Не читать и не коммитить `.env*`, базу, ключи, `release/`.
- Не открывать запись через помощника — только чтение (запись позже,
  отдельной задачей, с подтверждением).
- Не менять поведение `/api`, cookie и входа.

В конце: что сделано, версия, адреса `/assist/assistant.json` и
`/assist/help.json`, список методов в `ASSIST_METHODS`, пример ответа
`assistMe` (с вымышленным сотрудником).
