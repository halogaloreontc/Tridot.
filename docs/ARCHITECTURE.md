# Архитектура прототипа

## Вертикальный срез

```text
Flutter UI
→ AssistantController (маршрутизатор коннекторов)
→ ExtensionRegistry: только включённые навыки и подключения (ADR-005)
→ Utterance: общий разбор сообщения — слова, кавычки, метки, срок, коды
→ Connector.match у каждого коннектора → самое уверенное совпадение
→ Connector.run победителя
   TasksConnector → ScenarioParser → TaskService → TaskRepository
                  → JsonTaskRepository → локальный файл
   CalculatorConnector → Calculator (свой разбор, точные дроби)
   другие коннекторы → HttpTransport / SecretStore (ADR-004)
→ ответ: session.reply(id, факты) → ReplyLibrary (стиль, род, «вы»/«ты»,
  эмодзи помощника) → AssistantResponse с автором Liorio или Noda (ADR-006, ADR-008)
```

Название приложения — `AppInfo` (`lib/core/app_info.dart`, ADR-009): «Связной» в русском интерфейсе, Relay — латиницей. Приложение — хаб, а помощники Liorio и Noda работают в нём; роль помощника и название приложения не смешиваются.

Коннекторы — `lib/core/connectors/`, как написать свой — `docs/CONNECTORS.md`. Навыки, подключения и паки — `lib/core/extensions/`, `docs/EXTENSIONS.md`. Каталог ответов и помощники — `lib/core/replies/`, `lib/core/personas/`, `docs/REPLIES.md`.

## История чатов

Чаты — `lib/core/chats/` (чистый Dart, без Flutter; ADR-010):

```text
HomePage → ChatBook (чаты в памяти, открытый чат, стек «назад», правила)
         → ChatStore: JsonChatStore (<документы>/assistant/chats/) | InMemoryChatStore
HomePage → AssistantController.handle(text, chatTaskId: …) / enterChat(taskId: …)
         → AssistantSession.chatTaskId → TasksConnector (цель по умолчанию)
```

- **Модель.** `ChatThread` — `main` («Главный») или `task:<taskId>`; у чата задачи `parentTaskId` — задача, из чата которой она создана (первый уровень иерархии контекста). Метаданные: время создания и последней активности, адресат «Кому:» этого чата, «не прочитано». `ChatMessage` — автор (`user`, `persona`, `system`), помощник, готовый текст, время, статус, ссылка на задачу, карточка массовой команды (`BulkChecklist.toJson`) и `ChatLink` («Открыть чат задачи», «из чата «Главный»»).
- **Файлы.** `chats/index.json` (метаданные всех чатов — для меню «Чаты» и счётчиков) и файл на чат: `main.json`, `task-<id>.json` (символы кроме `[A-Za-z0-9_-]` в id заменяются на `_`). У всех `schema_version: 1`; каждый файл чата самодостаточен — в нём копия метаданных.
- **Чтение лениво.** При старте — `index.json` и `main.json`; чат задачи — при первом открытии. Пустой чат задачи на диск не пишется. Запись в чат, сообщения которого ещё не прочитаны (написали сразу после открытия, ответ пришёл в неоткрытый чат), ждёт чтения и пишет сохранённое вместе с новым — история не затирается, новое не теряется. Новый чат задачи тоже сначала читает свой файл: файл мог остаться без записи в index (сбой между записями) или лежать в архиве.
- **Запись.** Отложенная (500 мс) по изменённым чатам; сначала файлы чатов, затем index; каждый файл — атомарно (`.tmp` → `rename`) и по очереди, ошибка одной записи не мешает следующим и не роняет приложение. `flush()` — при уходе приложения в фон (`AppLifecycleState.paused/inactive/detached`), в `dispose` и при закрытии окна на компьютере: `didRequestAppExit` ждёт записи (не дольше 3 с) и только потом разрешает выход.
- **Лимит** — последние 1000 сообщений на чат (`ChatStore.maxMessages`), обрезка при записи и чтении, молча.
- **Повреждения.** Битый `index.json` (не JSON, не UTF-8) или неизвестная версия → `index.json.broken` и пересборка по шапкам файлов чатов; файл чата, которого нет в index, добавляется по своей шапке; битый файл чата (в том числе не UTF-8) → `<файл>.broken`, чат пустой, остальные целы; битое сообщение пропускается. `tasks.json` и `settings.json` хранилище чатов не трогает.
- **Не восстанавливается** после перезапуска: ожидание «да»/«нет» (карточка читается устаревшей), «Отменить» массового изменения, «обрабатывается…», выбор задачи в главном чате, курсор ↑/↓. Открывается главный чат.
- **Только в памяти.** `HomePage` по умолчанию берёт `InMemoryChatStore` (тесты, веб-превью; «Хранилище» пишет «только в памяти»), `main.dart` — `JsonChatStore`. Размер в «Хранилище» — `tasks.json` плюс файлы чатов.
- **Чат задачи — контекст.** Интерфейс передаёт задачу чата в `handle(…, chatTaskId:)`; маршрутизатор ставит `session.chatTaskId` и `Utterance.withChat`, выбирает задачу чата. `TasksConnector` берёт её целью «готово», «перенеси на завтра» без вопроса «какую?»; короткие «закрой», «на завтра» понимает только в чате задачи (`TaskChatPhrases`). Остальные коннекторы контекст не видят. Подробно — `docs/CONNECTORS.md`, «Чат задачи».
- **Смена чата** — `enterChat(taskId:)`: снимает ожидание подтверждения (карточка в покинутом чате устаревает), выбор главного чата запоминается и возвращается; если ответ ещё готовится, смена применяется после него, а ответ пишется в чат, из которого отправлена команда.
- **Создание задачи** в любом чате: ответ получает ссылку «Открыть чат задачи», в чат новой задачи копируются команда и ответ (ссылка «из чата …» ведёт обратно). Чаты удалённых задач убирает `ChatBook.prune`: файл уходит в `chats/archive/` и возвращается оттуда, если задача снова появится (например, `tasks.json` восстановили из копии после того, как приложение запустилось без него); «Очистить историю» стирает и архив. Чат выполненной задачи остаётся (в шапке — «Вернуть в работу»).
- **Шапка чата задачи** выбирает раскладку по ширине, которая ей досталась (рядом поиск и кнопка панели), а не по ширине окна: одна строка (название, срок, статус, «Выполнено»/«Вернуть в работу», значки), если названию остаётся не меньше 180 px — тексты меряются тем же шрифтом; иначе срок и статус под названием, действия значками; уже 320 px или крупный шрифт — название и меню. Так же строка «Задачи › «её»» в главном чате. В свёрнутом боковом меню (700–1099 px) чаты задач — значки с подсказкой и точкой «не прочитано».
- **Проактивное.** Ежедневное сообщение о просроченных — в главный чат; если открыт другой, у «Главного» точка «не прочитано».

## Правила

1. Сценарий и `match` коннектора только распознают намерение и параметры, без ввода-вывода.
2. Маршрутизатор выбирает коннектор и переспрашивает, если два коннектора одинаково уверены; коннектор проверяет контекст и возвращает уточнение вместо угадывания.
3. Task Service единственный изменяет задачи через репозиторий.
4. Репозиторий скрывает способ хранения.
5. Время приходит через Clock и полностью контролируется в тестах.
6. Ответ строится по фактически возвращённому объекту: факты передаются в запись каталога ответов значениями, текст вокруг них — из каталога, в каждом стиле с теми же фактами.
7. Пользователь выбирает задачу в UI или называет её словами. Поиск по названию идёт только по словам из команды: сначала точное совпадение, затем нечёткое по основам слов (короткие слова и числа — только целиком); несколько похожих — уточнение, ни одной — «не нашёл», без тихой подмены выбранной задачей. Если совпала только половина слов запроса, задача не меняется — помощник переспрашивает. Слова «её», «эту», «выбранную», «текущую», «последнюю» означают выбранную задачу.
8. Сеть — только внутри коннекторов (ADR-004).
9. Код расширений — только в составе приложения; паки — данные, они ничего не выполняют (ADR-005).

## Ограничения первого среза

- Название можно не брать в кавычки: оно извлекается как остаток фразы после команды («добавь задачу», «напомни мне»), срока с предлогом («на завтра в 10»), меток и вежливых слов. Удаляются только целые слова. Кавычки остаются способом задать точное название и имеют приоритет. Разговорное вступление перед командой («слушай,», «можешь», «нет,») тоже убирается; «нет,» с запятой — поправка, а не отрицание команды.
- Час без минут понимается после «в/к»: «в 10», «в 2 часа дня», «в 10 пожалуйста», «в 10 позвонить». Час 1–6 без «утра/дня/вечера/ночи» («к 5») переспрашивается, «в 03» (номер службы), количества («1.5 кг») и версии («flutter до 3.24») не считаются сроком.
- Сроки — по правилам `DueParser` (docs/CORPUS.md): даты «15.11» и «15 ноября», дни недели, «через N …», части суток и месяца. Повторяющиеся сроки («по пятницам»), «в обед», «на этой неделе» без дня пока не поддерживаются (`known_gap` в `test/corpus/`).
- У задач шесть намерений: создание, список, перенос и завершение одной задачи и массовые перенос и завершение («перенеси всё на выходные», `BulkParser`); другие команды добавляются коннекторами.
- JSON-хранилище подходит для проверки архитектуры, но не для больших данных, сложных запросов и распределённой синхронизации.
- Массовые перенос и завершение — только после вопроса со списком задач и галочками; отменить можно последнее массовое изменение (до перезапуска). Повторяющиеся задачи, удаление и отмена одиночных действий относятся к следующим итерациям.

## Следующие технические проверки

1. Заменить JSON на SQLite без изменения публичных интерфейсов сервисов.
2. Проверить XLSX чтение/запись и потоковый CSV на Android и Windows.
3. Проверить OAuth-перенаправления для обоих дисков на каждой платформе.
4. Измерить размер release-сборки, холодный запуск, память в простое и пиковую память при обработке файла.
5. Вынести синхронизацию в append-only журнал с идемпотентным применением операций.
