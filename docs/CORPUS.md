# Регрессионный корпус фраз

Корпус — это набор русских команд с ожидаемым разбором. Он проверяет `ScenarioParser` целиком и защищает от регрессий при добавлении новых правил. Прогоняется обычным `flutter test` (`test/scenario_corpus_test.dart`).

## Файлы

`test/corpus/*.jsonl` — одна строка = один JSON-объект = одна фраза. Пустые строки и строки, начинающиеся с `//`, пропускаются.

| Файл | Назначение |
| --- | --- |
| `create.jsonl` | создание задач, сроки, виды кавычек |
| `reschedule.jsonl` | перенос |
| `bulk.jsonl` | массовые команды над несколькими задачами (`rescheduleMany`, `completeMany`): выбор задач (`scope`), новый срок и сдвиг (`shift`); отрицательные примеры — команды над одной задачей («перенеси встречу на завтра», «всё, задача закрыта») |
| `complete_list.jsonl` | завершение, список, неизвестные команды |
| `unquoted.jsonl` | названия без кавычек, удаление срока и вежливых слов, цель переноса и завершения (`targetQuery`) |
| `natural_dates.jsonl` | дни недели, «через N минут/часов/дней/недель/месяцев», «на выходных», «в конце недели», «на следующей неделе»; граничные случаи с явным `now` (сегодняшний день недели, прошедшая «эта пятница», воскресенье) и слова, похожие на сроки («пятничный отчёт», «среда разработки») |
| `implicit.jsonl` | команды без маркера: создание по инфинитиву («через 3 дня сдать отчёт», «надо купить хлеб»), завершение по прошедшему времени («я купил хлеб», «отчёт сдал»), час сразу после дня («в следующий понедельник в 9 планёрка»); отрицательные примеры — вопросы, приветствия, фразы с существительного. «Сейчас» — четверг 2026-11-05 12:00 |
| `connectors.jsonl` | фразы других коннекторов и границы между коннекторами |
| `extensions.jsonl` | расширения с карточкой-формой (ADR-024): архиватор (`connector: archiver`, `archiver.zip`, `archiver.extract`, `archiver.list`), конвертер (`connector: converter`, `converter.convert`), загрузчик видео (`connector: ytdl`, `ytdl.download`) и отрицательные строки — задачи со словами «архив», «сжать», «распаковать», «сконвертировать» остаются задачами; «переведи 100 долларов в рубли», «переведи файл на английский», «конвертируй доллары в рубли» конвертер не берёт (`intent: unknown`); голую ссылку, «скачай музыку», «загрузи видео на ютуб …» загрузчик не берёт, «скачать музыку» и «напомни скачать видео завтра» — задачи, фразу со ссылкой не берёт конвертер |
| `talk.jsonl` | беседа (`connector: talk`, `intent` — команды `talk.*`): реплики целиком и ловушки, которые беседой не являются («привет, добавь задачу …», «пока не забыл, …» — уходят задачам); справочные вопросы `talk.question` («напомни, какая формула суммы в гугл таблицах?», `talk-q*`) |
| `data.jsonl` | навык «Данные» (`connector: data`): копия и восстановление без объекта и голое «хранилище» — уточняющий вопрос (`data.clarify`), явные «все данные» (`data.backup`, `data.restore`, `data.open`, `data.lock`), контекст сессии (`after`) и отрицательные примеры («сделай копию договора», «купить хранилище для велосипеда», «нужно сделать бэкап» — задача) |
| `calc.jsonl` | калькулятор (`connector: calc`): примеры с ожидаемым ответом `answer` и фразы с числами, которые примерами не являются (даты, время, телефоны, диапазоны, задачи) |
| `titles.jsonl` | названия без кавычек в именительном падеже («напомни про встречу» → «Встреча»), «поставь»/«заведи» с инфинитивом или кавычками, «запиши меня к врачу», «мне нужно «…»» |
| `part_of_day.jsonl` | части суток как срок («утром», «днём», «после обеда», «вечером») с точностью `partOfDay` и вместе с точным временем |
| `weather.jsonl` | навык «Погода» (`connector: weather`, ADR-030): `weather.now`, `weather.day`, `weather.week`, `weather.rain`, `weather.wear`, `weather.open`, `weather.past`, `weather.range`; поле `form` — `day` (дата, ISO), `place` (город в именительном падеже, как его ищет Open-Meteo) и `range` (`week`, `weekend`). Отрицательные: «погоди минутку», «напомни взять зонт, если будет дождь», «купить зонт», «температура от -5 до 12 градусов», «погода в доме» |
| `voice.jsonl` | надиктованные фразы (задача #4): обрывки распознавателя («поставь зэд напоминание»), вступления («нужен», «ну это», «эм»), «с утра», «на утро написать …», «чтобы я написал Андрею» → «Написать Андрею», время словами («в девять», «полдевятого», «завтра на десять»), имена с заглавной; вопросы после «напомни» («напомни, где лежат ключи?») — `unknown` для задач |
| `files.jsonl` | навык «Файлы сессии» (`connector: files`, ADR-028): `files.delete` — «удали этот файл», «удали его» с `after: converter`; отрицательные: «удали запись … из паролей», «удали задачу …», «удали эту сессию» |
| `task_edits.jsonl` | правки текущей или названной задачи (ADR-033): `intent: task.edit`, поле `form` — `kind` (`due`, `remind`, `pickTime`, `note`, `rename`, `items`), `target` (название словами пользователя: «эссену» — падеж ищет коннектор), `text` (заметка строкой фактов или новое название), `items` (пункты через `\|`), `due`/`precision`/`issue`, `bare: true` — одна дата без глагола (только с `after: tasks`). Фразы владельца («Поставь время 11:00», «напомни про них», «в эссен запиши, что их 22шт в ок…»), перефразирование названий («напомни, нужно доделать отчёт» → «Доделать отчёт») и отрицательные: создание, будильник, одно «сегодня». Любая строка задач, которую коннектор понял бы как правку, падает (`правка задачи вместо разбора`) |
| `first_person.jsonl` | дело от первого лица в будущем времени (ADR-033): «напомни, что я позвоню маме» → «Позвонить маме», «мы заберём посылку», «я буду звонить маме» → «Звонить маме» — только глаголы из закрытой таблицы `FirstPersonVerbs`; без команды («завтра я позвоню маме») — только со сроком и с вопросом «Создать?»; отрицательные: без срока, с «не», вопросом, третьим лицом, «это», «тебе», рассказ с местоимением |
| `frames.jsonl` | разговорная обёртка вокруг команды любого навыка (`CommandFrame`): «так, …», «короче, …», «будь добр, …», «если не трудно, …», «слышь, …», «плиз, …», «эээ …», «а можешь …?» (инфинитив из таблицы — в повелительное), «…, пожалуйста» в конце, «-ка», «запиши себе …». Фраза как есть — главная; без обёртки берётся, только если её понял тот же навык той же командой, или фразу как есть не понял никто, или без обёртки — явная команда, а как есть — догадка. Отрицательные: «так держать», «короче говоря, …», «будь добр к людям», «напомни сказать маме спасибо», «ок, всё понял, спасибо!» |
| `layout.jsonl` | набрано не в той раскладке (`LayoutFix`): «yfgjvyb pfdnhf d 10 gjpdjybnm vfvt» — «напомни завтра в 10 позвонить маме» — для всех навыков; только если фразу как есть не понял никто явно. «,» и «.» рядом с буквой — «б» и «ю» (на ЙЦУКЕН точка и запятая — на других клавишах), иначе — как на телефоне, только внутри слова; «^» между цифрами — двоеточие. Не трогается: кириллица во фразе, ссылки, почта, буквы с цифрами вперемешку (пароли, коды), фразы о паролях (исправленный текст повторяется в чате). Запись (задача, будильник, файлы…) — только после «Да» |
| `typos.jsonl` | опечатки в словах команд любого навыка (`TypoFix`): «постпвь будильник», «склоько венских стульев», «что пишло сегодня» — спасательным проходом, только если фразу как есть не понял никто явно; слово заменяется на единственное слово словаря команд (`command_lexicon.g.dart`, собран из корпуса `tool/gen_lexicon.dart`, без этого файла) на расстоянии одной правки не в первой и не в последней букве, от пяти букв. Опечатка в слове срока при понятой команде («напоми заввтра в 10 …») исправляется, если команда та же. Отрицательные: «выключи будильник» (не «включи»), «наполни ванну», «двинь стол» |
| `colloquial.jsonl` | разговорные формы команд (`CommandFrame`, закрытый список сочетаний): «кинь напоминалку», «не дай мне забыть», «запомни:», «черкани» (со сроком), «закинь в задачи», «вычеркни», «перекинь/отодвинь» (только со сроком), «покажи туду», «будилка», «буди меня», «кинь таймер», «отсчитай», «покеда», «сгенери», «забэкапь», «переделай/вытащи звук из видео в mp3», «вытащи файлы из архива», «в чём идти на улицу»; глагол в конце («на 7 будильник поставь», «архив распакуй»). Отрицательные: «кинь мяч», «перекинь деньги маме» |
| `generated.jsonl` | фразы от моделей, перенесённые `tools/corpus_gen` (`promote`) |
| `regressions.jsonl` | найденные ошибки; каждая строка закрывает конкретный дефект |
| `gaps.jsonl` | ещё не поддержанные фразы (`status: known_gap`); сейчас пуст — все известные пробелы закрыты (см. «Решения по бывшим пробелам») |

## Поля

| Поле | Обязательно | Значение |
| --- | --- | --- |
| `id` | да | уникальный идентификатор во всём корпусе |
| `text` | да | фраза пользователя как есть |
| `intent` | да | для `tasks`: `createTask`, `listTasks`, `completeTask`, `rescheduleTask`, `rescheduleMany`, `completeMany`, `unknown`; для других коннекторов — `commandId` или `unknown` |
| `connector` | нет | id коннектора, который должен забрать фразу; по умолчанию `tasks` |
| `now` | нет | «текущее» локальное время, по умолчанию `2026-11-02T16:30` (понедельник) |
| `title` | нет | ожидаемое название (из кавычек как есть или остаток фразы, начало которого в именительном падеже — см. «Названия без кавычек»); `null` — названия быть не должно |
| `targetQuery` | нет | для переноса и завершения без кавычек — слова, по которым ищется задача; `null` — кавычки или команда относится к выбранной задаче |
| `due` | нет | ожидаемый срок `YYYY-MM-DD` или `YYYY-MM-DDTHH:MM` (для `partOfDay` — с условным временем части суток: `2026-11-03T19:00`); `null` — срока нет |
| `precision` | нет | `date`, `dateTime` или `partOfDay` (часть суток без точного времени: «завтра вечером»). Независимо от поля всегда проверяется, что точность есть ровно тогда, когда есть срок (`dueAt == null` ⇔ `duePrecision == null`) |
| `issue` | нет | `inPast`, `invalidDate`, `invalidTime`, `conflictingDays`, `conflictingTimes`, `ambiguousHour` (час 1–6 без уточнения: «к 5»), `missingTime` (день есть, а фраза кончается висящим «в/на/к/до»: «перенеси её на завтра в»); отсутствие означает `none` и проверяется всегда |
| `titleIssue` | нет | `unbalancedQuotes`, `multipleTitles`; отсутствие означает `none` и проверяется всегда |
| `projects` | нет | метки проектов из команды (`#работа` вне кавычек) в нижнем регистре, без `#`; у массовых команд — метки выбора задач |
| `scope` | нет | только у `rescheduleMany` и `completeMany`: какие задачи выбраны — `all`, `overdue`, `noDue` или `date:ГГГГ-ММ-ДД`, затем метки через пробел: `overdue #работа` (`BulkSelection.label`) |
| `shift` | нет | у `rescheduleMany` — сдвиг каждой задачи, у `rescheduleTask` — сдвиг одной задачи от её срока («перенеси звонок на час позже»), вместо нового срока — `+1h`, `-2d`, `+30m` (неделя — `+7d`; `DueShift.label`); `null` — сдвига нет |
| `status` | нет | `active` (по умолчанию) или `known_gap` |
| `note` | нет | пояснение для человека |
| `source` | нет | откуда фраза: `manual`, имя модели-генератора и т. п. |
| `tags` | нет | произвольные метки |
| `roles` | нет | id включённых ролей строки (ADR-012): `personal`, `storekeeper`; по умолчанию — все встроенные. Расширения выключенных ролей в споре не участвуют (`["personal"]` — склад молчит) |
| `after` | нет | id коннектора, который только что отвечал в этом чате (контекст сессии, `Utterance.recentConnectorId`): `"after": "passwords"` — «сделай бэкап» после разговора о паролях. Строка разбирается с этим контекстом; если победитель отдаёт фразу другому навыку (`Reroute`), проверяется разбор канонической фразы — как в маршрутизаторе |
| `connected` | нет | `true` — склад подключён (подсказки роли «Кладовщик» действуют: «сегодня» — приходы, голый артикул — уверенно «где лежит»); по умолчанию `false` |
| `answer` | нет | только для `connector: calc` с `intent: calc.evaluate`: ожидаемый ответ калькулятора без примера — «6», «≈ 3,333333333», «2 400», «На ноль делить нельзя.» (`CalcResult.answer`). Разряды пишутся обычным пробелом: неразрывный пробел ответа при сравнении заменяется обычным |
| `route` | у `intent: unknown` — да | кого выберет маршрутизатор для фразы, которую навык строки не должен понять как свою команду: `none` — никого, `ambiguous` — переспросит, или id коннектора (беседа как запасной ответ, справочный вопрос, чужой навык: «сколько будет 2+2» в строке задач — `calc`). Без этого поля отрицательная строка задач, ушедшая складу или файлам, проходила бы тест. `tools/corpus_gen` (`promote`) записывает его по ответу приложения; у других намерений поля нет |
| `form` | нет | что навык получит из фразы, объектом «поле: значение» строками: у конвертера и будильника — поля карточки и будильника, у погоды (ADR-030) — `day` (ISO-дата), `place` (город в именительном падеже) и `range` (`week`, `weekend`); у склада (ADR-031) — поля запроса (`q`, `cell`: что склад будет искать — «64115», а не «по 64115») и `how`, если вопрос понят не обычной фразой описания: `total` — обо всём складе («сколько позиций на складе»: склад этого не считает, ответ без запроса), `ask` — искать нечего, помощник спросит; у правки задачи (`intent: task.edit`, ADR-033) — поля `TaskEdit.form` |

Отсутствующие `title`, `targetQuery` и `due` не проверяются, явный `null` в них проверяется как «должно быть пусто». Остальные поля не могут быть `null`. Для `rescheduleTask` и `completeTask` поле `title` — то, по чему ищется задача: точное название в кавычках или, без кавычек, запрос (так размечает и `tools/corpus_gen`); `targetQuery` проверяет только запрос без кавычек и позволяет отличить одно от другого; нечёткий поиск задачи по запросу проверяется в `test/assistant_controller_test.dart`, а не в корпусе.

## Коннекторы

Строка с `connector` проверяется так:

- для `tasks` (по умолчанию) — разбор `ScenarioParser`, как описано выше;
- для другого коннектора — его `match`: `intent` должен совпасть с `commandId`, `unknown` — коннектор не откликается. Поля разбора задач (`title`, `due`, …) в таких строках могут быть только пустыми (`null`, `none`): их значения для других коннекторов не проверяются;
- для строки с `intent: unknown` — поле `route`: маршрутизатор выбирает именно его (`none`, `ambiguous` или id коннектора);
- для любой строки с `intent` ≠ `unknown` — маршрутизация: среди включённых коннекторов из `_connectorFactories` (`test/scenario_corpus_test.dart`) побеждает указанный и без уточнения «к чему относится команда». Правила выбора — общая функция `RoutePolicy.pick` (`lib/core/scenario/route_policy.dart`), та же, что в маршрутизаторе и `tool/route_phrases.dart`; совпадения с уверенностью 0 в выборе не участвуют.

**Роли в корпусе.** Коннекторы строки собираются в `ExtensionRegistry` с выбором ролей строки. По умолчанию включены обе встроенные роли — «Личное» и «Кладовщик», — а склад **не подключён**: так склад спорит за каждую фразу всех файлов корпуса (строже всего для перехватов), но подсказки роли, которым нужно подключение, молчат — «сегодня» без обращения складу не достаётся (`wh-040`). Строки, зависящие от роли, задают `roles` и `connected` явно: `wh-064`–`wh-074` в `warehouse.jsonl` («сегодня»/«вчера»/«64115» с подключённым складом; склад молчит при `roles: ["personal"]`; задачи, калькулятор и беседа с подключённым складом не меняются).

Склад (`connector: warehouse`) — коннектор по описанию `assistant/1`, собранный из встроенной копии `test/fixtures/assistant/depotdesk-1.4.62.json` (ADR-031); его фразы — `test/corpus/warehouse.jsonl`: примеры описания, фразы `say` с подставленными значениями (`source: manifest`), ручные и отрицательные («сегодня», «привет», «сколько будет 2+2», «сколько у меня задач» — `source: manual`). Учебный «Пример склада» (`warehouse_example`) в корпусе больше не участвует, его строки перенесены на `warehouse` с `commandId` `warehouse.where`.

Архиватор (`connector: archiver`), конвертер (`connector: converter`) и загрузчик видео (`connector: ytdl`, ADR-024) в приложении выключены по умолчанию (загрузчика нет на Android, macOS и в сборке для Google Play), а в корпусном тесте и в `tool/route_phrases.dart` включены всегда, на любой платформе — как «Пароли»: их фразы спорят за каждую строку корпуса. Их строки — `test/corpus/extensions.jsonl` (`ext-001`…).

Неизвестный `connector` роняет тест. Как добавить коннектор в корпус — `docs/CONNECTORS.md`. Неизвестные поля, повторяющиеся `id`, отсутствие обязательных полей, неверные значения перечислений и дат роняют тест с указанием файла и строки — это защищает от опечаток в данных, сгенерированных моделями.

`known_gap` — фраза, которую парсер пока разбирает неверно. Тест проходит, пока разбор не совпадает с ожиданием, и падает, когда совпал: значит, возможность появилась и строку нужно перевести в `active`.

## Дни недели и относительные сроки

Правила `DueParser` (`lib/core/connectors/due_parser.dart`), по которым размечен `natural_dates.jsonl`:

- день недели без уточнения — ближайший будущий; если сегодня тот же день, то со временем, которое ещё не прошло, — сегодня, иначе и без времени — через неделю («в понедельник» в понедельник почти всегда значит следующий);
- «в следующую пятницу», «на следующей неделе в пятницу» — пятница следующей календарной недели (с понедельника); «в эту пятницу» — текущей недели, прошедшая — `inPast`; «на следующей неделе» без дня — её понедельник;
- «на выходных», «на выходные», «в выходные» — ближайшая суббота (в воскресенье — следующая), «на следующих выходных» / «на следующие выходные» — суббота следующей календарной недели; «в конце недели» / «к концу недели» — пятница текущей недели (прошедшая — `inPast`);
- «через N минут/часов» — точное время (по прошедшему времени, а не по настенным часам), «через N дней/недель/месяцев» — день (со временем — `dateTime`); части складываются («через 2 часа 30 минут»), дробные часы («через 2,5 часа»), числа словами («двадцать пять», «трое суток»), «2ч», «часик», «недельку» понимаются; диапазон («через 10-15 минут») — `conflictingTimes`/`conflictingDays`; «через час пик», «через минуту-другую» — не сроки;
- «на следующую неделю» — как «на следующей неделе»; несколько дней через «и/или/запятую», даже без второго предлога («в среду или четверг») — `conflictingDays`; день сразу после исходного времени («с 10:00 в пятницу на понедельник») — тоже исходный;
- полные названия дней — только после предлога в падеже предлога («в/на/по пятницу», «до пятницы», «к пятнице»), перед временем или одним словом; сокращения пн…вс — так же, с любым из этих предлогов. Перед временем день считается сроком только в именительном падеже (или с «следующую/эту»), без чужого предлога и не после числа: «в среде 10:00», «развернуть среду в 10», «лампа 60 вт в 10» — не дни. «среда» перед «разработки», «исполнения», «окружения» и т. п. — не день даже с предлогом. «пятничный отчёт» — не срок.

## Даты словами и части месяца

- Число и месяц в родительном падеже — дата: «15 ноября», «на 20 декабря», «до 15 ноября», «16 апреля 2027 [года]». Без года — ближайшая не раньше сегодняшнего дня, как у ДД.ММ: «25 октября» 2 ноября — 2027-10-25, «29 февраля» — ближайший високосный год. С годом в прошлом — `inPast` («15 ноября 1999 года», как и «15.11.1999»), несуществующая с годом — `invalidDate` («29 февраля 2100 года»). Год — число 1900–2199 или любое четырёхзначное со словом «года»/«г» (и слитно: «2026г»); другое число после даты годом не считается («15 ноября 5000 рублей»). Дата вместе с предлогом убирается из названия, час после неё понимается, как после дня («15 ноября в 10 созвон» — 10:00). Месяц без числа («в ноябре») — не срок.
- Несуществующая дата словами («31 февраля», «30 февраля в 10», «45 марта») — `invalidDate`; как и у «31.02», дата не попадает в название. Час больше 23 с уточнением часа («в 25 часов», «в 30 вечера») или с минутами («25:00») — `invalidTime`; одно число «в 25» без уточнения — не время (может быть номером). Срок работы или количество часов — не время и остаётся в названии без `invalidTime`: число больше 23 со словом «час(а/ов)», кратное суткам («сдать проект в 48 часов», «уложиться в 24 часа»), или с обычным словом после («подготовиться к 25 часов эфира»). Если неверны и дата, и время («31 февраля в 25:00», «31.04 в 25:30», «30.02 в 25 часов») — `invalidDate`: дата важнее. Разбор при этом доходит до конца фразы, поэтому из названия уходят и дата, и время.
- Части месяца (точность `date`): «в начале месяца», «к началу месяца», «на начало месяца» — 1-е число ближайшего ещё не начавшегося месяца (2026-11-02 и 2026-11-01 — 2026-12-01); «в середине месяца», «к середине месяца» — 15-е этого месяца, а если оно уже прошло, — следующего (2026-11-15 — ещё 2026-11-15, 2026-11-20 — 2026-12-15); «в конце месяца», «к концу месяца», «до конца месяца», «на конец месяца» — последний день этого месяца (в последний день — сегодня). С «следующего месяца» — то же в следующем месяце («в конце следующего месяца» — 2026-12-31), с «этого/текущего месяца» — в этом (прошедшее «в начале этого месяца» — `inPast`). Сроком часть месяца бывает только после своего предлога (в/к/до/на: «в начале», «к началу», «до конца», «на конец»); «с начала месяца», «после середины месяца», «отчёт о конце месяца», «для конца месяца» и форма без предлога — не срок, фраза остаётся в названии целиком. Строки — `nd-106`…`nd-126` в `natural_dates.jsonl`.

- Разговорные формы времени (b2, свежая проба): «через часа полтора», «через минут десять» — единица перед числом; «через час с небольшим/с лишним» — уточнение в срок, а не в название; «через сутки» — ровно 24 часа (`dateTime`); «в полдень», «в полночь», «до полудня», «до обеда» (12:00; «с утра до обеда» — промежуток, не срок); «в половину восьмого»; «в 17 часов 20 минут»; «в 18 30» после «в/к/до/на» — 18:30, если дальше не слово счёта («в 2 50 рублей» — не время); «ровно/примерно в …» и «по мск» — часть срока; «в это же время», «на то же время» — нынешнее время (у переноса одной задачи коннектор берёт время самой задачи, `ParsedCommand.sameTime`; у массового с исходным днём — сдвиг на дни); «в начале/середине (следующей) недели» — понедельник/среда; «на след неделе». «Без четверти пять», «полшестого» без части суток — как «в 5»: `ambiguousHour` («в шесть ноль пять» — как сказано).
- Поправка срока на ходу: «в четверг, нет, в пятницу», «не на завтра, а на послезавтра», «в 10, точнее в 11» — срок последний; «завтра, а не послезавтра» — первый. «В четверг или в пятницу» — по-прежнему `conflictingDays`.
- Дата в названии, а не срок: «купить билеты на 8 марта», «столик на пятницу» (после слов брони — `_bookingNouns`); «напомни завтра заказать торт к пятнице» — при другом дне «к …» после дела остаётся в названии.

Строки `gap-001`, `gap-003`, `gap-004`, `gap-005`, `gap-006`, `gap-008`, `gap-009` переведены из `gaps.jsonl` в `natural_dates.jsonl` с прежними `id`. `gap-007` («во вторник утром») — в `part_of_day.jsonl`.

## Части суток

- «утром» (и «утречком»), «днём», «после обеда», «вечером» (и «вечерком», «этим вечером») — срок с точностью `partOfDay`. В `dueAt` — условное время части: утро 09:00, день 13:00, после обеда 14:00, вечер 19:00; показывается словами: «завтра вечером», «6 ноября утром» (`formatDue`). Слово части суток — часть срока, а не названия: «добавь купить хлеб вечером» → «Купить хлеб», сегодня 19:00. С днём: «завтра утром», «в пятницу вечером», «через 3 дня вечером», «на выходных утром».
- Часть суток прошла, когда кончилась: утро — в 12:00, день — в 17:00, после обеда — в 18:00, вечер — в полночь. «Вечером» в 19:30 — ещё сегодня (условные 19:00 уже прошли, но задача не просрочена: `isOverdue` для `partOfDay` смотрит на конец части). Дальше — как с часом: без дня прошедшая часть — завтра («утром» в 16:30 — завтра 09:00, как «в 9» после 9:00), с явным днём — `inPast` («сегодня утром» в 16:30). Сегодняшний день недели — как со временем: «в понедельник вечером» в понедельник днём — сегодня, «в понедельник утром» в понедельник после полудня — через неделю.
- Точное время важнее, а часть суток уточняет час без «утра/вечера»: «завтра вечером в 8» — 20:00 `dateTime`, «утром в 5» — 05:00 без `ambiguousHour`, «вечером в 10:30» — 22:30. Несовместимое время с минутами («утром в 20:00») — как написано. Одиночный час, который после уточнения не попадает в часть суток (утро 4–12, день 12–17, после обеда 12–18, вечер 17–23), — `ambiguousHour`, а не дневное время: «вечером в 1», «вечером в 12», «утром в 3», «днём в 10». «утром или вечером» — `conflictingTimes`.
- Число после одной части суток без дня — час, только если оно попадает в часть суток и дальше не слово при числе: «утром в 5 пробежку» — 05:00, но «вечером в 2 магазина зайти», «днём в 10 классе провести урок» — количество и номер: срок — сама часть суток, «в 2 магазина», «в 10 классе» остаются в названии.
- «на вечер», «на утро» (существительным после «на») — тоже часть суток: «перенеси созвон на вечер» → сегодня 19:00 `partOfDay`, «на утро» в 16:30 — завтра 09:00, «на вечер пятницы», «на завтра на вечер», «на вечер завтра». «С утра на вечер» — «с утра» исходный срок переноса, в `targetQuery` не попадает. «На вечер встречи выпускников» — событие, не срок. «На день» сроком не считается («на день рождения»).
- Часть суток рядом с датой словами — в этот день: «5 ноября вечером» — 2026-11-05 19:00 `partOfDay`. «5-го вечером», «вечером 5 числа» — тоже в этот день: единственное число месяца без предлога («напомни 15-го», «5го», «15 числа») — срок (рядом с другим днём — исходный: «встречу 12-го на 18-е»). Рядом с датой, которую разбор не понимает («вчера вечером», «в ноябре вечером»), — не срок: иначе срок вышел бы уверенно неверным (сегодня вечером вместо 5-го). Вся фраза остаётся в названии, срока нет.
- «В обед» — часть дня: условные 13:00, точность `partOfDay`, но кончается раньше — в 15:00: «добавь позвонить маме в обед» в 14:59 — сегодня 13:00, в 15:00 и позже — завтра 13:00, «сегодня в обед» в 16:30 — `inPast`. С днём: «завтра в обед», «в пятницу в обед». Хранится и показывается как «днём» (13:00) — отдельной части суток в задаче нет. «Утром и в обед» — две части суток, `conflictingTimes`. Только с «в»: «сходить на обед с коллегами», «что в меню на обед?» — «обед» здесь событие, остаётся в названии.
- «На завтрашнее утро», «на завтрашний вечер», «на сегодняшний вечер», «на послезавтрашнее утро» — день из прилагательного и часть суток: «сдвинь её на завтрашнее утро» → 2026-11-03 09:00 `partOfDay`. Цель может стоять и после такого срока: «перенеси на завтрашний вечер звонок» → «Звонок», 2026-11-03 19:00. «На завтрашний вечер встречи выпускников» — событие, не срок (как «на вечер встречи»): после прилагательного и части суток слово на «-а/-я/-и/-ы» читается как родительный падеж события.
- Не сроки (остаются в названии): «ночью» — это и поздний вечер, и раннее утро; «после работы», «к вечеру», «к утру» — пока не поддержаны («ближе к вечеру», «ближе к утру», «ближе к обеду» — та же часть суток); «с днём рождения», «днём раньше», «каждым утром», «после обеда с клиентом» — не время. «Ночью», «после работы/учёбы/школы», «перед сном/работой» в начале фразы не мешают задаче по инфинитиву после них и остаются в названии: «после работы зайти в аптеку» → «После работы зайти в аптеку» (см. «Команды без маркера»).
- Хранение: `due_precision: "partOfDay"` в JSON задачи; файлы без поля читаются как `dateTime`, незнакомое значение — тоже `dateTime`. `tools/corpus_gen` пишет такой срок как `"due": "2026-11-03T19:00", "precision": "partOfDay"`.

## Названия без кавычек

Правила `NounForms` (`lib/core/connectors/noun_forms.dart`), по которым размечен `titles.jsonl`:

- Начало названия без кавычек — главное слово начальной именной группы (до первого предлога, союза, запятой) и прилагательные перед ним — ставится в именительный падеж, остальное остаётся как написано: «добавь встречу с клиентом» → «Встреча с клиентом», «добавь новую презентацию» → «Новая презентация», «запиши покупку кофе» → «Покупка кофе». «Отчёт», «документы», «счёт», «кофе», «такси» не меняются. Так же — запрос переноса и завершения: «перенеси встречу на завтра» → `targetQuery` «Встреча»; поиск сравнивает слова по основе и коротким падежным окончаниям («мама»/«маму»), поэтому задачи со старыми названиями («Встречу …») находятся.
- После «напомни» и других маркеров предлоги «про», «о», «об», «насчёт», «по поводу» убираются, если слово после них удалось привести: «напомни про встречу с клиентом завтра в 10» → «Встреча с клиентом», «напомни о звонке маме» → «Звонок маме», «напомни об оплате счёта» → «Оплата счёта», «напомни насчёт отчёта» → «Отчёт», «о дне рождения мамы» → «День рождения мамы», «о ДР Саши» → «ДР Саши». «Напомни о том, что …» — как «напомни, что …».
- Правила — по частым окончаниям и короткие списки слов (без словаря): винительный женского рода «-у/-ю» → «-а/-я» («встречу», «Машу» → «Маша»), «-ию» → «-ия»; предложный «-ке» после согласных женского рода («о поездке», «о справке», «об уборке», но не «о ребёнке», «о списке», «о ноутбуке», «о вторнике»), «-аче/-ече», «-аше» → «-а» («о встрече», «о Маше», но не «о малыше», «о плаще»), «-лате» → «-а» («об оплате», но не «о брате», «о салате»); «-ии» — средний род по суффиксу «-ании/-ении/-ытии/-ятии/-стии/-ствии» → «-ие» («о собрании», «о путешествии», «об участии»), иначе женский «-ия» («о гарантии», «о партии», «о церемонии», «о премии»); мужской род на «-ий» и неясное («о сценарии», «об условии», имена «о Евгении», «о Дмитрии») — как написано; родительный после «насчёт» «-ы» → «-а», «-ачи/-ечи/-аши/-ажи» → «-а» («насчёт встречи», «насчёт продажи»), но не женский род на «-ь» («насчёт помощи», «насчёт ночи», «насчёт речи» — как написано); мужской и средний род в предложном и родительном («о плане», «о звонке», «о письме») — только из списка. Местоимения и порядковые перед главным словом женского рода — по списку: «о моей встрече» → «Моя встреча», «насчёт нашей встречи» → «Наша встреча», «о третьей встрече» → «Третья встреча». Несклоняемые («кофе», «такси», «рагу», «кенгуру», «Баку», «барбекю») не меняются.
- Без предлога «-у» может быть дательным падежом, поэтому меняется, только если дальше конец группы, родительный падеж на «-а/-я/-ов/-ей» или несклоняемое слово: «встречу клиента» → «Встреча клиента», но «добавь клиенту счёт» → «Клиенту счёт». Слово на «-ы/-и» дальше — и родительный, и множественное число, поэтому с ним меняются только явно женские формы («уборку квартиры», «встречу команды», «презентацию»): «добавь Олегу цветы», «добавь заказчику документы» — как написано. Частые мужские имена и «-чику/-щику» в дательном («Олегу», «заказчику») не меняются никогда.
- Не меняются: названия в кавычках (точное название), названия с инфинитивом («напомни позвонить маме», «машину помыть», «Машу забрать из школы» — винительный там к месту), сообщения о сделанном без маркера («встречу провёл»), числа, артикулы, латиница («66580», «1с», «iPhone»). Если форма не ясна, название остаётся как написано — вместе с предлогом: «напомни о Москве» → «О Москве», «напомни про клиента» → «Про клиента», «о новом проекте» → «О новом проекте». Лучше не изменить слово, чем испортить.
- Кавычки после дела — его предмет, а не всё название: «добавь задачу посмотреть фильм «1+1»» → «Посмотреть фильм «1+1»» (инфинитив между командой и кавычками; «напомни выполнить «Отчёт»» — по-прежнему «Отчёт»: предмет «выполнить/сделать» — сама задача).
- Края названия: обращение к помощнику после запятой («…, Нода») и «спасибо» в конце убираются («сказать маме спасибо» — дело, остаётся); вставки «ну это», «в общем», «короче» перед делом убираются; поправка дела на ходу («позвонить Олегу, точнее написать Олегу», «купить молоко, ой, кефир») — берётся поправка. Одушевлённый винительный («про врача», «стоматолога») не приводится: «про дела» ≠ «дел»; поиск задачи — по основе.

## Список задач

`listTasks` — явная просьба («покажи задачи», «список задач», «что запланировано?») или вопрос о своих планах целиком (`_isListQuery` в `ScenarioParser`): все слова вне срока — из закрытого словаря просьбы о списке, есть просьба показать («покажи», «выведи», «глянь», «хочу глянуть», «мне бы посмотреть») или вопрос («что», «какие», «?») и есть то, что показывать: «задачи», «дела», «план», «расписание», «календарь», «список», «встречи», «незавершённые», метка `#работа`. Примеры: «выведи весь список дел», «что в расписании?», «какие у меня встречи на завтра?», «Что у меня в планах на конец месяца?», «что там по тегу #работа», «список». Без такого слова — «что у меня на завтра?» (вопрос о себе со сроком), «что мне нужно сделать?», «что там у меня осталось?». Кавычки — только как название списка после «список» («покажи список "Дом"») или пример после «типа». Любое чужое слово — не список: «какие есть планы на выходные в городе?», «покажи список моих контактов», «что мне сделать с котом?», «хочу глянуть «позвонить в банк» и ещё что там осталось на завтра» — `unknown`; «посмотреть план» без «хочу/бы/дай» — задача по инфинитиву.
Просьба — также «дай», «посмотри», «взгляни» и «напомни» («напомни, что я там планировал», «напомни, что у меня на завтра»; с чужим словом — напоминание: «напомни, что завтра встреча» → задача «Встреча»); «Список» первым словом вместе с ещё одним словом о задачах — заголовок-просьба («Список дел на сегодня»). Показывать — также «график» и вопрос о своём: «что» с «мне/нужно/надо/должен» и «сделать/делать/доделать/доработать/недоработать» («покажи что я должен сделать», «покажи всё, что нужно сделать», «что у меня осталось недоработать?»), с «записал/запланировал/планировал/наметил/записано/намечено» («покажи что я записал на пятницу», «Глянь, что там записано на завтра»). «На день», междометия из одной повторённой буквы («ааа», «эээ») — служебные. Срок в кавычках — выделение, а не название: «Список дел на «сегодня»». Не список: «список покупок», «Список дел на «Ромашку»», «дай мне хлеб», «покажи график работы магазина», «что я записал в блокнот», «Что мне нужно выполнить сегодня?». Строки — `done-021`…`done-029`.

## Маркеры создания

Создают задачу «добавь», «создай», «запиши», «напомни» (и их формы), «новая задача». «Поставь», «заведи», «сделай» (и «поставить», «завести», «поставьте»…) — вместе с «задачу»/«напоминание» (через «мне», «новую», вежливые слова): «поставь задачу купить хлеб» — создание, «поставь чайник», «сделай погромче» — нет. «Поставь» и «заведи» создают задачу и без «задачу», если сразу после них (через «мне», «пожалуйста», срок) инфинитив или название в кавычках: «поставь подготовить презентацию к понедельнику» → «Подготовить презентацию», срок — понедельник; «Поставь «Подготовить презентацию к понедельнику»» → точное название без срока. Бытовые инфинитивы — не задача (закрытый список в `_notTaskAfterPut`): кухня («поставь кипятить воду», «поставь варить кашу», «поставь греть ужин», «поставь греться чайник»), стирка («поставь стирать бельё», «поставь сушить бельё»), устройства и медиа («поставь заряжать телефон», «поставь качать фильм», «поставь смотреть фильм», «поставь слушать подкаст», «поставь играть музыку»). Остальные инфинитивы — дела: «поставь подготовить отчёт», «поставь созвониться с клиентом». «Сделай» без «задачу» не создаёт и с кавычками: «сделай «Отчёт»», «сделай «Ноду» основной» — не задачи. «Запиши меня (нас) к/на …» — задача записаться: «запиши меня к врачу на пятницу» → «Записаться к врачу». «Задача:» с двоеточием в начале фразы — заголовок новой задачи. Инфинитив «записать» с кем-то другим и «к/на» — само дело, а не маркер: «не забыть записать ребёнка к стоматологу», «надо записать маму на приём» — задачи по инфинитиву «Записать ребёнка к стоматологу», «Записать маму на приём» («записать меня к врачу» — по-прежнему «Записаться к врачу»). «Не забудь» сразу после «напомни» — повтор просьбы и в название не входит: «напомни не забудь купить хлеб вечером» → «Купить хлеб»; после «добавь» оно часть названия («добавь не забыть полить цветы» → «Не забыть полить цветы»). «Надо», «нужно», «мне» перед маркером — вступление и в название не попадают: «нужно поставить задачу купить хлеб» → «Купить хлеб». Числа в названии (артикул «66580», «1с») сроком не считаются: `reg-053`…`reg-068` в `regressions.jsonl`.

## Команды без маркера

Правила `ScenarioParser`, по которым размечен `implicit.jsonl`:

- **Создание с кавычками.** Одно название в кавычках без других слов, кроме срока, вежливых слов и вступления, — `createTask` с точным названием из кавычек, если есть хотя бы одно из трёх: вступление с «надо», «нужно», «необходимо» или «не забыть» («мне нужно "помыть машину" после обеда» → «помыть машину», после обеда), срок (««Полить цветы» на сегодня в 12:00», «в пятницу в 18 "созвониться с клиентом"», ««Связаться с юристом» на завтра») или слово «задача» («Нужна задача „Зайти в банк“ послезавтра»). После кавычек допустимо короткое пояснение — до трёх слов, начиная с предлога: «через час "позвонить в клинику" по записи» → «позвонить в клинику», через час; пояснение в название не входит (название в кавычках точное), с «не»/«нет» в нём фраза — не команда. Если признак задачи — только срок (без «надо», «не забыть», «задача»), кавычки должны быть похожи на дело, а не на цитату: название без «?» («"Кто там?" в обед» — `unknown`), не приветствие («"Спокойной ночи" в 22:00», «"Доброе утро" завтра» — `unknown`), а пояснение после кавычек допустимо, только если название начинается с инфинитива («через час "позвонить в клинику" по записи» — задача, ««Мастер и Маргарита» завтра в кино» — `unknown`). Одно существительное в кавычках со сроком («"Матрица" по пятницам», ««Отчёт» в пятницу») — задача: без списка задач правила не отличат фильм от дела. Не команда: одни кавычки без срока (««купить хлеб»», «"Кто тебя создал?"» — так пишут и реплики беседы), «хочу «отпуск»», «в понедельник "записаться к стоматологу" не нужно», длинный хвост после кавычек (««Купить хлеб» завтра для мамы с папой на даче»).
- **Создание.** В сообщении нет маркера ни одной команды («добавь», «перенеси», «заверши», «покажи задачи»…), и после срока и вступления («надо», «нужно», «необходимо», «мне надо», «мне нужно», «не забыть», «не забудь», «хочу», вежливые слова) фраза начинается с инфинитива на «-ть», «-ти», «-чь». Это `createTask`, `title` — остаток фразы. Здесь «не» в «не забыть» — часть вступления, а не отрицание. Перед инфинитивом может стоять обстоятельство времени, которое не срок (закрытый список: «ночью», «после работы/учёбы/школы/занятий/пар/тренировки», «перед сном/работой/выходом», «по дороге домой/на работу»), — оно остаётся в названии: «ночью проверить что файлы сохранились» → «Ночью проверить что файлы сохранились»; одно обстоятельство или обстоятельство с существительным («после работы хлеб») — `unknown`. Инфинитив прямо перед названием в кавычках — задача с названием из кавычек, как с маркером («добавь испечь «пирог»»): «хочу в субботу испечь «яблочный пирог с карамелью»» → «яблочный пирог с карамелью», суббота; других слов, кроме вступления, срока и вежливых, быть не должно, глагол завершения перед кавычками («Нужно выполнить «Отчёт» завтра») — `unknown`. «Не забыть/не забудь про (о, об, насчёт) X» — как «напомни про X»: «не забыть про оплату подписки через пару дней» → «Оплата подписки», через 2 дня; если X не приводится к именительному или это местоимение («не забудь про меня», «не забудь о себе», «не забыть про него», «про это», «про всё») — реплика, `unknown`; поворот после X («не забыть про хлеб, а вообще ладно»: «а», «но», «ладно», «впрочем», «хотя», «однако») — тоже `unknown`, «и» между предметами — нет («не забыть про хлеб и молоко» → «Хлеб и молоко»). Инфинитив распознаёт `VerbForms.isInfinitive` (общий с правилом «в 10 позвонить»): «-ть» после гласной или «з» («купить», «лезть»), но «-уть» только как «-нуть»/«-дуть» («вернуть»; «жуть», «путь» — нет), «-оть» только после «л»/«р» с гласной («колоть»; «мякоть», «локоть» — нет); «-ти» после «д», «й», «з» или «ас/ес/яс/юс» («идти», «зайти», «везти», «нести»; «кстати», «ногти», «дети», «кисти», «гости» — нет); «-чь» после «е», «о», «и» («испечь», «помочь», «стричь»); плюс список существительных («кровать», «сеть», «ночь», «дичь», «прочь»). Не создание:
  - вопрос с «?» или с «ли» («купить ли хлеб»), приветствия, «кстати»;
  - отрицание и оценка после глагола: «не купить хлеб», «купить хлеб не надо», «знать надо», «посмотреть кино было бы неплохо»;
  - глаголы состояния и модальные первым словом: «быть», «жить», «стать», «хотеть», «мочь», «знать», «видеть», «спать»;
  - просьбы к самому помощнику: «показать», «вывести», «удалить», «отменить», «найти», «отметить», «завершить» и фразы со словами «задача», «список» («показать список», «удалить задачу хлеб») — такую задачу добавляют явно: «Добавь задачу отметить юбилей»;
  - «узнать/посмотреть/проверить» + «где»/«сколько» — вопрос к помощнику: «узнать, где лежит 64115» уходит складу;
  - один глагол без предмета и без срока («сделать», «купить»); возвратный глагол («постричься») и глагол со сроком («позвонить завтра») — задача;
  - фразы, начинающиеся с существительного («Хлеб купить», «в следующий понедельник в 9 планёрка»).

  Совпадение без маркера помечено `implicit`: маршрутизатор отдаёт фразу коннектору с явным совпадением, даже менее уверенным (`"connector":"warehouse"` у «узнать где лежит 64115»). Если активная задача с таким же названием уже есть, новая не создаётся: «Задача «…» уже есть».
- **Завершение по сделанному.** Без маркера, не вопрос, без «не», о себе (нет «он», «она», «мама», «мать»…; множественное «купили» — только с «мы») и с предметом («я купил», «вчера звонил», «я поел и поспал», «сходил и вернулся» — не завершение: одни глаголы, в том числе через «и»): первое или последнее значимое слово (кроме «я», «мы», «уже», срока) — глагол прошедшего времени на «-л», «-ла», «-ли», «-ло» с гласной перед «л» («купил», «сдала», «позвонили»; «дела», «стол», «школа» — не глаголы). Это `completeTask`, `targetQuery` — фраза без «я»/«уже» и других служебных слов сообщения («вот», «ну», «так», «наконец(-то)», «сегодня», «вчера», «утром»…; «и» — только на краю), вместе с глаголом: «я купил хлеб» → «Купил хлеб», «наконец-то сдал проект» → «Сдал проект», «хлеб и молоко купил» → «Хлеб и молоко купил». Глагол сделанного и одно название в кавычках без других слов — завершение по точному названию (`title`): «Вернул «Книгу в библиотеку»» → «Книгу в библиотеку»; как и без кавычек, глагол угадан по форме, поэтому сначала вопрос-подтверждение (с явным маркером «сделал «…»» — сразу); о другом человеке («мама вернула «Книгу»») — `unknown`. Глаголы, которые не сообщают о сделанном, — не завершение ни с кавычками, ни без: забыть и потерять («забыл», «потерял», «упустил», «пропустил», «проспал», «провалил»), чувства («любил», «обожал», «ненавидел», «хотел», «мечтал»), восприятие и ожидание без приставки («смотрел», «видел», «слышал», «ждал», «помнил», «знал», «думал»): «я забыл «Отчёт»», «Я смотрел «Друзей»», «я забыл отчёт» — `unknown`; с приставкой дело закончено («Посмотрела вебинар» — завершение). Фраза, где сделанное — только в первой части («хлеб купил, молоко ещё надо»), под правило не подходит: ни первое, ни последнее значимое слово не глагол сделанного — `unknown`. С явным маркером в прошедшем времени («сделал», «выполнил», «завершил») запрос, как и раньше, без маркера: «сделал презентацию» → «Презентацию». Задача по такому запросу не завершается сразу: помощник спрашивает «Отметить «…» выполненной?» (проверяется в `test/assistant_controller_test.dart`).
- **Час после дня.** Одиночный час после «в/к» сразу за днём («завтра», «в пятницу», «через 3 дня», «в следующий понедельник», допускается запятая) — время, даже если дальше обычное слово: «Добавь завтра в 10 созвон с командой» → 10:00, «Созвон с командой». Без дня перед ним «в 2 магазинах» по-прежнему текст. Час 1–6 без уточнения — `ambiguousHour`.

## Массовые команды

Правила `BulkParser` (`lib/core/scenario/bulk_parser.dart`), по которым размечен `bulk.jsonl`. Массовая команда ничего не меняет сразу: помощник спрашивает со списком задач и галочками (`docs/CONNECTORS.md`, «Подтверждение изменяющих действий»).

- **Глагол.** Перенос — «перенеси», «отложи», «сдвинь», «передвинь», «перекинь» (и «перенести»… после «можешь»); завершение — «закрой», «заверши», «отметь … выполненными/сделанными/как выполненные» («отметь всё» без слова о готовности — не завершение).
- **Явный признак многих задач** обязателен: «всё/все/всех/весь», «просроченные», «сегодняшние/завтрашние/вчерашние», «без срока (даты, дедлайна)» «задачи/дела/задания/напоминания» во множественном числе — и без «все» («перенеси задачи на завтра», «закрой дела»: о многих задачах, поэтому вопрос со списком, а не тихий перенос одной), «задач/дел/заданий» — только вместе с меткой или днём («задачи на пятницу перенеси на понедельник»). «Перенеси задачу на завтра», «на завтра перенеси» — перенос одной (выбранной) задачи. Начальное «всё» с запятой или тире перед глаголом — конец реплики, а не выбор: «всё, перенеси на пятницу» — перенос задачи из разговора, «всё, закрой задачу» — завершение выбранной, «всё, закрой» — `unknown`, как «закрой»; «всё, перенеси все на пятницу» — массовая команда по второму «все».
- **Каждое слово** — часть команды, выбора, срока, метки или вежливости («пожалуйста», «давай», «сразу», «мне»…). Иначе это команда над одной задачей: «перенеси встречу на завтра», «перенеси все встречи на завтра» (неизвестное слово «встречи» — цель поиска). Кавычки — название одной задачи («закрой «Все задачи по ремонту»»), кроме кавычек после «кроме».
- **Исключения** «кроме …» (и «исключая …») в самой команде: «закрой всё, кроме хлеба», «перенеси все задачи кроме отчёта на завтра», «перенеси всё на завтра, кроме хлеба и «Сдать отчёт»». Названия — слова после «кроме» до срока, метки или конца фразы, через запятую, «и», «или». Выбор (`scope`) от них не меняется: в корпусе исключения не размечаются, а в списке такие задачи стоят без отметки. «Закрой всё, кроме» без названия — не массовая команда.
- **Выбор задач** (`scope`): все активные (`all`); просроченные (`overdue`, по тому же правилу, что красная пометка в списке); без срока (`noDue`); задачи на один день (`date:…`) — «сегодняшние», срок до глагола переноса («все задачи на пятницу перенеси на понедельник»), срок с «с/со» («с пятницы на понедельник», «со вчера на сегодня»), а у завершения — любой срок во фразе («отметь всё на сегодня выполненным»). Метки «#работа» (и «с/по/из/для #…», «по проекту #…») сужают любой выбор. Два разных признака («на пятницу на понедельник» после глагола, «просроченные и сегодняшние») — `conflictingDays`: помощник переспросит.
- **Новый срок** переноса — срок после глагола без исходного дня, по обычным правилам `DueParser` («на выходные» — ближайшая суббота, «на завтра в 10», «на завтра вечером»). В прошлом — `inPast`.
- **Сдвиг** (`shift`): «на N минут/часов/дней/недель позже (попозже, вперёд, дальше)» или «раньше (пораньше, назад)», а после «сдвинь», «отложи», «передвинь» — и без «позже» («отложи всё на 2 дня» — `+2d`): каждая задача сдвигается от своего срока. Часы и минуты — только задачам с точным временем, дни — любым со сроком; задачи без срока в список не попадают. Это отличие от команды над одной задачей, где «отложи на 3 дня» без «позже» — «через 3 дня» (с «позже/раньше» — сдвиг и у одной задачи: «перенеси звонок маме на час попозже» — `shift: +1h` от её срока; без срока или часы у задачи на день — помощник спросит, на когда; сдвиг в прошлое — уточнение «уже прошло»; «на 2 дня назад» у одной задачи — по-прежнему `inPast`): у многих задач разные сроки, и сдвиг каждой естественнее, чем один общий срок. После «перенеси» длительность без «позже» («перенеси всё на 2 часа») — не срок и не сдвиг: помощник спросит, на когда.
- **«Закрой всё»** без уточнений — все активные задачи. Это безопасно: ничего не выполняется без «да», а список показывает, что именно будет закрыто.
- **«Отмени»**, «отмени перенос», «верни всё как было» — отмена последнего массового изменения (`task.bulk.undo`), команда коннектора задач, а не намерение разбора: в корпусе её нет. Отдельное «отменить» по-прежнему `unknown`. Пока ждёт ответа новый вопрос со списком, «отмени», «отмени перенос», «отмени всё», «отмена переноса», «не переноси» — отказ от этого вопроса, а прошлое применённое изменение остаётся.

## Чат задачи

Строки корпуса разбираются без контекста чата — как в главном чате. Поэтому «закрой», «на завтра», «на пятницу в 10» без объекта в корпусе остаются `unknown`. В чате задачи те же фразы закрывают или переносят её (`docs/CONNECTORS.md`, «Чат задачи»); проверки — `test/connectors/task_chat_test.dart`: там же регресс, что в главном чате они по-прежнему не поняты. Контекст чата задачи в корпусе пока не задаётся; контекст сессии (кто только что отвечал) — поле `after`.

## Решения по бывшим пробелам

Эти правила закрыли строки `known_gap` (в основном `generated.jsonl`); те же правила — в `LABEL_SYSTEM` (`tools/corpus_gen/corpus_gen/prompts.py`). Проверки — `test/scenario_rules_test.dart` и строки `done-007…`, `nd-127…`, `pod-031…`, `imp-101…`, `reg-069…`.

- **Завершение другими словами** (`completeTask`, цель — `targetQuery` в именительном по правилам `NounForms`; у цели завершения «про», «о», «об», «насчёт» и «по» убираются, если слово после них удалось привести, и всегда — перед инфинитивом):
  - «закрой (задачу) X», «закрой «X»», «закрыть задачу X»; «закрыл/закрыла/закрыли X» — сообщение о сделанном (`pastTense`): «я закрыла отчёт по проекту» → «Отчёт по проекту». «Закрой» — завершение, только если есть «задача»/«задачу» или название в кавычках, или первое слово цели — не бытовой предмет: «закрой окно», «закрой дверь», «закрой вкладку с почтой», «закрой» без предмета — `unknown`. То же в прошедшем времени: «я закрыла дверь», «закрыл глаза», «закрыл окно» — `unknown`, а не сообщение о сделанном. «Закрыта»/«закрыто» — только со словом «задача»: «всё, задача закрыта» → завершение выбранной задачи (`targetQuery: null`), «магазин закрыт» — `unknown`;
  - «пометь/отметь (как) готовым/выполненным/завершённое/сделанное X», «отметь галочкой X», «отметь что сдал X» → X («что» и глагол сделанного убираются); без слова о готовности «отметить юбилей» — не завершение. «Отметил X» → X (`pastTense`);
  - «поставь галочку (на/напротив) X» → X;
  - «по X всё готово» → «Тренировка» из «по тренировке»; «с X всё, сделано» → X без «с»: «С врачом всё, сделано» → «Врачом» (творительный падеж не приводится, но «с» перед целью до слова о готовности убирается всегда); «по» остаётся, если слово после него не привести (как «про» у «напомни»: «Про iPhone»): «по отчёту всё, сделано» → «По отчёту»; «всё», «готово», «сделано» — служебные;
  - «заверши задачу про позвонить подруге» → «Позвонить подруге»; дата сразу после «про/о/об/насчёт» — часть цели, а не срок: «заверши задачу про 15 ноября, уже всё сделала» → «Про 15 ноября».
- **Кавычки без команды** — см. «Создание с кавычками» выше.
- **«В обед»** — см. «Части суток».
- **«На этой неделе»** (также «на эту неделю», «в эту неделю», и в переносе) без дня — пятница этой недели (`date`); в субботу и воскресенье — воскресенье этой недели. Фраза из названия убирается. Без предлога («отчёт этой недели») — не срок. С днём («на этой неделе в среду») неделя только уточняет день.
- **Повторение** — «по пятницам», «каждую пятницу», «каждый понедельник», «recurring/еженедельно/регулярно по пятницам». Повторяющихся задач пока нет (docs/PLANS.md): `createTask`, срок — ближайший такой день по правилу «в пятницу» (сегодняшний день без времени — через неделю), фраза повторения из названия убирается: «Поставь задачу выносить мусор по пятницам» → «Выносить мусор», 2026-11-06. «Сделай recurring по пятницам — выносить мусор» — создание: повторение сразу после «сделай» работает как «задачу». Несколько дней («по понедельникам и средам») — `conflictingDays`. Без маркера и с существительного («по пятницам тренировка в 19:00») и вопрос («по пятницам у меня бассейн?») — `unknown`.
- **Цели переноса:**
  - «на выходной» — ближайшая суббота, как «на выходные»;
  - число месяца без месяца: «на 20 число», «на 20-е», «на 18-е число», «до 20-го», «к 20-му» — это число в этом месяце, если оно ещё не прошло, иначе в следующем (в месяце без такого числа — в ближайшем, где оно есть: «на 31-е» 2 ноября — 2026-12-31). «С 12-го (числа)» — исходный срок. «12-го» без предлога — исходный срок, только если во фразе есть и новый: «с встречи 12-го на 18-е перенеси» → 18-е, цель «Встречи» («с» оторвано от исходного срока и тоже убирается). Без предлога и без нового срока («созвон 5-го вечером») — не срок, как раньше;
  - «с завтра на X» — «с завтра» исходный срок, срок — X;
  - «на 15:00 пятницы» — день недели в родительном падеже сразу за временем: пятница 15:00;
  - «на следующую неделю (во) вторник» — вторник следующей недели, а не `conflictingDays`;
  - «на более позднее (раннее) время», «на другое время», «на другой день», «на попозже», «попозже» — перенос без срока (помощник спросит, когда), фраза в цель не входит;
  - «на вчера», «на позавчера», «на 5 дней назад», «на неделю назад» — `inPast`. «Вчера» без «на/с» по-прежнему не срок («вчера звонил»);
  - «с перенесением/переносом на четверг» — перенос на четверг, цели нет;
  - лишнее «на» перед «через» («на через 2-3 дня») — часть срока;
  - пояснение после срока и запятой — не цель: «перенеси встречу на 15 ноября, у меня тогда свободнее» → «Встреча». Только если слова цели стоят до срока.
- **Час без предлога после дня:** «на завтра 9 утра», «в пятницу 7 вечера» — время, только с «утра», «вечера», «ночи» («завтра 2 дня» — не время).
- **Команда в конце фразы:** «…, добавь (это)», «…, запиши», «…, поставь (плз)», «…, создай», «…, не забудь» в самом конце после запятой или тире — `createTask` для всего, что перед ней; сама команда в название не входит. Вступление («надо», «нужно», «мне надо», «я хочу», «не забыть») и глагол создания в инфинитиве («напомнить», «добавить», «записать») с начала фразы убираются: «я в обед хочу напомнить прозвонить по страховке, поставь» → «Прозвонить по страховке», завтра 13:00. Кавычки — точное название: ««Отчёт» в пятницу, запиши». Если раньше в фразе другая команда («перенеси на завтра, не забудь»), решает она, а хвост не попадает в цель. «Через полтора часа» — +90 минут. Без запятой или тире перед ней («не забудь» одно) — не команда. «Не забудь» и «поставь» в конце бывают и репликой («всё понятно, не забудь», «я забыл, не забудь», «у меня всё, не забудь», «чайник, поставь» — `unknown`): с ними фраза до хвоста — задача, только если в ней есть инфинитив, срок или кавычки. «Добавь», «запиши», «создай» в конце — команда всегда.
- **Устойчивость:**
  - сообщение целиком заглавными (не меньше четырёх букв, ни одной строчной) — название без кавычек обычным предложением: «НАПОМНИ ВСТРЕЧА В 5 КОРПУСЕ СЕГОДНЯ В 15:00» → «Встреча в 5 корпусе»; аббревиатуры в таком сообщении тоже становятся строчными. Название в кавычках остаётся точным («ДОБАВЬ "КУПИТЬ ХЛЕБ" ЗАВТРА» → «КУПИТЬ ХЛЕБ»). Если хоть одна буква строчная — регистр как написан («отчёт для ООО Ромашка»);
  - латинские буквы-двойники (a, c, e, o, p, x, y, k, m, t и заглавные A, B, C, E, H, K, M, O, P, T, X, Y) внутри слов, где есть и русские буквы, заменяются русскими до разбора и в названии: «завтрa» → «завтра», «Mилк» → «Милк». Слова целиком латиницей («iPhone», «recurring») не меняются. Слово меняется, только если русских букв в нём больше, чем латинских, и все латинские — двойники: латинское название с русским окончанием остаётся как написано — «Zoomе», «iPhoneа», «PDFку», «Excelе», «Telegramе», «SMSку»;
  - опечатки — только в словах команды и только одна правка (замена, вставка, пропуск, перестановка соседних букв) в словах от пяти букв: первое слово сообщения — глагол команды («поставни» → «поставь» через «постави», «пеернеси» → «перенеси»), слово сразу после команды — «задачу», «напоминание» («задау» → «задачу»). Правка последней буквы (и перестановка двух последних) не опечатка, а другая форма: «напомню», «запишу», «задача», «добавьь», «напомин» не исправляются. Правка первой буквы — другое слово: «запомни», «двинь», «оставь». Настоящие слова в одной правке от команды — не опечатки: «записи в блоге не грузятся», «наполни ванну», «запили видео», «выполи грядку», «обложи налогом», «заверни подарок», «отмени встречу», «отмерь ткань», «отметки за четверть», «добавки хочешь?» остаются как написаны. Остальной текст остаётся как написан: «позвонитть».

  - «на 15 часов», «на 7 вечера», «на 2 часа дня» — время на часах: час 13–23 со словом «час(а/ов)» или час с «утра/вечера/часа дня/часа ночи»; «на 2 часа», «на 3 дня» — длительность, остаётся в названии («добавь сходить в спортзал на 2 часа»); «на 2 ночи» без «часа» — число ночей, тоже остаётся в названии («добавь бронь отеля на 2 ночи»), а «в 2 ночи», «на 2 часа ночи» — время;
  - после просьбы отсрочить — повелительной формы («отложи», «откладывай», «сдвинь», «сдвигай», «передвинь», «отложим», «сдвинем») или инфинитива после «можешь/можете/можно» («можешь отложить встречу на 3 дня») — «на N минут/часов/дней/недель/месяцев» — как «через N …»: «отложи на 3 дня напоминание про полис» → 2026-11-05, «сдвинь встречу на час» → 17:30. Глагол или прилагательное отсрочки внутри названия — не просьба, «на N …» остаётся длительностью: «добавь задачу сдвинуть встречу на 2 часа» → «Сдвинуть встречу на 2 часа», «добавь задачу отложенный платёж на 3 дня» — без срока. «Перенеси на 2 часа» так не читается;
  - «на завтрашний день», «к завтрашнему дню», «до сегодняшнего дня» — день из прилагательного (`date`); «на завтрашний день рождения» — событие, не срок;
  - «с 15 на 17 марта» — у исходного числа без месяца месяц нового срока: «с 15» — исходный срок, в цель не входит;
  - несовершенный вид переноса — «переноси», «сдвигай», «передвигай», «откладывай» — команда, только если во фразе есть срок: «с понедельника на среду сдвигай тренировку в зале» → «Тренировка в зале», среда; «переноси коробки аккуратно» — `unknown`;
  - «напоминание», «пункт» сразу после команды переноса и завершения — как «задачу»: «закрой напоминание про звонок брату» → «Звонок брату», «Выполни пункт про оплату счетов» → «Оплата счетов»; дальше по фразе — часть цели («заверши поход в пункт выдачи»). «Закрой напоминание …» — завершение, как «закрой задачу …»; опечатка в «напоминание» после «закрой» исправляется. У цели переноса «про» остаётся, как и раньше: «отложи напоминание про полис» → «Про полис»;
  - союзы «и», «а», «или», «потом», «затем» на краю цели не входят в неё: «перенеси на завтра и потом на послезавтра звонить в страховую» → «Звонить в страховую», `conflictingDays`;
  - одинарные кавычки ('…') — не кавычки названия: это слова цели или названия, заглавной становится первая буква после апострофа («'Готовить презентацию'»).
- **Кавычки в сломанных фразах** — прежние правила: если хоть одна кавычка не закрыта, это `unbalancedQuotes` (важнее `multipleTitles`), а текст после неё остаётся в разборе: «добавь задачу "Сделать "Срочно" завтра» — `unbalancedQuotes`, срок завтра; «добавь "напомнить о встрече в «кабинете 302 на завтра» — `unbalancedQuotes`, срок завтра.

Правила третьего круга (713 строк `generated.jsonl`, проверки — `test/passwords/passwords_phrases_test.dart`, `test/connectors/manifest/manifest_relaxed_test.dart`, `test/skills/calculator_test.dart`, `test/skills/talk_test.dart`):

- **Пароли.** Обращение («Лиорио, …», «…, Лиорио», «…, Лиорио, …» — `PersonaAddressing.withoutAddress`) и вежливые слова по краям разбор не видит. Новые формы: логин и почта для входа («на какой имейл регался в озоне», «какая почта привязана к госуслугам», «вк какой там логин?», «под каким именем зашёл в почту»; «на какую почту отправить отчёт» — не вход), потеря и переезд устройства в любом порядке слов рядом с паролями или сейфом («мобила сломалась, пароли пропали»), без них — только с вопросом, как вернуть данные («потерял смартфон, как вернуть доступ к данным?»), забытый мастер-пароль в любом порядке и «сейф не открывается», генератор без слова «пароль» с параметрами сразу после глагола («сгенерируй на 16 символов без цифр»; «придумай стих из 5 слов» — нет), проверка надёжности одного пароля и «какие пароли плохие», вопросы о копии и импорте — справка, импорт из браузера и текстового файла без слова «пароли» («перенеси всё из сафари»; см. «Импорт» ниже). Слова перед глаголом навыка проверяются так же, как у генератора: «напомнить маме сменить пароль» — не команда; отглагольное действие перед паролем («смена пароля от госуслуг в середине марта») — название дела. Фразы о копии, бэкапе и восстановлении без слов «пароль», «сейф», «хранилище паролей» навык не берёт: в приложении есть и общая резервная копия данных. Их забирает навык «Данные» с уточняющим вопросом «Копию чего: паролей или всех данных?» (решение владельца 3): такие строки размечены `connector: data, intent: data.clarify` с `note`; те, что забирают задачи («помоги создать резервную копию», «нужно сделать бэкап»), и вопросы без просьбы («бэкап в облако можно делать?») остались `connector: passwords, intent: unknown`.
- **Склад.** Фраза, которая расходится с образцом `say` только уточнением, приводится к нему в Tridot (не в описании): период у команды без своего периода («приходы без фото за сегодня»; «за день» — сегодня), те же слова в другом порядке, артикул впереди («120734 остатки»), место в конце («сколько на 215-3»), вопрос после ячейки («на 215-3 что стоит»), срок и срочность рядом с одним артикулом. После обращения вопрос о состоянии («склад работает?») и инфинитив («переместить») — не товар.
- **Склад: запрос словами пользователя** (`lib/core/connectors/manifest/manifest_query.dart`, проверки — `test/connectors/manifest/manifest_query_test.dart`, `wh-119`…`wh-159`). Поле запроса — без служебных слов по краям: «по 64115», «64115 лежит», «64115, пожалуйста», «стул венский на складе», «у нас лежат венские стулья» → то, что склад будет искать (поле `form` строк склада); голос «64 115» → «64115». Вопрос обо всём складе («сколько позиций/товаров/наименований на складе», «сколько у нас всего товара») — не поиск товара «позиций»: склад общего числа не считает, ответ `warehouse.total` без запроса. Искать нечего («сколько на складе») — вопрос, что искать. Пересказ словами описания: «наличие 64115», «поищи», «где мне найти», «в какой ячейке лежит», «покажи ячейку», «по чём», «какой остаток по артикулу», «X сколько осталось», «поступления», «за последнюю неделю». Вопрос о наличии («есть ли X», «а X есть?») похож на обычную речь, поэтому он — складу, только если назван склад или артикул, склад только что отвечал или подключён для роли «Кладовщик», и в нём нет слов других навыков («есть ли смысл ждать», «есть ли резервная копия»); уверенность 0,75 — явная команда другого навыка сильнее. «Сколько осталось до отпуска», «сколько стоит доллар» — не товар.
- **Калькулятор.** Маркер в конце («…, посчитай»), просьба в конце — слабый маркер («…, быстро», «…, помоги», «… дай»), действие после запятой над всем, что до неё («пять плюс семь, умножить на два» = 24), действие в конце («тысячу на четыре разделить»), «квадрат 12» с маркером, числа-существительные («восьмёрку») только рядом с действием; пример в последней части «…, а 9×9 сколько?» уступает любой команде (0.6, `implicit`).
- **Беседа.** Команда задачи где угодно в реплике — не беседа; несколько откликов перед репликой («хорошо, круто, давай на ты»); «кто ты и что умеешь» — возможности; «здорово» с обращением по имени — приветствие.

Поправки после ревью третьего круга (ложные срабатывания — отрицательные строки `pw-161`…`pw-212` в `passwords.jsonl` и группа «ревью» в `test/passwords/passwords_phrases_test.dart`):

- **Пароли — не тема и не дело.** Проверка надёжности — не разговор о паролях вообще и не дело: «статья про одинаковые пароли», «доклад о надёжности паролей», «почему простые пароли опасны», «провести лекцию про слабые пароли» — задачи. Почта, адрес, имейл, аккаунт — вход только с глаголом входа или у известного сервиса и устройства: «какая почта у Ивана», «подскажи почту для связи с поддержкой», «на какой адрес была доставка», «где почта в Химках» — не навык («был» — вход только с «я»: «на какой почте я в озоне был»). Перед вопросом о логине «узнать, …», «уточнить, …» — дело. Устройство без слова о паролях — только с вопросом «как» или «восстановить доступ», и предмет — к самому устройству или данным: «нужно вернуть всё в магазин», «восстановить базу в 1С», «купил ноутбук, нужно перенести данные» — не навык. Тренировка — опора «пароли/сейф», не «мастер» («мастер-класс по тренировке памяти»); без неё — только явная команда (решение владельца 4): «тренировка памяти» целой фразой (как «потренируй мою память», `pw-133`) или со словом-просьбой после неё («посложнее», «давай»), «потренируй память»; разговор о тренировке вообще («тренировка памяти полезна?», «тренировка памяти, игра», «… каждый день», «для детей», «по английскому») — нет. «Главный код» — без техники («на котле», «ошибки»); «Сейф» — имя навыка в интерфейсе (решение владельца 5, `pw-197`…`pw-199` переразмечены: «сейф не открывается», «доступ к сейфу закрыт» — `masterForgot`, «закрой сейф, уходим» — `lock`; нужно подтверждение владельца): якорь — «сейф», «сейф паролей», «хранилище паролей» в любом месте фразы; без глагола навыка «сейф» не команда («купить сейф для дома»), «сейфовая дверь» — не сейф. Голое «хранилище» — не якорь (в приложении есть и общие данные, слово «Хранилище» оставлено за будущим «Хранилищем контекста»): «открой хранилище», «сделай копию хранилища», «хранилище не открывается» — не навык «Пароли», а уточняющий вопрос навыка «Данные» (`connector: data, intent: data.clarify`: `pw-213`…`pw-216`, `pw-236` и строки `generated.jsonl` с `note`); команда целиком с объектом «хранилище» («закрой хранилище», «восстановить хранилище из копии») — явная и выше задач, а не завершение задачи «Хранилище»; «как перенести хранилище на новый ноутбук» (`gen-1a6ff80b96cc`) забирают задачи как перенос — осталось `unknown`; рядом со словом о паролях («хранилище не открывается, мастер-пароль не менял») — сейф. Генератор без слова «пароль»: «для …» — сервис или устройство, после параметров — только параметры («сделай для поста на 280 символов текст» — не он). Справка о копии и импорте — опора при самой копии («копия сейфа», «импорт из хрома»), «опера» без «импорта» — и театр. «Сколько записей в хранилище» — склад (`warehouse.count`).
- **Импорт.** Без слова «пароли» — из браузера или файла txt/csv (в приложении их загружает только импорт паролей), повелительным, инфинитивом или существительным («хочу перенести данные из хрома», «хочу загрузить список из txt»), с предметом «всё, данные, список» и без другого места назначения («перенеси с хрома закладки», «перенеси данные из csv в таблицу» — нет).
- **Инфинитив.** Инфинитив команды навыка — команда (разметка владельца: «добавить пароль от банка», «хочу изменить пароль от банка»): «стереть пароль от вк» — удаление, «показать пароль от вк» — показ. Инфинитив чужого глагола — дело («поставить пароль на wifi», «узнать пароль от wifi»).
- **Копия** — в любом порядке слов: «сделай бэкап паролей», «бэкап паролей, сделай».
- **Беседа.** Что человек сделает с шуткой потом, просьбу не меняет: «расскажи шутку про IT — вставь в презентацию» — шутка (закрытый список глаголов, только у шутки).
- **Склад.** Приходы по артикулу («за неделю приходы 120734», «120734, приходы за сегодня?») — `intent: unknown`: у команд прихода нет поля артикула, а общий список вместо ответа про артикул вводит в заблуждение.
- **`tool/route_phrases.dart`** (проверка `promote`) — как корпусный тест: ошибка коннектора — ответ `error` (строка остаётся `accepted`), выбор — `RoutePolicy.pick` (совпадение с нулевой уверенностью не участвует), поле `after` — контекст сессии, строки с `roles` и `connected` не разбираются.

## Как пополнять

1. Добавить строку в подходящий файл. Для исправленного дефекта — в `regressions.jsonl` с `note`, что именно было не так.
2. Прогнать `flutter test test/scenario_corpus_test.dart`.
3. Если фраза пока не поддерживается и правило не входит в текущую задачу — пометить `known_gap`.

## Генерация фраз языковыми моделями

Языковые модели в приложении не используются (ADR-001). Их можно использовать только при разработке, чтобы пополнять корпус. Для этого есть `tools/corpus_gen` (см. его README): фразы от моделей попадают в `test/corpus/generated.jsonl`. Фразы от моделей сначала попадают в кандидаты, проходят перекрёстную разметку второй моделью и проверку человеком и только потом добавляются в `test/corpus/` с полем `source`. Если у фразы всего один разметчик другого семейства, вместо второй модели её разметку подтверждает приложение (`tool/route_phrases.dart`: маршрутизатор и `ScenarioParser`, те же правила, что в этом тесте); такие строки помечены тегом `labels:<разметчик>,parser`, а расхождения уходят на проверку человеку. В модели отправляются только синтетические фразы — никаких реальных задач пользователя.
