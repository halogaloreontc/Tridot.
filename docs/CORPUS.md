# Регрессионный корпус фраз

Корпус — это набор русских команд с ожидаемым разбором. Он проверяет `ScenarioParser` целиком и защищает от регрессий при добавлении новых правил. Прогоняется обычным `flutter test` (`test/scenario_corpus_test.dart`).

## Файлы

`test/corpus/*.jsonl` — одна строка = один JSON-объект = одна фраза. Пустые строки и строки, начинающиеся с `//`, пропускаются.

| Файл | Назначение |
| --- | --- |
| `create.jsonl` | создание задач, сроки, виды кавычек |
| `reschedule.jsonl` | перенос |
| `complete_list.jsonl` | завершение, список, неизвестные команды |
| `unquoted.jsonl` | названия без кавычек, удаление срока и вежливых слов, цель переноса и завершения (`targetQuery`) |
| `connectors.jsonl` | фразы других коннекторов и границы между коннекторами |
| `regressions.jsonl` | найденные ошибки; каждая строка закрывает конкретный дефект |
| `gaps.jsonl` | ещё не поддержанные фразы (`status: known_gap`) |

## Поля

| Поле | Обязательно | Значение |
| --- | --- | --- |
| `id` | да | уникальный идентификатор во всём корпусе |
| `text` | да | фраза пользователя как есть |
| `intent` | да | для `tasks`: `createTask`, `listTasks`, `completeTask`, `rescheduleTask`, `unknown`; для других коннекторов — `commandId` или `unknown` |
| `connector` | нет | id коннектора, который должен забрать фразу; по умолчанию `tasks` |
| `now` | нет | «текущее» локальное время, по умолчанию `2026-11-02T16:30` (понедельник) |
| `title` | нет | ожидаемое название (из кавычек или остаток фразы); `null` — названия быть не должно |
| `targetQuery` | нет | для переноса и завершения без кавычек — слова, по которым ищется задача; `null` — кавычки или команда относится к выбранной задаче |
| `due` | нет | ожидаемый срок `YYYY-MM-DD` или `YYYY-MM-DDTHH:MM`; `null` — срока нет |
| `precision` | нет | `date` или `dateTime` |
| `issue` | нет | `inPast`, `invalidDate`, `invalidTime`, `conflictingDays`, `conflictingTimes`, `ambiguousHour` (час 1–6 без уточнения: «к 5»); отсутствие означает `none` и проверяется всегда |
| `titleIssue` | нет | `unbalancedQuotes`, `multipleTitles`; отсутствие означает `none` и проверяется всегда |
| `projects` | нет | метки проектов из команды (`#работа` вне кавычек) в нижнем регистре, без `#` |
| `status` | нет | `active` (по умолчанию) или `known_gap` |
| `note` | нет | пояснение для человека |
| `source` | нет | откуда фраза: `manual`, имя модели-генератора и т. п. |
| `tags` | нет | произвольные метки |

Отсутствующие `title`, `targetQuery` и `due` не проверяются, явный `null` в них проверяется как «должно быть пусто». Остальные поля не могут быть `null`. Для `rescheduleTask` и `completeTask` поле `title` — то, по чему ищется задача: точное название в кавычках или, без кавычек, запрос (так размечает и `tools/corpus_gen`); `targetQuery` проверяет только запрос без кавычек и позволяет отличить одно от другого; нечёткий поиск задачи по запросу проверяется в `test/assistant_controller_test.dart`, а не в корпусе.

## Коннекторы

Строка с `connector` проверяется так:

- для `tasks` (по умолчанию) — разбор `ScenarioParser`, как описано выше;
- для другого коннектора — его `match`: `intent` должен совпасть с `commandId`, `unknown` — коннектор не откликается. Поля разбора задач (`title`, `due`, …) в таких строках могут быть только пустыми (`null`, `none`): их значения для других коннекторов не проверяются;
- для любой строки с `intent` ≠ `unknown` — маршрутизация: среди всех коннекторов из `_connectorFactories` (`test/scenario_corpus_test.dart`) побеждает указанный и без уточнения «к чему относится команда».

Неизвестный `connector` роняет тест. Как добавить коннектор в корпус — `docs/CONNECTORS.md`. Неизвестные поля, повторяющиеся `id`, отсутствие обязательных полей, неверные значения перечислений и дат роняют тест с указанием файла и строки — это защищает от опечаток в данных, сгенерированных моделями.

`known_gap` — фраза, которую парсер пока разбирает неверно. Тест проходит, пока разбор не совпадает с ожиданием, и падает, когда совпал: значит, возможность появилась и строку нужно перевести в `active`.

## Как пополнять

1. Добавить строку в подходящий файл. Для исправленного дефекта — в `regressions.jsonl` с `note`, что именно было не так.
2. Прогнать `flutter test test/scenario_corpus_test.dart`.
3. Если фраза пока не поддерживается и правило не входит в текущую задачу — пометить `known_gap`.

## Генерация фраз языковыми моделями

Языковые модели в приложении не используются (ADR-001). Их можно использовать только при разработке, чтобы пополнять корпус. Для этого есть `tools/corpus_gen` (см. его README): фразы от моделей попадают в `test/corpus/generated.jsonl`. Фразы от моделей сначала попадают в кандидаты, проходят перекрёстную разметку второй моделью и проверку человеком и только потом добавляются в `test/corpus/` с полем `source`. В модели отправляются только синтетические фразы — никаких реальных задач пользователя.
