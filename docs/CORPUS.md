# Регрессионный корпус фраз

Корпус — это набор русских команд с ожидаемым разбором. Он проверяет `ScenarioParser` целиком и защищает от регрессий при добавлении новых правил. Прогоняется обычным `flutter test` (`test/scenario_corpus_test.dart`).

## Файлы

`test/corpus/*.jsonl` — одна строка = один JSON-объект = одна фраза. Пустые строки и строки, начинающиеся с `//`, пропускаются.

| Файл | Назначение |
| --- | --- |
| `create.jsonl` | создание задач, сроки, виды кавычек |
| `reschedule.jsonl` | перенос |
| `complete_list.jsonl` | завершение, список, неизвестные команды |
| `unquoted.jsonl` | названия без кавычек, удаление срока и вежливых слов, цель переноса и завершения (`targetQuery`) |
| `natural_dates.jsonl` | дни недели, «через N минут/часов/дней/недель/месяцев», «на выходных», «в конце недели», «на следующей неделе»; граничные случаи с явным `now` (сегодняшний день недели, прошедшая «эта пятница», воскресенье) и слова, похожие на сроки («пятничный отчёт», «среда разработки») |
| `implicit.jsonl` | команды без маркера: создание по инфинитиву («через 3 дня сдать отчёт», «надо купить хлеб»), завершение по прошедшему времени («я купил хлеб», «отчёт сдал»), час сразу после дня («в следующий понедельник в 9 планёрка»); отрицательные примеры — вопросы, приветствия, фразы с существительного. «Сейчас» — четверг 2026-11-05 12:00 |
| `connectors.jsonl` | фразы других коннекторов и границы между коннекторами |
| `talk.jsonl` | беседа (`connector: talk`, `intent` — команды `talk.*`): реплики целиком и ловушки, которые беседой не являются («привет, добавь задачу …», «пока не забыл, …» — уходят задачам) |
| `calc.jsonl` | калькулятор (`connector: calc`): примеры с ожидаемым ответом `answer` и фразы с числами, которые примерами не являются (даты, время, телефоны, диапазоны, задачи) |
| `regressions.jsonl` | найденные ошибки; каждая строка закрывает конкретный дефект |
| `gaps.jsonl` | ещё не поддержанные фразы (`status: known_gap`) |

## Поля

| Поле | Обязательно | Значение |
| --- | --- | --- |
| `id` | да | уникальный идентификатор во всём корпусе |
| `text` | да | фраза пользователя как есть |
| `intent` | да | для `tasks`: `createTask`, `listTasks`, `completeTask`, `rescheduleTask`, `unknown`; для других коннекторов — `commandId` или `unknown` |
| `connector` | нет | id коннектора, который должен забрать фразу; по умолчанию `tasks` |
| `now` | нет | «текущее» локальное время, по умолчанию `2026-11-02T16:30` (понедельник) |
| `title` | нет | ожидаемое название (из кавычек или остаток фразы); `null` — названия быть не должно |
| `targetQuery` | нет | для переноса и завершения без кавычек — слова, по которым ищется задача; `null` — кавычки или команда относится к выбранной задаче |
| `due` | нет | ожидаемый срок `YYYY-MM-DD` или `YYYY-MM-DDTHH:MM`; `null` — срока нет |
| `precision` | нет | `date` или `dateTime`. Независимо от поля всегда проверяется, что точность есть ровно тогда, когда есть срок (`dueAt == null` ⇔ `duePrecision == null`) |
| `issue` | нет | `inPast`, `invalidDate`, `invalidTime`, `conflictingDays`, `conflictingTimes`, `ambiguousHour` (час 1–6 без уточнения: «к 5»); отсутствие означает `none` и проверяется всегда |
| `titleIssue` | нет | `unbalancedQuotes`, `multipleTitles`; отсутствие означает `none` и проверяется всегда |
| `projects` | нет | метки проектов из команды (`#работа` вне кавычек) в нижнем регистре, без `#` |
| `status` | нет | `active` (по умолчанию) или `known_gap` |
| `note` | нет | пояснение для человека |
| `source` | нет | откуда фраза: `manual`, имя модели-генератора и т. п. |
| `tags` | нет | произвольные метки |
| `answer` | нет | только для `connector: calc` с `intent: calc.evaluate`: ожидаемый ответ калькулятора без примера — «6», «≈ 3,333333333», «2 400», «На ноль делить нельзя.» (`CalcResult.answer`). Разряды пишутся обычным пробелом: неразрывный пробел ответа при сравнении заменяется обычным |

Отсутствующие `title`, `targetQuery` и `due` не проверяются, явный `null` в них проверяется как «должно быть пусто». Остальные поля не могут быть `null`. Для `rescheduleTask` и `completeTask` поле `title` — то, по чему ищется задача: точное название в кавычках или, без кавычек, запрос (так размечает и `tools/corpus_gen`); `targetQuery` проверяет только запрос без кавычек и позволяет отличить одно от другого; нечёткий поиск задачи по запросу проверяется в `test/assistant_controller_test.dart`, а не в корпусе.

## Коннекторы

Строка с `connector` проверяется так:

- для `tasks` (по умолчанию) — разбор `ScenarioParser`, как описано выше;
- для другого коннектора — его `match`: `intent` должен совпасть с `commandId`, `unknown` — коннектор не откликается. Поля разбора задач (`title`, `due`, …) в таких строках могут быть только пустыми (`null`, `none`): их значения для других коннекторов не проверяются;
- для любой строки с `intent` ≠ `unknown` — маршрутизация: среди всех коннекторов из `_connectorFactories` (`test/scenario_corpus_test.dart`) побеждает указанный и без уточнения «к чему относится команда».

Неизвестный `connector` роняет тест. Как добавить коннектор в корпус — `docs/CONNECTORS.md`. Неизвестные поля, повторяющиеся `id`, отсутствие обязательных полей, неверные значения перечислений и дат роняют тест с указанием файла и строки — это защищает от опечаток в данных, сгенерированных моделями.

`known_gap` — фраза, которую парсер пока разбирает неверно. Тест проходит, пока разбор не совпадает с ожиданием, и падает, когда совпал: значит, возможность появилась и строку нужно перевести в `active`.

## Дни недели и относительные сроки

Правила `DueParser` (`lib/core/connectors/due_parser.dart`), по которым размечен `natural_dates.jsonl`:

- день недели без уточнения — ближайший будущий; если сегодня тот же день, то со временем, которое ещё не прошло, — сегодня, иначе и без времени — через неделю («в понедельник» в понедельник почти всегда значит следующий);
- «в следующую пятницу», «на следующей неделе в пятницу» — пятница следующей календарной недели (с понедельника); «в эту пятницу» — текущей недели, прошедшая — `inPast`; «на следующей неделе» без дня — её понедельник;
- «на выходных» — ближайшая суббота (в воскресенье — следующая), «в конце недели» / «к концу недели» — пятница текущей недели (прошедшая — `inPast`);
- «через N минут/часов» — точное время (по прошедшему времени, а не по настенным часам), «через N дней/недель/месяцев» — день (со временем — `dateTime`); части складываются («через 2 часа 30 минут»), дробные часы («через 2,5 часа»), числа словами («двадцать пять», «трое суток»), «2ч», «часик», «недельку» понимаются; диапазон («через 10-15 минут») — `conflictingTimes`/`conflictingDays`; «через час пик», «через минуту-другую» — не сроки;
- «на следующую неделю» — как «на следующей неделе»; несколько дней через «и/или/запятую», даже без второго предлога («в среду или четверг») — `conflictingDays`; день сразу после исходного времени («с 10:00 в пятницу на понедельник») — тоже исходный;
- полные названия дней — только после предлога в падеже предлога («в/на/по пятницу», «до пятницы», «к пятнице»), перед временем или одним словом; сокращения пн…вс — так же, с любым из этих предлогов. Перед временем день считается сроком только в именительном падеже (или с «следующую/эту»), без чужого предлога и не после числа: «в среде 10:00», «развернуть среду в 10», «лампа 60 вт в 10» — не дни. «среда» перед «разработки», «исполнения», «окружения» и т. п. — не день даже с предлогом. «пятничный отчёт» — не срок.

Строки `gap-001`, `gap-003`, `gap-005`, `gap-006`, `gap-009` переведены из `gaps.jsonl` в `natural_dates.jsonl` с прежними `id`.

## Команды без маркера

Правила `ScenarioParser`, по которым размечен `implicit.jsonl`:

- **Создание.** В сообщении нет маркера ни одной команды («добавь», «перенеси», «заверши», «покажи задачи»…), и после срока и вступления («надо», «нужно», «мне надо», «не забыть», «не забудь», «хочу», вежливые слова) фраза начинается с инфинитива на «-ть», «-ти», «-чь». Это `createTask`, `title` — остаток фразы. Здесь «не» в «не забыть» — часть вступления, а не отрицание. Инфинитив распознаёт `VerbForms.isInfinitive` (общий с правилом «в 10 позвонить»): «-ть» после гласной или «з» («купить», «лезть»), но «-уть» только как «-нуть»/«-дуть» («вернуть»; «жуть», «путь» — нет), «-оть» только после «л»/«р» с гласной («колоть»; «мякоть», «локоть» — нет); «-ти» после «д», «й», «з» или «ас/ес/яс/юс» («идти», «зайти», «везти», «нести»; «кстати», «ногти», «дети», «кисти», «гости» — нет); «-чь» после «е», «о», «и» («испечь», «помочь», «стричь»); плюс список существительных («кровать», «сеть», «ночь», «дичь», «прочь»). Не создание:
  - вопрос с «?» или с «ли» («купить ли хлеб»), приветствия, «кстати»;
  - отрицание и оценка после глагола: «не купить хлеб», «купить хлеб не надо», «знать надо», «посмотреть кино было бы неплохо»;
  - глаголы состояния и модальные первым словом: «быть», «жить», «стать», «хотеть», «мочь», «знать», «видеть», «спать»;
  - просьбы к самому помощнику: «показать», «вывести», «удалить», «отменить», «найти», «отметить», «завершить» и фразы со словами «задача», «список» («показать список», «удалить задачу хлеб») — такую задачу добавляют явно: «Добавь задачу отметить юбилей»;
  - «узнать/посмотреть/проверить» + «где»/«сколько» — вопрос к помощнику: «узнать, где лежит 64115» уходит складу;
  - один глагол без предмета и без срока («сделать», «купить»); возвратный глагол («постричься») и глагол со сроком («позвонить завтра») — задача;
  - фразы, начинающиеся с существительного («Хлеб купить», «в следующий понедельник в 9 планёрка»).

  Совпадение без маркера помечено `implicit`: маршрутизатор отдаёт фразу коннектору с явным совпадением, даже менее уверенным (`"connector":"warehouse_example"` у «узнать где лежит 64115»). Если активная задача с таким же названием уже есть, новая не создаётся: «Задача «…» уже есть».
- **Завершение по сделанному.** Без маркера, не вопрос, без «не», о себе (нет «он», «она», «мама», «мать»…; множественное «купили» — только с «мы») и с предметом («я купил», «вчера звонил» — не завершение): первое или последнее значимое слово (кроме «я», «мы», «уже», срока) — глагол прошедшего времени на «-л», «-ла», «-ли», «-ло» с гласной перед «л» («купил», «сдала», «позвонили»; «дела», «стол», «школа» — не глаголы). Это `completeTask`, `targetQuery` — фраза без «я»/«уже», вместе с глаголом: «я купил хлеб» → «Купил хлеб». С явным маркером в прошедшем времени («сделал», «выполнил», «завершил») запрос, как и раньше, без маркера: «сделал презентацию» → «Презентацию». Задача по такому запросу не завершается сразу: помощник спрашивает «Отметить «…» выполненной?» (проверяется в `test/assistant_controller_test.dart`).
- **Час после дня.** Одиночный час после «в/к» сразу за днём («завтра», «в пятницу», «через 3 дня», «в следующий понедельник», допускается запятая) — время, даже если дальше обычное слово: «Добавь завтра в 10 созвон с командой» → 10:00, «Созвон с командой». Без дня перед ним «в 2 магазинах» по-прежнему текст. Час 1–6 без уточнения — `ambiguousHour`.

## Как пополнять

1. Добавить строку в подходящий файл. Для исправленного дефекта — в `regressions.jsonl` с `note`, что именно было не так.
2. Прогнать `flutter test test/scenario_corpus_test.dart`.
3. Если фраза пока не поддерживается и правило не входит в текущую задачу — пометить `known_gap`.

## Генерация фраз языковыми моделями

Языковые модели в приложении не используются (ADR-001). Их можно использовать только при разработке, чтобы пополнять корпус. Для этого есть `tools/corpus_gen` (см. его README): фразы от моделей попадают в `test/corpus/generated.jsonl`. Фразы от моделей сначала попадают в кандидаты, проходят перекрёстную разметку второй моделью и проверку человеком и только потом добавляются в `test/corpus/` с полем `source`. В модели отправляются только синтетические фразы — никаких реальных задач пользователя.
