# Расширения

Человек настраивает Связной под свои нужды, а не получает всё сразу. Всё, что Связной умеет сверх ядра, — расширения трёх видов. Решение и правила безопасности — ADR-005 в `docs/DECISIONS.md`.

| Вид | `ExtensionKind` | Что это | Сейчас | Как ставится |
| --- | --- | --- | --- | --- |
| Навыки | `skill` | своя логика в составе приложения, без сети | задачи (`tasks`), калькулятор (`calc`), беседа (`talk`) | встроены, включаются и выключаются |
| Подключения | `connector` | связь с внешним приложением (склад, expeora) | пока нет | кодом в составе приложения (`docs/CONNECTORS.md`) |
| Паки | `pack` | только содержимое, без кода: шутки, каламбуры, фразы, стили ответов | «Базовые шутки» (`jokes.basic`) | встроены в приложение или вставляются JSON-текстом |

Код навыков и подключений есть только в составе приложения: скачивать и запускать чужой код небезопасно и запрещено магазинами приложений. На лету ставятся только паки — это данные, они ничего не выполняют.

## Как включить и выключить

«Настройки → Расширения»: три группы — «Навыки», «Подключения», «Паки». У каждой строки название, описание, версия и автор, бейдж «встроено» и переключатель. Задачи выключить нельзя (бейдж «всегда включено», переключатель неактивен).

- Переключение применяется **сразу**, без перезапуска, и **ничего не сбрасывает**: задачи, история чата, выбранная задача, текст в поле ввода и ожидание подтверждения других коннекторов остаются. Снимается только ожидание подтверждения того коннектора, который выключили, — его «да» больше некому принять. Проверка — `test/home_page_test.dart`, группа «расширения включаются и выключаются без сброса».
- Выключенный навык не участвует в разборе сообщений: «2+2» при выключенном калькуляторе — обычное «не понял».
- Изначально включён минимум: задачи, калькулятор, беседа, базовый пак шуток.

### Как хранится выбор

В `settings.json` рядом с остальными настройками (`AppSettings`):

```json
{
  "reduce_motion": false,
  "show_timestamps": true,
  "disabled_extensions": ["calc"],
  "enabled_extensions": []
}
```

- `disabled_extensions` — выключенные из включённых по умолчанию;
- `enabled_extensions` — явно включённые из выключенных по умолчанию.

Поэтому новое расширение, включённое по умолчанию (`defaultEnabled: true`), после обновления приложения появляется включённым, даже если пользователь что-то выключал раньше. Битые значения (не список, не строки) читаются как пустые наборы и не мешают запуску.

### Код

`lib/core/extensions/`:

| Файл | Что в нём |
| --- | --- |
| `extension_kind.dart` | `ExtensionKind` — `skill`, `connector`, `pack` |
| `extension_info.dart` | `ExtensionInfo` (паспорт для настроек), `ExtensionChoice` (выбор пользователя) |
| `extension_registry.dart` | `ExtensionRegistry` — все навыки, подключения и паки, выбор, `enabledConnectors` для маршрутизатора, `packEntries` для навыков, `replies`/`replyLibrary` — каталог ответов с записями коннекторов и стилями паков |
| `pack.dart` | `Pack`, `PackEntry`, `PackPersona`, `PackStyle`, `PackFormat` — формат и строгая проверка |
| `pack_store.dart` | `PackStore` — встроенные и пользовательские паки, импорт, удаление; `replySchema` — против чего проверяются паки ответов |

Навыки и подключения реализуют обычный интерфейс `Connector`; вид, версия, автор, `defaultEnabled` и `required` — поля `ConnectorInfo` (`docs/CONNECTORS.md`). Регистрация — `lib/main.dart`:

```dart
final extensions = ExtensionRegistry(
  connectors: <Connector>[
    TasksConnector(taskService: tasks, parser: ScenarioParser(clock: clock)),
    const CalculatorConnector(),
    TalkConnector(taskService: tasks),
  ],
  packs: PackStore(loadBuiltIn: _builtInPacks, userDirectory: '<документы>/assistant/packs'),
);
final assistant = AssistantController(extensions: extensions, clock: clock);
```

`AssistantController(connectors: …)` по-прежнему работает: тогда все коннекторы включены. `HomePage` применяет выбор из настроек к `assistant.extensions` при запуске и при каждом изменении.

## Паки

Пак — один JSON-файл. Встроенные лежат в `assets/packs/*.json` (каталог зарегистрирован в `pubspec.yaml`), пользовательские — в `<документы приложения>/assistant/packs/<id>.json`. Добавить пак: «Настройки → Расширения → Добавить пак», вставить текст файла. Если пак с таким id уже установлен, помощник спросит, заменить ли его. Пользовательский пак можно удалить («Удалить» с подтверждением), встроенный — только выключить. Удалённый пак забывается и в выборе пользователя: если добавить его снова, он придёт включённым; замена пака новой версией выбор сохраняет.

Паки сохраняются на диск компактным JSON (без отступов, без `"persona": "any"`), поэтому сохранённый файл не больше вставленного текста и проходит предел 1 МБ при следующем запуске. Проверка «такой id уже есть» и запись файла — одна операция в общей очереди: два одновременных импорта одного нового id не пройдут оба без подтверждения. Ошибка записи (нет места, нет доступа) показывается в диалоге текстом, пак не принимается. Удаление стирает именно тот файл, из которого пак загружен, даже если имя файла не совпадает с id.

### Формат `assistant-pack/1`

```json
{
  "format": "assistant-pack/1",
  "id": "jokes.office",
  "type": "jokes",
  "title": "Офисные шутки",
  "author": "Мария",
  "language": "ru",
  "version": "1.0.0",
  "description": "Про планёрки, отчёты и кофе.",
  "entries": [
    {
      "id": "j1",
      "text": "Планёрка прошла продуктивно: запланировали следующую планёрку.",
      "tags": ["планёрка", "задачи"],
      "persona": "any",
      "styles": ["friendly", "neutral"]
    },
    {
      "id": "j2",
      "text": "Кофе — это способ превратить «не могу» в «уже делаю».",
      "tags": ["кофе"],
      "persona": "noda"
    }
  ]
}
```

| Поле | Обязательно | Правило |
| --- | --- | --- |
| `format` | да | ровно `assistant-pack/1`; другая версия — «Версия формата … не поддерживается» |
| `id` | да | `[a-z0-9][a-z0-9._-]{1,63}`: 2–64 символа. Не совпадает с id встроенного пака и с id навыка или подключения (`tasks`, `calc`) |
| `type` | да | `jokes`, `puns`, `phrases` или `replies` (стиль ответов, см. ниже); другой вид отклоняется с перечнем поддерживаемых. Новый вид добавляется в `PackFormat.types` вместе с навыком, который им пользуется |
| `title`, `author` | да | непустые строки до 100 символов |
| `language` | да | пока только `ru` |
| `version` | да | вида `1.0.0` |
| `description` | нет | строка до 500 символов |
| `entries` | да | непустой список, не больше 5000 записей; у пака `replies` — объект `{id записи каталога: варианты}` |
| `entries[].id` | да | `[a-z0-9][a-z0-9._-]{0,63}`, уникален в паке |
| `entries[].text` | да | непустая строка до 500 символов |
| `entries[].tags` | нет | до 10 меток, каждая — непустая строка до 30 символов; хранятся в нижнем регистре, «ё» → «е» |
| `entries[].persona` | нет | `any` (по умолчанию), `rio` или `noda` |
| `entries[].styles` | нет | подмножество `neutral`, `friendly`, `brief`, `business`; пусто — любой стиль |

Общие правила проверки (`PackFormat.parse`):

- файл не больше 1 МБ, это JSON-объект;
- неизвестные поля — ошибка (и на верхнем уровне, и в записях): опечатка в имени поля не теряется молча;
- типы строгие: строка должна быть строкой, список — списком;
- метка порядка байтов (BOM) в начале текста допускается и отбрасывается;
- управляющие символы (кроме перевода строки и табуляции) и знаки направления текста (U+200E, U+200F, U+202A–U+202E, U+2066–U+2069, U+061C) запрещены во всех строковых полях, включая метки: иначе название могло бы показаться в настройках задом наперёд;
- ошибки — по-русски, с местом: «entries[3]: текст длиннее 500 символов.»; проверяются все записи, показываются первые 20 и «И ещё ошибок: N.» с настоящим числом остальных;
- пак, не прошедший проверку, не сохраняется. Битый файл в каталоге паков пропускается при запуске и не мешает остальным (`PackStore.loadErrors`).

Текст записи — только текст. Он ничего не выполняет и не читается как разметка: `<b>`, `**` и `${…}` показываются как есть.

### Пак ответов (`type: replies`)

Пак ответов — свой стиль общения: id пака — id стиля, `title` — его название в «Настройки → Помощники». Вместо списка записей `entries` — объект `{id записи каталога: "вариант" | ["вариант", …]}`, 1–3 варианта на запись, до 500 символов каждый. Варианты пишутся разметкой каталога ответов (`{title}`, `{м:…|ж:…}`, `{вы:…|ты:…}`, `{мн:…}`, `{э:…}`) — это единственное место, где текст пака читается как разметка, и разметка только подставляет факты, ничего не выполняя.

Проверка (`PackFormat.parse` с `ReplySchema`): известные id записей (встроенные и записи подключённых коннекторов), только их подстановки, разметка без ошибок, каждый факт — в любом роде, обращении и форме числа (одна, две, пять), вопросы остаются вопросами, «≈» не пропадает, без эмодзи не пропадает конец предложения, метка `{э:…}` не приклеена к словам с обеих сторон, эмодзи только в `{э:…}`. **Предупреждения и вопросы-подтверждения** (список `protected` нейтрального каталога и `ConnectorInfo.protectedReplies`: «На ноль делить нельзя», «Это время уже прошло», «Отметить «…» выполненной?», «Передать жалобу администратору?») пак не переопределяет — такая запись в паке ошибка, и звучит текст встроенного стиля. id пака не совпадает со встроенным стилем. Формат, пример и правила — `docs/REPLIES.md`.

Включённый пак ответов появляется ещё одним стилем у каждого помощника; выключенный — пропадает, и помощник с этим стилем говорит нейтрально.

### Как паки используются

Паки ответов дают стили: `ExtensionRegistry.replyStyles` и `replyLibrary` — стили включённых паков. Паки шуток (`jokes`) и каламбуров (`puns`) читает навык «Беседа» (раздел ниже). Навыки берут записи через реестр — только из включённых паков:

```dart
final jokes = extensions.packEntries(
  type: 'jokes',
  tags: <String>{'понедельник'},   // все метки должны быть у записи
  persona: PackPersona.noda,        // any подходит обоим помощникам
);
```

Выбор записи — детерминированный (как варианты каталога ответов), стиль общения сужает выбор по `styles`, помощник — по `persona`. `PackStore.entries` даёт то же без учёта выбора пользователя (для предпросмотра и тестов).

## Навык «Калькулятор»

`lib/core/skills/calculator/`: `CalculatorConnector` (id `calc`, команда `calc.evaluate`), разбор и счёт — `Calculator`, точные числа — `Rational`.

- Понимает цифры с запятой или точкой, разряды через пробел («2 400»), `+ - * / × ÷ : ^ **`, скобки, унарный минус, `%`, `√`; слова «плюс», «минус», «умножить на», «умножь на», «помножить на», «разделить на», «поделить на», «делить на», «в степени», «в квадрате», «в кубе», «корень из», «квадратный корень из», «извлеки корень из»; кубический корень «корень кубический из 27», «кубический корень из −8» (= −2), знак `∛`; множители словами «дважды два», «трижды три», «пятью пять»; денежные единицы после числа не мешают («12% от 5000 рублей», «300 ₽ + 15%»); «X% от Y», «Y плюс/минус X%»; «умножить 3 на 4»; числа словами от «ноль» до «девятьсот», «тысяча» («двадцать пять», «две тысячи»), в том числе в родительном падеже («15% от двухсот», «корень из шестнадцати»); проценты со знаком и после множителя («−15% от 200» = −30, «10 × 15% от 2400» = 3 600); тире «—» как минус. «Корень из 1/4» словами — корень из дроби (0,5), знак «√1/4» — по правилам, (√1) / 4.
- Маркеры: «сколько будет …», «посчитай …», «вычисли …», «реши …», «рассчитай …», «чему равно …», «… равно?», «=» в конце, «извлеки(те) корень …» (без корня «извлеки» — не маркер: «извлеки данные из 5 файлов»), «найди корень из …» только с числом после корня («найди корень проблемы», «найди корень из зла», «найди корень из» — не примеры); «делить 5 на ноль» — как «умножить 3 на 4»; частица впереди («а 4.5 умножить на 3.2?», «ну 2+2») маркером не считается; слабый маркер «сколько» впереди или в конце («5% от 3200, сколько?», «2 в степени 8 это сколько», «пять разделить на три сколько будет») и просьба об ответе в конце («5 в кубе, дай ответ», «17 разделить на 5, какой остаток», «…, какой результат») — он, как «сколько …» впереди, не делает примером «10/3» или артикул. С маркером — уверенность 0.9, сообщение целиком — пример — 0.85 (нужно хотя бы одно действие: операция, корень, степень, «% от»).
- Не примеры: даты «12.11», время «18:30» и «в 10», одиночные числа и артикулы, диапазоны «10-15 минут», телефоны «+7 999 123-45-67» и «8-800-555-35-35», версии «2.10», метки, задачи с числами («купить 2 кг муки», «добавь задачу 2+2»), «через 2 часа». Без маркера не считаются и целые числа, сцепленные вплотную «-» или «/» без других знаков: артикулы «64115-01», «64115/2», телефоны «555-1234», диапазоны «10-15», «2–3», даты «12/11», «05/11/2026», «24/7». С пробелами («10 - 15»), с другими знаками («2+10/5») или с маркером («посчитай 24/7») это пример. Двоеточие вплотную отбрасывается, только если похоже на время («18:30», «9:05»): «2,5:0,5» и «100:4» — деление. Двойное отрицание «−(−3)» — пример, одно «−3» — нет.
- Счёт точный: рациональные числа на `BigInt`; корень точный для полных квадратов (кубический — для полных кубов), иначе приближённо с «≈»; дробная степень — приближённо. Никакого `eval`.
- Ответ: «2 + 2 × 2 = 6», «15% от 2 400 = 360», «10 / 3 ≈ 3,333333333» (10 значащих цифр), «1 / 8 = 0,125». Конечная дробь длиннее 20 знаков после запятой пишется точно с порядком, без «≈», если в ней не больше 20 значащих цифр: «10^−21 = 1 × 10^−21», «1 / 2^21 = 4,76837158203125 × 10^−7». Ошибки: «На ноль делить нельзя.», «Получается слишком большое число — такое не посчитаю.», уточнение «Не понял пример. Например: «сколько будет 15% от 2400».».
- Пределы: пример до 200 символов (длина проверяется до любого разбора, так что длинная вставка не тормозит), скобки до 20 уровней, целая степень до 1000 по модулю, не больше 1000 цифр в числителе и знаменателе результата («10^999» считается, «10^1000» и «10^−1000» — «слишком большое число»). Приближённый счёт идёт в `double`: что больше ~1,8 × 10^308, тоже «слишком большое число».

Проверки: `test/skills/calculator_test.dart` (ответы, пределы, не примеры, совместная работа с задачами) и корпус `test/corpus/calc.jsonl` — там у строк калькулятора есть поле `answer` с ожидаемым ответом (`docs/CORPUS.md`).

## Навык «Беседа»

`lib/core/skills/talk/`: `TalkConnector` (id `talk`, навык, встроен, включён по умолчанию), распознавание — `TalkPhrases`. Беседа заготовленная, а не свободная (ADR-001): помощник понимает короткие реплики **целиком** и отвечает записями каталога ответов (`talk.*`, `docs/REPLIES.md`) голосом Liorio или Noda.

| Команда | Что понимает | Ответ |
| --- | --- | --- |
| `talk.greet` | «привет», «здравствуй(те)», «добрый день/вечер», «доброе утро», «хай», «йо», «👋» | приветствие по времени суток из `Clock`: утро 4–11, день 12–17, вечер 18–22, ночь 23–3. «Доброе утро» в 22:00 (через одну часть суток) — шутливая поправка, только в дружеском стиле (`talk.greet.mismatch`); остальные стили просто здороваются по часам |
| `talk.bye` | «пока», «до завтра», «до свидания», «спокойной ночи» | прощание |
| `talk.thanks` | «спасибо», «спс», «благодарю», «спасибо большое» и своими словами: «спс за инфу», «благодарю за быстрый ответ», «спс, выручил», «ок, понял, спасибо» | «Пожалуйста!». Если помощник ждёт «да» или «нет» — переспрос (см. ниже) |
| `talk.howAreYou` | «как дела», «как ты», «как жизнь», «всё в порядке?» | из настоящего состояния: активные и просроченные задачи и проверка здоровья каждого включённого коннектора (`ConnectorHealth`, `docs/CONNECTORS.md`). Есть проблема — что не так и вопрос «Передать жалобу администратору?»; «да» пока отвечает, что передача жалоб появится вместе с поддержкой на сервере коннектора, без сетевых запросов |
| `talk.whoAreYou` | «кто ты», «как тебя зовут», «ты кто такой/такая» | помощник представляется: имя, роль в дуэте (основной или второй) или в соло — «помощник»/«помощница» в своём роде и «в Связном» (ADR-009), что делает |
| `talk.capabilities` | «что ты умеешь», «помощь», «help», «чё умеешь делать», «помощь по командам»; вопрос с темой — «что ты умеешь в плане анализа данных?», «что умеешь, кроме шуток?» (ответ тот же: что умеет на самом деле) | **включённые** навыки и подключения из реестра, по одному примеру (`ConnectorInfo.examples.first`); выключенные не рекламируются |
| `talk.joke` | «расскажи шутку», «пошути», «анекдот», «каламбур», «ещё шутку» и своими словами: «расскажи анекдот про кошку», «аха, ну давай ещё анекдотик», «а можно ещё одну?», «повесели меня», «хочу посмеяться», «пошути, а то скучно», «Давай что-нибудь смешное, плз», «шути давай», «шутку, тема: политика», «расскажи шутку для выступления на мите», «каламбуры не люблю, дай анекдот», «спс за шутку, ну ещё!» | запись включённого пака `jokes` или `puns` (см. ниже) |
| `talk.reaction` | «ок», «понял», «круто», «👍» | короткий отклик. Если помощник ждёт «да» или «нет», «ок» и «👍» — согласие (раньше беседы), а «хорошо», «ладно», «понял», «отлично», «🙂» — переспрос (см. ниже) |
| `talk.rude` | грубость в адрес помощника: «ты тупой», «дурак», «отстань» | спокойно, без нравоучений; один вариант в каждом стиле |
| `talk.setting` | просьбы о стиле общения (таблица ниже) | подтверждение из каталога уже новым голосом |

**Не перехватывает команды.** Совпадение беседы — `ConnectorMatch(fallback: true)`: если откликнулся любой другой коннектор, побеждает он. Реплика — только сообщение целиком (до 8 слов, без цифр; «ну», «пожалуйста» и имена помощников не мешают): «привет, добавь задачу купить хлеб» — задача «Купить хлеб» (приветствие, благодарность и «пока не забыл» в начале команды разбор задач снимает сам), «пока не забыл, купить хлеб» — задача, «до завтра сдать отчёт» — задача. Вступление перед командой (`SocialPrefix`: «ну привет», «всем привет», «привет, Нода», «привет, как дела», «отлично,», «да,», «спасибо», «пока не забыл») снимают и задачи, и калькулятор: «привет, сколько будет 2+2» — 4, «круто, добавь задачу молоко» — задача «Молоко». Отклик без знака после него («хорошо выспаться») — часть названия.

**Своими словами.** Кроме точных фраз беседа понимает просьбы о шутке и о стиле, сказанные иначе: в реплике есть ядро просьбы (слово о шутке — «шутку», «анекдотик», «каламбур», «прикол», «юмор», «что-нибудь смешное»; глагол — «пошути», «повесели», «развлеки», «поржать»; «ещё один/одну»; слово о стиле, смайликах, «на ты/вы», частоте шуток), а все остальные слова — из короткого словаря болтовни вокруг неё («давай», «можно», «какую-нибудь», «ахаха», «а то скучно», «но короче», «про кошку», «плз», «pls»). Любое чужое слово — и это уже не беседа: «расскажи шутку на корпоративе», «добавь задачу рассказать шутку», «добавь смайлики в презентацию». Такую реплику целиком разбор задач не забирает, даже если угадал в ней поручение без маркера («хочу посмеяться» — не задача «Посмеяться», «расскажи прикол» — не отчёт о сделанном); с маркером уступает только просьба о стиле ответов («добавь смайликов в ответы»). «Слишком официально, сбавь тон» — жалоба и просьба: стиль задаёт «сбавь тон». Язык ответов («говори по-английски») — не настройка: её нет. «Ты основной?» — вопрос, ответ «кто ты».

**Замечания, цепочки, опечатки.** Замечание после запятой из короткого словаря (грубость, «а то ты сухой», «мне нравится», «а ты подожди», «не смешно») не мешает просьбе о шутке, стиле или «что умеешь»: «говори короче, задолбал» — стиль; после запятой команда — уже не беседа («говори короче, добавь задачу …»). Несколько фраз одной темы подряд — одна реплика: «пока, до завтра», «кто ты вообще, что за бот?». «Главный» — то же, что «основной», место («в чате», «здесь») просьбу не меняет; «официально не надо», «не будь таким официальным» — стиль наоборот. Имя с одной опечаткой в обращении в начале реплики, с той же первой буквой, читается как имя: «Лео, что умеешь?», «Лииорио, анекдот», «Нод, привет»; дальше в реплике — нет: «пусть отвечает Лион» — не беседа.

**Вступление и реплика.** «Привет, говори короче», «спасибо, пока», «спасибо и пока», «привет, ты тупой» — тема второй реплики. Имя помощника в любом месте реплики («спасибо, Нода», «как дела, Нода?») — в дуэте отвечает названный, его голосом и из его шуток, и дальше в этом чате пишем ему («ещё шутку» — снова от него, `docs/REPLIES.md`); в соло имя — просто текст.

**Отклик на вопрос подтверждения.** «Спасибо», «хорошо», «ладно», «понял», «отлично», «супер», «🙂» сразу после вопроса («Отметить «Купить хлеб» выполненной?», «Передать жалобу администратору?») — не «да» и не новая команда (`ConnectorMatch.acknowledgement`). Молча снять вопрос нельзя — так легко решить, что действие выполнено. Помощник отвечает `common.confirm.unclear` («Пока ничего не сделал. Ответьте, пожалуйста: «да» или «нет»?»), ничего не делает, и вопрос остаётся в силе ещё на одно сообщение. Любая другая реплика беседы («как дела?») или команда снимает вопрос, как раньше.

**Шутки.** Из включённых паков `jokes` и `puns` (`PackStore` через `ExtensionRegistry.packEntries`): только записи для `any` или для того, кто говорит, а если у записи указаны `styles` — подходящие стилю говорящего (если таких нет, стиль не сужает выбор). «Каламбур» — сначала пак `puns` и записи с меткой «каламбур». Последние 10 рассказанных в этом разговоре не повторяются; если пак меньше, повторяется самая давняя. Нет включённого пака шуток — помощник так и говорит и подсказывает «Настройки → Расширения».

**Частота шуток** (`jokes` в `settings.json`, «Настройки → Помощники → Шутки», просьбы «шути меньше/больше») влияет только на то, добавит ли беседа лёгкий каламбур к приветствию или «спасибо»: «Не шутить» — никогда, «Изредка» — каждый четвёртый раз, «Чаще» — каждый второй. Счёт детерминированный, ответы задач и других навыков шуток не получают никогда.

**Просьбы о стиле** меняют настройки того помощника, который отвечает (или к которому обратились: «Noda, говори официально»):

| Просьба | Что меняется |
| --- | --- |
| «говори короче», «говори кратко» | стиль — краткий |
| «говори подробнее», «говори нормально» | стиль — нейтральный |
| «давай дружелюбнее», «давай повеселее» | стиль — дружеский |
| «говори официально», «говори по-деловому» | стиль — деловой |
| «давай на ты», «на вы» | обращение (общее для обоих) |
| «без смайликов», «можно со смайликами» | эмодзи |
| «шути меньше», «шути больше», «не шути» | частота шуток на ступень реже/чаще, «не шути» — выключить |
| «Noda, будь основной», «пусть отвечает Лиорио», «Лио, будь основным», «сделай Ноду основной» | в дуэте — основной помощник, в соло — кто отвечает; подтверждает уже новый помощник |

Ответ несёт `AssistantResponse.settingsChange` (`PersonaSettingsChange`) — изменение, а не готовые настройки. Маршрутизатор применяет его к своим настройкам, интерфейс — к своим текущим `AppSettings` тем же путём, что экран настроек (`_changeSettings`: применить, сохранить в `settings.json`). Поэтому просьбы в чате покрыты теми же проверками неизменности данных (`test/home_personas_test.dart`), а перемены, сделанные в настройках во время ответа, не теряются. Если всё уже так («на вы» при «вы») — «Так уже и есть.», настройки не трогаются.
