# Каталог ответов, стили и помощники Liorio и Noda

Каждое сообщение помощника — запись каталога ответов по идентификатору (`task.created`, `calc.result`, `router.ambiguous`…) с подстановками фактов (`{title}`, `{due}`, `{result}`). Код передаёт только факты: название, срок, число, список кандидатов. Каталог оборачивает их в слова — в стиле, роде и обращении текущего помощника. Решение — ADR-006 в `docs/DECISIONS.md`.

## Где что лежит

| Путь | Что там |
| --- | --- |
| `assets/replies/<стиль>.json` | встроенные каталоги: `neutral`, `friendly`, `brief`, `business` (зарегистрированы в `pubspec.yaml`) |
| `lib/core/replies/reply_template.dart` | `ReplyTemplate` — разметка внутри текста, `ReplyGender`, `ReplyAddress`, `ReplyFormatException` |
| `lib/core/replies/reply_catalog.dart` | `Reply`, `ReplyVoice`, `ReplyStyles`, `ReplySpec`, `ReplySchema`, `ReplyCatalog`, `ReplyFormat` — формат файла и проверка |
| `lib/core/replies/reply_library.dart` | `ReplyLibrary` — все стили, выбор варианта, записи коннекторов, стили из паков |
| `lib/core/replies/builtin_replies.g.dart` | копия `assets/replies/*.json` для ядра на чистом Dart; создаётся `dart run tool/gen_replies.dart` |
| `lib/core/personas/` | `Persona`, `Personas` (Liorio, Noda), `AssistantMode`, `JokeFrequency`, `PersonaSettings`, `PersonaAddressing` |
| `lib/app/widgets/personas_section.dart` | раздел «Настройки → Помощники», `PersonaMark` |

Ядро не зависит от Flutter, поэтому читает каталоги из сгенерированной копии, а не через `rootBundle`. После правки JSON запустите генератор: тест `test/replies/reply_catalog_test.dart` сверяет копию с файлами и падает, если их забыли синхронизировать.

## Формат каталога `assistant-replies/1`

```json
{
  "format": "assistant-replies/1",
  "style": "friendly",
  "title": "Дружеский",
  "description": "Тепло и с улыбкой, иногда с эмодзи.",
  "entries": {
    "task.created": [
      "Готово! {м:Добавил|ж:Добавила} задачу «{title}» {э:✅}",
      "Записал{м:|ж:а}: «{title}». Не забудем!"
    ],
    "task.list.empty": "Активных задач нет — можно выдохнуть {э:😌}"
  }
}
```

- `entries` — объект `{id: вариант | [1–3 варианта]}`; вариант — непустая строка до 500 символов без управляющих символов и знаков направления текста.
- id записи — слова латиницей через точку: `task.created`, `task.ask.title`.
- **Нейтральный каталог — основа.** Каждая запись обязана быть в нём, он задаёт подстановки записи (`ReplySchema`). В нём ровно один вариант на запись и нет эмодзи: нейтральный стиль Liorio на «вы» дословно повторяет прежние тексты помощника.
- Остальные стили дают свои варианты только для части записей; недостающие берутся из нейтрального.

## Разметка внутри текста

| Разметка | Что значит | Пример |
| --- | --- | --- |
| `{имя}` | подстановка факта; имя латиницей, со строчной буквы | `«{title}» на {due}` |
| `{м:…\|ж:…}` | род помощника: Liorio — мужской, Noda — женский | `{м:Добавил\|ж:Добавила}` |
| `{вы:…\|ты:…}` | обращение к пользователю | `{вы:Укажите\|ты:Укажи}` |
| `{мн:имя\|одна\|две\|пять}` | форма слова по числу из подстановки `имя` | `{count} {мн:count\|задача\|задачи\|задач}` |
| `{э:…}` | эмодзи; без букв и цифр | `Готово {э:✅}` |
| `{{`, `}}` | фигурная скобка как есть | `{{пример}}` |

- Варианты рода и обращения — оба обязательны, порядок любой, вариант может быть пустым: `Записал{м:|ж:а}`.
- Внутри вариантов можно ставить подстановки и эмодзи, но не другой выбор.
- Эмодзи вне `{э:…}` — ошибка: так переключатель «Эмодзи в ответах» убирает их все. При выключенных эмодзи метка исчезает без двойного пробела и без пробела перед знаком препинания; значения подстановок при этом не трогаются.
- Метка `{э:…}` не приклеивается к тексту с обеих сторон: хотя бы с одной стороны пробел или край текста. «Готово{э:✅}«{title}»» — ошибка загрузки: без эмодзи вышло бы «Готово«Хлеб»».
- Знак конца предложения ставится **перед** меткой эмодзи: «Готово! Добавил «{title}». {э:✅}», а не «… «{title}» {э:✅}». Если нейтральный текст кончается «.», «!», «?» или «…», вариант без эмодзи обязан кончаться так же — иначе соседние фразы («Как дела?» из нескольких записей) слипнутся без точки.
- Значение подстановки вставляется как есть: `{м:x}` в названии задачи остаётся текстом.

## Проверка при загрузке

`ReplyFormat.parse` и `ReplySchema.check` проверяют каждый вариант каждого стиля (и пака ответов) сразу при загрузке. Ошибки — по-русски, с местом: `entries.task.created[1]: не во всех вариантах рода и обращения есть {title}.`

- разметка без ошибок: закрытые метки, оба варианта рода и обращения, три формы числа, эмодзи только в метке;
- только известные записи и подстановки (из нейтрального каталога и записей коннекторов);
- **факты не теряются:** каждая подстановка записи попадает в текст при любом роде, обращении, с эмодзи или без и при каждой форме числа — проверка подставляет числа на …1, …2 и …5, поэтому подстановка только внутри одной формы `{мн:…}` или форма, где число написано словом («две задачи»), — ошибка;
- **вопросы остаются вопросами:** если нейтральный текст — вопрос («?»), то и каждый вариант;
- **конец предложения не пропадает:** если нейтральный текст кончается знаком конца предложения, то и каждый вариант без эмодзи;
- **предупреждения не пропадают:** знак «≈» приближённого ответа есть в каждом варианте; текст не пустой. Предупреждения и вопросы-подтверждения («Это время уже прошло», «На ноль делить нельзя», «Отметить «…» выполненной?», «Передать жалобу администратору?») перечислены в поле `protected` нейтрального каталога (у коннектора — `ConnectorInfo.protectedReplies`). Встроенные стили говорят их по-своему (их тексты проверены тестами), а пак ответов переопределить их не может: такая запись в паке — ошибка, и звучит текст встроенного стиля. Так пак не скажет «Готово!» вместо «На ноль делить нельзя» и «Отметил» вместо вопроса.

Битый встроенный каталог — ошибка запуска (`FormatException`), это проверяют тесты. Битый пак ответов просто не принимается.

Тест `test/replies/reply_catalog_test.dart` проходит каждую запись × стиль × вариант × род × обращение × эмодзи (а записи с числами — ещё при 1, 2, 3, 5, 11, 21) и проверяет инвариант: все факты на месте, вопрос — вопрос, «≈» на месте, без эмодзи — ни одного эмодзи, ни двойного пробела и конец предложения на месте, краткий стиль не длиннее нейтрального.

## Выбор варианта

`ReplyLibrary.render(reply, voice, turn: n)`: вариант = `(FNV-1a(id) + n) mod число вариантов`. Хеш одинаков на всех платформах и запусках, номер реплики `n` (`AssistantSession.turn`) растёт с каждой репликой разговора. Поэтому тесты воспроизводимы, а два подряд одинаковых ответа звучат по-разному.

## Как ответ попадает в чат

```dart
// В коннекторе: факты — значениями, текст — из каталога.
return session.reply(
  'task.created.withDue',
  values: <String, String>{'title': task.title, 'due': due},
  intent: 'task.create',
  status: AssistantStatus.completed,
  task: task,
);
```

`session.reply` рендерит запись голосом текущей реплики (`session.voice`) и возвращает `AssistantResponse` с готовым `message`, `replyId` и `values`. Маршрутизатор ставит голос в начале сообщения и подписывает ответ помощником (`personaId`). В истории чата хранится готовый текст и автор: смена стиля, помощника или режима старые сообщения не переписывает.

Свои записи коннектор объявляет в `ConnectorInfo.replies` — нейтральный текст с той же разметкой (пример — «Пример склада» в `docs/CONNECTORS.md`). Реестр расширений добавляет их в каталог; id не должен совпадать со встроенной записью или записью другого коннектора. Остальные стили говорят их нейтральным текстом, паки ответов могут дать свои варианты.

## Пак ответов: свой стиль

Пак `assistant-pack/1` вида `replies` (`docs/EXTENSIONS.md`) — именованный стиль: id пака становится id стиля, `title` — названием в настройках.

```json
{
  "format": "assistant-pack/1",
  "id": "replies.pirate",
  "type": "replies",
  "title": "Пиратский",
  "author": "Мария",
  "language": "ru",
  "version": "1.0.0",
  "entries": {
    "task.created": ["Йо-хо! {м:Записал|ж:Записала} в судовой журнал: «{title}». {э:🏴‍☠️}", "Так точно, «{title}» на борту!"],
    "task.ask.rescheduleWhen": "На какую склянку переносим?"
  }
}
```

- `entries` — объект, как в каталоге стиля, а не список записей; проверка та же (известные id, подстановки, разметка, факты, вопросы, «≈», конец предложения без эмодзи). Предупреждения и вопросы-подтверждения (`protected`) в паке — ошибка: их пак не переопределяет. Общие пределы паков действуют: 1 МБ, до 5000 записей, до 500 символов в варианте, до 3 вариантов на запись.
- id пака не может совпадать со встроенным стилем (`neutral`, `friendly`, `brief`, `business`).
- Установленный и включённый пак ответов — ещё одна кнопка стиля у каждого помощника. Выключенный или удалённый пак из выбора пропадает; помощник, у которого он был выбран, говорит нейтрально, а сам выбор сохраняется — включите пак снова, и стиль вернётся.

## Помощники Liorio и Noda

| | Liorio | Noda |
| --- | --- | --- |
| id | `rio` (от прежнего имени Rio, ADR-008) | `noda` |
| имя кириллицей | «Лиорио» (не склоняется) | «Нода» |
| другие имена для обращения | «Lio», «Лио» | «Нодочка», «Нодь» |
| косвенные падежи (только в беседе) | — | «Ноды», «Ноде», «Ноду», «Нодой», «Нодочку» |
| метка | «L» | «N» |
| род | мужской («добавил») | женский («добавила») |
| цвет метки | голубой `#8FB3D9` | розовый `#D9A3C4` |
| стиль по умолчанию | нейтральный | дружеский |

Данные и коннекторы у них общие: любой выполняет любую команду сам.

- **Дуэт** (по умолчанию, основной — Liorio). Основной отвечает на всё. Написать второму можно двумя способами — и оба действуют одинаково: **к кому обратились, тот и продолжает**:
  - начать сообщение с имени: «Noda, …», «Нода: …», «нода — …», «Liorio …», «Лиорио, …», «Лио: …», «Нодочка, …», «Нодь, …» — любым именем из таблицы, латиницей или кириллицей, без учёта регистра, после имени запятая, двоеточие, точка с запятой, «!», «?», точка, многоточие, тире или пробел («Noda!», «Лио.», «Noda;2+2»). Имя снимается до разбора, отвечает названный помощник. Слово, которое лишь начинается с имени («Лион», «Нодаа», «нодальный»), косвенный падеж («Ноду …»), прежнее имя «Рио»/«Rio» (и «Рио-де-Жанейро») и имя в середине команды обращением не считаются. Одно имя без команды — отклик «Слушаю…». В реплике беседы имя может стоять где угодно («спасибо, Нода», «как дела, Нода?», «говори короче, Нода») — отвечает названный. Обращение по имени делает названного адресатом чата, ровно как нажатие на переключатель ниже: «Нода, расскажи шутку», затем «ещё шутку» — снова Noda, из её шуток и её стилем; так же для команд, вопросов и всего остального. «Лио, …» возвращает Liorio; обращение к основному снимает выбор (дальше — тот, кто основной). Ответ ядра отмечает обращение (`AssistantResponse.addressedPersonaId`), а `AssistantController.addresseeAfter` говорит интерфейсу, кто теперь адресат. Имя в просьбе «пусть отвечает Лиорио» / «Noda, будь основной» / «сделай Ноду основной» — не обращение, а новый основной: выбор адресата снимается, дальше отвечает новый основной. Если названный и так основной («пусть отвечает Лио», а адресат сейчас Noda), настройки не меняются, но выбор адресата тоже снимается: «Так уже и есть» отвечает Liorio, и дальше — снова он;
  - выбрать адресата над полем ввода («Кому: Liorio | Noda», ключи `addressee-rio`, `addressee-noda`). Переключатель стоит вне прокрутки нижней части и нажимается и на 320 px при крупном шрифте. Выбор живёт, пока открыт этот чат (очистка чата его сбрасывает), и не сохраняется; обращение по имени важнее и само меняет выбор. Нажатие на основного — «по умолчанию»: после смены основного в настройках отвечает новый основной. Смена настроек выбор не трогает: если адресат совпал с новым основным, он просто основной; в соло адресат не используется, а после возврата в дуэт он прежний.
  - Ответ на вопрос подтверждения («Отметить «…» выполненной?») уходит коннектору, который спросил, и звучит от того, кто спросил, даже если адресат с тех пор сменился (`AssistantSession.pendingSpeaker`). Если в ответе назвали помощника по имени — в начале («Лио, да») или в конце после запятой или тире («да, Лиорио», «спасибо, Нодочка» на переспрос), — действие то же, а отвечает названный — и он становится адресатом. «Да» без имени адресата не меняет.
  - Второй помощник пишет первым — второй относительно основного из настроек, а не относительно текущего адресата. Сейчас — одно сообщение о просроченных задачах при открытии приложения или при смене дня, пока оно открыто: «У вас 2 просроченные задачи: «Отчёт», «Счёт».». Не чаще раза в день: день записан в `settings.json` (`notice_day`), поэтому ни перезапуск, ни смена настроек помощников сообщение не повторяют. Если день сменился, пока готовится ответ, напоминание приходит после ответа, а не между командой и ответом.
- **Соло.** Один выбранный помощник отвечает на всё и сам пишет первым; имя другого в начале сообщения — обычный текст, оно не снимается и адресата не закрепляет.
- В чате у каждого ответа — метка с буквой имени цвета помощника и имя (`message-author-rio`, `message-author-noda`). Приветствие пишет основной помощник. Сообщение, отправленное, пока настройки ещё читаются, ждёт их: ответит и поприветствует помощник из настроек, а не по умолчанию.

### Настройки

«Настройки → Помощники»: режим «Дуэт»/«Соло», кто основной (в дуэте) или кто отвечает (в соло), стиль каждого помощника с живым примером одной фразы из каталога, обращение «на вы»/«на ты», «Эмодзи в ответах», «Шутки» (не шутить, изредка, чаще; ключи `jokes-off`, `jokes-rare`, `jokes-normal`). Хранятся в `settings.json` рядом с остальными:

```json
{
  "assistant_mode": "duo",
  "main_persona": "rio",
  "solo_persona": "rio",
  "persona_styles": {"noda": "friendly", "rio": "neutral"},
  "address": "vy",
  "emoji": true,
  "jokes": "rare"
}
```

Неизвестные и битые значения читаются по каждому полю отдельно как значения по умолчанию; испорченный файл целиком — дуэт, основной Liorio. Id `rio` — это Liorio: файл, записанный до переименования, читается без изменений (ADR-008). `jokes` (`off`/`rare`/`normal`) — как часто беседа добавляет каламбур к приветствию и «спасибо» (`docs/EXTENSIONS.md`, «Навык «Беседа»»).

### Смена настроек ничего не сбрасывает

Переключения дуэт ↔ соло, кто основной, стиль каждого помощника, «вы»/«ты», эмодзи оставляют прежними задачи, историю чата (авторы и тексты), выбранную задачу, открытый чат, черновик в поле ввода, ожидание подтверждения и выбор расширений. Ответ, который готовится в момент смены, договаривается прежним голосом: голос фиксируется в начале сообщения, новые настройки — со следующего. Проверки — `test/home_personas_test.dart` (группа «смена настроек помощников ничего не сбрасывает»), `test/personas/`.

### Просьбы в беседе

Те же настройки можно поменять словами — навык «Беседа» (`docs/EXTENSIONS.md`): «говори короче» (краткий), «говори подробнее» (нейтральный), «давай дружелюбнее» (дружеский), «говори официально» (деловой), «давай на ты» / «на вы», «без смайликов» / «можно со смайликами», «шути меньше» / «шути больше» / «не шути», «Noda, будь основной» / «пусть отвечает Лиорио» / «сделай Ноду основной». Стиль меняется у того, кто отвечает или к кому обратились по имени.

- Изменение приходит в ответе (`AssistantResponse.settingsChange`) и применяется тем же путём, что и кнопки экрана настроек: сохраняется в `settings.json`, ничего не сбрасывает, видно в «Настройки → Помощники» (проверка — `test/home_personas_test.dart`, «просьбы в беседе идут тем же путём…»).
- Единственное исключение из правила «голос фиксируется в начале сообщения»: подтверждение такой просьбы звучит уже **новым** голосом — «без смайликов» отвечают без смайликов, «давай на ты» — на «ты», «пусть отвечает Лио» подтверждает Liorio.
- Уже так — «Так уже и есть.», настройки не меняются.

### Записи беседы

Ответы беседы — записи `talk.*` встроенного каталога, во всех четырёх стилях: `talk.greet` (`{daypart}` — «Добрый вечер»), `talk.greet.mismatch` (`{said}`, `{daypart}`, `{time}`; звучит только в дружеском стиле), `talk.bye`, `talk.bye.night`, `talk.thanks`, `talk.pun` (`{pun}`), `talk.reaction`, `talk.rude` (один вариант в каждом стиле), `talk.status.ok`, `talk.status.okUnchecked` (`{unchecked}` — включённые подключения без проверки здоровья), `talk.status.tasks.none`, `talk.status.tasks` (`{active}`), `talk.status.tasks.overdue` (`{active}`, `{overdue}`), `talk.status.problem` (`{problems}`, вопрос), `talk.complaint.later`, `talk.complaint.declined`, `talk.who.main`, `talk.who.secondary` (`{name}`, `{other}`), `talk.who.solo` (`{name}`), `talk.capabilities` (`{skills}`), `talk.joke` (`{joke}`), `talk.joke.none`, `talk.set.*` (подтверждения просьб; `talk.set.main` и `talk.set.solo` — `{name}`), `talk.set.already`. Текст шутки и список навыков — факты: стиль оборачивает их, но не меняет. Ответ «Как дела?» и приветствие с каламбуром складываются из нескольких записей: между ними всегда точка или другой знак конца предложения, и при выключенных эмодзи тоже.

Общая запись маршрутизатора `common.confirm.unclear` — переспрос «да» или «нет», когда на вопрос подтверждения ответили «хорошо» или «спасибо» (`docs/CONNECTORS.md`, «Подтверждение изменяющих действий»).
