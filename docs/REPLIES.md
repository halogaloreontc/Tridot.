# Каталог ответов, стили и помощники Связной, Лиорио и Нода

Каждое сообщение помощника — запись каталога ответов по идентификатору (`task.created`, `calc.result`, `router.ambiguous`…) с подстановками фактов (`{title}`, `{due}`, `{result}`). Код передаёт только факты: название, срок, число, список кандидатов. Каталог оборачивает их в слова — в стиле, роде и обращении текущего помощника. Решение — ADR-006 в `docs/DECISIONS.md`.

## Где что лежит

| Путь | Что там |
| --- | --- |
| `assets/replies/<стиль>.json` | встроенные каталоги: `neutral`, `friendly`, `brief`, `business` (зарегистрированы в `pubspec.yaml`) |
| `lib/core/replies/reply_template.dart` | `ReplyTemplate` — разметка внутри текста, `ReplyGender`, `ReplyAddress`, `ReplyFormatException` |
| `lib/core/replies/reply_catalog.dart` | `Reply`, `ReplyVoice`, `ReplyStyles`, `ReplySpec`, `ReplySchema`, `ReplyCatalog`, `ReplyFormat` — формат файла и проверка |
| `lib/core/replies/reply_library.dart` | `ReplyLibrary` — все стили, выбор варианта, записи коннекторов, стили из паков |
| `lib/core/replies/builtin_replies.g.dart` | копия `assets/replies/*.json` для ядра на чистом Dart; создаётся `dart run tool/gen_replies.dart` |
| `lib/core/personas/` | `Persona`, `Personas` (Связной, Лиорио, Нода), `TeamMode`, `PersonaDuty`, `PersonaCast`, `PersonaNames`, `DutyZones`, `JokeFrequency`, `PersonaSettings`, `PersonaAddressing` |
| `lib/app/widgets/personas_section.dart` | раздел «Мой Связной» → «Помощники», `PersonaMark` |

Ядро не зависит от Flutter, поэтому читает каталоги из сгенерированной копии, а не через `rootBundle`. После правки JSON запустите генератор: тест `test/replies/reply_catalog_test.dart` сверяет копию с файлами и падает, если их забыли синхронизировать.

## Формат каталога `assistant-replies/1`

```json
{
  "format": "assistant-replies/1",
  "style": "friendly",
  "title": "Дружеский",
  "description": "Тепло и с улыбкой, иногда с эмодзи.",
  "entries": {
    "task.created": [
      "Готово! {м:Добавил|ж:Добавила} задачу «{title}» {э:✅}",
      "Записал{м:|ж:а}: «{title}». Не забудем!"
    ],
    "task.list.empty": "Активных задач нет — можно выдохнуть {э:😌}"
  }
}
```

- `entries` — объект `{id: вариант | [1–3 варианта]}`; вариант — непустая строка до 500 символов без управляющих символов и знаков направления текста.
- id записи — слова латиницей через точку: `task.created`, `task.ask.title`.
- **Нейтральный каталог — основа.** Каждая запись обязана быть в нём, он задаёт подстановки записи (`ReplySchema`). В нём ровно один вариант на запись и нет эмодзи: нейтральный стиль на «вы» в мужском роде дословно повторяет прежние тексты помощника.
- Остальные стили дают свои варианты только для части записей; недостающие берутся из нейтрального.

## Разметка внутри текста

| Разметка | Что значит | Пример |
| --- | --- | --- |
| `{имя}` | подстановка факта; имя латиницей, со строчной буквы | `«{title}» на {due}` |
| `{м:…\|ж:…}` | род помощника из настроек (по умолчанию Лиорио — мужской, Нода — женский, Связной до выбора — мужской) | `{м:Добавил\|ж:Добавила}` |
| `{вы:…\|ты:…}` | обращение к пользователю | `{вы:Укажите\|ты:Укажи}` |
| `{мн:имя\|одна\|две\|пять}` | форма слова по числу из подстановки `имя` | `{count} {мн:count\|задача\|задачи\|задач}` |
| `{э:…}` | эмодзи; без букв и цифр | `Готово {э:✅}` |
| `{{`, `}}` | фигурная скобка как есть | `{{пример}}` |

- Варианты рода и обращения — оба обязательны, порядок любой, вариант может быть пустым: `Записал{м:|ж:а}`.
- Внутри вариантов можно ставить подстановки и эмодзи, но не другой выбор.
- Эмодзи вне `{э:…}` — ошибка: так переключатель «Эмодзи в ответах» убирает их все. При выключенных эмодзи метка исчезает без двойного пробела и без пробела перед знаком препинания; значения подстановок при этом не трогаются.
- Метка `{э:…}` не приклеивается к тексту с обеих сторон: хотя бы с одной стороны пробел или край текста. «Готово{э:✅}«{title}»» — ошибка загрузки: без эмодзи вышло бы «Готово«Хлеб»».
- Знак конца предложения ставится **перед** меткой эмодзи: «Готово! Добавил «{title}». {э:✅}», а не «… «{title}» {э:✅}». Если нейтральный текст кончается «.», «!», «?» или «…», вариант без эмодзи обязан кончаться так же — иначе соседние фразы («Как дела?» из нескольких записей) слипнутся без точки.
- Значение подстановки вставляется как есть: `{м:x}` в названии задачи остаётся текстом.

## Проверка при загрузке

`ReplyFormat.parse` и `ReplySchema.check` проверяют каждый вариант каждого стиля (и пака ответов) сразу при загрузке. Ошибки — по-русски, с местом: `entries.task.created[1]: не во всех вариантах рода и обращения есть {title}.`

- разметка без ошибок: закрытые метки, оба варианта рода и обращения, три формы числа, эмодзи только в метке;
- только известные записи и подстановки (из нейтрального каталога и записей коннекторов);
- **факты не теряются:** каждая подстановка записи попадает в текст при любом роде, обращении, с эмодзи или без и при каждой форме числа — проверка подставляет числа на …1, …2 и …5, поэтому подстановка только внутри одной формы `{мн:…}` или форма, где число написано словом («две задачи»), — ошибка;
- **вопросы остаются вопросами:** если нейтральный текст — вопрос («?»), то и каждый вариант;
- **конец предложения не пропадает:** если нейтральный текст кончается знаком конца предложения, то и каждый вариант без эмодзи;
- **предупреждения не пропадают:** знак «≈» приближённого ответа есть в каждом варианте; текст не пустой. Предупреждения и вопросы-подтверждения («Это время уже прошло», «На ноль делить нельзя», «Отметить «…» выполненной?», «Передать жалобу администратору?») перечислены в поле `protected` нейтрального каталога (у коннектора — `ConnectorInfo.protectedReplies`). Встроенные стили говорят их по-своему (их тексты проверены тестами), а пак ответов переопределить их не может: такая запись в паке — ошибка, и звучит текст встроенного стиля. Так пак не скажет «Готово!» вместо «На ноль делить нельзя» и «Отметил» вместо вопроса.

Битый встроенный каталог — ошибка запуска (`FormatException`), это проверяют тесты. Битый пак ответов просто не принимается.

Тест `test/replies/reply_catalog_test.dart` проходит каждую запись × стиль × вариант × род × обращение × эмодзи (а записи с числами — ещё при 1, 2, 3, 5, 11, 21) и проверяет инвариант: все факты на месте, вопрос — вопрос, «≈» на месте, без эмодзи — ни одного эмодзи, ни двойного пробела и конец предложения на месте, краткий стиль не длиннее нейтрального.

## Выбор варианта

`ReplyLibrary.render(reply, voice, turn: n)`: вариант = `(FNV-1a(id) + n) mod число вариантов`. Хеш одинаков на всех платформах и запусках, номер реплики `n` (`AssistantSession.turn`) растёт с каждой репликой разговора. Поэтому тесты воспроизводимы, а два подряд одинаковых ответа звучат по-разному.

## Как ответ попадает в чат

```dart
// В коннекторе: факты — значениями, текст — из каталога.
return session.reply(
  'task.created.withDue',
  values: <String, String>{'title': task.title, 'due': due},
  intent: 'task.create',
  status: AssistantStatus.completed,
  task: task,
);
```

`session.reply` рендерит запись голосом текущей реплики (`session.voice`) и возвращает `AssistantResponse` с готовым `message`, `replyId` и `values`. Маршрутизатор ставит голос в начале сообщения и подписывает ответ помощником (`personaId`). В истории чата хранится готовый текст и автор: смена стиля, помощника или режима старые сообщения не переписывает.

Свои записи коннектор объявляет в `ConnectorInfo.replies` — нейтральный текст с той же разметкой (пример — «Пример склада» в `docs/CONNECTORS.md`). Реестр расширений добавляет их в каталог; id не должен совпадать со встроенной записью или записью другого коннектора. Остальные стили говорят их нейтральным текстом, паки ответов могут дать свои варианты.

Записи склада (`ConnectionSlots.warehouse`, ADR-011): описание приложения даёт нейтральный факт, каталог — голос. `warehouse.answer`, `warehouse.empty`, `warehouse.reply` — `{text}` (текст описания как есть), `warehouse.more` — «Показаны не все — {вы:уточните|ты:уточни} запрос.», `warehouse.fallbackEmpty` — факт и примеры вопросов (`examples`), `warehouse.help` — «Склад понимает: {list}.», `warehouse.ask` — вопрос, когда фразу с полем начали и не договорили («где лежит» без артикула): «Уточните, что искать: {label}. Например: «{example}».». Предупреждения (`protected`): `warehouse.notConnected`, `warehouse.auth.token`, `.auth.expired`, `.auth.staff`, `.auth.role`, `warehouse.offline`, `.timeout`, `.serverError`, `.busy`, `warehouse.serverSaid` («Склад ответил: {error}»). Пак ответов может переписать обёртку ответа, но не предупреждения.

Действия склада (ADR-013) — записи `warehouse.act.*` во встроенном каталоге, во всех четырёх стилях (не в слоте: у них свой голос в каждом стиле): вопросы карточки `warehouse.act.ask.move` (`{qty}`, `{from}`, `{to}`) и `.ask.post` (`{marks}`, `{no}`), вопросы по ходу `.ask.row`, `.ask.qty`, `.ask.to`, `.ask.entry`, просьба нажать кнопку `.pressButton`, итоги `.moved`, `.posted`, `.settled`, `.already`, `.declined` и отказы (`.off`, `.needLogin`, `.otherLogin`, `.unsupported`, `.serverOff`, `.denied`, `.locked`, `.lockedOwn`, `.draft`, `.notFound`, `.notInCell`, `.short`, `.noCell`, `.cellGroup`, `.sameCell`, `.onlyThere`, `.qtyLimit`, `.noPlace`, `.clock`, `.mismatch`, `.tooMany`, `.expired`, `.stale`, `.unknown`, `.pending`, `.voided`, `.failed`). Все, кроме `.declined` и `.already`, — `protected`. Подписи кнопок карточки («Подтвердить», «Отмена», «Проверить») — в виджете, не в каталоге.

Запись ролей (ADR-012) — во встроенном каталоге, во всех четырёх стилях: `role.notConnected` (`{app}`, `{role}`, `{button}`; `protected`) — «Склад ещё не подключён — Мой Связной → Помощники → Роли → Кладовщик → Подключить склад.»: роль включила подключение, а входа нет. `warehouse.notConnected` остаётся для подключения вне ролей.

Будильник и уведомления (ADR-029) — во встроенном каталоге: `alarm.confirm` (`{time}`, `{details}` — « по будням», « с подписью «…»» или пусто), `alarm.timer.confirm` (`{duration}`, `{details}`), итоги `alarm.set`, `alarm.timer.set`, отказ `alarm.cancelled`, предложения напоминания вместо будильника `alarm.date`, `alarm.unavailable.platform`, `alarm.unavailable.noClock` (`{when}` — «завтра в 7:00», «через 5 минут»), вопросы `alarm.clarify.time`, `alarm.clarify.duration`, `alarm.past` (`{time}`); строки ведущего оповещений `notify.granted`, `notify.off`, `notify.exactOff`. Вопросы и предупреждения — `protected`. Подписи кнопок («Поставить», «Отмена», «Напомнить», «Не надо») — в навыке, не в каталоге.

Погода (ADR-030): `weather.now` (`{place}`, `{temp}`, `{sky}`, `{feels}`, `{wind}`), `weather.day` (`{place}`, `{day}`, `{sky}`, `{min}`, `{max}`, `{chance}`), `weather.week`, `weather.rain.yes` (`{kind}`, `{chance}`), `weather.rain.maybe`, `weather.rain.no`, `weather.wear` (`{advice}` — из записей `weather.wear.frost` … `weather.wear.hot` и добавок `weather.wear.umbrella`, `weather.wear.boots`, `weather.wear.wind`), `weather.setup`, `weather.city.missing`, `weather.place.notFound` (`{query}`), `weather.network.off`, `weather.offline.cached` (`{time}`, начало ответа с сохранённым прогнозом), `weather.offline.none`, `weather.busy`, `weather.failed`, `weather.range` (`{last}`), `weather.past`, `weather.link.opened`, `weather.link.city`, `weather.link.failed`, `weather.app.opened`, `weather.app.fallback`, `weather.app.missing`. Подписи неба (`{sky}`) — таблица `WeatherCodes`, не каталог. Предупреждения `weather.network.off`, `weather.offline.*`, `weather.link.city` — `protected`.

## Пак ответов: свой стиль

Пак `assistant-pack/1` вида `replies` (`docs/EXTENSIONS.md`) — именованный стиль: id пака становится id стиля, `title` — названием в настройках.

```json
{
  "format": "assistant-pack/1",
  "id": "replies.pirate",
  "type": "replies",
  "title": "Пиратский",
  "author": "Мария",
  "language": "ru",
  "version": "1.0.0",
  "entries": {
    "task.created": ["Йо-хо! {м:Записал|ж:Записала} в судовой журнал: «{title}». {э:🏴‍☠️}", "Так точно, «{title}» на борту!"],
    "task.ask.rescheduleWhen": "На какую склянку переносим?"
  }
}
```

- `entries` — объект, как в каталоге стиля, а не список записей; проверка та же (известные id, подстановки, разметка, факты, вопросы, «≈», конец предложения без эмодзи). Предупреждения и вопросы-подтверждения (`protected`) в паке — ошибка: их пак не переопределяет. Общие пределы паков действуют: 1 МБ, до 5000 записей, до 500 символов в варианте, до 3 вариантов на запись.
- id пака не может совпадать со встроенным стилем (`neutral`, `friendly`, `brief`, `business`).
- Установленный и включённый пак ответов — ещё одна кнопка стиля у каждого помощника. Выключенный или удалённый пак из выбора пропадает; помощник, у которого он был выбран, говорит нейтрально, а сам выбор сохраняется — включите пак снова, и стиль вернётся.

## Помощники Связной, Лиорио и Нода

| | Связной | Лиорио | Нода |
| --- | --- | --- | --- |
| id | `sado` | `rio` (от прежнего имени Rio, ADR-008) | `noda` |
| обязанность | главный: беседа, задачи, планирование, калькулятор | расширения: склад, «Пароли», подключения | оповещения: напоминания, просрочки, сигналы склада |
| имя кириллицей | «Связной», в женском роде «Связная» (ADR-017) | «Лиорио» (не склоняется) | «Нода» |
| другие имена для обращения | «Связной» и «Связная» при любом роде, «Svyaznoy» | «Lio», «Лио» | «Нодочка», «Нодь» |
| косвенные падежи (только в беседе) | «Связного», «Связному», «Связным», «Связном», «Связную», «Связною» (склоняется как прилагательное) | — | «Ноды», «Ноде», «Ноду», «Нодой», «Нодочку» |
| метка | «С» | «Л» | «Н» |
| род по умолчанию | не выбран (ответы — в мужском роде) | мужской («добавил») | женский («добавила») |
| цвет метки | фиолетовый `#B69CFF` | лазурный `#8ED1F2` | розовый `#F5A8CB` |
| стиль по умолчанию | нейтральный | нейтральный | дружеский |

Имя, род и стиль каждого — из настроек (`PersonaCast`, ADR-016): метка — первая буква текущего имени, «другие имена» и косвенные падежи действуют, только пока имя встроенное. Встроенное имя главного следует за родом: «Связной» до выбора и в мужском роде, «Связная» — в женском; своё имя от рода не зависит (ADR-017). У своего имени — косвенные падежи по окончанию (`nameCaseForms`): «сделай Свету основной», «дуэт с Мирой», «дуэт со Светой» («со» перед именем — как «с»); обращение — только именительный падеж. Данные и коннекторы у помощников общие; кто отвечает, решает зона фразы.

- **Режимы.** **Трио** (по умолчанию) — все трое; **Дуэт** — Связной и один помощник на выбор, зона второго возвращается к главному; **Соло** — всё делает Связной. Имя выключенного режимом помощника в начале сообщения обращением не считается, но снимается до разбора: «Нода, добавь задачу хлеб» в Соло — задача «Хлеб» от главного. Смена режима с экрана снимает и продолжение разговора с выключенным помощником, а на его вопрос отвечает ведущий зоны навыка.
- **Кто отвечает.** Без обращения по имени — хозяин зоны фразы (`DutyZones.dutyOf`): беседа, задачи, калькулятор, «Данные» — Связной; склад, «Пароли», подключения — ведущий расширений (по умолчанию Лиорио); выключенный режимом помощник отдаёт зону Связной. Обязанности переназначаются в «Мой Связной» → «Помощники» («Расширения ведёт», «Оповещения ведёт»), обе можно отдать одному помощнику.
- **Обращение по имени**: «Нода, …», «Лиорио: …», «Лио — …», «Связной, …» — текущим именем из настроек или встроенной формой, без учёта регистра и разницы «е»/«ё» («Алена» — та же «Алёна»), после имени запятая, двоеточие, точка с запятой, «!», «?», точка, многоточие, тире или пробел. Имя снимается до разбора, отвечает названный активный помощник, и он становится адресатом чата: «Нода, расскажи шутку», затем «ещё шутку» — снова Нода. Обращение к главному снимает выбор. Слово, которое лишь начинается с имени («Лион», «Нодаа»), косвенный падеж («Ноду …»), прежнее имя «Рио» и имя в середине команды обращением не считаются. Одно имя без команды — отклик «Слушаю…». В реплике беседы имя может стоять где угодно («спасибо, Нода»). Ответ ядра отмечает обращение (`AssistantResponse.addressedPersonaId`), `AssistantController.addresseeAfter` говорит интерфейсу, кто теперь адресат.
- Ответ на вопрос подтверждения («Отметить «…» выполненной?») уходит коннектору, который спросил, и звучит от того, кто спросил (`AssistantSession.pendingSpeaker`). Если в ответе назвали помощника по имени («Лио, да», «да, Лиорио»), действие то же, а отвечает названный.
- **Оповещения** пишет ведущий оповещений (`PersonaCast.notifier`, по умолчанию Нода): в пустой сессии под приветствием — строка с его знаком «Просрочена 1 задача ›» (нажатие — «Мой Связной» → «Сводка»), сигналы склада и жалоба. Тексты склада, вопросы и карточка «Подтвердить» — от ведущего расширений. Сообщением в сессию никто первым не пишет (ADR-010); `task.overdue` остался в каталоге для паков.
- В чате у каждого ответа — метка с буквой имени цвета помощника и имя (`message-author-sado`, `message-author-rio`, `message-author-noda`); старые сообщения показываются под текущими именами. Приветствие — пустая сессия со знаком главного. Сообщение, отправленное, пока настройки ещё читаются, ждёт их.

### Настройки

«Мой Связной» → «Помощники»: режим «Соло»/«Дуэт»/«Трио» (в Дуэте — с кем), у каждого помощника имя (проверка — `PersonaNames.validate`: одно слово от 2 до 24 знаков, только буквы и дефис, не имя другого помощника, не обращение к подключению вроде «склад», «пароли», «сейф» и не обычное слово в начале фраз — «добавь», «напомни», «привет», «да», «нет»; пока род главного не выбран, под его примером — «Пример — в мужском роде, пока род не выбран»), пол и стиль с живым примером одной фразы из каталога; кто ведёт расширения и оповещения; обращение «на вы»/«на ты», «Эмодзи в ответах», «Шутки» (ключи `jokes-off`, `jokes-rare`, `jokes-normal`). Пол Связной при первом запуске выбирается карточкой на экране новой сессии. Хранятся в `settings.json` рядом с остальными:

```json
{
  "team_mode": "trio",
  "duo_helper": "rio",
  "persona_names": {"noda": "Мира"},
  "persona_genders": {"sado": "m", "rio": "m", "noda": "f"},
  "duty_extensions": "rio",
  "duty_notifications": "noda",
  "persona_styles": {"noda": "friendly", "rio": "neutral", "sado": "neutral"},
  "assistant_mode": "duo",
  "main_persona": "rio",
  "solo_persona": "rio",
  "address": "vy",
  "emoji": true,
  "jokes": "rare"
}
```

Неизвестные и битые значения читаются по каждому полю отдельно как значения по умолчанию; неверное имя — встроенное. Пока пол главного не выбран, ключа `sado` в `persona_genders` нет. `assistant_mode`, `main_persona` и `solo_persona` пишутся только для отката на прошлую версию. Файл прежней версии (нет `team_mode`): дуэт или ключа нет — Трио, соло — Соло; Связной получает стиль прежнего отвечающего; `role_owners` в обязанности не переносится (ADR-016). Id `rio` — это Лиорио (ADR-008). `jokes` (`off`/`rare`/`normal`) — как часто беседа добавляет каламбур к приветствию и «спасибо» (`docs/EXTENSIONS.md`, «Навык «Беседа»»).

### Записи чата задачи

`task.reopened` (`{title}`) — «Вернуть в работу» в шапке чата задачи: «Задача «{title}» снова в работе.»; `task.chat.alreadyDone` (`{title}`) — «готово» или перенос в чате уже выполненной задачи: «Задача «{title}» уже выполнена.» (`docs/CONNECTORS.md`, «Чат задачи»). Обе — во всех четырёх стилях. Кнопка «Выполнено» в шапке пишет обычную `task.completed`. Подписи интерфейса («Открыть сессию задачи», «из сессии «…»», «Выполнено», «Вернуть в работу», «Перенести…», «Новая сессия», «Сегодня», «Вчера», «На неделе», «Ранее», «Закреплённые», «Переименовать», «Закрепить», «Удалить», «Просрочена N задач») — не реплики помощника и в каталог не входят. Сохранённая история хранит готовый текст и автора (ADR-010): смена стиля старые сообщения не переписывает и после перезапуска.

### Смена настроек ничего не сбрасывает

Переключения Соло, Дуэт и Трио, переименование, пол, обязанности, стиль каждого помощника, «вы»/«ты», эмодзи оставляют прежними задачи, историю чата (авторы и тексты), выбранную задачу, открытый чат, черновик в поле ввода, ожидание подтверждения и выбор расширений. Ответ, который готовится в момент смены, договаривается прежним голосом: голос фиксируется в начале сообщения, новые настройки — со следующего. Чаты задач, их сообщения и адресат каждого чата тоже не меняются, в том числе после перезапуска с сохранёнными чатами. Проверки — `test/home_personas_test.dart` (группа «смена настроек помощников ничего не сбрасывает»), `test/personas/`.

### Просьбы в беседе

Те же настройки можно поменять словами — навык «Беседа» (`docs/EXTENSIONS.md`): «говори короче» (краткий), «говори подробнее» (нейтральный), «давай дружелюбнее» (дружеский), «говори официально» (деловой), «давай на ты» / «на вы», «без смайликов» / «можно со смайликами», «шути меньше» / «шути больше» / «не шути», «включи трио» / «включи дуэт с Нодой» / «включи соло»; «пусть отвечает Лиорио» и «сделай Ноду основной» отвечают, что главный здесь — Связной. Стиль меняется у того, кто отвечает или к кому обратились по имени.

- Изменение приходит в ответе (`AssistantResponse.settingsChange`) и применяется тем же путём, что и кнопки экрана настроек: сохраняется в `settings.json`, ничего не сбрасывает, видно в «Мой Связной» → «Помощники» (проверка — `test/home_personas_test.dart`, «просьбы в беседе идут тем же путём…»).
- Единственное исключение из правила «голос фиксируется в начале сообщения»: подтверждение такой просьбы звучит уже **новым** голосом — «без смайликов» отвечают без смайликов, «давай на ты» — на «ты». Режим («включи соло», «включи дуэт с Нодой», «включи трио») меняет и подтверждает Связной; «пусть отвечает Лио» настроек не меняет — главный всегда Связной (`talk.set.mainFixed`, ADR-016).
- Уже так — «Так уже и есть.», настройки не меняются.

### Записи беседы

Ответы беседы — записи `talk.*` встроенного каталога, во всех четырёх стилях: `talk.greet` (`{daypart}` — «Добрый вечер»), `talk.greet.mismatch` (`{said}`, `{daypart}`, `{time}`; звучит только в дружеском стиле), `talk.bye`, `talk.bye.night`, `talk.thanks`, `talk.pun` (`{pun}`), `talk.reaction`, `talk.rude` (один вариант в каждом стиле), `talk.status.ok`, `talk.status.okUnchecked` (`{unchecked}` — включённые подключения без проверки здоровья), `talk.status.tasks.none`, `talk.status.tasks` (`{active}`), `talk.status.tasks.overdue` (`{active}`, `{overdue}`), `talk.status.problem` (`{problems}`, вопрос), `talk.complaint.later`, `talk.complaint.declined`, `talk.who.main` (`{name}`, `{appPrepositional}`), `talk.who.helper` (`{name}`, `{duties}`), `talk.who.byName`, `talk.who.self.helper` (`{name}`, `{duties}`, `{appPrepositional}`), `talk.who.mainRef` (`{main}`), `talk.who.secondary` (`{name}`, `{other}`, `{appPrepositional}`; кодом больше не используется, оставлена для паков), `talk.who.solo` (`{name}`, `{appPrepositional}`), `talk.status.okPending` (всё, что подключено, работает; дальше — подсказка `role.notConnected` о подключении, в которое ещё не вошли), `talk.capabilities` (`{skills}`; в конце — путь «Мой Связной → Помощники → Роли» и «Настройки → Расширения»), `talk.capabilities.roles` (`{skills}`, `{roles}` — то же одной записью, когда включено что-то сверх роли «Личное»: два склеенных текста давали два смайлика и два предложения с одного слова), `talk.roles` (`{roles}` — «с задачами и со складом»: дописывается после «кто ты», если включено что-то сверх роли «Личное»), `talk.joke` (`{joke}`), `talk.joke.none`, `talk.set.*` (подтверждения просьб; `talk.set.main` и `talk.set.solo` — `{name}`, кодом больше не используются; `talk.set.mainFixed` — `{main}`, ответ на «пусть отвечает Лиорио»: главный всегда Связной; `talk.set.modeSolo`, `talk.set.modeDuo` и `talk.set.modeTrio` — `{team}`, «включи соло/дуэт/трио»), `talk.set.already`, `talk.openHub` (подтверждение «открой мой Связной»; без имени помощника), `session.handoff.note` (`{roles}`, `{name}` — строка экрана новой сессии «… ведёт Лиорио — такие фразы передам», голосом главного и без рода: строка видна и до выбора пол главного). Текст шутки и список навыков — факты: стиль оборачивает их, но не меняет. Ответ «Как дела?» и приветствие с каламбуром складываются из нескольких записей: между ними всегда точка или другой знак конца предложения, и при выключенных эмодзи тоже.

**«Кто ты»: роль и название не смешиваются** (ADR-009, уточнено ADR-016). Помощник представляется ролью в своём роде и приложением, в котором работает: «Я Связной, главный помощник в Tridot…», «Я Нода, помощница в Tridot…». Себя по названию приложения помощник не называет. `{appPrepositional}` — название в предложном падеже (`AppInfo.namePrepositional`); оно звучит в ответе ровно один раз. В Соло — `talk.who.solo`. В Дуэте и Трио Связной говорит о себе (`talk.who.main`), о каждом активном помощнике (`talk.who.helper`) и закрывает `talk.who.byName`; помощник говорит о себе (`talk.who.self.helper`) и о главном (`talk.who.mainRef`). `{duties}` собирает код из фиксированных фраз в именительном падеже без рода: «расширения (склад, пароли)», «оповещения (напоминания, просрочки, сигналы склада)», обе через «и»; выключенный навык не называется. **Метка рода `{м:…|ж:…}` — род того, о ком фраза**: `talk.who.helper` рендерится с родом помощника, `talk.who.mainRef`, `talk.set.mainFixed` — с родом Связной, а стиль, обращение и эмодзи остаются говорящего (`ReplyVoice.copyWith(gender:)`, `AssistantSession.sayAs`). Обратного рода («{м:вторая помощница|ж:второй помощник}») больше нет: имена и род берутся из настроек, пару разного рода никто не обещает. **Имена в каталоге — только в именительном падеже** (`{name}`, `{main}`, `{other}`, `{team}` — текущие русские имена из настроек): переименованного помощника не склонить. Поэтому «Остальным занимается {other}», а не «к {other}». Выбор внутри выбора не поддерживается, поэтому в соло «вы»/«ты» стоит отдельно от рода: «помощница в Tridot: отвечаю на {вы:ваши|ты:твои} сообщения».

Общая запись маршрутизатора `common.confirm.unclear` — переспрос «да» или «нет», когда на вопрос подтверждения ответили «хорошо» или «спасибо» (`docs/CONNECTORS.md`, «Подтверждение изменяющих действий»).

### Записи массовых команд

Ответы массовых команд задач (`docs/CONNECTORS.md`, «Массовые команды задач: вопрос со списком») — записи `task.bulk.*` встроенного каталога, во всех четырёх стилях. Числа — `{count}` (сколько отмечено, изменено или возвращено) и `{total}` (сколько задач в списке) с формами `{мн:count|задачу|задачи|задач}`; `{due}` — новый срок словами (`formatDue`: «7 ноября», «завтра в 10:00»), `{shift}` — сдвиг («на 1 час позже», `DueShift.describe`).

| Запись | Когда | Подстановки |
| --- | --- | --- |
| `task.bulk.ask.reschedule`, `task.bulk.ask.shift`, `task.bulk.ask.complete` | вопрос со списком: «Перенести 4 задачи на 7 ноября? Лишние задачи можно снять в списке.» (`protected`) | `count`, `due` / `shift` |
| `task.bulk.ask.noneChecked` | после «кроме …» не осталось отмеченных — вопрос остаётся | — |
| `task.bulk.ask.when` | «перенеси всё» без срока | — |
| `task.bulk.empty.all`, `.overdue`, `.noDue`, `.day`, `.tag`, `.shift` | ничего не подходит: «Просроченных задач нет.», «Задач на {day} нет.», «Подходящих задач с {tags} нет.» | `day`, `tags` |
| `task.bulk.unchecked`, `task.bulk.onlyChecked`, `task.bulk.notInList` | начало повторного вопроса после «кроме …», «только …» или если такой задачи в списке нет | `titles`, `query` |
| `task.bulk.unclear` | начало повторного вопроса после согласия с непонятной оговоркой («да, хлеб тоже»): по списку не применяем, переспрашиваем | — |
| `task.bulk.declined`, `task.bulk.noneChecked` | «нет» / «да» без отмеченных — ничего не меняется | — |
| `task.bulk.stale` | список уже не действует (`protected`) | — |
| `task.bulk.rescheduled`, `task.bulk.shifted`, `task.bulk.completed` и их `.partial` | итог: все отмеченные или «{count} из {total}» | `count`, `total`, `due` / `shift` |
| `task.bulk.undone`, `task.bulk.undone.partial`, `task.bulk.undo.nothing` | «Отменить», «отмени» | `count`, `total` |

Повторный вопрос после «кроме …» собирается из двух записей: начало (`session.say('task.bulk.unchecked', …)`) передаётся в `session.reply(…, prefix:)`, а вопрос остаётся отдельной защищённой записью — так ни один стиль не может потерять в нём вопрос.

Подписи карточки («Перенести (N)», «Выбрать все», «Перенесено 3 из 4», «Вопрос устарел — повторите команду») — надписи интерфейса, а не реплики помощника: они в `lib/app/widgets/bulk_checklist_card.dart`, а не в каталоге.
