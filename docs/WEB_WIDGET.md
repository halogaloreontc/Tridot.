# Веб-помощник «Связной» на складе

Решение — ADR-032 (`docs/DECISIONS.md`), выпуск из GitHub — ADR-035,
полный помощник (разговоры, проекты, задачи, напоминания) — ADR-038.
Шаги владельца по кнопкам — `tool/widget_release/README.md`.

## Выпуск — кнопкой в GitHub

Владелец ничего не ставит к себе: ни Flutter, ни OpenSSL, ни aws-cli.

1. **Ключ издателя** создаёт склад в браузере (WebCrypto Ed25519):
   Управление → Инструменты → Помощник → «Ключ издателя» → «Создать
   ключ». Закрытый ключ (PEM PKCS#8) показывается один раз, на сервер не
   уходит; владелец кладёт его в секрет `SVYAZNOY_SIGN_KEY` репозитория
   Tridot (Settings → Secrets and variables → Actions). Склад сохраняет
   только открытый ключ; второму складу его вставляют руками («У меня уже
   есть ключ»). Со склада ключ задаётся, только пока его нет;
   `ASSIST_WEB_PUBKEY` в `config.php` главнее.
2. **Выпуск** — `.github/workflows/web-assistant-release.yml`, «Выпуск
   веб-помощника»: Actions → Run workflow, поля version (`1.0.0`) и notes.
   Шаги: проверка версии (вид `1.0.0`, тега `web-v<версия>` ещё нет,
   больше прежнего `web-v*`, теги — через `gh api`) и секретов → Flutter
   (как в `ci.yml`, действия закреплены по коммиту) → `dart compile exe`
   инструмента (без ключа) → `pubkey` и `fingerprint` (открытый ключ и
   отпечаток — в итоги запуска) → `web` — `flutter build web` без ключа →
   `build --skip-build` — подпись → `verify` → если
   заданы все три `SVYAZNOY_BUCKET`, `AWS_ACCESS_KEY_ID`,
   `AWS_SECRET_ACCESS_KEY` — `upload.sh` и проверка, что `latest.json`
   читается без входа → `gh release create web-v<версия>` с архивом и
   `latest.json`. Выпуск в Releases — последним: упала загрузка — тот же
   запуск можно повторить с той же версией. Тег не перезаписывается.
   Затем тот же архив и `latest.json` — в постоянный предвыпуск
   `web-latest` (сначала архив, потом `latest.json`; прежние архивы
   удаляются).
3. **Склад** сам берёт выпуск из `web-latest` публичного репозитория
   (`…/releases/download/web-latest/latest.json`, переадресацию GitHub
   проходит сам — до 5 шагов, только https и не внутренние адреса):
   «Установить помощника», дальше «Проверить» → «Установить». Или из
   архива Releases («Загрузить архив…»). Бакет — по желанию.

Секреты попадают в шаги только через `env`, ввод формы — тоже (в `run:`
нет `${{ inputs.* }}`); ключ подписи пишется во временный файл 600 и
стирается, в журнал не печатается. Ключ есть только в шагах, где не
исполняется чужой код: `flutter build web` (хуки пакетов, плагины) идёт в
шаге без него, а сам `release.dart` и локально запускает Flutter без
`SVYAZNOY_SIGN_KEY*` и ключей бакета в окружении (`buildEnvironment`);
подписывает и считает открытый ключ инструмент, собранный `dart compile
exe` до шага с ключом, — без `dart run` и хуков. Checkout — с
`persist-credentials: false`, токен в `.git/config` не остаётся.

### Отпечаток ключа

Один и тот же на складе, в итогах запуска и в описании выпуска: sha256 от
32 байт открытого ключа Ed25519 (не base64 и не DER), первые 16 знаков hex
строчными, по 4 через пробел (64 бита — подобрать ключ с тем же отпечатком
не по силам; 32 бита подбирались бы за часы). Ключ RFC 8032 (тест 1)
`11qYAYKxCrfVS/7TyWQHOg7hcvPapiMlrwIaaPcHURo=` → `21fe 31df a154 a261` — этот пример
проверяют тесты Tridot и склада. В Dart — `publisherFingerprint`
(`release_core.dart`), в командной строке —
`release.dart fingerprint <ключ>`.

## Что это

Тот же «Связной», собранный для браузера из общего кода Tridot: описание
склада (`assets/connectors/depotdesk.assistant.json`), `ManifestConnector`,
каталог ответов, карточки склада (`WarehouseCardView`) и действий
(`ActionCardView`). Склад DepotDesk или halowarekeep ставит его к себе в
`assistant/v/<версия>-<sha8>/` и открывает кнопкой-роботом в шапке —
фреймом того же адреса поверх склада: на телефоне во весь экран, на
компьютере справа шириной 420 (склад может расширить панель — тогда
разговоры колонкой слева).

Есть: склад, задачи (`TasksConnector`: «добавь задачу…», «напомни
завтра…», «готово»), разговоры и проекты как в приложении, напоминания при
открытии, калькулятор и беседа. Нет: файлов, паролей, конвертера, голоса
Vosk, сканера QR, системных уведомлений, настроек. Помощник один —
Связной, без эмодзи.

## Разговоры, проекты, задачи

- **Где лежат.** На складе 1.4.74+ — личное хранилище сотрудника `my_*`
  (README склада, «Договор для «Связного»» §7.3): видно с любого
  устройства и во вкладке склада «Проекты». В браузере — только кэш
  (`svz:chats:`, `svz:chat:`, `svz:projects:`, `svz:tasks:`, `svz:my:` +
  логин). Склад без хранилища (`ask_me` без `store`) или ответ `my_*`
  400/401/403 — записи только в этом браузере до выхода; вход и вопросы
  складу при этом работают, ключ не считается устаревшим.
- **Синхронизация** — `WidgetStore` (`lib/web_widget/widget_store.dart`):
  `my_sync` при входе и при каждом открытии панели; правки — очередью
  (`my_put`/`my_patch` по полям, `my_chat_new`/`my_chat_append`, `my_del`),
  неотправленное ждёт в `svz:my:<логин>`.
- **Прежняя история** `svz:hist:<логин>` — один раз на склад (`my_import`)
  или, без склада, разговором «Разговор в браузере».
- **Интерфейс.** Шире 700 — колонка слева: «Новый разговор», задачи
  (галочка — «готово», календарь — срок, нажатие — разговор задачи),
  проекты с разговорами и меню («Новый разговор в проекте»,
  «Переименовать», «Закрепить», «Удалить проект»), разговоры по дням с меню
  «Переименовать / Закрепить / В проект… / Удалить». Уже (панель 420,
  телефон) — то же в меню по кнопке ☰ в заголовке.
- **Напоминания.** Склад шлёт `signal` или помощник читает `my_signals`
  (если `store.signals`): полоса «Напоминание: …» над лентой с кнопками
  напоминания, «ещё N напоминаний ›»; показанные — `my_signal_ack seen`.
  Без напоминаний склада — свои: просроченные и на сегодня задачи.

## Вход

1. Страница склада (свой вход сотрудника) вызывает `assist_web_key` — склад
   выдаёт ключ помощника (`scope: assist`), привязанный к входу страницы:
   гаснет при выходе, виден на странице «Подключить Связного» как
   «Веб-помощник», его можно отключить.
2. Помощник шлёт `hello`, страница отвечает `init` с адресом склада и
   ключом.
3. `ConnectionService.connectWithKey`: описание с сервера (не получено —
   встроенное), ключ — только в памяти (`InMemorySecretStore`), пароль
   склада не нужен (`tokenless`), затем `ask_me` — логин, имя, роль,
   права. Прежний ключ на складе не гасится: его заменяет склад.
4. Права — роль сотрудника и переключатели администратора склада: их
   проверяет сервер. «Разрешить действия» у помощника включено для логина
   входа — решает склад.
5. 403 `need: login` или 401 без пароля — `need-key`, страница присылает
   `key`, вопрос повторяется один раз.

Запросы идут `fetch` с `credentials: omit` (cookie склада не уходят),
`redirect: error`, тайм-аут — `AbortController`.

## Договор `postMessage` (версия `api` 2, выпуск — `minApi: 1`)

В каждом сообщении `svz: 1`. Помощник принимает сообщения только с того же
адреса (`origin`) и только от окна родителя, отправляет — только родителю
на свой адрес.

| направление | `type` | поля |
|---|---|---|
| помощник → склад | `hello` | `version`, `api: 2`, `caps: [signal, open-chat, changed, layout]` |
| склад → помощник | `init` | `base`, `sid`, `login`, `name`, `roleLabel`, `theme` (`light`/`dark`), `device` (`phone`/`desktop`), `voice: {available, reason}`, `layout: {can, wide}` (по желанию) |
| склад → помощник | `signal` | `v: 1`, `reason`, `focus`, `items` (до 5 напоминаний) |
| склад → помощник | `open-chat` | `id` разговора хранилища |
| помощник → склад | `changed` | `what`: `data` (записали на складе), `my` (личные записи), `sig` (напоминания) |
| помощник → склад | `layout` | `wide` — широкая панель на компьютере (только если `init.layout.can`) |
| помощник → склад | `need-key` | — |
| склад → помощник | `key` | `sid` или `error` |
| помощник → склад | `close` | — |
| склад → помощник | `back`, `logout`, `visible: {on}` | — |
| склад → помощник | `theme` | `theme` (`light`/`dark`) — тему склада переключили, пока помощник загружен |
| помощник → склад | `open` | `hash` (`#/…` или пусто — главная склада): строка карточки и «Открыть в складе» у ответа про одну вещь — `#/sku/<артикул>`, `#/entry/<id>`, id %-кодом (`WidgetMessages.linkHash`); ячейку склад по ссылке не открывает |
| помощник → склад | `update-ready` | `version` |
| помощник → склад | `voice` | `op` (`start`/`stop`/`cancel`/`download`), `id`, `lang: ru-RU` |
| склад → помощник | `voice-ev` | `id`, `ev` (`state`/`partial`/`final`/`error`), `text`, `code` |

- `back`: идёт распознавание — отменить, иначе `close`.
- Escape на компьютере ловит сам помощник (фокус внутри фрейма) и ведёт себя
  как `back`; страница склада ловит Escape, когда фокус у неё.
- `logout`: ключ уже погашен вместе со входом — помощник стирает свои
  ключи `svz:*` и ключ в памяти без запроса на склад.
- `update-ready`: раз в 10 минут и при `visible: {on: true}` помощник читает
  `assistant/current.json`; версия другая — сообщает, только когда ничем не
  занят (ответ не готовится, поле ввода пусто, голос не слушает, карточка
  действия не ждёт ответа).

## Голос

Только в приложениях склада для Android (модуль Capacitor `WhVoice`,
распознавание на устройстве: `SpeechRecognizer.createOnDeviceSpeechRecognizer`,
Android 12+, ru-RU, без облака). `window.Capacitor` есть только у главной
страницы, поэтому распознавание запускает страница склада, а помощник шлёт
ей `voice` и получает `voice-ev`.

| `voice.reason` | Что показывает помощник |
|---|---|
| `ok` (`available: true`) | Кнопка микрофона; `partial` — в строке над полем, `final` — вопрос складу |
| `sdk`, `no-ondevice` | Кнопка — подсказка «Нажмите микрофон на клавиатуре» |
| `no-lang` | Кнопка — `download`: скачать русский |
| `web` | Кнопки нет (браузер, компьютер, Electron) |

## Хранение в браузере

`localStorage`, все ключи начинаются с `svz:` (страница склада при выходе
стирает их по началу): `svz:conn:<app>` — запись подключения без ключей,
`svz:desc:<app>` — кэш описания; кэш записей сотрудника — см. «Разговоры,
проекты, задачи» (по 200 последних сообщений на разговор; места не хватило —
кэш других разговоров уходит первым). `svz:hist:<логин>` прежних версий
переносится и убирается. Ключ помощника — только в памяти.

## Сборка и размер

```sh
flutter build web --release -t lib/web_widget/main.dart \
  --no-web-resources-cdn --no-source-maps
```

JS + CanvasKit (без `--wasm`: WasmGC нет в старых WebView и Safari).
`tool/widget_release` убирает лишнее: варианты CanvasKit кроме `canvaskit/`
и `chromium/`, символы отладки, ассеты Tridot (паки, пароли, голос,
каталоги — ядро берёт их из `builtin_replies.g.dart`), шрифты Cormorant и
JetBrains Mono (и из `FontManifest.json`), `NOTICES` → `LICENSES.txt`.
Архив — около 7 МБ, при первом открытии в Chrome скачивается около 3,5 МБ
со сжатием (main.dart.js ~0,9, chromium/canvaskit.wasm ~2,1, шрифты);
дальше — из кэша: папки версий не меняются.

Тега `<base>` нет: папка версии заранее неизвестна, относительные пути
считаются от адреса `index.html`. Своего service worker нет; страница
склада исключает `/assistant/` из своего `sw.js`. CSP в `<meta>`: только
свой адрес, `wasm-unsafe-eval` для CanvasKit. Запасных шрифтов нет, за
gstatic помощник не ходит.

`flutter_bootstrap.js` до загрузчика оборачивает
`WebAssembly.compileStreaming`: если сервер отдал `.wasm` с чужим типом
(TypeError), модуль компилируется из ArrayBuffer. Без этого загрузчик
Flutter с типом `application/octet-stream` показывает пустую страницу
(«Incorrect response MIME type»; проверено Playwright на настоящей сборке),
а склад требовал бы правки `mime.types` на сервере.

## Формат выпуска

- `svyaznoy-web-<версия>.zip`: файлы сборки и в корне `_release.json`
  (`{product: "svyaznoy-web", version, minApi, minServer: {depotdesk,
  halowarekeep}, notes, pubkey, files: {путь: sha256}, total}`) и
  `_release.sig` (base64 подписи Ed25519 байтов
  `"SVYAZNOY-WEB-RELEASE-V1\n"` + `_release.json`).
- `latest.json`: `{version, minApi, minServer, url, size, sha256, notes,
  sig, pubkey}`; `sig` — base64 подписи `"SVYAZNOY-WEB-LATEST-V1\n<version>\n<sha256>\n<size>\n<minApi>"`.
- `pubkey` — открытый ключ, которым подписан выпуск (base64), только
  подсказка: подпись не сошлась — склад пишет оба отпечатка, свой и этот.
  Проверяет склад всегда своим ключом; старые склады поле не читают.
- Имена в архиве — только то, что примет склад: без `..`, `\`, ведущей
  `/`, имён с точкой в начале; расширения `html js mjs json wasm css png
  svg ico webp otf ttf woff2 bin symbols txt frag`; не больше 3000 файлов и
  80 МБ. Время файлов постоянное: одинаковая сборка — одинаковый архив.
- Подпись — OpenSSL 3 (`openssl pkeyutl -sign -rawin`), проверка на
  складе — `sodium_crypto_sign_verify_detached` (совместимость проверяет
  тест `test/tool/widget_release_test.dart`, если есть `php` с sodium).
  Ключ из WebCrypto (PKCS#8, 48 байт) OpenSSL читает как есть; текст из
  секрета `release.dart` сначала приводит к PEM (`normalizePrivateKeyPem`:
  `\r\n`, одна строка, буквальные `\n`).

## Проверки

К проверкам Tridot добавляется сборка помощника:
`flutter build web --release -t lib/web_widget/main.dart --no-web-resources-cdn --no-source-maps`.
Сборка APK не меняется. Выпуск (`web-assistant-release.yml`) запускается
только руками и в `ci.yml` не входит.
