# Коннекторы

Коннектор — подключаемый набор команд помощника. Коннекторы бывают двух видов (`ConnectorInfo.kind`, `docs/EXTENSIONS.md`): **навыки** — своя логика без сети (встроенные `tasks` — задачи, `calc` — калькулятор, `talk` — беседа), и **подключения** к внешним приложениям. Первое подключение — склад halowarekeep: коннектор по описанию `assistant/1` (раздел «Коннектор по описанию `assistant/1`», ADR-011); следующие — expeora и сторонние программы. Этот документ — точная инструкция, как написать коннектор, проверить его и подключить. Решение о коннекторах и правила безопасности — ADR-004 в `docs/DECISIONS.md`.

Языковой модели в приложении нет (ADR-001): коннектор распознаёт фразы правилами, на основе общего предварительного разбора `Utterance`.

## Как устроено

```text
сообщение
→ AssistantController: Utterance.analyze(текст) — один раз
→ если коннектор ждёт подтверждения и текст — «да»/«нет»: run этого коннектора
  с ConfirmationAnswer (см. «Подтверждение изменяющих действий»), конец
→ если ждёт и понимает уточнение ответа (ConfirmationFollowUp: «кроме хлеба»):
  run этого коннектора с его совпадением, конец
→ если ждёт уточняющий вопрос с вариантами (Clarification) и текст — вариант:
  заново весь разбор канонической фразы варианта, конец
→ каждый коннектор: match(utterance) → ConnectorMatch? (без ввода-вывода)
→ «да, …»/«нет, …» с пояснением и без явных совпадений: тоже ответ владельцу
→ совпадения на крайний случай (fallback, беседа) отбрасываются, если есть любые другие
→ совпадения без маркера (implicit) отбрасываются, если есть явные
→ выбор самого уверенного совпадения (или уточнение, если спорно; в споре
  выигрывает коннектор из контекста сессии) — RoutePolicy.pick
→ если победитель отдаёт фразу другому навыку (Reroute): разбор его фразы
→ run(match, session) победителя (здесь можно ходить в сеть)
→ AssistantResponse → интерфейс
```

## Интерфейс

```dart
abstract interface class Connector {
  ConnectorInfo get info;
  ConnectorMatch? match(Utterance utterance);
  Future<AssistantResponse> run(ConnectorMatch match, AssistantSession session);
}
```

### `ConnectorInfo`

| Поле | Значение |
| --- | --- |
| `id` | постоянный id латиницей: `warehouse`. Уникален среди подключённых — повтор роняет конструктор `AssistantController`. Совпадает с полем `connector` в корпусе |
| `title` | имя для пользователя: «Склад». Попадает в уточнение «к чему относится команда» |
| `description` | одно предложение о возможностях |
| `examples` | фразы, которые коннектор обязан понимать; тест проверяет каждую |
| `requiresNetwork` | `true`, если `run` ходит в сеть |
| `access` | `readOnly` (по умолчанию) или `readWrite` |
| `kind` | `ExtensionKind.connector` (по умолчанию) — подключение к внешнему приложению; `ExtensionKind.skill` — навык без сети. Определяет группу в «Настройки → Расширения» («Подключения» или «Навыки»). `pack` запрещён: пак — данные, а не коннектор |
| `version`, `author` | для пользователя в настройках; по умолчанию `1.0.0` и «Tridot» (`AppInfo.name`: автор виден в интерфейсе, ADR-009, ADR-016) |
| `defaultEnabled` | включён, пока пользователь не выключил (по умолчанию `true`); новый коннектор с `true` после обновления появляется включённым |
| `required` | нельзя выключить (по умолчанию `false`; `true` только у `tasks`) |
| `replies` | свои записи каталога ответов: id → нейтральный текст с разметкой (`docs/REPLIES.md`). Id не совпадает со встроенной записью и записями других коннекторов |
| `protectedReplies` | какие из `replies` — предупреждения и вопросы-подтверждения («Склад не принял токен», «Списать 3 шт.?»): паки ответов их не переопределяют |

### `match(Utterance utterance)`

- Чистая синхронная функция: без сети, файлов, хранилища, таймеров и изменения состояния. Вызывается на **каждое** сообщение у **каждого** коннектора.
- Возвращает `null`, если фраза не его. Лучше вернуть `null`, чем слабое совпадение «на всякий случай».
- Всё, что понадобится в `run` (код товара, разобранный срок), кладётся в `payload` — `run` не разбирает текст заново.
- Исключение в `match` не ломает помощника: маршрутизатор пропускает этот коннектор. Но это ошибка, её надо исправить.

### `run(ConnectorMatch match, AssistantSession session)`

- Здесь допустимы ввод-вывод и сеть (если `requiresNetwork: true`).
- Исключение превращается маршрутизатором в ответ `failed` с текстом «Не удалось выполнить действие: …» и `intent = match.commandId`. Ожидаемые ситуации (нет токена, 404, 401) лучше разбирать самому и отвечать понятным текстом.
- Ответ — `AssistantResponse(message, intent, status)`. Текст для пользователя берите из каталога ответов: `session.reply('warehouse.located', values: {…}, intent: …, status: …)` — факты передаются значениями, слова и стиль помощника (Садо, Лиорио или Нода, «вы»/«ты», эмодзи) добавляет каталог (`docs/REPLIES.md`). Свои записи объявляются в `ConnectorInfo.replies`. Статусы:
  - `completed` — ответ получен или действие выполнено (в том числе «товар не найден»);
  - `needsClarification` — нужен ответ пользователя, ничего не сделано;
  - `noAction` — действие невозможно, ничего не сделано (коннектор не настроен);
  - `failed` — ошибка.
- `intent` — `commandId` команды: `warehouse.locate`.

### Тексты ответов: каталог

Коннектор не пишет текст ответа сам — он передаёт факты, а слова берутся из каталога ответов (`docs/REPLIES.md`):

1. Объявите записи в `ConnectorInfo.replies`: id латиницей через точку (`warehouse.located`), нейтральный текст с подстановками `{code}` и разметкой рода `{м:нашёл|ж:нашла}` и обращения `{вы:Подключите|ты:Подключи}`. Эмодзи — только в `{э:…}` (нейтральный текст обходится без них).
2. В `run` отвечайте `session.reply(id, values: {...}, intent:, status:)`; часть ответа — `session.say(id, values)`. Значения — готовые строки: числа, даты (`formatDue`), названия в «».
3. Уточнение — вопрос со «?»: каталог проверяет, что во всех стилях и паках ответов он остаётся вопросом, а каждый факт не теряется ни в одном роде и обращении. Ошибка разметки — исключение при создании `ExtensionRegistry`, её ловит первый же тест.
4. Не склеивайте ответ из кусков с условиями в коде, если можно завести отдельную запись: `warehouse.notFound` и `warehouse.located` лучше, чем один текст с «не».
5. Остальные стили говорят записи коннектора нейтральным текстом; свои варианты можно дать паком ответов (`type: replies`) — кроме записей из `protectedReplies`: предупреждения и вопросы-подтверждения пак не переписывает («Готово!» вместо «Склад не принял токен» не пройдёт проверку).

### `AssistantSession`

Общее состояние диалога; живёт столько же, сколько `AssistantController`.

| Член | Значение |
| --- | --- |
| `clock` | источник времени; не вызывайте `DateTime.now()` |
| `speaker`, `personas`, `voice` | кто отвечает на текущее сообщение (Садо, Лиорио или Нода — по зоне навыка или обращению, ADR-016), настройки помощников и голос на начало сообщения; ставит маршрутизатор |
| `extensions` | реестр расширений: включённые коннекторы и паки (так беседа узнаёт, что умеет помощник и какие шутки включены) |
| `reply(id, values:, intent:, status:, task:)`, `say(id, values)` | ответ (или текст) из каталога ответов голосом текущего помощника; голос (`voice`) ставит маршрутизатор в начале сообщения |
| `select(connectorId, itemId)` | запомнить выбранный объект («её», «его») |
| `selectedItemFor(connectorId)` | выбранный объект **этого** коннектора или `null` |
| `forget(connectorId, itemId)` | снять выбор, если выбран этот объект |
| `lastConnectorId` | какой коннектор обработал **предыдущее** сообщение; `null`, если его никто не взял или маршрутизатор переспросил |
| `requestConfirmation(PendingConfirmation)` | запомнить действие, которое ждёт «да» или «нет» в **следующем** сообщении |
| `reply(…, checklist:, prefix:)` | ответ со списком для карточки в чате (`BulkChecklist`, массовые команды) и с началом из другой записи (`say`) — «Снял отметку: «Хлеб». Перенести 3 задачи…?» |
| `pendingConfirmation` | ожидающее действие или `null`; маршрутизатор забирает его (`takePendingConfirmation`) в начале каждого сообщения |
| `chatTaskId` | задача чата, в котором пришло сообщение (`null` — главный чат); ставит маршрутизатор, см. «Чат задачи» |

Выбор хранится один на диалог: выбор товара снимает выбор задачи. Коннектор читает только `selectedItemFor(свой id)` — «Заверши её» после вопроса о товаре не завершит задачу.

### `Utterance` — общий разбор сообщения

Строится маршрутизатором один раз. Все смещения (`CharSpan`, полуоткрытые `[start, end)`) — в исходном тексте `original`.

| Член | Значение |
| --- | --- |
| `original` | текст как есть |
| `normalized` | нижний регистр, «ё» → «е»; длина та же, что у `original` |
| `analysisText` | `normalized`, где кавычки с содержимым и метки заменены пробелами |
| `tokens` | слова вне кавычек и меток: `text` (нормализованный), `original`, `span`, `isNumber` |
| `words` | только `text` слов |
| `quotedTitles` | названия в парных кавычках с фрагментами; `unbalancedQuotes` — незакрытая кавычка |
| `hashtags` | метки `#проект` вне кавычек: `name` без «#» в нижнем регистре |
| `due` | срок (`dueAt`, `precision`, `issue`) и `spans` — какие фрагменты занял срок вместе с предлогом |
| `codes` | числа из 5–6 цифр: артикулы, номера ячеек. Никогда не читаются как дата или время |
| `numbers` | все слова из одних цифр |
| `isQuestion` | есть «?» вне кавычек |
| `hasAnyWord({...})`, `firstOf({...})` | поиск нормализованных слов целиком |
| `tokensOutside(spans)`, `Utterance.isCovered(token, spans)` | слова вне фрагментов |
| `remainder(spans)` | остаток исходного текста без фрагментов, кавычек и меток: регистр сохранён, пробелы схлопнуты, знаки по краям убраны |
| `Utterance.capitalize(text)` | первая буква заглавная |
| `chatTaskId`, `withChat(id)` | задача чата, в котором написано сообщение (`null` — главный); ставит маршрутизатор |

Правила, которые важно помнить:

- Слова сравниваются **целиком**: `hasAnyWord({'завтра'})` не срабатывает на «завтрак». Не ищите подстроки в `normalized`.
- «ё» уже заменена на «е»: пишите ключевые слова через «е» (`'еще'`, а не `'ещё'`).
- Слова — это буквы и цифры: «A-03» даёт два слова `a` и `03`, «2.10» — `2` и `10`.
- Дата, время и номер версии разбираются один раз в `due`; не разбирайте их сами. «до версии 2.10» не срок. «в 10» — срок только после «в/к» и если дальше нет обычного слова («в 2 магазинах» — не время), стоит инфинитив («в 10 позвонить») или сразу перед ним день («завтра в 10 созвон», «в следующий понедельник в 9 планёрка»).

## Чат задачи

У каждой задачи свой чат (ADR-010). Интерфейс передаёт задачу чата в `AssistantController.handle(text, chatTaskId: …)`; маршрутизатор ставит `AssistantSession.chatTaskId`, выбирает эту задачу («её») и строит `Utterance` с `chatTaskId` (`withChat`). Смена чата — `enterChat(taskId:)`: ожидание подтверждения снимается (`onDropped`), выбор главного чата запоминается и возвращается при выходе; во время ответа смена откладывается до его конца.

Правила коннектора задач (только при `chatTaskId != null`):

1. **Цель по умолчанию — задача чата**, важнее выбора: «готово», «сделано», «выполнено», «заверши», «отметь выполненной» закрывают её, «перенеси на завтра» переносит — без «какую задачу?» при любом числе активных задач.
2. **Названа другая задача** — она: в кавычках («закрой «Хлеб»», не нашлась — «не нашёл») или точным названием / единственным уверенным совпадением поиска. Задача чата среди лучших совпадений («закрой хлеб» в чате «Купить хлеб») — она. Не нашлась, несколько похожих или совпала половина слов — тот же вопрос, что в главном чате (`task.notFound`, `task.ask.severalMatch`, `task.ask.didYouMean`): задачу чата по чужому названию не меняем. Не название — только междометия и благодарность (`TaskChatPhrases.isFiller`): «готово, спасибо», «сделано, ура» закрывают задачу чата.
3. **«Я купил хлеб»** в чате «Купить хлеб» — сразу эта задача, без вопроса, если она среди лучших совпадений; иначе — вопрос, как везде.
4. **Фразы только для чата задачи** (`TaskChatPhrases`, `lib/core/connectors/task_chat_phrases.dart`; срабатывают, лишь когда обычный разбор дал `unknown`): «закрой», «закрывай», «закрой её», «можно закрывать», «отметь», «выполнена» — завершение (уверенность 0,8); фраза, которая целиком срок («на завтра», «на пятницу в 10», «завтра в 9», «давай на понедельник»), — перенос (0,75). Реплика беседы целиком (`TalkPhrases`: «до завтра») и срок с «до» («до понедельника») — прощание, а не перенос. В главном чате они не поняты, как раньше.
5. **Задача чата уже выполнена:** «готово» и перенос ничего не меняют — `task.chat.alreadyDone`; вернуть в работу — кнопкой в шапке чата (`task.reopened`).
6. Создание задач, массовые команды, калькулятор и беседа контекст не видят: «добавь задачу молоко» в чате задачи создаёт новую задачу (у её чата `parentTaskId` — задача исходного чата), цель чата не меняется.

Тесты — `test/connectors/task_chat_test.dart` (корпус пока не умеет контекст чата, поэтому фразы чата задачи проверяются там, а не в `test/corpus/`).

## Шкала уверенности

| `confidence` | Когда |
| --- | --- |
| 0.9 | явная команда коннектора: глагол и объект, фраза целиком о нём. «Где лежит 64115», «Добавь задачу …» |
| 0.8–0.85 | команда понятна, но короче или опирается на контекст: «Заверши её», «Перенеси отчёт на завтра» |
| 0.6 | есть признаки, но фраза может быть частью чужой команды: «… где лежит 64115» внутри «Добавь задачу проверить, где лежит 64115» |
| < 0.5 | слабая догадка; такое совпадение не спорит с другими и выигрывает, только если больше никто не откликнулся. Обычно лучше вернуть `null` |

Встроенный `tasks`: создание, список и массовые команды — 0.9, перенос и «отмени» — 0.85, завершение — 0.8. Команды без маркера ниже: создание по инфинитиву («купить хлеб») — 0.6, со сроком («через 3 дня сдать отчёт») — 0.75; сообщение о сделанном без маркера («я купил хлеб») — 0.6. Такие совпадения помечены `ConnectorMatch(implicit: true)`: маршрутизатор отбрасывает их, если хоть один коннектор вернул явное совпадение, даже менее уверенное. Поэтому «узнать, где лежит 64115» (задачи угадали инфинитив, склад нашёл свой вопрос) уходит складу без уточнения. Ставьте `implicit: true`, если намерение угадано только по форме фразы, без слова-команды.

`ConnectorMatch(fallback: true)` — совпадение на крайний случай: маршрутизатор отбрасывает его, если откликнулся **любой** другой коннектор, даже без маркера. Так устроена беседа (`talk`, уверенность 0.6): «привет» — ей, «привет, добавь задачу купить хлеб» и «пока не забыл, купить хлеб» — задачам. Ставьте `fallback: true` коннектору, который отвечает на короткие реплики целиком и не должен спорить с командами.

## Правила уточнений

1. **Маршрутизатор** спрашивает «Не понял, к чему относится команда: «Задачи» или «Склад»?», если у двух **разных** коннекторов уверенность не ниже 0.5 (`AssistantController.ambiguityFloor`) и разница не больше 0.15 (`ambiguityMargin`). Ничего не выполняется. Поэтому не завышайте уверенность: 0.9 на любую фразу с числом создаст спор с задачами.
2. **Коннектор** спрашивает сам (`needsClarification`), если фраза его, но данных не хватает или они неоднозначны: несколько кодов, несколько найденных товаров, нет обязательного параметра. Уточнение не меняет данных и не ходит в сеть, если ответ сети не нужен для вопроса.
3. Не угадывайте: при сомнении — уточнение, а не действие.
4. **Изменяющие действия** (`access: readWrite`, всё, что меняет данные внешнего приложения) выполняются только после явного подтверждения пользователя (ADR-004). Стандартный способ — ожидание подтверждения в сессии, см. следующий раздел.

## Уточняющий вопрос с вариантами

Когда фраза понятна, но двусмысленна по объекту — «сделай бэкап» (сейф с паролями или все данные?), «открой хранилище», — коннектор не отвечает «не понял», а спрашивает с вариантами (решение владельца 3). Механизм общий, текст вопроса — из каталога ответов.

1. **Вопрос.** `run` кладёт в `session.requestConfirmation(PendingConfirmation(connectorId: id, commandId: '<id>.clarify', payload: Clarification(...)))` уточнение: `questionId` (запись каталога) и варианты `ClarifyOption(label, text, answers, connectorId)`. `label` — подпись кнопки («Пароли», «Все данные»), `text` — **каноническая команда** варианта («сделай резервную копию сейфа»): только шаблон коннектора, никогда не фраза пользователя. Ответ — `needsClarification` с тем же объектом в `AssistantResponse.clarification`: интерфейс рисует под ответом кнопки вариантов, пока вопрос ждёт ответа (`AssistantController.pendingClarification`). Нажатие кнопки отправляет подпись обычным сообщением — тот же путь, что набранный текст. В историю чата варианты не попадают (`ChatMessage.toJson` их не пишет).
2. **Ответ.** Маршрутизатор разбирает его до «да»/«нет» (`Clarification.choose`): подпись варианта, слово варианта («паролей», «сейф», «все данные»), «первое»/«второе»/«1»/«2» — выбранный вариант разбирается **заново** как его `text`, со всеми правилами (SecretGuard; фраза о паролях не уходит сетевым коннекторам). Вопрос, отрицание («не пароли»), слова сразу двух вариантов — не выбор.
3. «Нет», «отмена», «не надо» — `common.clarify.cancelled` («Хорошо, ничего не делаю.»). «Да», «хорошо», «спасибо» — не выбор: `common.clarify.unclear` с теми же вариантами, вопрос живёт ещё одно сообщение.
4. Любая другая фраза снимает вопрос и разбирается как обычно. Остальной жизненный цикл — как у подтверждения: одно сообщение, снятие при смене чата и выключении коннектора, на ответ отвечает спросивший.

**Контекст сессии.** Маршрутизатор помнит, какой коннектор последним выполнил фразу в этом чате (`Utterance.recentConnectorId`): не дальше двух обработанных сообщений (`AssistantController.contextMessages`) и не старше 10 минут (`contextWindow`). Только id и время, без текста, только в памяти. Беседа (`fallback`) тему не меняет; «не понял», «к чему относится команда?», скрытый пароль, уточняющий вопрос и смена чата контекст сбрасывают. Коннектор может опереться на него в `match`: «Данные» после разговора о паролях не спрашивают «копию чего?», а возвращают совпадение с `Reroute(text: 'сделай резервную копию сейфа', connectorId: 'passwords', noteReplyId: 'data.context.backup')` — маршрутизатор разбирает эту фразу заново (один раз) и начинает ответ с «Понял как копию паролей.» (слой 7, `docs/PLANS.md`). Если навык-адресат выключен, выполняется исходное совпадение с `Reroute.orElse`. В споре двух коннекторов с близкой уверенностью (`router.ambiguous`) выигрывает коннектор из контекста.

## Подтверждение изменяющих действий

Единый механизм для всех коннекторов: ожидание хранит `AssistantSession`, «да»/«нет» распознаёт и доставляет маршрутизатор. Своих полей `_pending` и проверок «а был ли вопрос последним» коннектору не нужно.

1. **Вопрос.** Первый `run` ничего не меняет: вызывает `session.requestConfirmation(PendingConfirmation(connectorId: id, commandId: 'warehouse.writeOff', itemId: '64115', payload: …))` и возвращает `needsClarification` с описанием действия и вопросом: «Списать 3 шт. артикула 64115 из ячейки A-03-2? Ответьте «да» или «нет».». В `payload` кладётся всё, что нужно для выполнения, — повторно текст разбирать не придётся.
2. **Ответ.** Маршрутизатор в начале **каждого** сообщения забирает ожидание (`takePendingConfirmation`) и проверяет сообщение целиком (`ConfirmationReply.of`):
   - «да», «ага», «угу», «конечно», «отмечай», «давай», «подтверждаю», «ок», «+», «👍», «✅» (в том числе «да, отмечай», «да, спасибо») — `ConfirmationReply.yes`;
   - «нет», «неа», «не надо», «отмена», «не отмечай», «нет, спасибо», «-», «👎» — `ConfirmationReply.no`;
   - ответ с пояснением — «да» или «нет» первым словом и дальше что угодно («да, купил хлеб», «нет, не купил», `ConfirmationReply.leading`) — тоже ответ, но только если ни один коннектор не нашёл в сообщении явной команды. «Нет, добавь задачу молоко» — новая команда: задачи вернули явное совпадение;
   - если ответ распознан, маршрутизатор **до обычного разбора** вызывает `run` коннектора-владельца с `ConnectorMatch(commandId: pending.commandId, confidence: 1, payload: ConfirmationAnswer(pending, reply))`. `match` других коннекторов не спрашивается: «да» не уйдёт чужому коннектору.
3. **Выполнение.** `run` различает ответ по типу `payload`: `ConfirmationAnswer` → при `confirmed` выполнить действие (проверив, что объект ещё существует), иначе ответить «Хорошо, не …» и ничего не делать.
4. **Срок жизни — одно сообщение.** Любое другое сообщение («нет, добавь задачу …», вопрос «да?», новая команда, «кстати») снимает ожидание и разбирается как обычно; «да» после него — уже обычная фраза. Новый вопрос заменяет прежний. Исключение — отклик, похожий на согласие («хорошо», «ладно», «спасибо», совпадение с `acknowledgement: true`): маршрутизатор отвечает «Пока ничего не сделал. Ответьте, пожалуйста: «да» или «нет»?» (`common.confirm.unclear`) и оставляет ожидание ещё на одно сообщение. Коннектор, который отвечает на такие короткие реплики, ставит своему совпадению `acknowledgement: true`.
5. Вопрос и отказ не меняют выбранный объект (`select`).
6. **Снятое ожидание.** Если вопрос сняли без ответа (другое сообщение, новый вопрос, выключенный коннектор, очистка чата), маршрутизатор один раз вызывает `PendingConfirmation.onDropped` — так карточка вопроса узнаёт, что он устарел. На ответ «да»/«нет» и переспрос `onDropped` не вызывается.
7. **Уточнение ответа.** Коннектор может понимать не только «да» и «нет»: реализуйте `ConfirmationFollowUp.matchFollowUp(utterance, pending)` — чистую функцию, как `match`. Маршрутизатор спрашивает владельца ожидания после проверки «да»/«нет» и до обычного разбора; совпадение уходит в `run` владельца, а ожидание снимается, если `run` не вызовет `requestConfirmation` снова. Так задачи понимают «кроме хлеба», «только отчёт» и «да, кроме счёта» в ответ на вопрос массовой команды. Второй метод, `matchLeadingAnswer(utterance, pending, reply)`, вызывается для ответа с пояснением («да, хлеб тоже», `ConfirmationReply.leading`), в котором нет явной команды: `null` — принять ответ как есть, совпадение — выполнить его вместо ответа (задачи переспрашивают: оговорка может исключать задачу из списка).

### Массовые команды задач: вопрос со списком

Задачи — собственные данные приложения, но массовая команда меняет сразу много задач, поэтому всегда спрашивает (ADR-004): «Перенеси всё на выходные» → «Перенести 4 задачи на 7 ноября? Лишние задачи можно снять в списке.» и карточка со списком (`AssistantResponse.checklist`, `BulkChecklist` из `lib/core/models/bulk.dart`). Один и тот же объект `BulkChecklist` лежит в `PendingConfirmation.payload` и в карточке, поэтому галочка в карточке сразу видна ответу «да».

- Галочки и «Выбрать все / Снять все» — не сообщения: `AssistantController.setBulkItemChecked`, `setAllBulkItems`. Вопрос ждёт ответа дальше, смена настроек помощников его тоже не сбрасывает.
- Ответ — «да» / «нет» в чате или кнопки карточки «Перенести (N)» / «Отмена» (`answerBulk`: то же, что ответ в чате, голосом спросившего). «Кроме …», «только …», «да, но не хлеб», «хлеб не трогай», «хлеб оставь» — `ConfirmationFollowUp`: отметки меняются, вопрос повторяется с новым числом, и карточка переезжает под новый вопрос. Названия сравниваются по словам с учётом окончаний («кроме воды» — «Купить воду»), короткие слова и предлоги — только целиком. Согласие с непонятной оговоркой («да, хлеб тоже») не применяется: помощник переспрашивает (`task.bulk.unclear`); «да, переноси», «давай, закрывай» — согласие. «Отмени перенос», «не переноси» во время вопроса — отказ от него, а не отмена прошлого изменения. Исключение можно дать и в самой команде: «закрой всё, кроме хлеба» — хлеб в списке без отметки.
- Ничего не подходит — понятный ответ без вопроса («Просроченных задач нет.»). Задача, которую успели завершить или удалить, пока список ждал ответа, пропускается: «Перенёс на 7 ноября 3 задачи из 4.».
- После применения карточка только показывает итог («Перенесено 3 из 4») и кнопку «Отменить» (`undoBulk`); то же — «отмени», «верни всё как было» в чате (`task.bulk.undo`). Отменить можно только последнее массовое изменение и только до перезапуска или очистки истории чатов (`clearConversation`); смена чата отмену не снимает. Отмена возвращает прежние срок, точность и статус, но не трогает задачу, которую с тех пор меняли (`TaskService.restore`).
- Постороннее сообщение снимает вопрос по общему правилу (одно сообщение), карточка становится устаревшей: «Вопрос устарел — повторите команду». В историю чата карточка пишется данными (`BulkChecklist.toJson`); после перезапуска неотвеченный вопрос читается устаревшим (`BulkChecklist.fromJson`), а «да» ничего не применит.

Код — `TasksConnector._askBulk`, `_answerBulk`, `_refineBulk`, `_undoBulk`, тесты — `test/bulk/`.

### Действия с записью во внешнем приложении: карточка и кнопка

Для записи во внешнем приложении (склад 1.4.57, ADR-013) «да» текстом мало: набор согласий широк, а «отметь» — ещё и глагол команды. Поэтому:

- вопрос — ответ `needsClarification` с **карточкой** (`AssistantResponse.card`, `ActionCard` из `lib/core/models/action_card.dart`): что изменится, от чьего имени, до какого времени; тот же объект лежит в `PendingConfirmation.payload`;
- **выполняет только кнопка** «Подтвердить» (`AssistantController.answerCard(card, apply: true)` → `ConfirmationAnswer(viaButton: true)`); кнопка «Отмена» и «нет»/«отмена» текстом отменяют; «да», «ок», «+» текстом — ответ `warehouse.act.pressButton` («Чтобы выполнить, нажмите «Подтвердить» на карточке»), ожидание ставится заново с той же карточкой;
- любое другое сообщение снимает ожидание по общему правилу, карточка устаревает (`onDropped`); срок карточки выходит и сам — кнопки гаснут;
- второе нажатие, нажатие на устаревшую или восстановленную после перезапуска карточку — `answerCard` возвращает `null`, ни одного запроса;
- неизвестный итог записи — карточка «итог неизвестен» и кнопка «Проверить» (`AssistantController.settleCard`): она спрашивает приложение, чем кончилось, и никогда не повторяет запись.

Карточка под последним ответом с ней; итог (`applied`, `failed`, …) виден в самой карточке, а ответ склада приходит отдельным сообщением. Код — `lib/core/connectors/manifest/manifest_actions.dart`, виджет — `lib/app/widgets/action_card_view.dart`, тесты — `test/connectors/manifest/manifest_actions_test.dart`, `test/screens/action_card_view_test.dart`, `test/home_actions_test.dart`.

Встроенные задачи — собственные данные приложения: явные команды над одной задачей («Заверши отчёт») выполняются сразу, массовые — только после вопроса со списком (выше). Тем же механизмом задачи подтверждают завершение по сообщению о сделанном: «я купил хлеб» → «Отметить «Купить хлеб» выполненной?» → «да». Код — `TasksConnector._askToComplete` и `_answer`, тесты — `test/assistant_controller_test.dart` (группа «завершение по сообщению о сделанном») и `test/connectors/router_test.dart`.

## Проверка здоровья

«Как дела?» (навык «Беседа») отвечает из настоящего состояния: задачи и здоровье каждого **включённого** коннектора. Проверку даёт необязательный интерфейс `ConnectorHealth`:

```dart
final class WarehouseConnector implements Connector, ConnectorHealth {
  @override
  Future<HealthReport> health() async {
    final token = await _secrets.read(tokenKey);
    if (token == null) {
      return const HealthReport(HealthStatus.notConnected, detail: 'не подключён');
    }
    if (_lastFailure case final DateTime since) {
      return HealthReport(HealthStatus.degraded, detail: 'сервер отвечает с ошибками', since: since);
    }
    return const HealthReport.ok();
  }
}
```

| Поле `HealthReport` | Значение |
| --- | --- |
| `status` | `ok` — всё работает; `degraded` — с перебоями (медленно, часть данных недоступна); `down` — не работает (нет связи, вход не принят); `notConnected` — ещё не подключено (входа не было или из приложения вышли): это не сбой |
| `detail` | что не так, по-русски, для пользователя: «нет связи с сервером склада». Без секретов и технических кодов |
| `since` | с какого момента такое состояние: начало сбоя или время последнего успеха; `null` — неизвестно |

- Проверка ничего не меняет и быстрая: лучше вернуть запомненное состояние последних запросов (связь, вход, время последнего успеха), чем делать новый тяжёлый запрос. Беседа ждёт не дольше `ConnectorHealth.timeout` (3 с): не ответил — «не ответил на проверку вовремя» (`degraded`), исключение — «проверка не удалась: …» (`down`).
- Коннектор без `ConnectorHealth` проверить нельзя: «Как дела?» не говорит о нём «все подключения работают», а называет его — «Навыки и подключения с проверкой работают. Проверить не могу: «Название».» (`talk.status.okUnchecked`). Встроенные `tasks` (читаются ли задачи), `calc` и `talk` всегда отвечают `ok`, если ничего не сломано.
- `notConnected` — задуманное состояние (роль «Кладовщик» включена, а в склад ещё не вошли или вышли), а не неисправность: «Как дела?» не говорит «не работает», не предлагает жалобу и не ставит вопрос. Ответ — `talk.status.okPending` («У меня всё в порядке: всё, что подключено, работает.») и, если подключение принадлежит включённой роли, короткая подсказка `role.notConnected` («Склад ещё не подключён — Настройки → Роли → Кладовщик → Подключить склад.»).
- Всё хорошо — «У меня всё в порядке: все навыки и подключения работают.» и число активных и просроченных задач. Есть проблема — «Не всё в порядке: «Склад» не работает: нет связи с сервером (с 9:05). Передать жалобу администратору?». Ответ «да» сейчас честно говорит, что передать жалобу пока нельзя: это появится вместе с поддержкой на сервере коннектора; «нет» — «Хорошо, не передаю.». Никаких сетевых запросов.

### Жалобы: что должен уметь сервер

Жалоба на сбой отправляется **серверу приложения коннектора** (у halowarekeep — новое действие «принять жалобу»), а не хранится в помощнике: закрытое приложение не должно терять жалобу, а отсчёт времени должен идти, даже когда телефон выключен. Требования к серверу:

1. **Принять жалобу** — `POST` с телом: коннектор, состояние и пояснение из `HealthReport`, `since`, время жалобы, версия помощника, текст пользователя (если есть). Без секретов и личных данных сверх того, что пользователь сам написал. Ответ — id жалобы; повторная отправка той же жалобы (тот же ключ идемпотентности) не создаёт вторую.
2. **Доставить редакторам** приложения сразу после приёма (уведомление, очередь, почта — как принято у приложения).
3. **Эскалировать администратору**, если за 3–5 часов никто из редакторов не ответил. Срок — настройка коннектора на сервере. Отсчёт и эскалация — только на сервере.
4. **Статус жалобы** по id (`принята`, `в работе`, `передана администратору`, `закрыта`) — чтобы помощник мог ответить на «что с моей жалобой?».
5. Права — текущего пользователя, как у остальных действий коннектора; жалоба — изменяющее действие, поэтому помощник отправит её только после «да» (ADR-004).

Пока сервер этого не умеет, коннектор не отправляет ничего, а беседа отвечает на «да» записью `talk.complaint.later`.

## Сеть и секреты

- В сеть ходит только `run` и только через `HttpTransport`, полученный в конструкторе. Своих `HttpClient` не создавайте: так тесты подставляют подделку, а приложение решает, давать ли сеть.
- `HttpTransport.send` бросает исключение при обрыве и таймауте (`HttpRequestData.timeout`, по умолчанию 10 с); ответ 4xx/5xx — это `HttpResponseData`, а не исключение. В приложении это `IoHttpTransport` (`lib/main.dart`), в тестах — `FakeHttpTransport` (`test/connectors/fakes.dart`): тесты в сеть не ходят.
- Токены, ключи и пароли — только через `SecretStore` (ключ `<id>.<имя>`: `warehouse.token`). Не в `settings.json`, не в коде, не в логах и не в тексте ответа. В приложении — `FileSecretStore` (отдельный файл в служебной папке, ADR-011; защищённое хранилище платформы — следующий шаг), в тестах — `InMemorySecretStore` с заведомо поддельными значениями.
- Если секрета нет — ответ `noAction` с понятным текстом и **без** обращения к сети. Не ссылайтесь в тексте на экран или пункт меню, которого в приложении нет.

### Как секреты и настройки попадают в коннектор

Так это сделано у склада (`ConnectionService`, экран `ConnectionScreen`), и так же — у следующих подключений:

1. **`SecretStore` один на приложение** — создаётся в `lib/main.dart` и передаётся всем коннекторам. Секреты — только в нём: `<id>.token`, `<id>.sid`.
2. **Несекретное** — адрес приложения, логин, уровень входа, описание (`version`, `etag`, отпечаток, дата проверки, `cached_from` — с какого адреса взят кэш) и здоровье — в `ConnectionStore` (`<документы>/assistant/connections/<app.id>.json`), кэш описания — рядом (`<app.id>.assistant.json`). В `settings.json` — только выбор пользователя: включено ли подключение.
3. **Значения, которые выдаёт другое приложение** (общий пароль склада, личный ключ сотрудника из QR-входа), — секреты: кто их знает, тот получает доступ.
4. **Как пользователь их вводит** — «Настройки → Роли → Кладовщик → Подключить склад» (или «Настройки → Расширения → Подключения → Склад → Настроить»): вставка ссылки входа или ввод вручную. Пароли и ссылка с кодом очищаются из полей после попытки; пароль сотрудника не хранится — только полученный личный ключ. `match`/`run` не принимают секреты из текста чата: история хранится открытым текстом.
5. **Ответ без настройки** — `noAction` без сети: при включённой роли — `role.notConnected` «Склад ещё не подключён — Настройки → Роли → Кладовщик → Подключить склад.», вне ролей — «Склад не подключён. Подключите его: Настройки → Подключения → Склад.».
6. **Сброс.** При 401 коннектор говорит «подключитесь заново» и отмечает сбой в здоровье; секреты молча не стираются. Стирает их только «Выйти».

## Коннектор по описанию `assistant/1`

Приложение само описывает, что помощник умеет: `assistant.json` формата `assistant/1` (у halowarekeep — в корне сайта, формат — `halowarekeep/tools/assistant/README.md`). Один `ManifestConnector` (`lib/core/connectors/manifest/`) работает с любым таким приложением; решение и правила безопасности — ADR-011.

**Слот.** Каждое приложение — свой `ConnectionSlot` в `ConnectionSlots` (`lib/core/connectors/manifest/connection_slots.dart`): id коннектора (`warehouse`), `app.id` описания (`halowarekeep`), обращения («на складе», «склад, …»), свои фразы справки, записи каталога ответов и встроенный профиль входа по ссылке для описаний без `auth.qr`. Слот — код приложения; описание — данные: из него берутся только образцы фраз, регулярные выражения `shape` и шаблоны. Expeora будет вторым слотом с тем же коннектором.

**Описание.** `ManifestDescription.parse` — порт `askCheck` из `core.mjs` плюс пределы Tridot: файл ≤ 256 КБ, команд ≤ 100, фраз в команде ≤ 50, фраза ≤ 120 знаков, `shape` ≤ 200 знаков и компилируется, `app.id` = слоту, **`api.url` того же источника (схема, хост, порт), что и описание** — иначе пароль ушёл бы на чужой хост, `api.method` — `POST`/`GET`, `api.body` — `json`, действие команды входит в `api.only`, **действие входа или выхода (`authActions`) — не команда**: его нет ни в `api.only`, ни в `call.action`. Необязательные поля склада 1.4.56 — `version`, `auth.qr` (вход по ссылке), `auth.logout` (выход на сервере) — читаются, если есть. Какое описание в работе — следующий абзац; без обоих `match` молчит. Описание проверяется заново при подключении, кнопкой «Обновить описание» и в фоне после успешного ответа, если проверке больше суток (`If-None-Match`/`If-Modified-Since`, `304` — без изменений). Не принятое описание прежнее не заменяет (абзац «Не принятое описание» ниже).

**Какое описание главное (ADR-012).** Главное — встроенная копия `assets/connectors/<app.id>.assistant.json` (у склада — описание 1.4.57: `version`, `auth.qr`, `auth.logout`, действия `actions[]`; равна `test/fixtures/assistant/halowarekeep-1.4.57.json`, это проверяет тест). По ней фразы понимаются и до подключения, по ней же идут вход по ссылке (`qr_take`) и выход (`sess_end`) — и со старым складом, у которого в описании этого нет (команд `ask_*` правка не касается). Описание сервера (`assistant.json` по адресу склада, кэш — `connections/<app.id>.assistant.json`) заменяет встроенное (`DescriptionAuthority.choose`, `lib/core/connectors/manifest/description_authority.dart`), только если **все** условия выполнены:

1. разобралось и прошло полную проверку `ManifestDescription.parse` — пределы, тот же источник `api.url`, список действий входа `authActions`;
2. его `version` **новее** встроенной (`1.4.60` > `1.4.56` по числам; нет версии или «1.5.0-beta» — не новее);
3. оно **не расширяет права** (`DescriptionAuthority.widening` — список отличий для экрана, пустой — прав не больше):
   - `api.only` и `call.action` команд — только из `api.only` встроенного описания. Действия входа и выхода сюда не входят: `sess_end` или `auth_check` командой чата не становятся;
   - `auth.qr.action`, `auth.logout.action`, `credentials.sid.get.action` — только из `authActions` своей роли и только в разделе `auth`;
   - `api.url`, `api.action.in` и `api.action.name` — **те же, что во встроенном**. Иначе тот же список действий звал бы другой адрес: `api.url: "api.php?action=item_delete"` с `api.action.name: "a"` дало бы запрос `api.php?action=item_delete&a=ask_stock` с паролем склада;
   - `auth.headers` — те же, что во встроенном: ключи не уходят в других заголовках.
   - `api.method`, `api.errors`, уровни `auth.access`, вход по логину (`credentials.sid.get`), по ссылке (`auth.qr`: действие, `param`, `take`) и выход (`auth.logout`) — те же; у знакомого действия в теле запроса — только знакомые поля (ADR-013);
   - действия записи и `act_settle` описание сервера не называет ни в `api.only`, ни у команды: запись — только из встроенной копии (ADR-013).

Иначе в работе встроенное. Экран подключения пишет, какое описание в работе и почему («В работе: встроенное описание 1.4.56: описание сервера 1.4.50 не новее.», «…описание сервера не принято (расширяет права (действия, которых нет во встроенном: item_delete)).», «В работе: описание сервера 1.4.60: новее встроенного 1.4.56.»). Ответ другого приложения или не описание — «Описание не принято», вход не начинается. Без встроенной копии (будущие слоты) — описание сервера, как раньше.

**Не принятое описание** — описание того же приложения (`format` и `app.id` совпали), которое не прошло проверку или расширяет права, — вход не останавливает, в кэш не попадает и **ничего не заменяет** (`ConnectionService._decide`):

- если кэш описания взят с этого же адреса (`manifest.cached_from` записи подключения равен адресу `assistant.json`), всё остаётся как было: описание в работе, кэш, запись подключения с её `version` и `etag`. `etag` отвергнутого ответа не запоминается — иначе следующая проверка получила бы `304` «не изменилось» про описание, которого у нас нет;
- иначе (первое подключение, другой сервер) в работе встроенное, запись — о нём, без `etag` и без `cached_from`.

Причина видна на экране («…; новое описание сервера не принято (…).») и в `manifestError`. Поэтому состояние сейчас и после перезапуска одно и то же — это проверяет `test/connectors/manifest/description_authority_test.dart`.

**Кэш привязан к серверу.** Файл кэша называется по `app.id`, а годится только серверу, с которого взят: `ConnectionService.restore` берёт кэш в работу, только если `cached_from` равен адресу описания в записи подключения, и `If-None-Match` шлётся только тогда. После «Выйти» и входа на другой склад описание первого вторым не управляет. Кэш без `cached_from` (записан до этого правила) в работу не идёт, `etag` при нём сбрасывается, и описание скачивается заново при следующей проверке.

**Разбор (`match`).** Текст — `SocialPrefix.rest` (снято «привет, …»), затем `askText` и правила `askCompile`/`askRule`/`askSlot`/`filler` из `core.mjs` один к одному. Сверху — правила Tridot:

| Случай | Уверенность |
| --- | --- |
| поле и ≥ 2 слов вокруг: «где лежит {q}», «что в ячейке {cell}» | 0.9 |
| поле и одно слово: «где {q}», «сколько {q}», «ячейка {cell}» | 0.75 |
| без поля, ≥ 2 слов: «что пришло сегодня», «за неделю», «без фото» | 0.9 |
| без поля, одно слово: «сегодня», «вчера», «помощь», «команды», **«привет»** | не берём (только с обращением «склад, сегодня») |
| голое поле с `shape` — весь текст код: «215-1-1-1», «без места» (не «215 - 3» с пробелами — это пример) | 0.85 |
| `fallback` описания — только один код 5–6 цифр («64115») | 0.7 |
| `fallback` с обращением: «на складе стул венский» | 0.75 |
| справка — своими фразами слота: «что умеет склад», «помощь по складу»; фразы `help` описания («привет», «что ты умеешь») не используются, их отвечает беседа | 0.9 |
| обращение в начале («на складе …», «склад, …») | +0.05 |
| роль «Кладовщик» включена и склад подключён (`RoleHints`, ADR-012): голый код 5–6 цифр | 0.9 |
| то же: одно слово без поля у команды с запросом — «сегодня», «вчера» (не справка); **не в чате задачи** и **не в ответ на вопрос помощника** | 0.85 |
| начало фразы с полем без самого поля, ≥ 2 слов: «где лежит», «сколько осталось» (после обращения — и одно слово: «склад, найди») — команда `<id>.<команда>` с вопросом `warehouse.ask`, без запроса | 0.9 |

С выключенной ролью «Кладовщик» коннектор склада не спрашивается вовсе (`ExtensionRegistry.enabledConnectors`), даже подключённый.

Подсказка для голых слов уступает задачам: в чате задачи (`Utterance.chatTaskId`) «сегодня» — новый срок задачи чата, а после вопроса помощника («На когда перенести задачу?», «да или нет?» — `Utterance.awaitingAnswer`, ставит маршрутизатор, когда предыдущий ответ был `needsClarification` или ждёт подтверждения) слово — ответ на вопрос, а не вопрос складу. С обращением («склад, сегодня») — всегда склад.

«Где лежит» без артикула (кнопка «Где лежит…» и сразу «Отправить», «подскажи, где лежит») — не поиск слова «лежит» правилом «где {q}»: коннектор спрашивает «Уточните, что искать: артикул или название. Например: «где лежит 64115».» (`warehouse.ask`, `needsClarification`, название поля — `slots.<поле>.label` описания) и в сеть не ходит. Фраза, которая целиком есть в описании («сколько пришло»), — не начало. Не подключено — обычная подсказка `role.notConnected`.

Текстовое поле (`type: text`) отклоняет фразу целиком, если в нём слова задач и чата (`задач*`, `напомин*`, `дел`), обращение к помощнику или о себе (`ты`, `тебе`, `мне`, …), пример (`+*/=^%`, «будет», «плюс»), время и возраст («времени», «дней», «лет») или слова срока из `Utterance.due` (коды 5–6 цифр сроком не бывают). Поэтому «сколько у меня задач» — задачам, «сколько будет 2+2» — калькулятору, «сколько тебе лет» — беседе, «где лежит 15.11» — никому. Образцы привязаны к началу и концу фразы: «Добавь задачу проверить, где лежит 64115» складу не достаётся. Перед разбором снимаются «кстати», «узнать», «проверить» в начале и запятые после связок («покажи мне, где лежит …»). Сообщение длиннее 200 знаков не разбирается: `shape` пришёл извне.

**Выполнение (`run`).** `reply`-команда («сколько стоит …») и справка — без сети. Без пароля — `noAction`: если склад включила роль — `role.notConnected` каталога («Склад ещё не подключён — Настройки → Роли → Кладовщик → Подключить склад.»), иначе `warehouse.notConnected`; без личного ключа для уровня `staff` — «Это видно только под своим логином», в обоих случаях ни одного запроса. Иначе — `POST <api.url>?<action.name>=<действие>` с телом `askBody` (`{$today}`, `{$yesterday}`, `{$today-6}`, `{$tz}` = `-timeZoneOffset` в минутах строкой, `{$zone}` — пусто: имени пояса в Dart без пакета нет) и заголовками `auth.headers` только для ключей уровня команды. Тайм-аут 15 с. Ответы:

| Ответ сервера | Запись каталога | Статус, здоровье |
| --- | --- | --- |
| 2xx, JSON-объект | `warehouse.answer` (+ строки, `warehouse.more`), `warehouse.empty`, `warehouse.fallbackEmpty` (голый код и пусто — примеры вопросов) | `completed`, ok |
| 2xx не JSON, 5xx | `warehouse.serverError` | `failed`, degraded |
| 401 | `warehouse.auth.token` | `failed`, down |
| 403 `need: login` с ключом / без | `warehouse.auth.expired` / `warehouse.auth.staff` | degraded / — |
| 403 `need: role` | `warehouse.auth.role` | — |
| 429 | `warehouse.busy` | — |
| другой 4xx с `error` | `warehouse.serverSaid` «Склад ответил: …» | `completed` |
| обрыв / тайм-аут | `warehouse.offline` / `warehouse.timeout` | `failed`, down |

**Ответ без сети** (`reply` описания, у склада — цена): если у слота есть своя запись (`ConnectionSlot.commandReplies`: `price` → `warehouse.price`), отвечает она — голосом помощника; текст описания (на «вы», о «помощнике» в третьем лице) — только для незнакомой команды (`warehouse.reply`).

**Обращение «склад, …».** После обращения без явной фразы описания остаток уходит в `fallback` (поиск товара), но не команда задач («склад, напомни …», «склад, запиши …») и не реплика («склад, спасибо», «склад, да», «склад, готово») — их коннектор не берёт, и маршрутизация та же, что без склада.

**Ответ.** Описание даёт нейтральный факт — текст `say`/`empty` без рода и «вы/ты» (`askView`, числа `num`, формы `plural`, даты `date`, `or`/`if`/`unless`, `max` и «и ещё N»). Каталог Tridot оборачивает его голосом помощника: `warehouse.answer` = `{text}`, «Показаны не все — {вы:уточните|ты:уточни} запрос.», предупреждения — `protected`. Строки списка (до 8 первого уровня) — текстом: `• 64115 — Стул венский — 1 200 шт.`, вложенные — `   – 215-1-1-1 — годен — 1 000 шт.`. Ссылки (`links`, артикул, ячейка, приход) пока не открываются: адресов для них в описании нет (docs/PLANS.md).

**Здоровье** — из запомненного состояния, без сети (успешная команда без личного ключа не снимает «ключ устарел» — его снимает команда с ключом или новый вход): «не подключён» — `notConnected` (не сбой: «Как дела?» не жалуется, см. «Проверка здоровья»); «нет связи с сервером», «не принял пароль» — `down`; «отвечает с ошибками», «команды под логином недоступны: нужен новый вход» — `degraded`; иначе `ok` с `since` = последний успех.

**Вход** (`ConnectionService`):

- **По ссылке.** В складе: «Профиль» → «Войти на телефоне» → «Скопировать ссылку», ссылка `https://<склад>/#qr=<32 hex>` вставляется в «Настройки → Роли → Кладовщик → Подключить склад» (или «Расширения → Подключения → Склад → Настроить»). Адрес сервера берётся из ссылки (не зашит в приложение): без `#`, `?` и `*.html`, только `https` (`http` — для своей сети: `localhost`, `127.*`, `10.*`, `192.168.*`, `172.16–31.*`), без логина в адресе. Дальше `GET <адрес>/assistant.json`, проверка, и действие входа: `auth.qr` описания (1.4.56) или встроенный профиль слота (`qr_take {code}`, без пароля склада). Ответ `{token, sid, login}` → `SecretStore`; 400/410/429 — тексты описания или слота. QR камерой телефона не сканируют: ссылка откроется в браузере, и одноразовый код потратит сайт склада. Кнопка «Скопировать ссылку» появилась в складе 1.4.56: в старом складе её нет, экран подключения и README так и говорят — подключать вручную. Ссылка, вставленная в чат, получает `common.loginLink` («её вставляют в Настройки → Подключения»), а код в историю чата и команд не пишется (`LoginLinks.redact`).
- **Вручную.** Адрес + «Пароль склада»: пароль проверяется безвредным чтением — первой командой уровня `shared` с полями «0» (у склада `ask_stock {q:"0"}`). Пароль принят только при 2xx с JSON-объектом без `ok:false`; 401 — «не принял пароль», 3xx и 404 — «не тот адрес», 429 — «подождите», не JSON — «отвечает не склад»; без команды уровня `shared` пароль не проверить — и он не сохраняется. По желанию логин и пароль сотрудника → `credentials.sid.get` (`auth_check`) → личный ключ; «осталось N попыток», «подождите N секунд». Пароль сотрудника не хранится. Без логина — уровень `shared`: остатки и ячейки; «Войти под логином» доступно позже.
- **Действия входа.** `auth.qr.action`, `auth.logout.action` и `auth.credentials.sid.get.action` зовутся с паролем и ключом, поэтому проверка описания пускает только известные безвредные действия (`ManifestDescription.authActions`: `qr_take`, `auth_check`, `sess_end`), не из `api.only`; и обратно — эти действия живут только в разделе `auth`: описание, где действие входа стоит в `api.only` или у команды, проверку не проходит; `get.body` — только поля со значениями `{login}` и `{pass}`, `get` — только у `sid`. Перед запросом `ConnectionService` проверяет то же ещё раз. Новое приложение — дописать его действия после чтения его кода.
- **Выход.** Если в описании есть `auth.logout` (1.4.56) — `sess_end` с паролем и ключом, ответ и ошибки не важны (ждём не дольше 5 с); пароль и ключ удаляются с устройства всегда. Адрес и кэш описания остаются; роль «Кладовщик» остаётся включённой, и фразы склада получают `role.notConnected` (вне ролей подключение выключается, как раньше).

**Действия с записью (склад 1.4.57, ADR-013).** Отметка проведения прихода и перемещение между ячейками — не команды, а отдельный путь (`lib/core/connectors/manifest/manifest_actions.dart`):

- **Откуда берутся.** Только из раздела `actions[]` **встроенной** копии (`ManifestConnector.builtIn`, разбор с `builtIn: true`); у описания сервера раздел не разбирается, даже когда оно в работе для чтения. Пара «расчёт — запись» — в коде (`ManifestDescription.writeActions`), тела запросов, карточка и ответы — код по виду (`move`, `post`).
- **Проверка формата** (как `core.mjs` склада): `api.only ∩ api.act = ∅`; у действия известный `kind`, `check` из `api.only`, `write` из `api.act`, доступ только с личным ключом, нет `call`/`answer`/`help`/`reply`, не `fallback`, у ячеек есть `shape`, в каждой фразе ≥ 2 слов вокруг полей; команды не зовут ни записи, ни расчёты; действия входа не из `api.act`. Описание сервера, которое называет запись или `act_settle` в `api.only` или у команды, отвергает `DescriptionAuthority.widening`; там же закреплены `api.method`, `api.errors`, `auth.access`, `credentials.sid.get`, `auth.qr`, `auth.logout` и поля тела знакомых действий.
- **Фразы** (`actions[].say`): «перемести/переложи {what} из {from} в {to}», «… из {from}», «… в {to}» (без «откуда» склад ищет по всем ячейкам), «проведи приход {no}», «… в 1с»/«в 1c» (только 1С), «… в sv»/«в св» (только SV), «отметь проведение прихода {no}», «приход {no} проведён …». Уверенность 0.9 (с обращением 0.95), проверяются раньше команд. Поле-ячейка с `shape` вшивается в выражение. `{what}` разбирает `ActWhat`: количество — ведущее («3», «3 шт», «три», «все»), 5–6 цифр — артикул, класс — последним словом («уценка», «брак», «реализация», «образец», «утиль»), остаток — запрос по названию, если он не про задачи, беседу, пример или срок. «Перенеси», «закрой» — слова задач (в корпусе `known_gap`).
- **Шлюзы без сети:** не подключено — `role.notConnected`; не под своим логином — `warehouse.act.needLogin`; «Разрешить действия» выключено — `.off`; разрешено для другого логина — `.otherLogin`; «без места» и одна и та же ячейка — `.noPlace`, `.sameCell`.
- **Ход:** расчёт `act_*_check` (`POST`, ключи только в заголовках, тело `{v: 1, …}` с числами — числами) → вопрос (`ask: row/qty/to/entry` → `warehouse.act.ask.*`, ответ номером, числом, «все» или ячейкой — `ConfirmationFollowUp`, не больше 4 вопросов — `.tooMany`) или «уже отмечено» (`.already`) или карточка (`.ask.move`, `.ask.post`) после сверки `commit` со сказанным (иначе `.mismatch`) → по кнопке запись `act_*` (тайм-аут 30 с, без автоповторов) с `rid`, `exp`, `stamp` → `.moved` / `.posted`.
- **Ответы записи:** 409 `stale` + `fresh` — старая карточка «заменена», новая с новым `rid` и словами `.stale` (в черновике «все» — новый расчёт по черновику, а не `fresh`: склад считает `fresh` по прежнему числу из `commit`); `short`, `locked`, `draft`, `not_found`, `no_cell`, `cell_group`, `only_there` (`.onlyThere`: «откуда» не названо, а товар лежит только в «куда»), `qty_limit` (`.qtyLimit`: «все» больше 9999 шт.), `clock_order` — свои записи, карточка «не выполнено», статус `failed`; `expired` — `.expired`; `void`/`rid_reused`/`in_progress`, обрыв и **любой 5xx, кроме `storage` и `selfcheck`** (`unknown` — «итог неизвестен», сбой без кода, 5xx без тела) — `act_settle` (`done` → итог, `void` → `.voided`, `failed` → тот же разбор отказа по коду, что у записи, `stale` — новый расчёт, `pending` → `.pending`, нет связи → `.unknown` и «Проверить»); 500 `storage`/`selfcheck` — «ничего не изменилось», `.failed`; 403 `off` — `.serverOff`, `no_right`/`rights_unknown` — `.denied`, `login` — `warehouse.auth.expired`; склад без патча отвечает на расчёт 400 без `code` — `.unsupported`. Прочие 4xx — `.failed` «Склад отказал: …».
- **Карточка в истории до записи.** По «Подтвердить» карточка становится `sending` и сохраняется в историю чата (`ActionCard.onSending` → `ChatBook.touch` + `flush`, не дольше 2 с) **до** запроса: приложение закрыли посреди записи — после перезапуска «итог неизвестен» с «Проверить», а не «устарела».
- **Адреса.** Ячейки сравниваются без различия «е»/«ё» и регистра (`_cellKey`): фраза приходит с «е», склад отвечает адресом схемы («303-ЗОНА ПРИЁМКИ»). `shape` ячеек действий пускает имя зоны из двух слов («303-зона приёмки»). Номер прихода `{no}` — с цифрой: «проведи приход завтра», «отметь проведение прихода утром» — не действие (слово срока уходит в задачи).
- **Чтение 1.4.57:** «что не проведено» — команда `unposted` (`ask_unposted`, уровень `staff`).

**Корпус.** `test/corpus/warehouse.jsonl` (примеры описания, фразы `say` с подставленными значениями, отрицательные), темы — `tools/corpus_gen/topics/warehouse.toml`, фабрика в `_connectorFactories` и `tool/route_phrases.dart` строит коннектор из `test/fixtures/assistant/halowarekeep.json` со встроенной копией 1.4.57 (`halowarekeep-1.4.57.json`, действия). Роли в корпусе: по умолчанию включены «Личное» и «Кладовщик», склад не подключён; поля строки `roles` и `connected` меняют это (`docs/CORPUS.md`). `commandId` — `warehouse.<id команды>`: `warehouse.where`, `.count`, `.price`, `.cell`, `.today`, `.yesterday`, `.week`, `.nophoto`, `.help`; действия — `warehouse.act.move`, `warehouse.act.post`.

**Тесты** — `test/connectors/manifest/` (описания: текущее, 1.4.56 и 1.4.57 с действиями — `manifest_actions_test.dart`, ответы сервера — `test/fixtures/assistant/responses/`) и `test/screens/connection_screen_test.dart`.

## Полный пример: «Пример склада»

Учебный коннектор с собственным API — образец «коннектора кодом». В приложении и в корпусе его нет: настоящий склад — коннектор по описанию (раздел выше). Пример живёт в `test/connectors/example_warehouse_connector.dart`, его тест рядом.

Учебный коннектор только для чтения: отвечает на «где лежит {код}». Тот же код лежит в `test/connectors/example_warehouse_connector.dart` и проверяется тестами `test/connectors/example_warehouse_connector_test.dart`; если меняете пример, меняйте оба места.

Сервис склада вымышленный: `GET {baseUri}items/{код}/location` с заголовком `Authorization: Bearer {токен}` отвечает `{"cell": "A-03-2", "quantity": 12}`, 404 — нет товара, 401/403 — неверный токен.

```dart
import 'dart:convert';

import 'package:local_assistant/core/connectors/connector.dart';
import 'package:local_assistant/core/connectors/http_transport.dart';
import 'package:local_assistant/core/connectors/secret_store.dart';

/// Что `match` разобрал из фразы и передаёт в `run`.
final class LocateRequest {
  const LocateRequest(this.codes);

  /// Артикулы из фразы. Больше одного — `run` переспросит.
  final List<String> codes;
}

/// «Пример склада»: только чтение, отвечает на «где лежит {код}».
final class ExampleWarehouseConnector implements Connector {
  ExampleWarehouseConnector({
    required HttpTransport transport,
    required SecretStore secrets,
    required Uri baseUri,
  })  : _transport = transport,
        _secrets = secrets,
        _baseUri = baseUri;

  static const String id = 'warehouse_example';

  /// Ключ токена в [SecretStore]: `<id коннектора>.<имя>`.
  static const String tokenKey = '$id.token';

  final HttpTransport _transport;
  final SecretStore _secrets;
  final Uri _baseUri;

  static const Set<String> _questionWords = <String>{'где'};

  static const Set<String> _locateVerbs = <String>{
    'лежит',
    'лежат',
    'хранится',
    'хранятся',
    'находится',
    'находятся',
  };

  @override
  ConnectorInfo get info => const ConnectorInfo(
        id: id,
        title: 'Пример склада',
        description: 'Подсказывает, в какой ячейке лежит товар по артикулу.',
        examples: <String>[
          'Где лежит 64115',
          'где хранится артикул 64115?',
          '64115 где лежит',
        ],
        requiresNetwork: true,
        access: ConnectorAccess.readOnly,
        // Тексты ответов — записи каталога (docs/REPLIES.md): нейтральный
        // текст с разметкой рода {м:…|ж:…} и обращения {вы:…|ты:…}.
        // Факты (код, ячейка, остаток) приходят подстановками.
        replies: <String, String>{
          'warehouse.ask.code': 'Какой артикул найти: {codes}?',
          'warehouse.notConnected':
              'Склад не подключён: токен склада не задан.',
          'warehouse.notFound': 'Артикул {code} на складе не найден.',
          'warehouse.badToken':
              'Склад не принял токен. {вы:Подключите|ты:Подключи} склад заново.',
          'warehouse.httpError': 'Склад ответил ошибкой {status}.',
          'warehouse.located':
              'Артикул {code} лежит в ячейке {cell}, остаток {quantity} шт.',
        },
      );

  @override
  ConnectorMatch? match(Utterance utterance) {
    final codes = utterance.codes;
    if (codes.isEmpty) return null;
    final asksWhere = utterance.hasAnyWord(_questionWords);
    final saysLies = utterance.hasAnyWord(_locateVerbs);
    if (!asksWhere && !saysLies) return null;
    // Фраза целиком о складе: начинается с «где» или с кода и содержит
    // и вопрос, и глагол. Иначе «где лежит» может быть частью другой
    // команды («Добавь задачу проверить, где лежит 64115») — тогда уверенность
    // средняя, и команда с явным глаголом уверенно победит.
    final first = utterance.tokens.first.text;
    final wholePhrase = first == 'где' || codes.contains(first);
    return ConnectorMatch(
      connectorId: id,
      commandId: 'warehouse.locate',
      confidence: asksWhere && saysLies && wholePhrase ? 0.9 : 0.6,
      payload: LocateRequest(codes),
    );
  }

  @override
  Future<AssistantResponse> run(
    ConnectorMatch match,
    AssistantSession session,
  ) async {
    final request = match.payload! as LocateRequest;
    if (request.codes.length > 1) {
      return session.reply(
        'warehouse.ask.code',
        values: <String, String>{'codes': request.codes.join(' или ')},
        intent: match.commandId,
        status: AssistantStatus.needsClarification,
      );
    }
    final code = request.codes.single;
    final token = await _secrets.read(tokenKey);
    if (token == null) {
      return session.reply(
        'warehouse.notConnected',
        intent: match.commandId,
        status: AssistantStatus.noAction,
      );
    }
    final response = await _transport.send(
      HttpRequestData(
        method: 'GET',
        uri: _baseUri.resolve('items/${Uri.encodeComponent(code)}/location'),
        headers: <String, String>{
          'Authorization': 'Bearer $token',
          'Accept': 'application/json',
        },
      ),
    );
    if (response.statusCode == 404) {
      return session.reply(
        'warehouse.notFound',
        values: <String, String>{'code': code},
        intent: match.commandId,
        status: AssistantStatus.completed,
      );
    }
    if (response.statusCode == 401 || response.statusCode == 403) {
      return session.reply(
        'warehouse.badToken',
        intent: match.commandId,
        status: AssistantStatus.failed,
      );
    }
    if (!response.isSuccess) {
      return session.reply(
        'warehouse.httpError',
        values: <String, String>{'status': '${response.statusCode}'},
        intent: match.commandId,
        status: AssistantStatus.failed,
      );
    }
    // Неверный JSON бросит исключение — маршрутизатор вернёт `failed`.
    final json = jsonDecode(response.body) as Map<String, Object?>;
    final cell = json['cell'] as String;
    final quantity = json['quantity'] as int;
    return session.reply(
      'warehouse.located',
      values: <String, String>{
        'code': code,
        'cell': cell,
        'quantity': '$quantity',
      },
      intent: match.commandId,
      status: AssistantStatus.completed,
    );
  }
}
```

Что здесь важно:

- `match` смотрит только на `utterance.codes` и слова целиком. Код «64115» уже отделён от дат: «Где лежит 15.11» не совпадёт, потому что кодов нет.
- Уверенность 0.9 только если фраза целиком о складе (начинается с «где» или с кода). В «Добавь задачу проверить, где лежит 64115» складу достаётся 0.6, задачам 0.9 — разница больше 0.15, побеждают задачи без уточнения.
- `run` сначала проверяет многозначность и токен — до сети.
- Тексты — записи каталога в `info.replies`; `run` передаёт только факты (`code`, `cell`, `quantity`). Лиорио скажет «не нашёл», Нода — «не нашла», в дружеском или деловом стиле — своими словами, но с теми же фактами.
- Неожиданный ответ (не JSON) бросает исключение, и маршрутизатор отвечает `failed`; помощник не падает.

## Подключение в `lib/main.dart`

Коннекторы регистрируются в `ExtensionRegistry` списком; порядок важен только при равной уверенности (и тогда всё равно будет уточнение). Что из них включено — выбор пользователя в «Настройки → Расширения» (`docs/EXTENSIONS.md`):

```dart
final extensions = ExtensionRegistry(
  connectors: <Connector>[
    TasksConnector(taskService: tasks, parser: ScenarioParser(clock: clock)),
    const CalculatorConnector(),
    // Подключения по описанию assistant/1: коннектор каждого слота.
    for (final connection in connections) connection.connector,
  ],
  packs: packs,
);
final assistant = AssistantController(extensions: extensions, clock: clock);
```

В тестах можно по-прежнему писать `AssistantController(connectors: <Connector>[…])` — тогда все коннекторы включены.

## Фразы коннектора в корпусе

Корпус (`docs/CORPUS.md`) общий для всех коннекторов. Строка с полем `connector` относится к этому коннектору; без поля — к `tasks`.

```json
{"id":"wh-001","text":"где лежит 64115","connector":"warehouse","intent":"warehouse.where","source":"manifest"}
{"id":"wh-041","text":"сегодня","connector":"warehouse","intent":"unknown","note":"однословные фразы без поля склад не берёт","source":"manual"}
```

- Для коннектора, отличного от `tasks`, `intent` — ожидаемый `commandId` или `unknown` («этот коннектор не должен откликнуться»). Поля разбора задач (`title`, `due`, …) в таких строках могут быть только пустыми (`null`, `none`) — их значения не проверяются.
- Для каждой строки с `intent` ≠ `unknown` тест проверяет и маршрутизацию: среди всех коннекторов из `_connectorFactories` должен победить указанный, причём без уточнения «к чему относится команда».
- Чтобы корпус знал коннектор, добавьте фабрику в `_connectorFactories` (`test/scenario_corpus_test.dart`) с подделками сети и секретов — `match` их не трогает.
- Новые фразы удобно размечать `tools/corpus_gen` (модели — только при разработке, ADR-001): файл тем `tools/corpus_gen/topics/<id>.toml`, где `intents` — **ровно** ваши `commandId` плюс `unknown` (формат — `tools/corpus_gen/README.md`). Генератор пишет такие фразы со `status: active`, а проверяет их этот тест; если строка падает, исправьте разметку или коннектор либо поставьте ей `known_gap`.

## Чек-лист перед подключением

- [ ] `id` уникален, `title` понятен пользователю, `examples` проверены тестом.
- [ ] Если у коннектора есть связь, вход или внешнее состояние — `ConnectorHealth` с понятным `detail` и `since` (раздел «Проверка здоровья»).
- [ ] Тексты ответов — записи `ConnectorInfo.replies` (нейтральный текст с разметкой рода и обращения), `run` отвечает через `session.reply`.
- [ ] `kind` указан (`skill` — без сети, `connector` — внешнее приложение), `version` и `author` заполнены; `defaultEnabled` обдуман: по умолчанию включается минимум (ADR-005).
- [ ] `match` без ввода-вывода; чужие фразы (задачи, даты, вопросы без кода) дают `null`.
