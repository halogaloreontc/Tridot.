# Tridot — технический прототип

**Tridot** (по-русски «Тридот»; служебное латинское имя — **Relay**, ADR-009, ADR-016) — локальное приложение на Dart/Flutter, в котором работают помощники Садо (главный: беседа, задачи, планирование, калькулятор), Лиорио (расширения: склад, пароли, подключения) и Нода (оповещения: напоминания, просрочки, сигналы склада), без обращения к языковой модели. Название не склоняется: «в Tridot», «настройки Tridot»; помощники себя по названию приложения не называют. Режимы — Соло, Дуэт и Трио; имена, пол и обязанности помощников настраиваются в «Мой Tridot» → «Помощники» (`docs/REPLIES.md`). Этот репозиторий реализует первый вертикальный срез, а не весь объём ТЗ.

## Что реализовано

- создание задачи обычной фразой: «Добавь задачу позвонить клиенту завтра в 10», «напомни мне завтра в 9:30 оплатить интернет»; точное название можно взять в кавычки « », “ ”, „ “ или " " — они важнее остального текста;
- сроки «сегодня», «завтра», «послезавтра», дата ДД.ММ[.ГГ|.ГГГГ], время ЧЧ:ММ, «в ЧЧ.ММ», «в 10», «в 9 утра», «в 7 вечера»; при переносе «с … на …» берётся новое значение;
- дни недели и относительные сроки: «в пятницу», «во вт в 10», «в пт к 18:00», «до субботы», «в следующую среду», «на следующей неделе в пятницу», «в эту пятницу», «через 3 дня», «через час», «через полчаса», «через пару дней», «через 2 часа 30 минут», «на следующую неделю», «на выходных», «в конце недели»; слова срока не попадают в название («напомни в пятницу купить хлеб» → «Купить хлеб»), а «пятничный отчёт» или «среда разработки» сроком не считаются;
- перенос и завершение задачи по названию — точному в кавычках или по словам: «Перенеси отчёт на завтра», «Заверши купить хлеб»; при нескольких похожих задачах помощник переспрашивает;
- задачи без слова «добавь»: фраза, которая начинается с действия, — это новая задача: «через 3 дня сдать отчёт», «надо купить хлеб», «не забыть оплатить интернет завтра»; вопросы («купить хлеб?», «купить ли хлеб»), отрицания («купить хлеб не надо»), просьбы к самому помощнику («показать список», «отметить хлеб») и фразы с существительного («ногти постричь») задачами не считаются; такая догадка уступает явной команде другого коннектора («узнать, где лежит 64115» — складу), а дубль активной задачи не создаётся;
- час сразу после дня — время, даже если дальше существительное: «Добавь в следующий понедельник в 9 планёрка» → 09:00, «Планёрка»;
- завершение рассказом о сделанном с подтверждением: «я купил хлеб», «отчёт сдал» → «Отметить «Купить хлеб» выполненной?» → «да»/«нет» (а также «да, купил», «👍», «неа»); рассказ о других («мама купила хлеб») и глагол без предмета («я купил») вопросом не становятся; тем же механизмом подтверждения будут пользоваться изменяющие действия внешних коннекторов (ADR-004);
- массовые команды над несколькими задачами: «перенеси всё на выходные», «перенеси просроченные на пятницу», «все задачи на пятницу перенеси на понедельник», «перенеси всё с #работа на понедельник», «сдвинь всё на час позже», «закрой все просроченные», «заверши всё по #ремонт», «закрой всё, кроме хлеба». Сначала вопрос «Перенести 4 задачи на 7 ноября?» и карточка со списком задач и галочками («Выбрать все / Снять все», «Перенести (N)», «Отмена»); в чате — «да», «нет», «кроме хлеба», «только отчёт», «да, но хлеб не трогай»; после применения — «Отменить» в карточке или «отмени» в чате (`docs/CONNECTORS.md`, `docs/CORPUS.md`, «Массовые команды»);
- склад halowarekeep (подключение, только чтение, ADR-011): «где лежит 64115», «сколько венских стульев», «что в ячейке 215-1-1-1», «что пришло сегодня/вчера/за неделю», «какие приходы без фото», «сколько стоит …» и «что умеет склад» — по описанию `assistant.json` самого склада; ответ — факт склада голосом помощника; «как дела» знает, если склад не отвечает. Как подключить — раздел «Подключить склад» ниже;
- действия на складе (ADR-013, склад 1.4.57): «перемести 3 венских стула из 215-1-1-1 в 215-3-2-1», «переложи 64115 из 215-1-1-1» (куда — спросит), «проведи приход 318» (SV и 1С), «проведи приход 318 в 1с» / «в sv» (одну отметку), «что не проведено». Только под своим логином и при включённом «Разрешить действия» в роли «Кладовщик» (выключено по умолчанию, привязано к логину, снимается при любой смене входа); склад сам считает карточку — что изменится, от чьего имени, до какого времени, — а запись уходит только по кнопке «Подтвердить» (текстовое «да» лишь просит нажать её, «нет» отменяет); вопросы по ходу — «какой?», «сколько?», «куда?»; при обрыве связи помощник спрашивает склад, чем кончилось, и запись не повторяет. Действия берутся только из встроенного описания склада: описание с сервера их не добавит. Со складом до 1.4.57 всё работает как раньше, только чтение;
- роли (ADR-012, `docs/EXTENSIONS.md`): «Настройки → Роли» — заготовки под сферу работы одним переключателем. «Личное» (задачи, калькулятор, беседа) включено по умолчанию, «Кладовщик» (складские вопросы через подключение к складу, кнопки «Где лежит…», «Что пришло сегодня», «Без фото») — нет; можно включить несколько. С «Кладовщиком» и подключённым складом голый артикул («64115») — «где лежит», а «сегодня»/«вчера» — приходы без «склад, …»; без него склад не отвечает вовсе, даже подключённый. Отвечает тот, чья это зона: склад — ведущий расширений (по умолчанию Лиорио), задачи и беседа — Садо (ADR-016); обращение по имени важнее. Выключенная роль прячет навыки и кнопки, но подключение и пароли остаются;
- расширения: Tridot настраивается под себя в «Настройки → Расширения» — навыки (задачи, калькулятор, беседа), подключения к внешним приложениям и паки с содержимым (шутки, каламбуры, фразы); включение и выключение сразу, без перезапуска и без сброса истории, выбора и черновика; паки — только данные формата `assistant-pack/1`, встроенные и вставленные JSON-текстом, со строгой проверкой (ADR-005, `docs/EXTENSIONS.md`);
- три помощника — Садо, Лиорио и Нода (ADR-006, ADR-008, ADR-016, `docs/REPLIES.md`): Садо — главный (беседа, задачи, планирование, калькулятор) и встречает в новой сессии; Лиорио ведёт расширения (склад, пароли, подключения), Нода — оповещения (просрочки на экране новой сессии, сигналы склада); режимы Соло (всё делает Садо), Дуэт (Садо и один помощник на выбор) и Трио; написать помощнику можно обращением по имени («Нода, …», «Лио, …», «Садо, …») — к кому обратились, тот и продолжает, пока открыт чат; у каждого ответа подпись и метка помощника (С, Л, Н); «Мой Tridot» → «Помощники» — режим, имя, пол и стиль каждого с живым примером, кто ведёт расширения и оповещения, «вы»/«ты», эмодзи, частота шуток; пол Садо выбирается при первом запуске; смена настроек ничего не сбрасывает и старые ответы не переписывает;
- каталог ответов: каждый ответ — запись по id с подстановкой фактов, стили нейтральный, дружеский, краткий и деловой (`assets/replies/*.json`), род помощника и обращение — разметкой в тексте; свой стиль ставится паком ответов (`type: replies`) со строгой проверкой: факты, вопросы и предупреждения одинаковы во всех стилях;
- калькулятор: «сколько будет 2+2*2», «15% от 2400», «корень из 144», «3,5 умножить на 12», «2400 плюс 15%», «два плюс два», «2^10», скобки и унарный минус; точный счёт на рациональных числах, ответ по-русски («10 / 3 ≈ 3,333333333», «2 400»), деление на ноль и слишком большие числа — понятным текстом; даты, время, телефоны, диапазоны и задачи с числами примерами не считаются;
- беседа: «привет» (по времени суток), «пока», «спасибо», «как дела?» — из настоящего состояния задач и проверки здоровья коннекторов, при сбое — вопрос о жалобе администратору; «кто ты», «что ты умеешь» (только включённые навыки), шутки и каламбуры из включённых паков без повторов, спокойный ответ на грубость; просьбы «говори короче», «давай на ты», «без смайликов», «шути меньше», «включи трио» меняют настройки сразу, тем же путём, что экран настроек; беседа никогда не перехватывает команды: «привет, добавь задачу купить хлеб» — задача, «привет, сколько будет 2+2» — 4; «хорошо» или «спасибо» в ответ на вопрос «Отметить …?» — переспрос, а не молчаливая отмена (`docs/EXTENSIONS.md`, «Навык «Беседа»»);
- слой коннекторов для команд других приложений: общий разбор сообщения, маршрутизатор с уточнением при спорном выборе, сеть и секреты только внутри коннекторов (ADR-004, инструкция — `docs/CONNECTORS.md`); задачи — встроенный коннектор;
- уточнение вместо догадки: время прошло, дата или время не существуют, несколько разных дней, времён или названий, незакрытая кавычка, отрицание и вопрос вместо команды;
- проекты через метки в команде: «Добавь задачу «Отчёт» #работа»;
- список, выбор, перенос и завершение задач, возврат выполненной задачи в работу;
- постоянное JSON-хранилище с атомарной записью, резервная копия одной кнопкой, настройки в `settings.json`;
- история чатов сохраняется между запусками (`<документы>/assistant/chats/`, файл на чат, ADR-010): сессии (при запуске — новая пустая, прежние — в меню по дням: «Сегодня», «Вчера», «На неделе», «Ранее», с «Закреплёнными» сверху; долгое нажатие — переименовать, закрепить, удалить) и у каждой задачи свой чат — он открывается нажатием на задачу в панели, Обзоре, Проектах и Планировании или ссылкой «Открыть чат задачи» под ответом о новой задаче; в чате задачи «готово», «сделано», «закрой» закрывают её, «перенеси на завтра» и просто «на завтра» переносят, а шапка показывает название, срок, статус и кнопку «Выполнено» / «Вернуть в работу»; меню «Чаты» — последние чаты по активности, «‹» — назад; смена настроек помощников чаты не сбрасывает;
- тёмный интерфейс (шрифт Inter) с разделами:
  - **Задачи** — диалог и документ задачи; строка выбранной задачи («её»), быстрые действия, документы с дисков и шаблоны команд по «+», микрофон для голоса при пустом поле, ↑/↓ для прошлых команд, кубик статуса, полоса истории команд, панель задач по группам сроков;
  - **Документ** — название, проект и заметки задачи с автосохранением и простой разметкой (заголовок, жирный, курсив, список, чекбокс);
  - **Обзор** — счётчики, ближайшие задачи, активность выполнения за 8 недель;
  - **Проекты**, **Планирование** (14 дней вперёд), **Данные** (путь, размер, чаты, копия, архив; Настройки → «Данные и резервная копия»), **Настройки** (меньше анимации, время сообщений, помощники, расширения, очистка истории чатов, лицензии);
- на телефоне меню и список задач открываются выдвижными панелями;
- модульные и сквозные тесты ядра;
- регрессионный корпус фраз `test/corpus/*.jsonl` (формат — `docs/CORPUS.md`).
- инструмент разработки `tools/corpus_gen` (Python): генерация и перекрёстная разметка фраз для корпуса несколькими моделями — Ollama, Claude, Kimi, DeepSeek, Qwen, Grok, OpenAI.

## Что ещё не реализовано

- голосовой режим общения с помощником: кнопка микрофона уже на месте (при пустом поле ввода) и сообщает, что режим в разработке; нужен выбор движка распознавания речи с учётом ADR-001;
- связка с Google Диском и Яндекс Диском для создания и правки документов через помощника: пункты уже есть в меню «+» с пометкой «скоро»;

- SQLite-репозиторий;
- паки по ссылке и выключение отдельных записей пака; отправка жалоб на сбой коннектора (нужна поддержка на сервере приложения, `docs/CONNECTORS.md`);
- поиск по истории чатов, резервная копия чатов, чаты проектов и документов (`docs/PLANS.md`);
- долговременная память о пользователе и отношения с помощниками (`docs/PLANS.md`, «Память и отношения помощников»);
- облачная синхронизация;
- у склада: открытие артикула, ячейки и прихода по ссылке из ответа, карточка ответа вместо строк текстом, секреты в Keychain/Keystore вместо отдельного файла (ADR-011); подключение expeora;
- вторая очередь действий склада (ADR-013, `docs/PLANS.md`): отмена перемещения обратным документом и замок для ручных сохранений склада (`ASSIST_LOCK_SET`); «перенеси …» и «закрой приход …» как фразы действий;
- сроки «в обед», «к вечеру», «на этой неделе» без дня и повторяющиеся («по пятницам»);
- Яндекс Диск и Google Drive;
- текстовые и табличные артефакты;

Platform runners для Android, Windows, Linux и macOS уже находятся в репозитории. Повторно выполнять `flutter create` при обычном клонировании или запуске не нужно.

## Требования

Установите стабильный Flutter SDK. Прототип проверен с Flutter 3.47.9 и встроенным Dart 3.13.7 на macOS arm64.

Дополнительные инструменты зависят от платформы:

- Android: Android SDK и Java 17;
- Windows: Visual Studio с рабочей нагрузкой «Разработка классических приложений на C++»;
- Linux: Clang, CMake, Ninja, pkg-config и заголовки GTK 3;
- macOS: полный Xcode и CocoaPods для нативного плагина `path_provider`.

Сейф паролей (ADR-014, ADR-025: защита ключом устройства и кодом восстановления, ПИН-код и вход по отпечатку / Face ID — по желанию; на Android ключ в Android Keystore, на Windows — под DPAPI, на macOS и Linux — честный запасной вариант файлом в папке приложения) использует libsodium через пакет `sodium` 4.x. Системная libsodium не нужна: build-хук пакета собирает её из исходников, вложенных в пакет, при первом `flutter test`, `flutter run`, `flutter build` или `dart run` (около полуминуты, дальше из кэша `.dart_tool`). Для этого нужен компилятор C и `make`: на Linux и macOS они уже есть вместе с инструментами выше (на чистом Ubuntu — `sudo apt-get install -y build-essential`, на раннере GitHub Actions `ubuntu-latest` есть из коробки), на Windows — Visual Studio с C++; сборка Android на Windows дополнительно требует bash (не из WSL), см. README пакета `sodium`.

Конвертер звука и видео на Android и macOS (ADR-026) кодирует MP3 встроенным LAME 3.100 (LGPL-2.0-or-later): исходники лежат в `packages/tridot_lame`, его build-хук так же сам собирает из них разделяемую библиотеку `libtridot_mp3` для Android, macOS и Linux (на Linux она нужна только тестам). Нужен тот же компилятор C. Swift-часть для macOS (`macos/Runner/MediaChannel.swift`, `MediaPipelines.swift`) собирается только в Xcode на Mac.

## Первый запуск

Клонирование и запуск из корня проекта:

```bash
git clone https://github.com/halogaloreontc/qenqritec.git
cd qenqritec
flutter pub get
flutter devices
flutter run -d macos
```

Вместо `macos` выберите доступную платформу:

```bash
flutter run -d windows
flutter run -d linux
flutter run -d android
```

Команда `flutter create --platforms=android,windows,linux,macos --project-name local_assistant .` нужна только для намеренного пересоздания runners, а не для обычной настройки. Перед такой регенерацией сохраните изменения: новые версии Flutter могут добавлять шаблонные файлы. Пакет и id приложений остаются `local_assistant`, а название Tridot (и служебное латинское Relay) после пересоздания нужно вернуть в заголовки окон, подписи и иконки запуска (список файлов — ADR-009, ADR-016).

## Подключить склад

Склад отвечает, пока включена роль «Кладовщик» («Настройки» → «Роли»). Роль можно включить и до подключения: тогда на складские фразы помощник отвечает «Склад ещё не подключён — Настройки → Роли → Кладовщик → Подключить склад». Адрес сервера не зашит в приложение: он берётся из ссылки входа или вводится вручную.

1. **По ссылке (удобнее).** В складе войдите под своим логином: «Профиль» → «Войти на телефоне» → «Скопировать ссылку». В Tridot: «Настройки» → «Роли» → «Кладовщик» → «Подключить склад» (или «Расширения» → «Подключения» → «Склад» → «Настроить»), вставьте ссылку (`https://<склад>/#qr=…`) и нажмите «Подключить». Не сканируйте QR камерой телефона и не открывайте ссылку в браузере: код одноразовый, живёт две минуты, и его потратит сайт склада. Кнопка «Скопировать ссылку» есть в складе с версии 1.4.56; в более старом складе её нет — подключайте вручную. Ссылку не вставляют в чат: помощник подскажет, куда её нести, а код в историю не запишет.
2. **Вручную.** «Ввести вручную»: адрес склада (`https://…`; `http://` — только в своей сети), «Пароль склада» и, по желанию, логин и пароль сотрудника. Без логина видны только остатки и ячейки; приходы — под своим логином («Войти под логином» можно и позже). Пароль сотрудника не сохраняется — только личный ключ. Пароль склада сохраняется, только если склад ответил на пробное чтение (200 и JSON); переадресация, 404 или страница вместо JSON — «не тот адрес».

**Действия (склад 1.4.57).** Чтобы помощник перемещал товар и отмечал проведение, нужно три вещи: на складе администратор вписал `const ASSIST_ACTIONS = true;` в `config.php` (без этого склад отвечает «Действия выключены на самом складе»), склад подключён под своим логином, и в «Настройки» → «Роли» → «Кладовщик» включён переключатель «Разрешить действия» (с подтверждением в диалоге). Каждое действие — карточка и кнопка «Подтвердить»; в «Истории» склада оно видно с логином и пометкой склада о помощнике (её текст задаёт склад: «через Связного»). Выход, вход под другим логином или устаревший ключ выключают «Разрешить действия» — его нужно включить заново.

После входа роль «Кладовщик» включается сама (если была выключена), в карточке роли и в строке «Склад» — статус («Подключён: ivanov · под своим логином»), на экране подключения — версия описания, какое описание в работе и почему («наше описание главное»: описание сервера берётся, только если оно новее встроенного 1.4.57 и не просит новых действий; действия с записью — только из встроенного) и «Обновить описание». «Выйти» удаляет пароль склада и личный ключ с устройства (ключ снимается и на сервере — действием `sess_end` встроенного описания); роль остаётся включённой и честно говорит «Склад ещё не подключён». Секреты лежат отдельно от задач и `settings.json`, в служебной папке приложения.

В реальном macOS-приложении через `flutter run -d macos` выполнен основной сценарий:

3. Тестовая задача выбрана нажатием и перенесена на сегодня в 18:00.
4. После первого полного завершения процесса и нового `flutter run` тестовая задача осталась в активных с перенесённым сроком.
5. Она была повторно выбрана и завершена. После второго полного перезапуска список показал только заранее существовавшую пользовательскую задачу.
6. Проверка `tasks.json` подтвердила у тестовой записи `status: done`, перенесённый `due_at` и заполненный `completed_at`; временный файл `.tmp` отсутствовал. Пользовательская запись не изменилась.

Debug-приложение: `build/macos/Build/Products/Debug/Relay.app`.
Release-приложение: `build/macos/Build/Products/Release/Relay.app`.

На macOS sandbox-файл находится по пути `~/Library/Containers/com.example.localAssistant/Data/Documents/assistant/tasks.json`. ### GitHub Actions и Android APK

Первый полный CI-запуск [41519500051](https://github.com/halogaloreontc/qenqritec/actions/runs/41519500051) успешно выполнил format/analyze/test и release-сборки всех четырёх платформ. Артефакты того запуска остаются доступны в GitHub Actions.

Для экономии минут текущий workflow использует более узкую схему:

- на каждый `push` и pull request запускается только `verify`: `flutter pub get`, format, analyze и test;
- Android APK дополнительно собирается после `verify` для тегов вида `v*`;
- ту же Android-сборку можно запустить вручную через **Actions → test-and-build → Run workflow**;
- Windows, Linux и macOS jobs в CI отключены, но их runners остаются в проекте для локальных сборок.

Для версионного обновления, например:

```bash
git tag v0.2.0
git push origin v0.2.0
```

Обычный `push` ветки не создаёт новый APK и не тратит минуты release-сборок. Workflow использует runners из репозитория и не вызывает `flutter create` повторно.

## Архитектурная граница

UI зависит от `AssistantController` и `TaskService`, но не от конкретного хранилища и не от коннекторов. Сценарный движок и `match` коннекторов не обращаются к файлам и сети. JSON-репозиторий можно заменить SQLite-реализацией без переписывания диалоговой логики.
