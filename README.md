# Личный помощник — технический прототип

Локальный персональный помощник на Dart/Flutter без обращения к языковой модели. Этот репозиторий реализует первый вертикальный срез, а не весь объём ТЗ.

## Что реализовано

- создание задачи обычной фразой: «Добавь задачу позвонить клиенту завтра в 10», «напомни мне завтра в 9:30 оплатить интернет»; точное название можно взять в кавычки « », “ ”, „ “ или " " — они важнее остального текста;
- сроки «сегодня», «завтра», «послезавтра», дата ДД.ММ[.ГГ|.ГГГГ], время ЧЧ:ММ, «в ЧЧ.ММ», «в 10», «в 9 утра», «в 7 вечера»; при переносе «с … на …» берётся новое значение;
- дни недели и относительные сроки: «в пятницу», «во вт в 10», «в пт к 18:00», «до субботы», «в следующую среду», «на следующей неделе в пятницу», «в эту пятницу», «через 3 дня», «через час», «через полчаса», «через пару дней», «через 2 часа 30 минут», «на следующую неделю», «на выходных», «в конце недели»; слова срока не попадают в название («напомни в пятницу купить хлеб» → «Купить хлеб»), а «пятничный отчёт» или «среда разработки» сроком не считаются;
- перенос и завершение задачи по названию — точному в кавычках или по словам: «Перенеси отчёт на завтра», «Заверши купить хлеб»; при нескольких похожих задачах помощник переспрашивает;
- задачи без слова «добавь»: фраза, которая начинается с действия, — это новая задача: «через 3 дня сдать отчёт», «надо купить хлеб», «не забыть оплатить интернет завтра»; вопросы («купить хлеб?», «купить ли хлеб»), отрицания («купить хлеб не надо»), просьбы к самому помощнику («показать список», «отметить хлеб») и фразы с существительного («ногти постричь») задачами не считаются; такая догадка уступает явной команде другого коннектора («узнать, где лежит 64115» — складу), а дубль активной задачи не создаётся;
- час сразу после дня — время, даже если дальше существительное: «Добавь в следующий понедельник в 9 планёрка» → 09:00, «Планёрка»;
- завершение рассказом о сделанном с подтверждением: «я купил хлеб», «отчёт сдал» → «Отметить «Купить хлеб» выполненной?» → «да»/«нет» (а также «да, купил», «👍», «неа»); рассказ о других («мама купила хлеб») и глагол без предмета («я купил») вопросом не становятся; тем же механизмом подтверждения будут пользоваться изменяющие действия внешних коннекторов (ADR-004);
- расширения: помощник собирается под себя в «Настройки → Расширения» — навыки (задачи, калькулятор, беседа), подключения к внешним приложениям и паки с содержимым (шутки, каламбуры, фразы); включение и выключение сразу, без перезапуска и без сброса истории, выбора и черновика; паки — только данные формата `assistant-pack/1`, встроенные и вставленные JSON-текстом, со строгой проверкой (ADR-005, `docs/EXTENSIONS.md`);
- два помощника — Rio и Noda (ADR-006, `docs/REPLIES.md`): дуэт (основной отвечает, второй пишет первым — например, о просроченных задачах раз в день) или соло; написать второму можно обращением «Noda, …» или выбором в поле ввода; у каждого ответа подпись и метка помощника; «Настройки → Помощники» — режим, основной, стиль каждого с живым примером, «вы»/«ты», эмодзи, частота шуток; смена настроек ничего не сбрасывает и старые ответы не переписывает;
- каталог ответов: каждый ответ — запись по id с подстановкой фактов, стили нейтральный, дружеский, краткий и деловой (`assets/replies/*.json`), род помощника и обращение — разметкой в тексте; свой стиль ставится паком ответов (`type: replies`) со строгой проверкой: факты, вопросы и предупреждения одинаковы во всех стилях;
- калькулятор: «сколько будет 2+2*2», «15% от 2400», «корень из 144», «3,5 умножить на 12», «2400 плюс 15%», «два плюс два», «2^10», скобки и унарный минус; точный счёт на рациональных числах, ответ по-русски («10 / 3 ≈ 3,333333333», «2 400»), деление на ноль и слишком большие числа — понятным текстом; даты, время, телефоны, диапазоны и задачи с числами примерами не считаются;
- беседа: «привет» (по времени суток), «пока», «спасибо», «как дела?» — из настоящего состояния задач и проверки здоровья коннекторов, при сбое — вопрос о жалобе администратору; «кто ты», «что ты умеешь» (только включённые навыки), шутки и каламбуры из включённых паков без повторов, спокойный ответ на грубость; просьбы «говори короче», «давай на ты», «без смайликов», «шути меньше», «Noda, будь основной» меняют настройки сразу, тем же путём, что экран настроек; беседа никогда не перехватывает команды: «привет, добавь задачу купить хлеб» — задача, «привет, сколько будет 2+2» — 4; «хорошо» или «спасибо» в ответ на вопрос «Отметить …?» — переспрос, а не молчаливая отмена (`docs/EXTENSIONS.md`, «Навык «Беседа»»);
- слой коннекторов для команд других приложений: общий разбор сообщения, маршрутизатор с уточнением при спорном выборе, сеть и секреты только внутри коннекторов (ADR-004, инструкция — `docs/CONNECTORS.md`); задачи — встроенный коннектор;
- уточнение вместо догадки: время прошло, дата или время не существуют, несколько разных дней, времён или названий, незакрытая кавычка, отрицание и вопрос вместо команды;
- проекты через метки в команде: «Добавь задачу «Отчёт» #работа»;
- список, выбор, перенос и завершение задач, возврат выполненной задачи в работу;
- постоянное JSON-хранилище с атомарной записью, резервная копия одной кнопкой, настройки в `settings.json`;
- тёмный интерфейс (шрифт Inter) с разделами:
  - **Задачи** — диалог и документ задачи; строка выбранной задачи («её»), быстрые действия, документы с дисков и шаблоны команд по «+», микрофон для голоса при пустом поле, ↑/↓ для прошлых команд, кубик статуса, полоса истории команд, панель задач по группам сроков;
  - **Документ** — название, проект и заметки задачи с автосохранением и простой разметкой (заголовок, жирный, курсив, список, чекбокс);
  - **Обзор** — счётчики, ближайшие задачи, активность выполнения за 8 недель;
  - **Проекты**, **Планирование** (14 дней вперёд), **Хранилище** (путь, размер, копия, архив), **Настройки** (меньше анимации, время сообщений, помощники, расширения, очистка чата, лицензии);
- на телефоне меню и список задач открываются выдвижными панелями;
- модульные и сквозные тесты ядра;
- регрессионный корпус фраз `test/corpus/*.jsonl` (формат — `docs/CORPUS.md`).
- инструмент разработки `tools/corpus_gen` (Python): генерация и перекрёстная разметка фраз для корпуса несколькими моделями — Ollama, Claude, Kimi, DeepSeek, Qwen, Grok, OpenAI.

Примеры команд:

```text
Добавь задачу позвонить клиенту завтра в 11:00
Добавь «Отчёт по „Ромашке“» #работа на 15.11
запиши сдать отчёт #работа
Покажи задачи
Перенеси её на сегодня в 18:00
Перенеси отчёт на завтра в 15:00
напомни в пятницу купить хлеб
через 3 дня сдать отчёт
я купил хлеб
Перенеси звонок клиенту через 3 дня
Заверши её
сколько будет 15% от 2400

как дела?
расскажи шутку
говори короче
```

## Что ещё не реализовано

- голосовой режим общения с помощником: кнопка микрофона уже на месте (при пустом поле ввода) и сообщает, что режим в разработке; нужен выбор движка распознавания речи с учётом ADR-001;
- связка с Google Диском и Яндекс Диском для создания и правки документов через помощника: пункты уже есть в меню «+» с пометкой «скоро»;

- SQLite-репозиторий;
- паки по ссылке и выключение отдельных записей пака; отправка жалоб на сбой коннектора (нужна поддержка на сервере приложения, `docs/CONNECTORS.md`);
- долговременная память;
- облачная синхронизация;
- сетевые коннекторы (первый — склад halowarekeep): интерфейс готов, реализации `HttpTransport` и защищённого `SecretStore` для приложения и разрешения на сеть добавляются вместе с первым из них;
- месяц словом («15 ноября») и части суток без часа («вечером») в сроках;
- Яндекс Диск и Google Drive;
- текстовые и табличные артефакты;

Platform runners для Android, Windows, Linux и macOS уже находятся в репозитории. Повторно выполнять `flutter create` при обычном клонировании или запуске не нужно.

## Требования

Установите стабильный Flutter SDK. Прототип проверен с Flutter 3.47.9 и встроенным Dart 3.13.7 на macOS arm64.

Дополнительные инструменты зависят от платформы:

- Android: Android SDK и Java 17;
- Windows: Visual Studio с рабочей нагрузкой «Разработка классических приложений на C++»;
- Linux: Clang, CMake, Ninja, pkg-config и заголовки GTK 3;
- macOS: полный Xcode и CocoaPods для нативного плагина `path_provider`.

## Первый запуск

Клонирование и запуск из корня проекта:

```bash
git clone https://github.com/halogaloreontc/qenqritec.git
cd qenqritec
flutter pub get
flutter devices
flutter run -d macos
```

Вместо `macos` выберите доступную платформу:

```bash
flutter run -d windows
flutter run -d linux
flutter run -d android
```

Команда `flutter create --platforms=android,windows,linux,macos --project-name local_assistant .` нужна только для намеренного пересоздания runners, а не для обычной настройки. Перед такой регенерацией сохраните изменения: новые версии Flutter могут добавлять шаблонные файлы.

### Проверка приложения и сохранения данных

В реальном macOS-приложении через `flutter run -d macos` выполнен основной сценарий:

1. Создана отдельная задача «Проверка сохранения» на завтра в 11:00.
2. Команда «Покажи задачи» сообщила о двух активных задачах, включая заранее существовавшую пользовательскую.
3. Тестовая задача выбрана нажатием и перенесена на сегодня в 18:00.
4. После первого полного завершения процесса и нового `flutter run` тестовая задача осталась в активных с перенесённым сроком.
5. Она была повторно выбрана и завершена. После второго полного перезапуска список показал только заранее существовавшую пользовательскую задачу.
6. Проверка `tasks.json` подтвердила у тестовой записи `status: done`, перенесённый `due_at` и заполненный `completed_at`; временный файл `.tmp` отсутствовал. Пользовательская запись не изменилась.

Debug-приложение: `build/macos/Build/Products/Debug/local_assistant.app`.
Release-приложение: `build/macos/Build/Products/Release/local_assistant.app`.

На macOS sandbox-файл находится по пути `~/Library/Containers/com.example.localAssistant/Data/Documents/assistant/tasks.json`. На других платформах используется аналогичный подкаталог `assistant/tasks.json` в каталоге документов приложения.

### GitHub Actions и Android APK

Первый полный CI-запуск [41519500051](https://github.com/halogaloreontc/qenqritec/actions/runs/41519500051) успешно выполнил format/analyze/test и release-сборки всех четырёх платформ. Артефакты того запуска остаются доступны в GitHub Actions.

Для экономии минут текущий workflow использует более узкую схему:

- на каждый `push` и pull request запускается только `verify`: `flutter pub get`, format, analyze и test;
- Android APK дополнительно собирается после `verify` для тегов вида `v*`;
- ту же Android-сборку можно запустить вручную через **Actions → test-and-build → Run workflow**;
- Windows, Linux и macOS jobs в CI отключены, но их runners остаются в проекте для локальных сборок.

Для версионного обновления, например:

```bash
git tag v0.2.0
git push origin v0.2.0
```

Обычный `push` ветки не создаёт новый APK и не тратит минуты release-сборок. Workflow использует runners из репозитория и не вызывает `flutter create` повторно.

## Архитектурная граница

UI зависит от `AssistantController` и `TaskService`, но не от конкретного хранилища и не от коннекторов. Сценарный движок и `match` коннекторов не обращаются к файлам и сети. JSON-репозиторий можно заменить SQLite-реализацией без переписывания диалоговой логики.

Подробнее: `docs/ARCHITECTURE.md`.
