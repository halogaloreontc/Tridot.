# Модель понимания — запасной слой «Связного» (ADR-041)

Когда правила ответили «не понял», приложение может спросить «Похоже, вы
хотите …?» (до двух вариантов). Догадку даёт маленький кодировщик фраз на
устройстве: дообученная модель превращает фразу в вектор, а ближайшие
примеры корпуса (kNN, k = 5, голос — сходство) называют команду. «Да» —
команда идёт через обычные правила и разборщики, запись — со своим
подтверждением. Правила модель не заменяет. Здесь — только сборка модели
(шаг 1); работа на устройстве — следующие шаги.

## Уровни

| уровень | в настройках | основа | лицензия | архив |
|---|---|---|---|---|
| `light` | «Лёгкая» | `cointegrated/rubert-tiny2` | MIT | ~33 МБ |
| `accurate` | «Точная» | `deepvk/USER-base` | Apache-2.0 | ~133 МБ |
| `web` | веб-помощник склада | модель `light` | MIT | ~33 МБ |

`web` — та же модель, что у «Лёгкой», но индекс знает только навыки,
которые веб-помощник выполняет сам (`warehouse`, `calc`, `talk` —
`lib/web_widget/widget_session.dart`): примеры других навыков в нём
помечены `none`, и порог подобран на этом наборе. Модель проверяется в
onnxruntime-web (WASM) — `webcheck`.

Версия основы закреплена коммитом (`config.py`, `revision`).

## Собрать у себя

```bash
python3.12 -m venv .venv-intent
.venv-intent/bin/pip install -r tools/intent_model/requirements.txt
.venv-intent/bin/python -m tools.intent_model build --tier light       # ~4 мин на 4 ядрах
.venv-intent/bin/python -m tools.intent_model build --tier accurate    # ~38 мин на 4 ядрах
.venv-intent/bin/python -m tools.intent_model build --tier web --reuse # из готовой light, секунды
(cd tools/intent_model/webcheck && npm ci) && \
  .venv-intent/bin/python -m tools.intent_model webcheck --tier web
.venv-intent/bin/python -m pytest -q tools/intent_model/tests
```

Запускать из корня репозитория: нужна история git (снимки корпуса).
Результат — `tools/intent_model/out/<уровень>/` (в git не попадает):
`tridot-intent-<уровень>-<версия>.zip`, `metrics.json`,
`calibration.json`. `INTENT_MODEL_OUT` меняет папку, `HF_HOME` — кэш
исходных моделей. `--reuse` не пересобирает готовые пробы и модель,
`--no-strict` собирает архив и вне бюджета ошибок (только для опытов).

Шаги по отдельности (так их запускает выпуск, параллельно):

| шаг | что делает |
|---|---|
| `prepare` | корпус → `data/train.jsonl`: метка `<навык>:<команда>` или `none`; без `known_gap`, реплик с `after`, «не понял» с маршрутом в навык, навыка «Пароли» и приватных фраз; дубликаты — один раз |
| `holdout --set fresh\|held2\|held3` | модель на снимке корпуса до разбора пробы (`eval/snapshots.json`), выгрузка в int8, векторы снимка и пробы → `calib/<проба>.npz` |
| `model` | дообучение на всём корпусе, ONNX (кодировщик + пулинг + нормировка), динамический int8, токенизатор, векторы примеров |
| `calibrate` | порог на int8, честно: каждая проба — на модели своего снимка; выбор на fresh, проверка на held2 + held3 |
| `index` | `index.bin`, `labels.json`, файлы пакета |
| `verify` | `metrics.json`: честные метрики, прогон собранного пакета, задержка, размеры; вне бюджета — ошибка |
| `pack --version` | `manifest.json` и архив |
| `finish --version` | calibrate + index + verify + pack |
| `latest` | `latest.json` выпуска из архивов |
| `check-labels` | у каждой метки корпуса есть описание |

## Обучение и порог

- **Дообучение** — SupCon (τ = 0,05), пакет — 16 меток по 4 фразы,
  метки с весом √(число фраз), AdamW, разогрев 10 %. «Лёгкая» —
  lr 1e-4, 4 эпохи; «Точная» — 3e-5, 3 эпохи и подсказка модели
  `query: ` перед фразой (в обучении и на устройстве — `prefix` в
  манифесте). Фразы не длиннее 64 токенов.
- **Подсказка** — победила не `none` и сходство лучшего примера
  победившей метки ≥ порога.
- **Бюджет ошибок** (`config.py`): неверных — не больше 6 % подсказок,
  ложных тревог на фразах «не команда» — не больше 5 %. Порог — наибольшая
  доля верных подсказок на fresh в бюджете. Выпуск падает, если на всех
  трёх пробах вместе бюджет превышен.
- **Порог — на int8.** Квантование сдвигает сходства (у USER-base ~−0,03),
  поэтому порог подбирается на выгруженной модели, а не на исходной.
- **Утечка.** Пробы `eval/fresh|held2|held3.jsonl` — синтетические фразы,
  которые прогнали правилами (`rule_outcome`, `rule_label`) до того, как
  по ним правили корпус. Честная оценка — модель, обученная на корпусе того
  коммита (`eval/snapshots.json`); строки снимка, совпадающие с фразами
  своей пробы (жаккар по словам ≥ 0,8), убираются. Выпускная модель учится
  на всём корпусе — её прогон на пробах (`seen` в `metrics.json`) только
  для сравнения.
- **Метрики.** `catch` — среди фраз, которых правила не поняли, доля
  верных подсказок; `wrong` — неверных; `wrong_of_suggested` — неверных
  среди подсказок; `false_alarm` — подсказок на фразах с меткой `none`.

## Описания команд

`labels.yaml` — что подставить в «Похоже, вы хотите …?»: глагол в
неопределённой форме, с маленькой буквы. Новая команда в корпусе — новая
строка здесь, иначе сборка падает, а `test/tool/intent_labels_test.dart` —
красный.

## Пакет

`tridot-intent-<уровень>-<версия>.zip`:

- `model.int8.onnx` — входы `input_ids`, `attention_mask` (и
  `token_type_ids`, если есть у модели; см. `inputs` в манифесте), int64
  `[пакет, длина]`; выход `embedding` — нормированный вектор `[пакет, dims]`;
  пулинг уже внутри графа;
- `tokenizer.json` и остальные файлы токенизатора;
- `index.bin` — векторы примеров fp16 и номера меток (формат — в
  `pack.py`);
- `labels.json` — метки: `id`, `connector`, `command`, `description`;
  `none` — номер 0;
- `manifest.json` — `format: "tridot-intent/1"`, `tier`, `base_model`,
  `base_revision`, `base_license`, `version`, `threshold`, `k`, `dims`,
  `max_length`, `pooling`, `inputs`, `connectors`, `corpus_hash`,
  `metrics`, `files` (размер и sha256 каждого файла).

## Выпуск

GitHub → Actions → «Выпуск модели понимания» → Run workflow → версия
(`1.0.0`, больше прежней). Секретов не нужно. Пробы (2 уровня × 3) и
модели идут параллельно, каждая задача — 5–20 минут; затем порог,
проверка бюджета, `webcheck`, выпуск `intent-v<версия>` (три архива и
`latest.json`) и постоянный предвыпуск `intent-latest`: сначала архивы,
потом `latest.json` — приложение берёт его по адресу
`…/releases/download/intent-latest/latest.json`:

```json
{"format": "tridot-intent-latest/1", "version": "1.0.0",
 "tiers": {"light": {"url": "…/tridot-intent-light-1.0.0.zip", "size": 0,
                     "sha256": "…", "threshold": 0.9, "k": 5, "dims": 312, …},
           "accurate": {…}, "web": {…}}}
```

## Приватность

- В обучении — только синтетический корпус `test/corpus` и синтетические
  пробы `eval/`. Настоящие фразы пользователей модели не учат никогда:
  выгрузку «Непонятые фразы» разработчик переписывает в синтетические
  аналоги для корпуса, и только они попадают в сборку.
- Навык «Пароли» и фразы о паролях, PIN, кодах, логинах из обучения и
  проверки убраны (`data.is_private` — с запасом). На устройстве такие
  фразы до модели не доходят вовсе (`PasswordPhrases.looksLike`,
  `SecretGuard`).
- Модель работает только на устройстве (в веб-помощнике — в браузере);
  никуда ничего не отправляется.
