# Модель понимания — запасной слой «Связного» (ADR-045)

Когда правила ответили «не понял», приложение может спросить «Похоже, вы
хотите …?» (до двух вариантов). Догадку даёт маленький кодировщик фраз на
устройстве: дообученная модель превращает фразу в вектор, а ближайшие
примеры корпуса (kNN, k = 5, голос — сходство) называют команду. «Да» —
команда идёт через обычные правила и разборщики, запись — со своим
подтверждением. Правила модель не заменяет. Здесь — только сборка модели
(шаг 1); работа на устройстве — следующие шаги.

## Уровни

| уровень | в настройках | основа | лицензия | архив |
|---|---|---|---|---|
| `accurate` | «Точная» | `deepvk/USER-base` | Apache-2.0 | ~133 МБ |
| `web` | веб-помощник склада | основа `accurate`, своя модель | Apache-2.0 | ~133 МБ |

Уровень `light` («Лёгкая», `cointegrated/rubert-tiny2`, ~33 МБ) снят
2026-11-25 (ADR-045, дополнение): приложение переводит его на «Точную».
Числа «Лёгкой» ниже оставлены для истории.

`web` — своя модель на основе «Точной» (USER-base, тот же размер):
дообучение на корпусе и синтетических перефразах команд склада
(`aug/warehouse.jsonl`), а индекс знает только навыки, которые веб-помощник
выполняет сам (`warehouse`, `calc`, `talk` —
`lib/web_widget/widget_session.dart`): примеры других навыков в нём помечены
`none`. Порог подбирается на fresh/held2/held3 и половине `cal` складской
пробы `eval/warehouse.jsonl`, вторая половина (`test`) — только честная
проверка (см. «Обучение и порог»). Модель проверяется в onnxruntime-web
(WASM) — `webcheck`. До 2026-11-24 уровень строился на основе «Лёгкой»
(rubert-tiny2, архив ~32 МБ): на проверочном складе она ловила заметно
меньше, чем хотелось, и владелец перевёл веб на «Точную» ценой более
тяжёлой закачки (~131 МБ вместо ~32; браузер кладёт файлы в кэш, но первый
запуск на слабом канале заметен). Уровень наследует от «Точной» скорость
обучения, эпохи, префикс `query: `, поканальное int8 и кодирование по одной
фразе (`bs1_vectors`).

Версия основы закреплена коммитом (`config.py`, `revision`).

## Собрать у себя

```bash
python3.12 -m venv .venv-intent
.venv-intent/bin/pip install -r tools/intent_model/requirements.txt
.venv-intent/bin/python -m tools.intent_model build --tier accurate    # ~38 мин на 4 ядрах
.venv-intent/bin/python -m tools.intent_model build --tier web         # ~35 мин на 4 ядрах
(cd tools/intent_model/webcheck && npm ci) && \
  .venv-intent/bin/python -m tools.intent_model webcheck --tier web
.venv-intent/bin/python -m pytest -q tools/intent_model/tests
```

Запускать из корня репозитория: нужна история git (снимки корпуса).
Результат — `tools/intent_model/out/<уровень>/` (в git не попадает):
`tridot-intent-<уровень>-<версия>.zip`, `metrics.json`,
`calibration.json`. `INTENT_MODEL_OUT` меняет папку, `HF_HOME` — кэш
исходных моделей. `--reuse` не пересобирает готовые пробы и модель,
`--no-strict` собирает архив и вне бюджета ошибок (только для опытов).

Шаги по отдельности (так их запускает выпуск, параллельно):

| шаг | что делает |
|---|---|
| `prepare` | корпус → `data/train.jsonl`: метка `<навык>:<команда>` или `none`; без `known_gap`, реплик с `after`, «не понял» с маршрутом в навык, навыка «Пароли» и приватных фраз; дубликаты — один раз |
| `holdout --set fresh\|held2\|held3\|warehouse` | модель на снимке корпуса до разбора пробы (`eval/snapshots.json`), выгрузка в int8, векторы снимка и пробы → `calib/<проба>.npz`; `warehouse` — только у `web` |
| `model` | дообучение на всём корпусе, ONNX (кодировщик + пулинг + нормировка), динамический int8, токенизатор, векторы примеров |
| `calibrate` | порог на int8, честно: каждая проба — на модели своего снимка; accurate — выбор на fresh, проверка на held2 + held3; web — выбор на fresh + held2 + held3 + `warehouse.cal`, проверка на `warehouse.test` |
| `index` | `index.bin`, `labels.json`, файлы пакета |
| `verify` | `metrics.json`: честные метрики, прогон собранного пакета, задержка, размеры; вне бюджета (у web — ещё и на `warehouse.test`) — ошибка |
| `pack --version` | `manifest.json` и архив |
| `finish --version` | calibrate + index + verify + pack |
| `latest` | `latest.json` выпуска из архивов |
| `check-labels` | у каждой метки корпуса есть описание |

## Обучение и порог

- **Дообучение** — SupCon (τ = 0,05), пакет — 16 меток по 4 фразы,
  метки с весом √(число фраз), AdamW, разогрев 10 %. «Точная» —
  lr 3e-5, 3 эпохи и подсказка модели
  `query: ` перед фразой (в обучении и на устройстве — `prefix` в
  манифесте); `web` — те же параметры, что у «Точной». Фразы не длиннее
  64 токенов.
- **Подсказка** — победила не `none` и сходство лучшего примера
  победившей метки ≥ порога.
- **Бюджет ошибок** (`config.py`): неверных — не больше 6 % подсказок,
  ложных тревог на фразах «не команда» — не больше 5 %. Порог — наибольшая
  доля верных подсказок на fresh в бюджете. Выпуск падает, если на всех
  трёх пробах вместе бюджет превышен.
- **Порог — на int8.** Квантование сдвигает сходства (у USER-base ~−0,03),
  поэтому порог подбирается на выгруженной модели, а не на исходной.
- **Кодирование — по одной фразе, где это важно.** Динамическое int8
  (`DynamicQuantizeLinear`) считает масштаб активаций по всему тензору
  пакета, включая паддинг до общей длины — вектор фразы зависит от того,
  с кем она попала в пакет. На устройстве фраза кодируется одна
  (`lib/core/intent/intent_encoder.dart`), а в сборке `Int8Encoder.encode`
  по умолчанию работает пакетами по 32. Измерено (bs=1 без паддинга —
  как на устройстве — против пакета 32, та же модель, те же фразы):

  | уровень | основа | косинус bs=1 vs bs=32 (min / медиана) | честный порог без/с правкой | честные ложные тревоги без/с правкой |
  |---|---|---|---|---|---|
  | light | rubert-tiny2 | 0,997 / 0,999 | не менялся | 2,3 % → не менялся |
  | accurate | USER-base | 0,84 / 0,96 | 0,88 → 0,895 | 4,6 % (held2+held3 — 6,5 %) → 3,1 % (held2+held3 — 2,4 %) |

  У `light` сдвиг косинуса пренебрежимо мал, бюджет не затронут — правка
  не включена. У `accurate` (`USER-base`, 12 слоёв) сдвиг большой: индекс,
  собранный пакетами по 32, и запрос с устройства (одна фраза) расходятся
  достаточно, чтобы честные метрики менялись на несколько пунктов, —
  `Tier.bs1_vectors = True` (`config.py`) заставляет `holdout`, `model` и
  `verify` кодировать индекс и пробы по одной фразе без паддинга, как
  будет на устройстве. `web` строится на основе «Точной» и наследует
  `bs1_vectors`; `light` оставлен как есть. Проверить и воспроизвести
  измерение (после `model --tier <уровень>`):

  ```bash
  .venv-intent/bin/python -m tools.intent_model.bs_compare accurate
  ```

  пишет `out/<уровень>/bs_compare.json` (не входит в сборку и выпуск,
  только для проверки).
- **Утечка.** Пробы `eval/fresh|held2|held3.jsonl` — синтетические фразы,
  которые прогнали правилами (`rule_outcome`, `rule_label`) до того, как
  по ним правили корпус. Честная оценка — модель, обученная на корпусе того
  коммита (`eval/snapshots.json`); строки снимка, совпадающие с фразами
  своей пробы (жаккар по словам ≥ 0,8), убираются. Выпускная модель учится
  на всём корпусе — её прогон на пробах (`seen` в `metrics.json`) только
  для сравнения.
- **Складская проба** (`eval/warehouse.jsonl`, 250 фраз) — для `web`:
  команды склада речью кладовщика, калькулятор и беседа на складе, «не
  команды» со словами «сколько», «остаток», «ячейка», «приход». Делится
  пополам `data.split_half` (по каждой метке через одну по id): `cal` —
  в подбор порога, `test` — нет. Перефразы для обучения `aug/warehouse.jsonl`
  — с другими товарами и ячейками, жаккар с любой фразой проб < 0,5
  (`tests/test_prepare.py`). Новые фразы в пробу после её разбора не
  дописываются: нужна новая проба со своим снимком.
- **Метрики.** `catch` — среди фраз, которых правила не поняли, доля
  верных подсказок; `wrong` — неверных; `wrong_of_suggested` — неверных
  среди подсказок; `false_alarm` — подсказок на фразах с меткой `none`.

## Что получилось (0.1.0, 2026-11-20)

Локально, 4 ядра; честно — каждая проба на модели своего снимка.

| уровень | порог | поймано: все / held2+held3 | неверных из подсказок | ложные тревоги | архив | фраза, 1 поток | сборка |
|---|---|---|---|---|---|---|---|
| light | 0,91 | 26,6 % / 20,7 % | 5,0 % | 2,3 % | 32 МБ | 0,7 мс | 4 мин |
| accurate (до правки bs=1) | 0,88 | 52,8 % / 53,2 % | 3,4 % | 4,6 % (held2+held3 — 6,5 %) | 131 МБ | 13,5 мс | ~38 мин подряд, ~10 мин на задачу в выпуске |
| **accurate (с правкой bs=1, 2026-11-22)** | **0,895** | **38,3 % / 36,0 %** | **3,5 %** | **3,1 % (held2+held3 — 2,4 %)** | 131 МБ | 8,5 мс | ~30 мин подряд |
| web (0.1.0) | 0,94 | 14,9 % фраз с командой своих навыков | 0 % | 0 % | 32 МБ | 0,7 мс | секунды после light |

`accurate` до правки калибровался на векторах, закодированных пакетами
по 32 (индекс и пробы), — распределение, которого устройство не видит:
оно кодирует запрос один (ADR-045, раздел «Кодирование — по одной фразе,
где это важно» выше). С правкой (`Tier.bs1_vectors`) порог и честные
метрики посчитаны на той же кодировке, что у устройства: поймано меньше
(модель честно теряет подсказки, которые раньше казались уверенными из-за
смещения квантования от соседей по пакету), но ложных тревог меньше и
бюджет больше не на грани (было 6,5 % на held2+held3 — уже вне бюджета,
если бы его проверяли отдельно от fresh). `light` правка не затронула —
бюджет и так не на грани (см. измерение выше).

`web` со складской пробой и своей моделью **на прежней основе rubert-tiny2**
(2026-11-22), отложенная половина `warehouse.test` (125 фраз: 49 команд,
которых правила не поняли, 35 «не команд»):

| `web` | порог | поймано | неверных из подсказок | ложные тревоги |
|---|---|---|---|---|
| модель light, порог по fresh (0.1.0) | 0,94 | 2,0 % | 0 % | 0 % |
| своя модель, порог по fresh+held2+held3+cal | 0,88 | 61,2 % | 0 % | 2,9 % |

Все пробы вместе: поймано 33,2 % (было 4,7 %), неверных 4,4 % подсказок,
ложных тревог 1,5 %; архив 32 МБ, 0,55 мс на фразу. Проба и перефразы
написаны по одним описаниям команд — 61 % скорее верхняя оценка.
С 2026-11-24 уровень `web` строится на основе «Точной» (USER-base):
числа выше относятся к прежней основе и оставлены для истории; новые
замеры появятся с первым выпуском на новой основе.

## Описания команд

`labels.yaml` — что подставить в «Похоже, вы хотите …?»: глагол в
неопределённой форме, с маленькой буквы. Новая команда в корпусе — новая
строка здесь, иначе сборка падает, а `test/tool/intent_labels_test.dart` —
красный.

## Пакет

`tridot-intent-<уровень>-<версия>.zip`:

- `model.int8.onnx` — входы `input_ids`, `attention_mask` (и
  `token_type_ids`, если есть у модели; см. `inputs` в манифесте), int64
  `[пакет, длина]`; выход `embedding` — нормированный вектор `[пакет, dims]`;
  пулинг уже внутри графа;
- `tokenizer.json` и остальные файлы токенизатора;
- `index.bin` — векторы примеров fp16 и номера меток (формат — в
  `pack.py`);
- `labels.json` — метки: `id`, `connector`, `command`, `description`;
  `none` — номер 0;
- `manifest.json` — `format: "tridot-intent/1"`, `tier`, `base_model`,
  `base_revision`, `base_license`, `version`, `threshold`, `k`, `dims`,
  `max_length`, `pooling`, `inputs`, `connectors`, `corpus_hash`,
  `metrics`, `files` (размер и sha256 каждого файла).

## Выпуск

GitHub → Actions → «Выпуск модели понимания» → Run workflow → версия
(`1.0.0`, больше прежней). Секретов не нужно. Пробы (`accurate` × 3,
`web` × 4) и модели идут параллельно, каждая задача — 5–20 минут; затем
порог, проверка бюджета, `webcheck`, выпуск `intent-v<версия>` (два архива
и `latest.json`) и постоянный предвыпуск `intent-latest`: сначала архивы,
потом `latest.json` — приложение берёт его по адресу
`…/releases/download/intent-latest/latest.json`:

```json
{"format": "tridot-intent-latest/1", "version": "1.0.0",
 "tiers": {"accurate": {"url": "…/tridot-intent-accurate-1.0.0.zip", "size": 0,
                        "sha256": "…", "threshold": 0.9, "k": 5, "dims": 768, …},
           "web": {…}}}
```

## Эталоны для Dart

Токенизаторы на устройстве (`lib/core/intent/intent_tokenizer.dart`, шаг 2)
сверяются с HuggingFace tokenizers:

```bash
.venv-intent/bin/python -m tools.intent_model.dart_fixtures --packs <папка с распакованным accurate/>
```

пишет `test/fixtures/intent/` (номера токенов для синтетических фраз
`phrases.txt` и урезанные `tokenizer.json` — только нужные этим фразам
токены и слияния) и `lib/core/intent/bert_chars.g.dart` (классы знаков
BertNormalizer и BertPreTokenizer по всем кодовым точкам). Эталоны снятой
«Лёгкой» (WordPiece) без её пакета не пересобираются, а переносятся как
есть. `test/fixtures/intent/accurate_expect.json` — векторы и подсказки
«Точной» для `test/intent/onnx_real_model_test.dart`; файла пока нет, тест
пропускается без него и без распакованного пакета.

## Приватность

- В обучении — только синтетический корпус `test/corpus` и синтетические
  пробы `eval/`. Настоящие фразы пользователей модели не учат никогда:
  выгрузку «Непонятые фразы» разработчик переписывает в синтетические
  аналоги для корпуса, и только они попадают в сборку.
- Навык «Пароли» и фразы о паролях, PIN, кодах, логинах из обучения и
  проверки убраны (`data.is_private` — с запасом). На устройстве такие
  фразы до модели не доходят вовсе (`PasswordPhrases.looksLike`,
  `SecretGuard`).
- Модель работает только на устройстве (в веб-помощнике — в браузере);
  никуда ничего не отправляется.
