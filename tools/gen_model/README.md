# Замеры «Продвинутой» — генеративная модель на устройстве (ADR-046, шаг 1)

Кандидаты — Qwen в GGUF Q4_K_M (`config.py`: ревизия и sha256
закреплены). Здесь только замеры: какая модель годится и для чего. Пакет
для приложения и выпуск — следующие шаги.

## Собрать у себя

```bash
python3 -m venv .venv-gen
CMAKE_ARGS="-DGGML_NATIVE=ON" .venv-gen/bin/pip install -r tools/gen_model/requirements.txt
.venv-gen/bin/python -m tools.gen_model fetch  --model qwen3-1.7b
.venv-gen/bin/python -m tools.gen_model intent --model qwen3-1.7b            # без примеров
.venv-gen/bin/python -m tools.gen_model intent --model qwen3-1.7b --shots 3  # 3 фразы на команду
.venv-gen/bin/python -m tools.gen_model bench  --model qwen3-1.7b
.venv-gen/bin/python -m tools.gen_model tasks  --model qwen3-1.7b            # поля, таблицы, пересказ
.venv-gen/bin/python -m tools.gen_model agree  --model qwen3-4b --tag intent-shots3
.venv-gen/bin/python -m pytest -q tools/gen_model/tests
```

Запускать из корня репозитория: примеры берутся из снимков корпуса в
истории git. Модели — в `~/.cache/tridot-gen` (`GEN_MODEL_CACHE`),
результаты — `tools/gen_model/out/<модель>/` (в git не попадают).

## Подсказка при «не понял»

- **Пробы и метрики — те же, что у «Лёгкой»** (`tools/intent_model`):
  fresh, held2, held3; `catch`, `wrong_of_suggested`, `false_alarm`;
  бюджет — не больше 6 % неверных подсказок и 5 % ложных тревог. Порог
  подбирается на fresh, проверка — held2 + held3. Прогоняются фразы,
  которых правила не поняли, и «не команды» (344 фразы).
- **Вывод ограничен списком меток** (`choose.py`): метки и `none`
  токенизируются в дерево, на каждом шаге разрешены только продолжения из
  него. Уверенность — произведение вероятностей шагов, перенормированных
  по разрешённым токенам.
- **Честность.** В запросе — описания команд из `labels.yaml`. С
  `--shots N` — ещё N фраз на команду из снимка корпуса до разбора пробы;
  фразы снимка, похожие на фразы пробы, убираются тем же правилом, что у
  «Лёгкой».

## Что получилось (2026-11-25)

CPU контейнера: 4 ядра x86, 4 потока; телефон будет медленнее.
«В бюджете» — есть ли порог, при котором уложились в бюджет ошибок.

| модель | примеры | поймано (без порога) | неверных из подсказок | ложные тревоги | в бюджете | фраза, медиана |
|---|---|---|---|---|---|---|
| «Лёгкая» (USER-base, kNN; для сравнения) | корпус | 38,3 % | 3,5 % | 3,1 % | да, порог 0,895 | 8,5 мс |
| Qwen2.5-1.5B | нет | 43,9 % | 56,1 % | 93,1 % | порог 0,99: 3,7 % поймано | 0,24 с |
| Qwen3-1.7B | нет | 17,3 % | 47,1 % | 23,1 % | нет | 0,24 с |
| Qwen3-1.7B | 3 | 30,8 % | 36,5 % | 17,7 % | нет | 0,40 с |
| Qwen3-4B-Instruct-2507 | нет | 65,9 % | 31,9 % | 63,1 % | нет | 0,63 с |
| Qwen3-4B-Instruct-2507 | 3 | **77,1 %** | 18,3 % | 53,8 % | нет | 0,95 с |

Скорость и память (`bench`, запрос 67 токенов, жадная генерация):

| модель | файл | память процесса | разбор запроса | генерация |
|---|---|---|---|---|
| Qwen2.5-1.5B | 1,1 ГБ | 2,2 ГБ | 215 ток/с | 19 ток/с |
| Qwen3-1.7B | 1,1 ГБ | 2,8 ГБ | 137 ток/с | 15 ток/с |
| Qwen3-4B-Instruct-2507 | 2,5 ГБ | 5,7 ГБ | 75 ток/с | 8 ток/с |

Память — с контекстом 4096 токенов. Системный запрос с описаниями команд
(934 токена, с примерами — 3303) прогоняется один раз и кэшируется.

**Выводы.**

- Qwen3-4B с примерами чаще всех угадывает команду: 77 % того, что не
  поняли правила, против 38 % у «Лёгкой». Но она слишком уверена в себе:
  «не команды» («через полтора часа поезд», «а пятница у нас какого
  числа») получают метку с уверенностью ~1,0. Ложных тревог 54 %, и
  никакой порог по уверенности не укладывает их в бюджет.
- Малые модели (1.5B, 1.7B) хуже «Лёгкой» по всем метрикам.
- Значит, **сама по себе** генеративная модель для этой подсказки не
  годится. Следующий опыт — согласие двух слоёв: подсказка, только если
  метка Qwen есть среди ближайших меток «Лёгкой» (её kNN уже отсекает
  «не команды»). Для него нужны векторы проб «Лёгкой» (`tools/intent_model`,
  шаг `holdout`).
- Пересказ по-русски Qwen3-1.7B пишет связно (`bench`, пример в
  `out/<модель>/bench.json`). Таблицы, поля и пересказ — свои пробы на
  следующих шагах.

## Согласие с «Лёгкой» (2026-11-26)

`agree.py`: подсказка Qwen, только если её метка среди m первых меток kNN
«Лёгкой» (`agree@m`); порог — по сходству «Лёгкой» для этой метки, подбор
на fresh, проверка — held2 + held3. Векторы «Лёгкой» — честные пробы
`tools/intent_model` (`holdout --tier accurate`, модель на снимке каждой
пробы); её числа совпали с ADR-045 (38,3 %, порог 0,895) — замер тот же.

| вариант | порог | поймано: все / held2+held3 | неверных из подсказок | ложные тревоги | в бюджете (held2+held3) |
|---|---|---|---|---|---|
| «Лёгкая» одна | 0,895 | 38,3 % / 36,0 % | 3,5 % | 3,1 % | да |
| **Qwen3-4B, 3 примера, agree@1** | 0,86 | **56,1 % / 56,8 %** | 2,4 % | 3,8 % (2,2 %) | **да** |
| Qwen3-4B, 3 примера, agree@2 | 0,88 | 45,3 % / 45,0 % | 4,0 % | 5,4 % (6,5 %) | нет |
| Qwen3-4B без примеров, agree@1 | 0,835 | 50,5 % / 50,5 % | 2,7 % | 7,7 % (13,0 %) | нет |
| Qwen3-1.7B, 3 примера, agree@1 | 0,825 | 24,8 % / 22,5 % | 1,9 % | 3,1 % (2,2 %) | да, но хуже «Лёгкой» |

Согласие Qwen3-4B с первой меткой «Лёгкой» служит фильтром: «Лёгкая»
может опустить порог (0,86 вместо 0,895) и ловит в полтора раза больше.

## Таблицы, поля, пересказ (2026-11-26)

`tasks`: 24 вопроса к двум таблицам, 30 фраз для карточки, 6 текстов.

| модель | таблицы: верных ответов | поля: название / дата / время / всё верно | пересказ: факты / длина к тексту | секунд на ответ (таблица, поле, пересказ) |
|---|---|---|---|---|
| Qwen2.5-1.5B | 62,5 % | 96,7 / 30,0 / 80,0 / 23,3 % | 100 % / 1,00 | 3,4 / 3,6 / 6,1 |
| Qwen3-1.7B | 41,7 % | 100 / 43,3 / 76,7 / 23,3 % | 83 % / 0,75 | 3,9 / 4,0 / 5,7 |
| **Qwen3-4B-Instruct-2507** | **95,8 %** | 100 / 63,3 / 90,0 / 56,7 % | 100 % / 0,99 | 7,5 / 6,5 / 13,5 |

- **Таблицы.** Qwen3-4B ошиблась в одном вопросе из 24: «сколько поставок
  на сумму больше 3000» — сумма вместо количества. Считает код, поэтому
  выдуманных чисел нет.
- **Поля.** Название все модели достают почти всегда, а даты путают
  («завтра» → 1 декабря). Значит, дату и время должны разбирать правила
  (`due_parser`), модель — только название и прочие поля.
- **Пересказ.** Выдуманных чисел нет ни у кого, но 1.5B и 4B почти дословно
  повторяют короткие тексты (длина 0,99–1,00): проба из 6 коротких
  текстов пересказ почти не меряет. Нужны длинные тексты.
- Время — CPU контейнера, 4 потока; на телефоне медленнее.

## Выпуск (2026-11-26)

`release.py` и GitHub → Actions → «Выпуск модели «Продвинутой»» → версия.
Официальные веса `Qwen/Qwen3-4B-Instruct-2507` (ревизия закреплена) →
bf16 GGUF (`convert_hf_to_gguf.py` из `tool/fetch_llama.sh`, окружение
`.venv-intent` + `requirements-convert.txt`) → Q5_K_M (llama-cpp-python) →
проба таблиц (не меньше 22 из 24, иначе выпуска нет) → части по 1900 МиБ
(GitHub не принимает файлы выпуска больше 2 ГиБ) → `gen-v<версия>` и
`gen-latest` (`latest.json`: размер и sha256 частей и целого файла).

```bash
tool/fetch_llama.sh
.venv-intent/bin/pip install -r tools/gen_model/requirements-convert.txt
.venv-gen/bin/python   -m tools.gen_model.release weights
.venv-intent/bin/python -m tools.gen_model.release convert
.venv-gen/bin/python   -m tools.gen_model.release quantize --version 1.0.0
.venv-gen/bin/python   -m tools.gen_model.release verify   --version 1.0.0
.venv-gen/bin/python   -m tools.gen_model.release split    --version 1.0.0
```

Своя сборка из официальных весов, проба таблиц (CPU контейнера, 4 потока):

| квантование | файл | таблицы | генерация |
|---|---|---|---|
| Q4_K_M | 2,50 ГБ | 22 из 24 (сумма вместо количества — дважды) | 6,6 ток/с |
| **Q5_K_M** | 2,89 ГБ | **24 из 24** | 5,2 ток/с |

Готовое квантование unsloth (Q4_K_M с матрицей важности) — 23 из 24;
своя Q4_K_M без матрицы — ровно на пороге, поэтому выпуск — Q5_K_M.
