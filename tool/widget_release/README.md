# Выпуск веб-помощника «Связной» для складов

Веб-помощник — тот же «Связной», собранный для браузера
(`lib/web_widget/main.dart`, ADR-032). Склад (DepotDesk и halowarekeep)
ставит его к себе в папку `assistant/` и открывает кнопкой-роботом в шапке
панелью поверх склада. Каждый выпуск — архив, подписанный ключом издателя:
склад ставит только архив с верной подписью.

Всё делается в интерфейсе склада и на сайте GitHub — без терминала и SSH
(ADR-035):

- **ключ издателя** создаётся на складе, в браузере: закрытый — в секрет
  GitHub `SVYAZNOY_SIGN_KEY`, открытый остаётся на складах;
- **выпуск** — кнопкой Run workflow в GitHub Actions: сборка, подпись,
  проверка, выпуск `web-v<версия>` в Releases и, если задан бакет, загрузка
  в него — тогда склады сами видят обновление;
- **ставит** всегда администратор склада.

Подробности устройства — `docs/WEB_WIDGET.md`. Как раньше, со своего
компьютера, — в конце, «Без GitHub Actions».

## Один раз

### 1. Ключ издателя — на складе

1. Склад → Управление → Инструменты → Помощник → блок «Веб-помощник
   «Связной»» → «Ключ издателя» → «Создать ключ».
2. Склад покажет **закрытый ключ** один раз: «Скопировать» или «Скачать
   файл .pem» (`svyaznoy-sign.pem`). Сохраните копию в менеджере паролей.
   Склад его не хранит и на сервер не отправляет; потеряете — новый ключ
   придётся задать на каждом складе.
3. GitHub → репозиторий Tridot → Settings → Secrets and variables →
   Actions → New repository secret:
   - Name: `SVYAZNOY_SIGN_KEY`;
   - Secret: весь текст ключа вместе со строками
     `-----BEGIN PRIVATE KEY-----` и `-----END PRIVATE KEY-----`;
   - Add secret.
4. Второй склад: тот же блок → «У меня уже есть ключ» → вставьте
   **открытый ключ** (44 знака, кончается на `=`) — его показывает первый
   склад, кнопка «Скопировать открытый ключ». Отпечатки (вида
   `21fe 31df a154 a261` — см. «Отпечаток ключа») на обоих складах должны
   совпасть.

Со склада ключ задаётся только пока его там нет. Потом склад показывает
отпечаток, а сменить ключ можно только на сервере: `ASSIST_WEB_PUBKEY` в
`config.php` главнее ключа из интерфейса. Так чужой, укравший вход
администратора, не подменит издателя.

### 2. Бакет для автообновлений — по желанию

Без бакета каждый выпуск ставится руками: архив из Releases → на складе
«Загрузить архив…» (в первый раз эта кнопка — рядом с «Установить
помощника»; чтобы склад не искал бакет, «Источник обновлений» → «Изменить»
→ «Без бакета»). С бакетом склады раз в сутки (или по «Проверить») сами
скачивают новую версию, проверяют подпись и предлагают «Установить».

Консоль Yandex Cloud (`console.yandex.cloud`), нужный каталог:

1. **Бакет.** Object Storage → «Создать бакет»:
   - имя — `svyaznoy-web`: склады по умолчанию смотрят
     `https://storage.yandexcloud.net/svyaznoy-web/svyaznoy-web/latest.json`.
     Имена бакетов общие на весь Yandex Cloud; если имя занято — возьмите
     другое и на складах в «Источник обновлений» → «Изменить» замените
     первое `svyaznoy-web` в адресе своим именем;
   - чтение объектов — **публичное**; чтение списка объектов и настроек —
     закрытое (ограниченное);
   - класс хранилища — стандартное, размера в 1 ГБ хватит надолго;
   - «Создать бакет».
2. **Сервисный аккаунт.** Identity and Access Management → «Сервисные
   аккаунты» → «Создать сервисный аккаунт»: имя `svyaznoy-release`, ролей
   не добавляйте → «Создать».
3. **Право писать в бакет.** Object Storage → бакет `svyaznoy-web` →
   «Безопасность» → «Права доступа» → «Назначить роли» → аккаунт
   `svyaznoy-release` → роль `storage.uploader` → «Сохранить». Если такой
   вкладки у бакета нет — выдайте ту же роль на каталог (каталог → «Права
   доступа» → «Назначить роли»): тогда аккаунт сможет писать во все бакеты
   каталога.
4. **Ключ доступа.** «Сервисные аккаунты» → `svyaznoy-release` → «Создать
   новый ключ» → «Создать статический ключ доступа» → «Создать». Консоль
   покажет идентификатор ключа и секретный ключ — один раз.
5. **Секреты в GitHub.** Tridot → Settings → Secrets and variables →
   Actions → New repository secret, три раза:
   - `SVYAZNOY_BUCKET` — имя бакета (`svyaznoy-web`);
   - `AWS_ACCESS_KEY_ID` — идентификатор ключа;
   - `AWS_SECRET_ACCESS_KEY` — секретный ключ.

   Нужны все три или ни одного: с частью секретов выпуск сразу отказывает.

### 3. На серверах складов

Обычно ничего руками: шаг «Сервер» на складе показывает, чего не
хватает, и объясняет. Нужны PHP-модули `sodium` и `zip`
(без них помощник не ставится вовсе), для автообновлений — `curl`; папку
`assistant/` готовит выкладка склада. Блок Nginx из README склада —
только ускорение, не обязателен. Cron отдельно настраивать не нужно.

Тип `.wasm` на сервере не важен: если сервер отдаёт его не как
`application/wasm` (старый `mime.types` Nginx), загрузчик помощника сам
компилирует CanvasKit из ArrayBuffer (`web/flutter_bootstrap.js`,
проверено в Chromium). Шаг «Сервер» тогда покажет совет — строка
`application/wasm wasm;` в `/etc/nginx/mime.types` лишь чуть ускоряет
первое открытие, её можно не добавлять.

## Каждый выпуск

1. GitHub → Tridot → Actions → «Выпуск веб-помощника» → Run workflow:
   - Branch — `main`;
   - version — три числа, больше прежней: `1.0.0`, `1.0.1`, `1.1.0`;
   - notes — что нового, это увидит администратор склада (можно пусто);
   - Run workflow.

   Кнопка появляется, когда файл `.github/workflows/web-assistant-release.yml`
   есть в `main`.
2. Минут через 5–10 — зелёная галочка. В итогах запуска (Summary) —
   **отпечаток ключа издателя**: он должен совпасть с отпечатком на складе.
   Не совпадает — склад выпуск не примет: в `SVYAZNOY_SIGN_KEY` другой ключ.
3. Releases → `web-v<версия>`: `svyaznoy-web-<версия>.zip` и `latest.json`.
4. На складе, Инструменты → Помощник:
   - первый раз — «Установить помощника» (с бакетом склад скачает выпуск
     сам) или рядом «Загрузить архив…» и zip из Releases — склад проверит
     подпись и поставит сразу;
   - дальше с бакетом — «Проверить» (или подождать до суток) →
     «Установить»;
   - дальше без бакета — скачайте zip из Releases → «Загрузить архив…» →
     «Установить».

До сборки запуск проверяет и сразу отказывает с понятной причиной: версия
не вида `1.0.0`, такой выпуск уже есть (выпуски не перезаписываются),
версия меньше прежней, нет `SVYAZNOY_SIGN_KEY` или в нём не ключ, бакет
задан не всеми тремя секретами. Загрузка в бакет упала — поправьте секреты
и запустите снова с той же версией: выпуск в Releases создаётся последним.
Бакет не отдаёт `latest.json` без входа — в итогах будет предупреждение:
включите у бакета публичное чтение объектов.

Ключ подписи — корень доверия всех складов, поэтому в запуске он есть
только в шагах без чужого кода: `flutter build web` (хуки пакетов,
плагины) идёт без него, а подписывает исполняемый файл инструмента,
собранный заранее (`dart compile exe`) — без `dart run` рядом с ключом.
Действия закреплены по коммиту, токен checkout в `.git/config` не
остаётся.

Если с новой версией что-то не так — Инструменты → Помощник →
«Откатить»: склад хранит предыдущую версию.

## Отпечаток ключа

Короткая строка, чтобы сверить ключ глазами: на складе, в итогах выпуска и
в описании выпуска в Releases она одна и та же.

- Берутся 32 байта открытого ключа Ed25519 — не base64 и не DER.
- sha256 от них, первые 16 знаков hex строчными, по 4 через пробел
  (64 бита: подобрать другой ключ с тем же отпечатком не по силам).
- Пример: ключ `11qYAYKxCrfVS/7TyWQHOg7hcvPapiMlrwIaaPcHURo=` (RFC 8032,
  тест 1) → `21fe 31df a154 a261`.

```sh
dart run tool/widget_release/release.dart fingerprint <открытый ключ>
# или без Dart:
printf %s '<открытый ключ>' | base64 -d | sha256sum | cut -c1-16 | sed 's/..../& /g; s/ $//'
```

Подпись склад проверяет полным ключом; отпечаток — только для глаз.

## Без GitHub Actions: со своего компьютера

Нужны Flutter, OpenSSL 3 (`openssl version` — 3.x; на Mac — `brew install
openssl@3`) и, для бакета, `aws-cli`.

### Ключ

Создать на складе («Создать ключ» → «Скачать файл .pem») или так:

```sh
openssl genpkey -algorithm ed25519 -out svyaznoy-sign.pem
chmod 600 svyaznoy-sign.pem
```

Храните `svyaznoy-sign.pem` только у себя, вне репозиториев. Открытый
ключ — на склад, «У меня уже есть ключ»:

```sh
SVYAZNOY_SIGN_KEY_FILE=svyaznoy-sign.pem \
  dart run tool/widget_release/release.dart pubkey
# или без Dart:
openssl pkey -in svyaznoy-sign.pem -pubout -outform DER | tail -c 32 | base64
```

### Сборка, проверка, загрузка

1. Сборка и подпись (из корня репозитория Tridot):

   ```sh
   export PATH=/opt/flutter/bin:$PATH        # где у вас Flutter
   export SVYAZNOY_SIGN_KEY_FILE=~/keys/svyaznoy-sign.pem
   dart run tool/widget_release/release.dart build --version 1.0.0 \
     --notes "Первая версия: вопросы складу, карточки, голос в приложении"
   ```

   Вместо пути к файлу можно передать сам ключ:
   `SVYAZNOY_SIGN_KEY="$(cat svyaznoy-sign.pem)"` (так делает выпуск в
   GitHub Actions) — инструмент положит его во временный файл с правами 600
   и сотрёт после подписи. Переносы `\r\n`, текст в одну строку и
   буквальные `\n` он поправит сам.

   Результат — `build/widget_release/1.0.0/`:
   - `svyaznoy-web-1.0.0.zip` — архив (внутри сборка, `_release.json` со
     списком файлов и их sha256, `_release.sig` — подпись);
   - `latest.json` — `{version, minApi, minServer, url, size, sha256,
     notes, sig}`.

   Дополнительно: `--notes-file файл.txt`, `--min-api 1`,
   `--min-server depotdesk=1.4.63,halowarekeep=1.4.67`, `--url`
   (по умолчанию архив лежит рядом с `latest.json`), `--skip-build`
   (взять готовую `build/web`; только если её собрал этот же инструмент с
   той же `--version` — иначе отказ: версия зашита в `main.dart.js`, и
   помощник с чужой версией не заметит ни обновления, ни отката).

2. Проверка — так же, как проверит склад:

   ```sh
   dart run tool/widget_release/release.dart verify \
     build/widget_release/1.0.0/latest.json --pubkey <открытый ключ>
   ```

3. Загрузка в бакет — **сначала архив, потом `latest.json`**:
   - скриптом:

     ```sh
     export SVYAZNOY_BUCKET=svyaznoy-web
     export AWS_ACCESS_KEY_ID=…  AWS_SECRET_ACCESS_KEY=…   # статический ключ
     tool/widget_release/upload.sh build/widget_release/1.0.0
     ```

   - или руками в консоли Yandex Cloud: папка `svyaznoy-web/` в бакете →
     загрузить `svyaznoy-web-1.0.0.zip`, затем `latest.json` (заменить
     прежний). У `latest.json` в свойствах объекта поставьте
     `Cache-Control: no-cache`.

4. Без бакета: на складе Инструменты → Помощник → «Загрузить архив…» →
   `svyaznoy-web-1.0.0.zip` → «Установить» (в первый раз «Загрузить
   архив…» — рядом с «Установить помощника», ставит сразу). Проверка
   подписи та же.

## Голос

Голос работает только в приложениях склада для Android (DepotDesk 1.6.0,
halowarekeep 1.5.0 и новее) на Android 12+: распознавание на самом телефоне,
без облака. Новые APK оболочек нужно собрать и раздать один раз — сам
помощник при этом обновляется архивами, как обычно. В браузере и на
компьютере кнопки микрофона нет.
