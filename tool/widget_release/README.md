# Выпуск веб-помощника «Связной» для складов

Веб-помощник — тот же «Связной», собранный для браузера
(`lib/web_widget/main.dart`, ADR-032). Склад (DepotDesk и halowarekeep)
ставит его к себе в папку `assistant/` и открывает кнопкой-роботом в шапке
панелью поверх склада. Каждый выпуск — архив, подписанный ключом владельца:
склад ставит только архив с верной подписью.

Подробности устройства — `docs/WEB_WIDGET.md`.

## Один раз: что сделать владельцу

### 1. Ключ подписи

Нужен OpenSSL 3 (`openssl version` — 3.x; на Mac — `brew install openssl@3`).

```sh
openssl genpkey -algorithm ed25519 -out svyaznoy-sign.pem
chmod 600 svyaznoy-sign.pem
```

- `svyaznoy-sign.pem` — **закрытый ключ**. Храните только у себя, вне
  репозиториев: в менеджере паролей или на зашифрованном диске, плюс копия
  на флешке в сейфе. Никому не пересылайте и никуда не загружайте.
- Открытый ключ (короткая строка, не секрет):

  ```sh
  SVYAZNOY_SIGN_KEY_FILE=svyaznoy-sign.pem \
    dart run tool/widget_release/release.dart pubkey
  ```

  или без Dart:

  ```sh
  openssl pkey -in svyaznoy-sign.pem -pubout -outform DER | tail -c 32 | base64
  ```

  Эту строку (44 знака, кончается на `=`) впишите на обоих складах в
  `ASSIST_WEB_PUBKEY` (в `config.php` или прямо в код — она не секрет) или
  пришлите разработчику.

Ключ потерян — новые выпуски не подписать: создайте новый ключ и впишите
его открытый ключ на складах. До замены склад не примет ни одного нового
архива — даже загруженного вручную: проверка подписи у них одна.

### 2. Бакет для обновлений (Yandex Object Storage)

1. Консоль Yandex Cloud → Object Storage → «Создать бакет».
   Имя, например, `svyaznoy-web`. Доступ на **чтение объектов — публичный**,
   на чтение списка объектов — **закрытый**.
2. Сервисный аккаунт с ролью `storage.uploader` только на этот бакет →
   «Создать новый ключ» → «Статический ключ доступа». Идентификатор и
   секрет сохраните у себя (менеджер паролей). В репозиторий не кладите.
3. Адрес обновлений для склада:
   `https://storage.yandexcloud.net/svyaznoy-web/svyaznoy-web/latest.json`
   — его впишите на складах в `ASSIST_WEB_UPDATES` (или пришлите
   разработчику).

Склад сам раз в сутки смотрит `latest.json`, скачивает новый архив,
проверяет подпись и размер и показывает администратору в «Инструменты →
Помощник»: «Доступна X — что нового — Установить / Отложить». Ставит
всегда администратор.

### 3. На серверах складов

- PHP с `sodium`, `zip` и `curl`: `php -m | grep -E 'sodium|zip|curl'`.
  Нет — `apt install php-zip php-curl` (sodium обычно в `php-common`). Без
  sodium или zip склад помощника не ставит вовсе и пишет почему; без curl —
  сам не скачивает обновления, остаётся «Загрузить архив…».
- PHP (пользователь PHP-FPM / Apache) должен иметь право записи в корень
  сайта — склад создаёт там папку `assistant/` — или заранее создайте
  `assistant/` и отдайте её этому пользователю.
- Nginx — один раз добавить блок `location /assistant/` из README склада.
- Cron отдельно настраивать не нужно.

## Каждый выпуск

1. Версия — три числа, больше прежней: `1.0.0`, `1.0.1`, `1.1.0`.
2. Сборка, проверка и подпись (из корня репозитория Tridot):

   ```sh
   export PATH=/opt/flutter/bin:$PATH        # где у вас Flutter
   export SVYAZNOY_SIGN_KEY_FILE=~/keys/svyaznoy-sign.pem
   dart run tool/widget_release/release.dart build --version 1.0.0 \
     --notes "Первая версия: вопросы складу, карточки, голос в приложении"
   ```

   Вместо пути к файлу можно передать сам ключ:
   `SVYAZNOY_SIGN_KEY="$(cat svyaznoy-sign.pem)"` — инструмент положит его
   во временный файл с правами 600 и сотрёт после подписи.

   Результат — `build/widget_release/1.0.0/`:
   - `svyaznoy-web-1.0.0.zip` — архив (внутри сборка, `_release.json` со
     списком файлов и их sha256, `_release.sig` — подпись);
   - `latest.json` — `{version, minApi, minServer, url, size, sha256,
     notes, sig}`.

   Дополнительно: `--notes-file файл.txt`, `--min-api 1`,
   `--min-server depotdesk=1.4.63,halowarekeep=1.4.67`, `--url`
   (по умолчанию архив лежит рядом с `latest.json`), `--skip-build`
   (взять готовую `build/web`; только если её собрал этот же инструмент с
   той же `--version` — иначе отказ: версия зашита в `main.dart.js`, и
   помощник с чужой версией не заметит ни обновления, ни отката).

3. Проверка — так же, как проверит склад:

   ```sh
   dart run tool/widget_release/release.dart verify \
     build/widget_release/1.0.0/latest.json --pubkey <открытый ключ>
   ```

4. Загрузка в бакет — **сначала архив, потом `latest.json`**:
   - скриптом (нужен `aws-cli`):

     ```sh
     export SVYAZNOY_BUCKET=svyaznoy-web
     export AWS_ACCESS_KEY_ID=…  AWS_SECRET_ACCESS_KEY=…   # статический ключ
     tool/widget_release/upload.sh build/widget_release/1.0.0
     ```

   - или руками в консоли Yandex Cloud: папка `svyaznoy-web/` в бакете →
     загрузить `svyaznoy-web-1.0.0.zip`, затем `latest.json` (заменить
     прежний). У `latest.json` в свойствах объекта поставьте
     `Cache-Control: no-cache`.

5. Без бакета (или сразу, не дожидаясь проверки раз в сутки): на складе
   Инструменты → Помощник → «Загрузить архив…» → выбрать
   `svyaznoy-web-1.0.0.zip` → «Установить». Проверка подписи та же.

Если что-то пошло не так — Инструменты → Помощник → «Откатить»: склад
хранит предыдущую версию.

## Голос

Голос работает только в приложениях склада для Android (DepotDesk 1.6.0,
halowarekeep 1.5.0 и новее) на Android 12+: распознавание на самом телефоне,
без облака. Новые APK оболочек нужно собрать и раздать один раз — сам
помощник при этом обновляется архивами, как обычно. В браузере и на
компьютере кнопки микрофона нет.
